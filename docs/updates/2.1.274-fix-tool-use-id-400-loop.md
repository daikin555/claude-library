## 原文（日本語訳）

「unexpected tool_use_id」という400エラーを延々とリトライし続けてスタックしてしまう問題を修正しました。破損したトランスクリプトは可能な場合は自動的に自己修復され、修復できない場合は明確なエラー（`/rewind` のヒント付き）を表示してループを終了するようになりました。

## 原文（英語）

Fixed sessions getting stuck endlessly retrying "unexpected tool_use_id" 400 errors: corrupted transcripts now self-heal where possible, and otherwise a clear error (with a `/rewind` hint) ends the loop

## 概要

何らかの原因でセッションのトランスクリプト（会話履歴）にツール呼び出しIDの不整合が生じると、APIから「unexpected tool_use_id」という400エラーが返され、これまではその状態のまま同じエラーを延々とリトライし続け、セッションが実質的にフリーズしてしまうことがありました。今回の修正では、可能な場合はトランスクリプトを自動的に修復して処理を継続し、修復できない場合は無限ループに陥る前に明確なエラーメッセージを表示し、`/rewind` コマンドを使った復旧方法をヒントとして案内するようになりました。

## 基本的な使い方

この修正はバグ修正であり、特別な操作は不要です。万が一トランスクリプトの不整合が検出された場合、自動修復されるか、以下のようなエラーが表示されます。

```
Error: Corrupted transcript detected (unexpected tool_use_id).
Hint: try `/rewind` to return to a previous, valid checkpoint.
```

## 実践例

### 修正前の挙動

以前は、トランスクリプトの不整合により「unexpected tool_use_id」400エラーが発生すると、Claude Codeが同じリクエストを延々とリトライし続け、ユーザーはセッションを強制終了するしかありませんでした。

### 修正後の挙動

同じ状況が発生しても、まず自動修復が試みられ、それでも解決しない場合は明確なエラーメッセージとともに `/rewind` で以前の状態に戻る方法が案内されるため、ユーザーは迷わず復旧できます。

```
/rewind
```

## 注意点

- 自動修復が常に成功するとは限りません。修復できない場合はエラーメッセージに従って `/rewind` を使い、問題が発生する前の状態に戻してください。
- この問題は主にトランスクリプトが何らかの理由で破損した場合にのみ発生する稀なケースです。
