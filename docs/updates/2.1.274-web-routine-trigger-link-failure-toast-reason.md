## 原文（日本語訳）
[Claude Code on the web] GitHubトリガーを連携できなかったルーティンを保存した際に表示されるトースト通知で、「リポジトリごとのトリガー数上限」のような具体的な理由を表示するように修正しました。これまでは「edit to retry（編集して再試行）」としか表示されていませんでした。

## 原文（英語）
[Claude Code on the web] Fixed the toast after saving a routine whose GitHub trigger couldn't be linked to show the reason, such as a per-repository trigger limit, instead of only "edit to retry"

## 概要
Claude Code on the webのルーティン機能では、GitHub上のイベント（issueの作成やPRのオープンなど）をトリガーとして自動実行を設定できます。しかし、リポジトリごとのトリガー数上限に達しているなどの理由でGitHubトリガーの連携に失敗した場合、これまでは原因が示されず「edit to retry」というメッセージしか表示されず、ユーザーは何を直せばよいのか分かりませんでした。今回の修正により、失敗理由が具体的にトースト通知に表示されるようになり、問題の特定と解決がしやすくなりました。

## 基本的な使い方
1. ルーティンの作成・編集画面でGitHubトリガーを設定する
2. ルーティンを保存する
3. トリガー連携に失敗した場合、表示されるトースト通知に具体的な失敗理由（例: リポジトリごとのトリガー数上限に到達）が表示される

## 実践例

### トリガー数上限に達した場合
1つのリポジトリに対して設定可能なGitHubトリガーの数に上限があり、既に上限に達している状態で新しいルーティンを保存しようとすると、トーストに「このリポジトリのトリガー数上限に達しています」といった具体的な理由が表示されます。

### 原因に応じた対処
表示された理由をもとに、不要になった既存のトリガー付きルーティンを削除する、あるいは別のリポジトリでルーティンを設定するなど、適切な対処を選択できるようになります。

## 注意点
- 表示される理由の文言は失敗要因によって異なります。
- トリガー連携が失敗しても、ルーティン自体の保存は可能な場合があります（トリガーなしの状態で保存されるなど）。詳細はルーティン編集画面の案内に従ってください。
