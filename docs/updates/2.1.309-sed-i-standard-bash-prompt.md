## 原文（日本語に翻訳）

`sed -i` を、シミュレートされたファイル編集プレビューではなく、標準のBashプロンプトで確認し、書かれたとおりに実行するよう変更しました。他のBash編集と同様、`/rewind` では復元されなくなります

## 原文（英語）

Changed `sed -i` to get the standard Bash prompt and run as written, not a simulated file-edit preview; like other Bash edits, it is no longer restored by `/rewind`

## 概要

これまで `sed -i` はEditツール風のdiffプレビューとして表示されていましたが、v2.1.309からは他のBashコマンドと同じ標準の権限プロンプトで確認され、入力されたとおりに実行されます。実際に走るコマンドと画面上の表示が一致します。一方、Bash経由の編集であるため `/rewind` によるコード復元の対象外になります。

## 基本的な使い方

```bash
claude "config.js の foo を bar に置換して"
# Claude が sed -i 's/foo/bar/g' config.js を提案
# → 通常のBash権限プロンプトが表示され、承認するとそのまま実行される
```

## 実践例

### 権限ルールで制御する

`sed -i` は通常のBashコマンドなので、権限ルールで管理できます。

```json
{
  "permissions": {
    "ask": ["Bash(sed -i:*)"]
  }
}
```

### 巻き戻しが必要な編集

`/rewind` で戻したい変更は、Edit/Writeツールで行うよう依頼するか、事前にgitでコミットしておきます。

```bash
git add -A && git commit -m "wip: before bulk replace"
claude "Editツールを使って src/ 内の旧API名を置換して"
```

## 注意点

- `sed -i` による変更は `/rewind` で復元されません
- プレビューがなくなるため、承認前にコマンド文字列（対象ファイルと置換式）をよく確認してください
- 大きな変更の前はgitコミットで退避しておくと安全です
