## 原文（日本語に翻訳）

プラグインおよびマーケットプレイスのメッセージ、ログ、そして `claude plugin marketplace list` が、git、ssh、またはマーケットプレイスのURLに保存されたパスワードやトークンを表示してしまっていた問題を修正

## 原文（英語）

Fixed plugin and marketplace messages, logs and `claude plugin marketplace list` showing a password or token stored in a git, ssh or marketplace URL

## 概要

認証情報を含むURL（例：`https://user:token@github.com/...` のような形式）でgitリポジトリやマーケットプレイスを指定している場合、これまではプラグイン・マーケットプレイス関連のメッセージやログ、および `claude plugin marketplace list` コマンドの出力にパスワードやトークンがそのまま表示されてしまうことがありました。これはログの共有やスクリーンショットの際に認証情報が漏洩するリスクがありました。今回の修正により、これらの表示箇所で機密情報がマスクされるようになりました。

## 基本的な使い方

認証情報を含むURLでマーケットプレイスを追加していても、一覧表示や関連ログで機密情報が露出しなくなりました。

```bash
claude plugin marketplace list
# → URLに含まれるトークンやパスワードはマスクされて表示される
```

## 実践例

### 認証情報付きのgit URLでマーケットプレイスを利用している場合

社内のプライベートリポジトリをトークン付きURLでマーケットプレイスとして登録しているケースで、ログや一覧表示に機密情報が残らなくなります。

```bash
claude plugin marketplace add https://x-access-token:ghp_xxxx@github.com/org/private-plugins
claude plugin marketplace list
# → トークン部分がマスクされて表示される
```

### ssh URLを使っている場合も同様に保護される

ssh形式の認証情報付きURLでも、ログやメッセージ内での機密情報の露出が防がれます。

```bash
claude plugin marketplace add ssh://git@internal.example.com/org/plugins.git
# ログ出力等で認証情報がそのまま表示されない
```

## 注意点

- この修正はログや表示上のマスキングに関するものであり、URLへの認証情報の埋め込み自体を推奨するものではありません
- 可能であればssh鍵やgit credential helperなど、URLに直接認証情報を埋め込まない方法の利用を検討してください
- 既にログファイルなどに出力済みの過去の認証情報は、この修正では保護されないため、必要に応じてローテーションしてください
