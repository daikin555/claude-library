## 原文（日本語訳）

vimモードのカーソル配置を修正しました。`dd`、`dj`、`dG`、または行全体の `p`/`P` の後はカーソルが最初の非空白文字に位置し、`yy` はカーソルを移動させなくなり、絵文字の後のEscでカーソルが絵文字の中に留まらなくなりました。

## 原文（英語）

Fixed vim mode cursor placement: after `dd`, `dj`, `dG` or a whole-line `p`/`P` it lands on the first non-blank, `yy` no longer moves it, and Esc after an emoji no longer leaves it inside the emoji

## 概要

Claude Codeのvimモードで、いくつかの操作の後にカーソルが本来のvimと異なる位置に配置される不具合がありました。行削除系の `dd`・`dj`・`dG`、行全体を貼り付ける `p`/`P` の後は、標準的なvimと同様にカーソルが行の最初の非空白文字に移動するようになりました。また、行をヤンクするだけの `yy` はカーソル位置を変えないように修正され、絵文字の直後にEscでノーマルモードに戻った際にカーソルが絵文字の内部（表示上不自然な位置）に留まってしまう問題も解消されました。

## 基本的な使い方

```
/vim
```

でvimモードを有効にし、以下のような操作でカーソル位置の挙動を確認できます。

```
dd    " 現在行を削除 → カーソルは次の行の最初の非空白文字へ
yy    " 現在行をヤンク → カーソル位置は変わらない
```

## 実践例

### 行削除後の続けざまの編集

`dd` で不要な行を削除した直後、カーソルが正しい位置（次の行頭の非空白文字）にあることで、そのまま続けて別の編集操作にスムーズに移れます。

### 絵文字を含むプロンプトの編集

絵文字を使ったメッセージ末尾でEscを押してノーマルモードに戻る際、カーソル位置が不自然にならず、その後の `x` や `a` といった操作が期待通りに機能します。

## 注意点

- これらの修正は標準的なvimの挙動に合わせるためのものです。vimに慣れているユーザーほど違いを感じやすい変更です
- 絵文字は表示上複数のバイト・コードポイントで構成されるため、他のテキストエディタでも同様のカーソル位置の問題が起きやすい領域です
