## 原文（日本語訳）

macOS/Linuxのネイティブビルドに組み込まれている `grep` が改善されました。メモリを枯渇させるような病的な正規表現パターンは、以前は処理が詰まってしまっていましたが、今回から早期に失敗するようになりました。また `-m N` オプションを `-A`（後方コンテキスト）や `-C`（前後コンテキスト）と併用した際に、正しいコンテキスト行が表示されるようになりました。

## 原文（英語）

Improved the embedded `grep` in native macOS/Linux builds: pathological patterns now fail fast instead of exhausting memory, and `-m N` with `-A/-C` prints correct context

## 概要

Claude CodeのネイティブビルドはGrepツールの実行に、外部の `grep` コマンドに依存しない組み込み実装を使用しています。今回の改善では、バックトラックが爆発的に増えるような複雑（病的）な正規表現パターンを検索に使った場合に、メモリを使い果たしてプロセスが不安定になる前に処理を早期に打ち切って失敗を返すようになりました。あわせて、マッチ件数を制限する `-m N` オプションと、マッチ周辺の行を表示する `-A`（after）や `-C`（context）オプションを同時に指定した際に、表示されるコンテキスト行がずれる・欠落するといった不具合も修正されています。

## 基本的な使い方

Grepツールやターミナル上での `grep` コマンド利用時に、通常の検索であれば挙動に変化はありません。複雑な正規表現を使った検索や、マッチ数の制限とコンテキスト表示を組み合わせた検索で違いが体感できます。

```bash
# マッチを3件までに制限しつつ、各マッチの前後2行を表示する
grep -m 3 -C 2 "TODO" src/**/*.ts
```

## 実践例

### 複雑な正規表現による大規模コードベースの検索

バックトラックが多発しやすい正規表現（例えば、ネストした量指定子を含むパターンなど）を大きなファイルやコードベース全体に対して実行すると、以前はメモリを使い切ってフリーズや異常終了につながる恐れがありました。今回の修正により、そうした病的パターンは早期に検出されエラーとして返るため、Claude Codeのプロセス全体が巻き込まれにくくなります。

```bash
# 意図せず病的な複雑さを持ってしまった正規表現の例
grep -E "(a+)+b" large_file.log
```

### マッチ件数の制限とコンテキスト表示を組み合わせる

ログファイルなどから最初の数件のエラーとその前後の文脈だけを確認したい場合に `-m` と `-A`/`-C` を組み合わせて使います。修正前はこの組み合わせでコンテキスト行がずれて表示されることがありましたが、修正後は指定した件数分、正しい前後の行が表示されます。

```bash
grep -m 5 -A 3 "Error" server.log
```

### エージェントによる自動検索の安定性向上

Claude CodeがGrepツールを内部的に使ってコードベースを調査する際、ユーザーが直接コマンドを入力するわけではありませんが、生成された検索パターンが複雑になるケースもあります。組み込みgrepが病的パターンに対して早期に失敗するようになったことで、こうした自動調査中に処理がハングするリスクが下がり、エージェントの動作全体の安定性向上につながります。

## 注意点

- この改善はmacOS/Linuxのネイティブビルドに組み込まれている `grep` 実装が対象です。他のプラットフォームや外部コマンドとしての `grep` には直接関係しません
- 病的パターンが「早期に失敗する」ようになったため、これまで（時間はかかっても）結果が得られていた一部の非常に複雑なクエリはエラーとして扱われる可能性があります。その場合は正規表現をよりシンプルな形に書き換えることを検討してください
