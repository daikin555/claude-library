## 原文（日本語訳）

[Claude Tag] Enterprise Grid内の別のワークスペースから依頼された場合に、組織全体で共有されているEnterprise Gridチャンネルの視聴をClaudeが拒否してしまう不具合を修正しました。

## 原文（英語）

[Claude Tag] Fixed Claude refusing to watch an Enterprise Grid channel shared with the whole organization when asked from another workspace in the grid

## 概要

Slack Enterprise Gridでは、複数のワークスペースが1つの組織に属し、チャンネルを組織全体で共有できます。これまで、あるワークスペースからグリッド共有チャンネルの監視をClaude Tagに依頼すると、権限確認のロジックに問題があり、正当な依頼であってもClaudeが視聴を拒否してしまうことがありました。今回の修正により、Enterprise Grid内の別ワークスペースからの依頼でも、組織全体に共有されたチャンネルであれば正しく認識され、視聴依頼が受け入れられるようになりました。

## 基本的な使い方

Slack上でClaude Tagに対して、グリッド共有チャンネルの監視を依頼するだけです。

```
@Claude このチャンネルの会話を見ておいて
```

別ワークスペースから依頼した場合でも、そのチャンネルが組織全体に共有されていれば、修正後は正しく処理されます。

## 実践例

### 別ワークスペースからの監視依頼

Enterprise Grid内でワークスペースAとワークスペースBがあり、`#company-announcements` のようなチャンネルが両方に共有されているケースを想定します。

```
# ワークスペースBのユーザーが依頼
@Claude #company-announcements の内容を追跡して、重要な更新があったら教えて
```

修正前はClaudeがこの依頼を拒否することがありましたが、修正後は正しくチャンネルを認識し、依頼を受け付けます。

### 修正前後の挙動比較

- 修正前: グリッド共有チャンネルへのアクセス権限チェックが、依頼元ワークスペースを基準に誤判定し、拒否メッセージを返すことがあった
- 修正後: チャンネルが組織全体で共有されている場合、依頼元のワークスペースに関わらず正しく視聴依頼を受け付ける

## 注意点

- この修正はEnterprise Gridを利用している組織にのみ関係します
- チャンネル自体へのアクセス権限は引き続き必要です（Claudeがチャンネルに参加していない、またはユーザーがチャンネルのメンバーでない場合は別の制約が適用されます)
- Claude Tagのセットアップや権限設定については公式ドキュメントを参照してください
