## 原文（日本語訳）

動的ワークフローの実行中に ← キーを押したり `/background` を実行したりすると、完了済みのサブエージェントが再起動してしまう問題を修正しました。現在は事前に確認を求め、何個のサブエージェントが再起動対象になるかを表示するようになりました。

## 原文（英語）

Fixed pressing ← or running `/background` during a dynamic workflow restarting its finished subagents; it now asks first and says how many subagents would restart

## 概要

動的ワークフロー（複数のサブエージェントを並行・連鎖的に動かす仕組み）の実行中に、履歴を戻る操作（←キー）やセッションをバックグラウンド化する `/background` コマンドを使うと、すでに完了しているサブエージェントまで意図せず再起動してしまう問題がありました。再実行によって余計なAPI呼び出しや作業の重複が発生し、ユーザーが気づかないうちにコストや実行時間が余分にかかる可能性がありました。この修正により、これらの操作を行った際にはまず確認プロンプトが表示され、再起動されるサブエージェントの数が明示されるようになります。

## 基本的な使い方

動的ワークフローの実行中に ← キーや `/background` を使うと、以下のような確認が表示されます。

```
この操作により、完了済みのサブエージェント3個が再起動されます。続行しますか？ (y/n)
```

ユーザーは再起動が本当に必要かどうかを確認してから操作を続行できます。

## 実践例

### 複数サブエージェントによる並行調査タスク

コードベース全体を複数のサブエージェントで並行調査させている最中に、誤って ← キーを押してしまうケースがあります。従来はそのまま完了済みの調査結果が失われて再実行されていましたが、修正後は事前に警告が出るため、誤操作による無駄な再実行を防げます。

### 長時間ワークフローをバックグラウンド化する場面

複数ステップのサブエージェントが連鎖するワークフローを `/background` でバックグラウンドに移そうとした際、すでに完了しているサブエージェントまで再起動されると時間とコストの無駄になります。確認メッセージにより、何個のサブエージェントが影響を受けるかを事前に把握してから判断できます。

### 誤操作からのリカバリー

作業中に誤って ← キーを押してしまった場合でも、即座に再起動が始まるのではなく確認ダイアログが挟まるため、意図しない再実行が発生する前にキャンセルできます。

## 注意点

- 確認は動的ワークフロー実行中に限った挙動です。通常の単一エージェント操作では表示されません
- 表示される再起動対象の数は、その時点で完了しているサブエージェントの数に基づきます
- 確認をキャンセルすれば、← キーや `/background` の操作自体も取り消されます
