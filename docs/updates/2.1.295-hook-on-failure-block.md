# フックの onFailure: "block" で失敗時にアクションをブロックする

## 原文（日本語に翻訳）

コマンドフックと HTTP フックに `onFailure: "block"` を追加しました。フックが起動できない、タイムアウトする、または想定外の終了コードで終わった場合に、アクションをそのまま通すのではなくブロックします。

## 原文（英語）

Added `onFailure: "block"` for command and HTTP hooks: a hook that can't start, times out, or exits with an unexpected code blocks the action instead of letting it through

## 概要

これまでフック自体が失敗した場合、アクションは通過する（フェイルオープン）のが基本でした。`onFailure: "block"` を指定すると、フックの失敗時にアクションを止める（フェイルクローズ）挙動にできます。セキュリティ上のガードとして使うフックで、ガードが動かないまま危険な操作が通るのを防げます。

## 基本的な使い方

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": "./scripts/guard.sh",
            "timeout": 10,
            "onFailure": "block"
          }
        ]
      }
    ]
  }
}
```

## 実践例

### 危険なコマンドのガードを確実に効かせる

ガードスクリプトが見つからない、依存コマンドが無い、タイムアウトした、といった場合でも Bash の実行を許可しません。

### HTTP フックで外部ポリシーサーバーに問い合わせる

```json
{
  "type": "http",
  "url": "https://policy.example.com/check",
  "timeout": 5,
  "onFailure": "block"
}
```

ポリシーサーバーが落ちている間は対象アクションが止まるため、監査要件が厳しい環境に向いています。

## 注意点

- フックの失敗でアクションが止まるため、タイムアウト値やスクリプトの存在を事前に確認してください。
- 設定キーの正確な配置は公式のフックドキュメントで確認してください。
