## 原文（日本語訳）
ローカルセッションにおけるアーティファクト監視の挙動が変更されました。他の場所で新しいバージョンが公開されても、もはやターンが自動開始されることはなく、Claudeは後続のArtifactツール結果を通じてそれを知ることになります。

## 原文（英語）
Changed artifact watching in local sessions: a new version published elsewhere no longer starts a turn; Claude learns of it from a later Artifact tool result

## 概要
Claude Codeのローカルセッションでは、アーティファクト（Artifact）が別の場所（例えば別セッションやWeb UI）で更新されると、それを検知する仕組みがあります。これまでは新バージョンの公開を検知すると自動的に新しいターンが開始されていましたが、これは意図しないタイミングでの割り込みにつながることがありました。今回の変更で、新バージョンの公開はもはやターンを自動的に開始せず、Claudeは次にArtifactツールを使った際の結果を通じて変更を認識するようになります。

## 基本的な使い方
ユーザー側で特別な操作は不要です。アーティファクトを扱うセッションを通常通り進めるだけです。

```
# アーティファクトを編集・参照する通常のやり取り
```

## 実践例

### 変更前の挙動
あるセッションでアーティファクトを開いている間に、別の場所（他のセッションやWeb UI）でそのアーティファクトの新バージョンが公開されると、ローカルセッションで自動的に新しいターンが始まり、ユーザーが意図しないタイミングでClaudeが応答することがありました。

### 変更後の挙動
同じ状況でも、ローカルセッションのターンは自動的には開始されません。Claudeは、次にArtifactツールを呼び出して結果を受け取ったタイミングで初めて新バージョンの存在を認識します。これにより、ユーザーが作業中に予期せぬ割り込みを受けることが減ります。

## 注意点
- アーティファクトの変更をすぐに反映させたい場合は、明示的にArtifactツールを使う操作（参照・更新など）を行う必要があります。
- この変更はローカルセッションにおける挙動であり、他の場所でのアーティファクト公開自体には影響しません。
