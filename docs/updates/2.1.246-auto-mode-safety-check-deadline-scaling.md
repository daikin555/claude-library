## 原文（日本語訳）

非常に大きなセッションにおいて、auto modeのツール呼び出しが「一時的に利用できません」として拒否されてしまう問題を修正しました。安全性チェックのタイムアウト（デッドライン）をプロンプトサイズに応じてスケールさせることで対応しています。

## 原文（英語）

Fixed auto mode tool calls being denied as "temporarily unavailable" on very large sessions by scaling the safety-check deadline with prompt size

## 概要

auto modeでは、ツール呼び出しを実行する前にバックグラウンドで安全性チェック（プロンプトインジェクションなどの検知）が行われます。このチェックには時間制限（デッドライン）が設けられていますが、従来は固定的な時間しか与えられていなかったため、非常に大きなセッション（長いコンテキストや大きなプロンプト）では安全性チェックの処理に通常より時間がかかり、デッドラインに間に合わずツール呼び出しが「一時的に利用できません」として拒否されてしまうことがありました。この修正では、安全性チェックのデッドラインをプロンプトサイズに応じて動的にスケールさせることで、大規模セッションでも安全性チェックが正常に完了し、正当なツール呼び出しが誤って拒否されなくなります。

## 基本的な使い方

この修正はauto mode内部の安全性チェック機構に関するもので、ユーザーが直接設定する項目はありません。大規模なコンテキストを扱うセッションでauto modeを使用している場合、以降は次のように改善されます。

```
修正前（大規模セッション）: ツール呼び出しが一時的に利用できません（安全性チェックのタイムアウト）
修正後: プロンプトサイズに応じてデッドラインが拡張され、安全性チェックが正常に完了してツールが実行される
```

## 実践例

### 大規模コードベースを扱う長時間セッション

大規模なリポジトリ全体を読み込んでコンテキストが肥大化した状態でauto modeを使っている場合、安全性チェックにかかる時間も比例して増加します。この修正により、そうした状況でも正当なツール呼び出しが不必要に拒否されることがなくなります。

### 長い会話履歴を持つ継続セッション

同じセッションで長時間にわたり多数のやり取りを重ね、プロンプト全体が大きくなっている状態でも、安全性チェックのデッドラインがそれに応じて調整されるため、auto modeの動作が安定します。

### 複数ファイルを一括で読み込む調査タスク

多数のファイルを読み込んで大きなコンテキストを構築した上でツールを呼び出すような調査タスクにおいても、安全性チェックが十分な時間を確保できるようになり、誤検知によるツール拒否が減少します。

## 注意点

- この修正は安全性チェック自体を無効化・簡略化するものではなく、チェックに要する時間の見積もりをより実態に合わせて調整するものです
- 極端に大きいプロンプトの場合でも、安全性チェックには依然として何らかの時間制限が存在します
- auto modeの安全性チェックに関する挙動全般については、公式ドキュメントも参照してください
