# Bashコマンドの「task output swap refused」エラーを修正（Mac）

## 原文（日本語訳）

一部のMac環境で、Bashコマンドが「task output swap refused (tasks dir moved or linked)」というエラーで失敗する問題を修正しました。

## 原文（英語）

Fixed Bash commands failing with "task output swap refused (tasks dir moved or linked)" on some Macs

## 概要

Claude Code 2.1.252では、Bashコマンドの実行結果（特にバックグラウンドタスクの出力）を一時的にディスクへ退避（スワップ）する処理が、特定のMac環境で失敗していた問題が修正されました。タスク用の一時ディレクトリがシンボリックリンクになっていたり、クラウド同期ツール（iCloud Drive、Dropboxなど）によって別の場所に移動・リンクされていたりする環境で発生していた不具合です。この修正により、該当する環境でもBashコマンドが正常に完了するようになりました。

## 基本的な使い方

この修正はClaude Code本体のバグ修正であり、ユーザー側で特別な操作をする必要はありません。Claude Codeを最新バージョンに更新するだけで適用されます。

```bash
# Claude Codeを最新版に更新
claude update

# バージョンを確認
claude --version
```

更新後は、通常通りBashツールやバックグラウンドタスクを利用できます。

```bash
# 通常のBashコマンド実行
ls -la

# バックグラウンドでの長時間実行タスク
# (Claude Codeに「バックグラウンドで実行して」と依頼するか、Ctrl+Bでバックグラウンドに移動)
npm run dev
```

## 実践例

### 1. iCloud Drive上のプロジェクトで作業する場合

macOSで `~/Library/Mobile Documents/` 配下（iCloud Driveでデスクトップ・書類フォルダを同期している場合など）にプロジェクトを置いていると、Claude Codeの一時タスクディレクトリがクラウド同期の対象になり、シンボリックリンク経由でアクセスされることがあります。今回の修正により、こうした環境でもBashコマンドの出力スワップが正しく処理されます。

```bash
# iCloud同期フォルダ内のプロジェクトでも問題なく動作
cd ~/Documents/my-project
claude
```

### 2. バックグラウンドタスクを多用するワークフロー

開発サーバーの起動やビルド監視など、出力が大きくなりがちなバックグラウンドタスクを頻繁に使う場合、この修正の恩恵を受けやすくなります。

```bash
# 開発サーバーをバックグラウンドで起動
# Claude Codeに以下のように依頼する
# 「npm run dev をバックグラウンドで実行して」
```

### 3. シンボリックリンクを使った開発環境

`ln -s` でホームディレクトリ配下の設定やキャッシュ領域を別ドライブへリンクしている場合も、今回の修正対象に含まれます。

```bash
# 例: タスクディレクトリの親がシンボリックリンクになっているケース
ls -la ~/.claude
```

## 注意点

- この修正はバグ修正のため、新しい設定項目やコマンドは追加されていません。
- 問題が解消しない場合は、`/doctor` コマンドで環境診断を実行し、一時ディレクトリの権限や同期状態を確認してください。
- 古いバージョンのClaude Codeを使い続けている場合はこの修正が適用されないため、`claude update` で更新することを推奨します。
