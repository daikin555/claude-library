## 原文（日本語訳）

フォアグラウンドから引き継がれたシェルコマンドが、バックグラウンドセッションで完了した際に内部エラーを記録したり、誤解を招く `[exited with code -1]` という行が表示されたりする問題を修正しました。

## 原文（英語）

Fixed shell commands carried over from the foreground logging an internal error or showing a misleading `[exited with code -1]` line when they finish in background sessions

## 概要

Claude Codeでは、フォアグラウンドで実行を開始したシェルコマンドをそのままバックグラウンドセッションに引き継いで継続実行できます。しかし、この引き継ぎ処理に不整合があり、コマンドが実際には正常終了していても内部エラーがログに記録されたり、実際の終了コードとは無関係な `[exited with code -1]` という誤解を招く行が出力されたりすることがありました。今回の修正で、フォアグラウンドから引き継がれたコマンドがバックグラウンドで完了した際も、正しい終了状態が報告されるようになりました。

## 基本的な使い方

長時間実行するコマンドをフォアグラウンドで開始し、途中でバックグラウンドに切り替えます。

```
npm run build
# 実行中に Ctrl+B などでバックグラウンドに切り替え
```

修正後は、バックグラウンドで完了した際に実際の終了コード（例: 正常終了なら `0`）が正しく報告されます。

## 実践例

### 長時間のビルドコマンドをバックグラウンド化する

ビルドやテストなど時間のかかるコマンドをフォアグラウンドで開始し、他の作業を進めるためにバックグラウンドへ切り替えた場合、コマンド完了時に正しい終了コードが表示されるようになり、成功/失敗の判断を誤ることがなくなります。

### 監視ツールやサーバープロセスの引き継ぎ

開発サーバーなど継続的に動作するプロセスをフォアグラウンドで起動後にバックグラウンドへ移した場合、後からプロセスが終了した際のログに誤った内部エラーが混入しなくなり、実際の問題と区別しやすくなります。

### 複数タスクの並行管理

複数のシェルコマンドをバックグラウンドで並行管理している際、フォアグラウンドから引き継いだタスクだけが誤ったエラー表示をする、という紛らわしい状況がなくなります。

## 注意点

- この修正はフォアグラウンドで開始してからバックグラウンドに切り替えたコマンドが対象です。最初からバックグラウンドで開始したコマンドの挙動には影響しません
- 実際にコマンドがエラー終了した場合は、正しい終了コードがそのまま表示されます
