## 原文（日本語に翻訳）

mTLSクライアント証明書のローテーションに再起動が必要だった問題を修正しました。Claude Codeは接続エラー発生時に、ローテーションされた証明書と鍵を自動的に再読み込みするようになりました。

## 原文（英語）

Fixed mTLS client certificate rotation requiring a restart; Claude Code now reloads the rotated cert and key automatically on connection errors

## 概要

Enterprise環境でmTLS（相互TLS）によるクライアント証明書認証を利用している場合、これまでは運用中に証明書と鍵をローテーション（更新）しても、Claude Codeを再起動しない限り新しい証明書が反映されず、接続エラーが発生し続けるという問題がありました。本アップデートにより、接続エラーが発生した際にClaude Codeがローテーション後の証明書・鍵を自動的に再読み込みするようになり、再起動なしで新しい証明書に切り替わるようになりました。

## 基本的な使い方

mTLSのクライアント証明書は環境変数または`settings.json`で指定します。修正後は、これらのパスが指す証明書・鍵ファイルの中身が更新（ローテーション）された場合、接続エラーをトリガーに自動で再読み込みされます。

```bash
# クライアント証明書・鍵のパスを指定
export CLAUDE_CODE_CLIENT_CERT=/etc/claude-code/certs/client-cert.pem
export CLAUDE_CODE_CLIENT_KEY=/etc/claude-code/certs/client-key.pem
```

```bash
# 証明書ローテーション後（同じパスに新しいファイルが配置される）
# 修正前: Claude Codeを再起動しないと古い証明書のままエラーが継続
# 修正後: 接続エラーを検知すると自動的に新しい証明書・鍵を再読み込みして再接続
```

## 実践例

### PKI基盤による定期的な自動ローテーションを運用している場合

HashiCorp VaultのPKIエンジンや社内CAが数か月〜1年ごとにクライアント証明書を自動更新し、同じファイルパスに新しい証明書・鍵を配置する運用をしているケースです。以前は、この自動ローテーションが行われても稼働中のClaude Codeプロセスは古い証明書を保持し続けており、手動での再起動が必要でした。修正後は、証明書の入れ替えによって接続エラーが発生すると自動的に新しい証明書・鍵を再読み込みするため、無停止での運用が可能になります。

```bash
# ローテーション後のファイルが同じパスに配置される
export CLAUDE_CODE_CLIENT_CERT=/etc/claude-code/certs/client-cert.pem
export CLAUDE_CODE_CLIENT_KEY=/etc/claude-code/certs/client-key.pem
# Claude Codeは再起動不要で新しい証明書に自動切り替え
```

### 証明書失効・緊急ローテーション時の運用負荷を削減したい場合

証明書の漏えいが疑われるなど緊急でクライアント証明書を差し替える必要がある場合、これまでは対象マシン上のすべてのClaude Codeプロセスを手動で再起動する必要があり、運用負荷が高くローテーション作業に時間がかかっていました。修正後は接続エラーをきっかけに自動再読み込みが行われるため、緊急時でも再起動作業を伴わずに新しい証明書へ移行できます。

```bash
# 緊急ローテーションで証明書・鍵を差し替え
# Claude Codeプロセスの再起動は不要
# 次回の接続エラー時に自動で新しい証明書を読み込む
```

## 注意点

- Claude Code v2.1.232での修正です。
- 自動再読み込みは「接続エラーの発生」をトリガーとするため、証明書を差し替えた直後の1回目の接続エラーまではタイムラグが生じる場合があります。
- `CLAUDE_CODE_CLIENT_KEY_PASSPHRASE`など関連する設定も併用している場合は、ローテーション後の値の整合性を確認してください。
- 子プロセス（MCPサーバーなど）が独自にTLS接続を行っている場合は、別途その挙動を確認してください。
