## 原文（日本語訳）

Wayland環境でコピーオンセレクト（テキスト選択時の自動コピー）がクリップボードに反映されないことがある問題を修正しました。2つの選択書き込み処理が競合しなくなりました。

## 原文（英語）

Fixed copy-on-select on Wayland sometimes not reaching the clipboard; the two selection writes no longer race

## 概要

Claude Codeのターミナルには、テキストを選択するだけで自動的にクリップボードへコピーされる「コピーオンセレクト」機能があります。Linux環境では、選択したテキストはシステムクリップボードと、中クリックでペーストできる`PRIMARY`セレクションの両方に書き込まれます。Wayland環境では、この2つの書き込み処理がほぼ同時に実行されることでレースコンディション（競合状態）が発生し、選択直後にクリップボードへ内容が反映されないことがありました。今回の修正で、この2つの書き込みが競合しないように順序が整理され、Wayland環境でも確実にクリップボードへコピーされるようになりました。

## 基本的な使い方

コピーオンセレクトは特別な操作を必要としません。ターミナル上でマウスやトラックパッドを使ってテキストをドラッグ選択するだけで、自動的にクリップボードへコピーされます。

```bash
# ターミナル上に出力されたコマンドやコードをドラッグ選択
$ npm run build

# 選択しただけでクリップボードにコピーされる
# 他のアプリケーションに Ctrl+V で貼り付け可能
```

## 実践例

### 修正前に起きていた問題

Wayland（GNOME、KDE Plasmaなど）を使用するLinux環境で、Claude Codeの出力からコマンドやファイルパスを選択してすぐに別のアプリケーションへ貼り付けようとすると、クリップボードが更新されておらず、直前に選択したはずのテキストではなく古い内容が貼り付けられてしまうことがありました。

```bash
# Claude Codeの出力からコマンドを選択
$ git checkout -b feature/new-widget

# すぐにターミナル外でCtrl+Vしても
# クリップボードとPRIMARYセレクションへの書き込みが競合し、
# 反映が間に合わず古い内容が貼り付けられることがあった
```

### 修正後の挙動

クリップボードとPRIMARYセレクションへの書き込み順序が整理されたことで、選択直後に別のアプリケーションへ貼り付けても、選択したテキストが確実にクリップボードへ反映されるようになりました。tmux内やフルスクリーン表示中でも同様に安定して動作します。

```bash
# 選択後すぐに貼り付けても、常に選択した内容が反映される
$ git checkout -b feature/new-widget
# → Ctrl+V で確実に "git checkout -b feature/new-widget" が貼り付けられる
```

## 注意点

- Wayland環境でクリップボード連携を利用するには、`wl-clipboard`（`wl-copy`/`wl-paste`）がインストールされている必要があります
- `wl-clipboard`が見つからない場合、クリップボード関連の機能が正しく動作しないことがあるため、インストール後はClaude Codeセッションを再起動することを推奨します
- 中クリックでのペースト（PRIMARYセレクション）とシステムクリップボードへのコピーは、Linuxでは異なる仕組みで管理されている点に留意してください
