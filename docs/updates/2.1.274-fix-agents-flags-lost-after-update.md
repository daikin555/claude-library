## 原文（日本語訳）

`claude agents` コマンドが、自動更新による再起動（relaunch）の後に `--model`、`--effort`、`--permission-mode`、`--allow-dangerously-skip-permissions`、`--agent` の各フラグを失ってしまう問題を修正しました。

## 原文（英語）

Fixed `claude agents` losing `--model`, `--effort`, `--permission-mode`, `--allow-dangerously-skip-permissions` and `--agent` after an auto-update relaunch

## 概要

Claude Codeは起動時に自動更新を検知すると、新しいバージョンで自身を再起動（relaunch）することがあります。これまで `claude agents` コマンドをフラグ付きで実行した直後に自動更新の再起動が発生すると、`--model` や `--effort`、`--permission-mode`、`--allow-dangerously-skip-permissions`、`--agent` といった指定していたフラグが再起動後に引き継がれず、デフォルト設定で起動してしまう不具合がありました。今回の修正で、自動更新による再起動後もこれらのフラグが正しく保持されるようになりました。

## 基本的な使い方

```bash
claude agents --model opus --effort high --permission-mode acceptEdits
```

自動更新の再起動が挟まっても、指定したフラグの内容がそのまま新しいプロセスに引き継がれます。

## 実践例

### 特定モデル・エフォートで自動化パイプラインを組んでいる場合

CI/CDやスクリプトの中で `claude agents --model opus --effort high` のように厳密なパラメータを指定して実行している場合、以前は自動更新のタイミングによってこれらの指定が失われ、意図しないモデルやエフォートで実行されてしまうリスクがありましたが、修正後はその心配がなくなりました。

```bash
claude agents --model sonnet --agent my-custom-agent --allow-dangerously-skip-permissions
```

### 権限モードを厳密に制御している場合

`--permission-mode` を明示的に指定して権限まわりを厳密に制御している環境でも、自動更新後にモードが意図せずリセットされることがなくなり、安全性が保たれます。

## 注意点

- この問題は自動更新による再起動というタイミング依存の不具合であったため、必ずしも毎回発生していたわけではありません。
- `--allow-dangerously-skip-permissions` は引き続き注意して使用すべき危険なフラグです。本番運用では利用を避けるか、十分な統制のもとで使用してください。
