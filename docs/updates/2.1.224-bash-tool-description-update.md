## 原文（日本語訳）

Bashツールの説明文（description）を変更し、コマンドの出力はモデルに表示されるものであり、ユーザーに確実に表示されるとは限らない、という点を常に明記するようにしました。

## 原文（英語）

Changed the Bash tool description to always note that command output is displayed to the model, not reliably to the user

## 概要

Claude Codeが内部で使用するBashツールには、モデル自身に対して「このツールはどのように振る舞うべきか」を伝える説明文（tool description）が付与されています。今回の変更は、Claude Codeのユーザー向け機能というよりも、Claudeモデルへの指示（システムプロンプト/ツール定義）の一部を修正したものです。具体的には、Bashコマンドを実行した際の出力（標準出力・標準エラー出力）は、あくまでモデル自身に返される情報であり、ユーザーのターミナルに必ずしもそのまま表示されているとは限らない、という前提を常に明記するようにしました。これにより、Claudeがコマンドの実行結果をユーザーがすでに見ている前提で振る舞ってしまう（例えば「上記の出力の通り」とだけ述べて説明を省略する）ことを防ぎ、重要な結果は応答メッセージの中で改めて要約・提示するよう促す狙いがあります。

## 基本的な使い方

これはツール定義側の変更であり、ユーザーが明示的に呼び出すコマンドや設定はありません。通常どおりClaudeにBashコマンドの実行を伴う作業を依頼するだけで、内部的にこの改善された説明文が適用されます。

```text
> npm test を実行してテスト結果を教えて
```

## 実践例

### バックグラウンドセッションやRemote Control経由で作業している場合

Remote Controlでスマートフォンから会話を見ている場合や、`claude agents`のようなバックグラウンドセッションでは、ユーザーがローカルターミナルの生の出力をリアルタイムに見ているとは限りません。この変更により、Claudeはコマンド出力をそのまま「見せた」つもりにならず、テスト結果やビルドエラーなどの要点を応答メッセージ内で明示的に説明するようになることが期待されます。

```text
> ビルドを実行して、失敗していたら原因を教えて

# Bashツールでビルドコマンドを実行した後、
# Claudeは出力をユーザーがそのまま見ている前提を置かず、
# 失敗の要因を応答文の中で明示的にまとめて説明する
```

### `claude -p`による非対話実行やCI連携の場合

`claude -p`のようなヘッドレス実行やCIパイプラインからの呼び出しでは、コマンドの生出力がユーザー（あるいは呼び出し元プロセス）にそのまま流れないことがあります。Bashツールの説明文が出力の可視性について前提を置かなくなったことで、こうした環境でもClaudeが重要な情報を応答の中に落とし込みやすくなります。

```bash
claude -p "lintを実行してエラー件数を教えて"
```

### 出力が長大・truncateされるコマンドを実行する場合

Bashツールの出力は一定の文字数で切り詰められる（truncate）ことがあります。ユーザー側のターミナル表示とモデルが受け取る内容が完全に一致するとは限らないという前提が明記されたことで、Claudeは「切り詰められた可能性がある」ことを踏まえて重要な情報を優先して要約するよう振る舞いやすくなります。

## 注意点

- これはツールの動作そのもの（出力の取得方法や切り詰めの仕様）を変更するものではなく、モデルに渡す説明文（プロンプト）を修正したものです。挙動の変化はClaudeの応答スタイルに表れる可能性がありますが、Bashツールが返すデータ自体の仕様は変わりません。
- フックやカスタムツール、MCPサーバーなど、Bashツールの説明文を前提にした独自の仕組みを組んでいる場合は、この変更を踏まえて挙動を確認しておくとよいでしょう。
- ユーザーがターミナルで実際にコマンド出力を目視できるかどうかは、実行環境（対話型ターミナル、Remote Control、`claude -p`、CIなど）によって異なります。重要な結果は必ずClaudeの応答メッセージ内で確認する習慣をつけることを推奨します。
