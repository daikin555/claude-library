## 原文（日本語訳）

モデルが廃止されたSlackスレッドが、返信のたびに毎回別のモデルにフォールバックし、処理が遅くフォールバックの注記も毎回表示されていた不具合を修正しました。現在は、そのスレッドは動作するモデルへ移行します。

## 原文（英語）

[Claude Tag] Fixed Slack threads whose model has been retired falling back to another model on every reply, slower and with a fallback note each time; the thread now moves to a working model

## 概要

Anthropicがモデルを廃止（retire）すると、それ以前に開始されたSlackスレッドで指定されていたモデルが使えなくなります。これまでは、こうしたスレッドで返信するたびに毎回代替モデルへのフォールバック処理が発生し、応答が遅くなるだけでなく、返信のたびに「フォールバックしました」という注記が繰り返し表示されるという煩わしい状態になっていました。今回の修正で、廃止されたモデルを使っていたスレッドは、以後は動作する代替モデルへ恒久的に移行するようになり、毎回のフォールバック処理と注記の繰り返しがなくなりました。

## 基本的な使い方

ユーザー側の対応は不要です。廃止されたモデルを使っていた既存のSlackスレッドでも、次回以降の返信から自動的に動作するモデルに移行し、通常の速度で応答するようになります。

## 実践例

### 長期間続いているプロジェクトスレッドでの継続利用

数ヶ月にわたって同じSlackスレッドでClaudeとやり取りを続けているプロジェクトチームでも、途中でモデルが廃止された場合にスムーズに新しいモデルへ移行し、快適な応答速度を維持できます。

### モデル廃止に伴う運用の手間削減

これまでは廃止されたモデルを使っているスレッドごとに手動で新しいスレッドを立て直すといった対応が必要になることがありましたが、自動移行によってそうした手間が減ります。

## 注意点

- モデルが移行すると、それ以降の応答の特性（文体や能力）が変わる可能性があります
- この修正はSlack上のClaude Tagスレッドに特有のものです
