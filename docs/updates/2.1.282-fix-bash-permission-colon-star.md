## 原文（日本語訳）

途中に `:*` を含むBash権限ルールが設定ファイルではスキップされる一方、`--allowedTools` では正しく機能していた不具合を修正しました。現在はすべてのソースから機能し、どのようにマッチするかを示す起動時警告も表示されます。

## 原文（英語）

Fixed Bash permission rules with a mid-pattern `:*` being skipped in settings files while `--allowedTools` honored them; they now work from every source, with a startup warning on how they match

## 概要

Bashの権限ルールでは、`Bash(git commit:*)` のようにコマンドの末尾に `:*` を付けてワイルドカードマッチさせるのが一般的ですが、`Bash(git commit:* --amend)` のように文字列の途中に `:*` が来るパターンは、`settings.json` などの設定ファイル経由では正しく解釈されずスキップされてしまう不具合がありました（`--allowedTools` コマンドラインオプションでは問題なく機能していました）。今回の修正で、設定ファイル経由でも同様のパターンが正しく機能するようになり、起動時にはそのルールがどのようにマッチするかを示す警告も表示されるようになりました。

## 基本的な使い方

`.claude/settings.json` に以下のようなルールを記述すると、これまで無視されていたパターンも正しく適用されるようになります。

```json
{
  "permissions": {
    "allow": ["Bash(git commit:* --amend)"]
  }
}
```

## 実践例

### 複雑なコマンドパターンの許可

特定のサブコマンドとオプションの組み合わせだけを許可したい場合など、途中にワイルドカードを含む複雑な権限ルールを設定ファイルで管理できるようになります。

### 起動時警告によるルールの検証

新しく設定した権限ルールが意図通りにマッチするかどうかを、起動時の警告メッセージで事前に確認し、意図しない過剰な許可や誤ったルールに早く気づけます。

## 注意点

- 既存の権限ルールがこの修正によって挙動を変える可能性があるため、起動時の警告メッセージは必ず確認してください
- `--allowedTools` を使っていた場合は元々問題なく動作していたため、目立った変化はありません
