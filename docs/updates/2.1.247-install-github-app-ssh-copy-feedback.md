## 原文（日本語訳）

SSH経由での `/install-github-app` を修正しました。コピー用のショートカットは、常に成功したと表示するのではなく、サインインURLがどのようにコピーされたかを表示するようになりました。また、ブラウザを開けない場合はURLが即座に表示されるようになりました。

## 原文（英語）

Fixed `/install-github-app` over SSH: the copy shortcut now says how the sign-in URL was copied instead of always claiming success, and the URL appears immediately when no browser can open

## 概要

`/install-github-app` はGitHub Appのセットアップを行うスラッシュコマンドですが、SSH経由のリモート環境ではクリップボードへのアクセス方法が環境によって異なり、実際にはコピーに失敗していても「コピーしました」と表示されてしまう問題がありました。さらに、ブラウザを自動で開けない環境ではサインインURLの表示が遅れ、ユーザーが手動でURLを取得しづらい状態になっていました。今回の修正で、コピー手段に応じた正確なメッセージ表示と、URLの即時表示が行われるようになりました。

## 基本的な使い方

SSH接続したリモート環境で通常通りコマンドを実行します。

```
/install-github-app
```

ブラウザが開けない環境では、サインイン用のURLがすぐに表示されるため、ローカルのブラウザにコピーしてアクセスできます。

## 実践例

### SSHでリモートサーバーに接続して作業している場合

クリップボード共有が有効なSSHクライアント（`ForwardX11` やターミナル統合など)を使っている場合、実際にどの方法でURLがコピーされたかがメッセージに反映されるため、コピーが実際に成功したかどうかを正確に把握できます。

### クリップボード連携がない環境

`tmux` やコンテナ内など、クリップボードにアクセスできない環境では、これまでは「コピーしました」という誤った表示のままURLを探す必要がありました。修正後はブラウザが開けない旨とURLが即座に表示されるため、URLをそのまま選択してローカル側に貼り付けられます。

### CI/自動化パイプラインからの実行

対話的にブラウザを開けない自動化環境でも、URLがすぐにログへ出力されるため、後続処理やオペレーターがログからURLを取得して認証を完了できます。

## 注意点

- コピー手段はSSHクライアントやOS設定によって異なるため、表示されるメッセージも環境によって変わります
- ブラウザが開けるかどうかの判定は環境依存であり、判定を誤った場合でもURLは常に表示されるため手動でのアクセスが可能です
