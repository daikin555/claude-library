## 原文（日本語訳）

排他的な `managed-mcp.json` の下でも `claude --chrome` を実行できるようにする管理者設定 `allowClaudeInChromeWithManagedMcp` を追加しました。Chromeがブロックされた際に表示されるエラーには、その設定名が明示されるようになりました。

## 原文（英語）

Added the `allowClaudeInChromeWithManagedMcp` managed setting to let `claude --chrome` run alongside an exclusive `managed-mcp.json`; the error shown when Chrome is blocked now names it

## 概要

企業が `managed-mcp.json` で利用可能なMCPサーバーを排他的に制限している環境では、これまで `claude --chrome`（Chrome連携機能）の起動がブロックされていました。新しい管理者設定 `allowClaudeInChromeWithManagedMcp` を有効にすると、この制限下でもChrome連携を許可できます。ブロックされた場合のエラーメッセージも改善され、原因の設定名が明示されるため、管理者への問い合わせがスムーズになります。

## 基本的な使い方

管理者が組織のmanaged settings（例: macOSの `managed-settings.json` やWindowsのポリシー）に追加します。

```json
{
  "allowClaudeInChromeWithManagedMcp": true
}
```

設定後、エンドユーザーは通常どおりChrome連携を起動できます。

```bash
claude --chrome
```

## 実践例

### ブラウザ操作を伴う社内ワークフローの解禁

社内ツールへのアクセスがMCPサーバー経由に限定されている企業で、Web UIの動作確認やスクレイピングにClaudeのChrome連携を使いたい場合、IT管理者がこの設定を追加することで利用可能になります。

### ブロック時のトラブルシューティング

`claude --chrome` がエラーで起動しない場合、エラーメッセージに表示される設定名（`allowClaudeInChromeWithManagedMcp` など）を管理者に伝えることで、迅速に原因を特定できます。

## 注意点

- この設定はエンドユーザーではなく管理者（managed settings）側で制御するものです
- `managed-mcp.json` が排他的にMCPサーバーを制限している構成が前提の設定です
- 有効化はセキュリティポリシーに関わるため、組織のセキュリティ担当者と相談の上で設定してください
