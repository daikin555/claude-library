## 原文（日本語訳）
[Claude Tag] 誰も応答を待っていない状態でセーフティフィルターによる停止が発生した際、Slackスレッドの文脈がサイレントにリセットされてしまう問題を修正しました。現在はClaudeが必ずその旨を伝え、まだ実行中のバックグラウンド作業をキャンセルすることもなくなります。

## 原文（英語）
[Claude Tag] Fixed a safety-filter stop silently resetting a Slack thread's context when nobody was waiting; Claude now always says so and no longer cancels background work still running

## 概要
Claude Tagには安全性のための仕組みとして、特定の条件下で応答を停止する「セーフティフィルター」があります。これまで、誰も応答を待っていないタイミング（例えばバックグラウンドで処理が進行している最中など）でこのセーフティフィルターによる停止が発生すると、Slackスレッドの文脈がユーザーに知らされないままサイレントにリセットされてしまい、さらに進行中だったバックグラウンド作業まで意図せずキャンセルされてしまう問題がありました。今回の修正により、セーフティフィルターによる停止が発生した場合は必ずその旨がスレッドに伝えられるようになり、実行中のバックグラウンド作業が不必要にキャンセルされることもなくなりました。

## 基本的な使い方
特別な操作は不要です。セーフティフィルターによる停止が発生した場合、自動的にスレッドへその旨のメッセージが投稿されるようになります。

## 実践例

### バックグラウンドタスク実行中の停止
Claudeが長時間のバックグラウンド作業（例えば大規模なコード生成やレビュー）を行っている最中にセーフティフィルターが作動しても、その作業自体は継続され、停止が発生した場合はスレッド上で明示的に通知されます。

### 文脈の一貫性維持
セーフティフィルターの作動によってスレッドの会話文脈が失われることがなくなったため、その後同じスレッドで会話を継続する際も、それまでのやり取りを踏まえた応答が得られます。

## 注意点
- セーフティフィルター自体の発動条件や基準は変更されていません。今回の修正はあくまで発動時の通知とバックグラウンド作業の扱いに関するものです。
- セーフティフィルターの詳細な仕組みについては、Claude Codeの安全性に関する公式情報を参照してください。
