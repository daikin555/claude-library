## 概要

Claude CodeのWorkflow機能（マルチエージェントによるオーケストレーション）には、生成されるワークフローの規模感をアドバイザリとして制御する「Dynamic workflow size guideline」という設定があります。これまでは `/config` から対話的に `small` / `medium` / `unrestricted` などを選ぶしかありませんでしたが、`workflowSizeGuideline` 設定キーが追加されたことで、`.claude/settings.json` などの設定ファイルから直接この値を指定できるようになりました。設定ファイルに値がある間は `/config` の該当行が自動的に非表示になり、設定ファイルが唯一の情報源（source of truth）として扱われます。

## 基本的な使い方

`.claude/settings.json` に `workflowSizeGuideline` キーを追加するだけで、対話的な設定なしにワークフローサイズガイドラインを固定できます。

```json
{
  "workflowSizeGuideline": "medium"
}
```

この状態で `/config` を開くと、Dynamic workflow size guidelineの行は表示されなくなります（設定ファイル側が優先されるため）。

## 実践例

### 組織全体でワークフロー規模の方針を統一する

複数チームが同じリポジトリを触る場合、各メンバーが個別に `/config` でガイドラインを変えてしまうと、生成されるワークフローの粒度がばらついてしまいます。プロジェクトの `.claude/settings.json` にキーを固定しておけば、リポジトリをcloneした全員に同じ方針が適用されます。

```json
{
  "workflowSizeGuideline": "small",
  "permissions": {
    "allow": ["Bash(git *)"]
  }
}
```

`small` にしておくことで、必要以上に多くのサブエージェントを並列起動する大規模ワークフローの提案を抑え、レビューしやすい小さな単位でのオーケストレーションを促せます。

### 個人設定でだけガイドラインを緩める

大規模なリファクタリングを頻繁に行う開発者は、ユーザーレベルの設定（`~/.claude/settings.json`）で `unrestricted` を指定し、必要なときに大規模なワークフローを制限なく組めるようにできます。

```json
{
  "workflowSizeGuideline": "unrestricted"
}
```

プロジェクト側の `settings.json` に値がなければ、このユーザー設定がそのまま有効になります。

### CI/エージェント実行環境でガイドラインを明示する

自動化されたエージェント実行環境（CIやスケジュール実行など）では対話的に `/config` を操作できないため、`.claude/settings.local.json` や環境専用の設定ファイルにあらかじめ値を書き込んでおくことで、非対話環境でも意図した規模感のワークフローが生成されるようにできます。

```json
{
  "workflowSizeGuideline": "medium"
}
```

## 注意点

- `workflowSizeGuideline` はあくまでアドバイザリ（推奨値）であり、ワークフローの生成を強制的に制限するハード制約ではありません。
- 設定ファイルに値が存在する間は `/config` 上の該当行が隠れるため、対話的に変更したい場合は設定ファイル側のキーを削除する必要があります。
- 複数の設定ファイル（ユーザー設定・プロジェクト設定・ローカル設定）で値が競合する場合は、Claude Codeの設定ファイルの優先順位（ローカル設定 > プロジェクト設定 > ユーザー設定など）に従って解決されます。
- 既存プロジェクトでチームに展開する場合は、`.claude/settings.json` をリポジトリにコミットすることで全メンバーに一貫した挙動を適用できます。
