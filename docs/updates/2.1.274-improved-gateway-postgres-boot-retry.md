## 原文（日本語訳）
Claude appsゲートウェイの起動処理を改善：最初のPostgres接続を最大3回までリトライするようになり、データベースの起動が数秒遅れて利用可能になった場合でも起動が失敗しなくなった。

## 原文（英語）
Improved Claude apps gateway boot: it now tries the first Postgres connection up to three times before exiting, so a database that is reachable a few seconds late no longer fails the boot

## 概要
Claude appsゲートウェイは起動時にPostgresデータベースへ接続します。これまでは、データベース側の起動がわずかに遅れているだけでゲートウェイの起動が即座に失敗してしまうことがありました。特にコンテナオーケストレーション環境などでは、アプリケーションとデータベースがほぼ同時に起動を開始するため、この問題が発生しやすい状況でした。今回の改善により、初回のPostgres接続が失敗しても最大3回までリトライするようになり、数秒遅れて到達可能になったデータベースに対しても起動が成功するようになりました。

## 基本的な使い方
特別な設定は不要です。Claude appsゲートウェイを起動すると、Postgres接続が自動的にリトライされるようになります。

```bash
# Claude appsゲートウェイの起動例
docker compose up gateway postgres
```

## 実践例

### コンテナオーケストレーションでゲートウェイとDBを同時起動する場合
DockerやKubernetesなどで、ゲートウェイとPostgresコンテナをほぼ同時に起動する構成では、以前はPostgresの初期化が少し遅れるだけでゲートウェイがクラッシュしてしまうことがありました。改善後は自動的に接続をリトライするため、`depends_on`のようなヘルスチェック待機を厳密に設定していなくても、数秒程度の起動遅延を吸収できます。

```yaml
# docker-compose.yml の例
services:
  gateway:
    image: claude-apps-gateway
    depends_on:
      - postgres
  postgres:
    image: postgres:16
```

### デプロイ時のローリング再起動での安定性向上
デプロイのたびにゲートウェイとデータベースが再起動するような運用でも、この改善によって一時的な接続失敗が原因のデプロイ失敗が減り、安定性が向上します。

## 注意点
- リトライは最大3回までであり、それでも接続できない場合（データベースが恒久的に到達不能など）は引き続き起動が失敗します。
- リトライには一定の待機時間がかかるため、データベースが長時間起動しない場合はゲートウェイの起動完了までの時間がわずかに延びる可能性があります。
