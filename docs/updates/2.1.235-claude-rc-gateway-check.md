## 原文（日本語訳）

Remote Control機能について、`claude rc` コマンドの起動時にも、通常の対話的起動と同じエンタープライズゲートウェイの可用性チェックが適用されるようになりました。

## 原文（英語）

Remote Control: `claude rc` now applies the same enterprise-gateway availability check as interactive startup

## 概要

`claude rc` はRemote Control機能を起動するコマンドで、ローカルで動いているClaude Codeセッションをスマートフォンやブラウザから操作できるようにするものです。通常、`claude` コマンドで対話モードを起動する際には、Amazon Bedrock・Google Cloud Vertex AI・自社のLLMゲートウェイ経由でClaudeを利用している組織向けに、ゲートウェイが実際に到達可能かどうかを確認する可用性チェックが行われます。これまで `claude rc` による起動時にはこのチェックが行われておらず、ゲートウェイに接続できない状態のままRemote Controlセッションが開始されてしまうことがありました。今回の修正で、`claude rc` でも通常起動と同じチェックが実行されるようになり、問題が早期に検出されるようになりました。

## 基本的な使い方

エンタープライズゲートウェイ（LLM Gateway）や `claude apps gateway` を利用している組織で、通常どおり `claude rc` を実行するだけで、この可用性チェックが自動的に適用されます。ユーザー側で追加の操作は必要ありません。

```bash
claude rc
```

ゲートウェイが正しく設定されていない、あるいはネットワークから到達できない状態で `claude rc` を実行すると、修正後はセッション開始前にエラーとして検出されるため、Remote Controlに接続してから初めて動作しないことに気づく、という状況を避けられます。

## 実践例

### LiteLLMプロキシ経由でClaude Codeを利用している環境

`ANTHROPIC_BASE_URL` を自社のLiteLLMゲートウェイに向けている組織で `claude rc` を実行した場合、ゲートウェイへの到達性が事前に確認されるため、ゲートウェイがダウンしているときにRemote Controlセッションだけが中途半端に開始されることがなくなります。

### Amazon Bedrock / Google Cloud Vertex AI経由の利用

BedrockやVertex AIをバックエンドとして利用している組織でも、通常の `claude` 起動時と同じ可用性チェックが `claude rc` にも適用されるため、認証や設定に問題がある場合はRemote Control起動時点で気づけます。

### 社内ネットワークからのリモート操作

オフィスのデスクトップで `claude rc` を起動し、外出先のスマートフォンから操作しようとするケースでも、ゲートウェイに問題があれば起動時点でエラーになるため、外出先で接続してから原因調査をする手間が減ります。

## 注意点

- この可用性チェックは、エンタープライズゲートウェイ（LLMゲートウェイやClaude apps gateway）を利用している構成でのみ意味を持ちます。Anthropicの標準APIを直接利用している場合は挙動に影響しません
- チェックに失敗した場合はRemote Controlセッションが開始されないため、ネットワーク設定やゲートウェイの稼働状況を確認する必要があります
- Remote Control自体は研究プレビュー段階の機能であり、Pro・Max・Team・Enterpriseプランで利用できます
