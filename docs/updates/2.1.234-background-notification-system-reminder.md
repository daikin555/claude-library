## 原文（日本語訳）

ターンとターンの間に配信されるバックグラウンドタスクの通知が、ターン実行中の配信と同様に `<system-reminder>` タグ内でモデルに送られるようになりました

## 原文（英語）

Background task notifications delivered between turns are now sent to the model inside `<system-reminder>` tags, matching mid-turn delivery

## 概要

Claude Codeはバックグラウンドで実行中のタスク（長時間のBashコマンドなど）が完了すると、その結果をモデルに通知します。この通知は、ターンの実行中（モデルが応答を生成している最中）に届く場合は `<system-reminder>` タグに包まれてモデルに渡されていましたが、ターンとターンの間（モデルが次の入力を待っている合間）に届く場合はこの形式が統一されていませんでした。今回の修正で、ターン間に届く通知もターン中と同じ `<system-reminder>` タグ形式で送られるようになり、Claudeがバックグラウンドタスクの完了通知を一貫した形式で認識できるようになりました。

## 基本的な使い方

これは内部的な通知フォーマットの統一であり、ユーザーが直接操作する項目はありません。バックグラウンドタスクを実行している通常のワークフローで、自動的にこの改善の恩恵を受けます。

```bash
# 長時間かかるコマンドをバックグラウンドで実行させる
claude
> 「npm run buildをバックグラウンドで実行して、他の作業を進めて」
```

## 実践例

### 複数のバックグラウンドタスクを並行させるワークフロー

ビルドやテストなど複数の長時間タスクをバックグラウンドで走らせつつ別の作業を進めている場合、タスクの完了タイミングはターンの実行中・ターンの合間のどちらでも起こり得ます。この修正により、どちらのタイミングで完了しても同じ形式でClaudeに伝わるため、完了通知の見落としや解釈の揺れが減り、後続の対応（テスト結果の確認など）がより安定して行われるようになります。

### 待機中に完了したタスクへの反応の一貫性

ユーザーが次の指示を入力する前にバックグラウンドタスクが完了したケースでは、以前は通知の形式が実行中とは異なっていたため、Claudeの認識にばらつきが生じる可能性がありました。修正後はこのようなタイミングのずれによる挙動の違いが解消されます。

## 注意点

- この変更は内部的な通知の配信形式に関するものであり、ユーザーから見える挙動に大きな変化はありません
- バックグラウンドタスクを多用するワークフローで、通知の一貫性が向上する形で間接的に体感できる場合があります
