## 原文（日本語訳）

MCPの診断情報が解決済みのシークレットを出力していた問題を修正しました。スコープ競合の警告は設定済みの `${VAR}` 形式で表示されるようになり、接続失敗時の詳細情報はサーバーのオリジンのみを表示するようになりました。

## 原文（英語）

Fixed MCP diagnostics printing resolved secrets: scope-conflict warnings now show the configured `${VAR}` form, and connection-failure details show only the server origin

## 概要

MCP（Model Context Protocol）サーバーの設定では、APIキーなどの機密情報を環境変数参照（`${VAR}` のような形式）として記述できます。しかし修正前のバージョンでは、MCPの診断出力（スコープ競合の警告や接続失敗時の詳細情報）において、この環境変数参照が実際の値に解決された状態、つまり生のシークレット値そのものが表示されてしまう不具合がありました。今回の修正により、スコープ競合の警告では設定ファイルに書かれた `${VAR}` の形式のまま表示され、接続失敗時の詳細情報にはサーバーのオリジン（ホスト部分）のみが表示されるようになり、機密情報が診断ログに露出しなくなりました。

## 基本的な使い方

この修正はセキュリティ関連のバグフィックスであり、ユーザー操作は不要です。MCPサーバーの設定に問題がある場合や接続に失敗した場合の診断メッセージを確認しても、APIキーなどの実際の値が表示されなくなります。

## 実践例

### スコープ競合の警告を確認する場合

```jsonc
// .mcp.json（プロジェクトスコープ）
{
  "mcpServers": {
    "my-server": {
      "url": "https://api.example.com",
      "headers": { "Authorization": "Bearer ${MY_API_KEY}" }
    }
  }
}
```

同名のサーバーがユーザースコープにも定義されている場合にスコープ競合の警告が出ますが、修正前は警告メッセージ中に `${MY_API_KEY}` が実際のキー値へ展開された状態で表示されることがありました。修正後は設定ファイル通り `${MY_API_KEY}` という表記のまま表示されます。

### MCPサーバーへの接続に失敗した場合

```
claude mcp list
```

接続失敗時の詳細情報として、以前はURLのクエリパラメータやパスに含まれる認証トークンなどが表示されてしまう可能性がありましたが、修正後はサーバーのオリジン（例: `https://api.example.com`）のみが表示され、パスやクエリに含まれ得る機密情報は表示されません。

## 注意点

- この修正は診断出力（ログ・CLI表示）への露出を防ぐものであり、MCPサーバー自体への認証には引き続き実際の値が使用されます
- チームで診断ログやスクリーンショットを共有する運用をしている場合、アップデート前のバージョンで取得したログにはシークレットが含まれている可能性があるため、取り扱いに注意してください
