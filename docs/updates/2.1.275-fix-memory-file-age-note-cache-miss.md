## 原文（日本語に翻訳）

コンパクションまたはレジューム後、復元されたメモリファイルの経過時間の注記がリクエストごとに変化してしまい、プロンプトキャッシュのミスを引き起こしていた問題を修正

## 原文（英語）

Fixed a restored memory file's age note changing between requests after a compaction or resume, which caused prompt cache misses

## 概要

Claude Codeはメモリファイル（会話の要約や記憶情報）に「最終更新から◯分経過」のような経過時間の注記を付与することがあります。コンパクション（会話の圧縮）やセッションのレジューム後、この経過時間の注記がリクエストごとに微妙に変化してしまい、プロンプトの内容が毎回わずかに異なる状態になっていました。その結果、Anthropic APIのプロンプトキャッシュが効かなくなり、レイテンシやコストが増加していました。この修正により、経過時間の注記が安定し、キャッシュヒット率が改善されます。

## 基本的な使い方

この修正はバックグラウンドの内部動作であり、ユーザー側で特別な操作は不要です。コンパクションやレジュームを行った通常のワークフローで自動的に改善が適用されます。

```bash
# 長いセッションでコンパクションが発生した後も
# プロンプトキャッシュが正しく機能するようになる
claude
```

## 実践例

### 修正前の挙動

コンパクションやレジュームの直後、メモリファイルに付与される経過時間の注記（例：「5分前に更新」）がリクエストのたびに変わってしまい、同一内容のはずのプロンプト先頭部分が毎回異なっていたため、キャッシュが再利用されずレイテンシが増加していました。

### 修正後の挙動

経過時間の注記が安定した値になり、同じセッション内で連続するリクエスト間でプロンプトの先頭部分が一致するようになりました。これにより、プロンプトキャッシュが正しく再利用され、応答速度とコスト効率が改善されます。

```bash
# 長時間のセッションやレジューム後でも
# キャッシュヒット率が安定するようになった
claude --resume
```

## 注意点

- この修正は内部的な安定性改善であり、ユーザーが明示的に設定する項目はありません
- プロンプトキャッシュの効果はセッションの長さや利用パターンによって異なります
- 大幅に時間が経過した後のレジュームでは、経過時間の表示自体は依然として変化する場合があります（それ自体は正常な挙動です）
