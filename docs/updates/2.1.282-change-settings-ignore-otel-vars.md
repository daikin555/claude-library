## 原文（日本語訳）

プロジェクト設定・ローカル設定が、テレメトリのエクスポートを有効化したり、エンドポイントを設定したり、`CLAUDE_CODE_ENABLE_TELEMETRY` や `OTEL_LOG_*` のようにコンテンツをキャプチャしたりするOpenTelemetry関連の環境変数を無視するように変更しました。

## 原文（英語）

Changed project and local settings to ignore OpenTelemetry variables that turn on export, set its endpoint, or capture content, like `CLAUDE_CODE_ENABLE_TELEMETRY` and `OTEL_LOG_*`

## 概要

これはセキュリティに関わる変更です。`CLAUDE_CODE_ENABLE_TELEMETRY` や `OTEL_LOG_USER_PROMPTS` のようなOpenTelemetry関連の環境変数は、テレメトリの有効化やエクスポート先の設定、プロンプト内容などのキャプチャに関わる、機微な情報の外部送信につながる可能性がある設定です。今回の変更で、こうしたテレメトリ関連の環境変数はプロジェクト設定やローカル設定ファイルからは反映されなくなりました。これにより、悪意のあるリポジトリの設定ファイルによって、ユーザーの意図しない形でテレメトリが有効化されたり、機微な内容が外部に送信されたりするリスクが防がれます。

## 基本的な使い方

テレメトリを有効にしたい場合は、プロジェクト設定ではなくユーザー設定（`~/.claude/settings.json`）や管理設定、あるいはシェルの環境変数として直接設定してください。

```bash
export CLAUDE_CODE_ENABLE_TELEMETRY=1
```

## 実践例

### 信頼できないリポジトリのチェックアウト時の安全性向上

外部から取得したリポジトリのプロジェクト設定ファイルに、意図しないテレメトリ有効化の設定が仕込まれていても、それが適用されなくなります。

### 組織全体でのテレメトリポリシーの一元管理

組織としてテレメトリの有効・無効やエクスポート先を一元管理したい場合、管理設定やユーザー設定側でコントロールする運用に統一できます。

## 注意点

- 既存のプロジェクト設定でテレメトリ関連の変数を利用していた場合、この変更以降は反映されなくなるため、必要であればユーザー設定や管理設定への移行が必要です
- 無視される設定があるかどうかは、[起動時のテレメトリ変数通知](./2.1.282-telemetry-ignored-notice.md)や `/status`、`claude doctor` で確認できます
