## 原文（日本語訳）

Windows: `~/.claude.json` が読み取り専用の場合、起動時にリネームのリトライを繰り返して処理が止まってしまう問題を修正しました

## 原文（英語）

Windows: startup no longer stalls on repeated rename retries when `~/.claude.json` is read-only

## 概要

Claude Codeは起動時に設定ファイル `~/.claude.json` を安全に更新するため、内部的にファイルのリネーム処理を行うことがあります。Windows環境において、このファイルが読み取り専用属性になっている場合、リネームが失敗してリトライを繰り返し、起動処理がなかなか完了しないという問題がありました。この修正により、`~/.claude.json` が読み取り専用でも起動時に処理が固まらなくなります。

## 基本的な使い方

特別な操作は不要です。Windows環境で `~/.claude.json`（ユーザーのホームディレクトリにある設定ファイル）が読み取り専用属性になっていても、修正後は `claude` コマンドの起動が正常に完了するようになります。

```powershell
claude
```

## 実践例

### 読み取り専用属性が付いた設定ファイルでの起動

セキュリティポリシーやバックアップツールなどにより `~/.claude.json` に読み取り専用属性が付与されている環境では、修正前は起動時にリネームのリトライが繰り返され、起動が非常に遅くなったり、場合によっては停止しているように見えたりすることがありました。修正後はこのようなケースでも起動が正常に完了します。

### 企業管理端末での想定外のファイル属性

社内のグループポリシーや資産管理ソフトによって、ユーザーのホームディレクトリ配下のファイルに意図せず読み取り専用属性が付与されるケースがあります。このような管理端末でClaude Codeの起動が遅い・固まると感じていた場合、この修正によって改善される可能性があります。

## 注意点

- この修正はWindows環境に固有のものです
- `~/.claude.json` に読み取り専用属性が付いている根本原因（グループポリシーなど）自体は解消されないため、設定の永続的な保存に問題がある場合は、ファイル属性を確認することを推奨します
- macOS・Linux環境には影響しません
