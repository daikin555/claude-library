## 原文（日本語に翻訳）

`SendMessage` は、素の名前（bare name）が稼働中のセッションのうち1つだけに完全一致する場合、確認のためにref（参照識別子）を尋ねることなく、そのまま配信するようになりました。

## 原文（英語）

`SendMessage` now delivers to a bare name that exactly matches one live session, instead of asking to confirm with a ref first

## 概要

これまで `SendMessage` に名前だけを指定すると、同名の候補が複数あるかどうかにかかわらず、確実性を高めるために ref（一意な参照識別子）での確認を求められることがありました。v2.1.232からは、指定した名前が稼働中のセッションのうちちょうど1つに完全一致する場合、確認なしでそのまま直接配信されるようになり、余計なやり取りが減りました。

## 基本的な使い方

```
SendMessage({ to: "backend-session", message: "デプロイの準備ができました" })
```

`to` に指定した名前が稼働中セッションの中で一意に定まる場合、そのまま該当セッションへメッセージが送信されます。

## 実践例

### 一意な名前のセッションへ即座にメッセージを送る

```
SendMessage({ to: "release-checker", message: "リリースノートの確認をお願いします" })
```

`release-checker` という名前のセッションが1つしか稼働していなければ、確認プロンプトなしで即座に届きます。

### 名前が重複する場合はrefで明示的に指定する

```
SendMessage({ to: "worker-word-word", message: "タスクを再実行してください" })
```

同じ名前のセッションが複数存在する場合は、これまでどおりref（一意な参照識別子）を使って対象を明示する必要があります。

### ListAgentsで名前を確認してから送信する

```
ListAgents()
# -> 稼働中セッションの名前一覧を取得
SendMessage({ to: "確認した名前", message: "..." })
```

事前に `ListAgents` で名前の一覧を確認しておくと、意図したセッションに確実に届けられます。

## 注意点

- Claude Code v2.1.232での変更です。
- 完全一致する稼働中セッションが複数ある場合は、従来どおり確認（ref指定）が必要です。
- v2.1.232で同時に導入された「セッション名の一意化」（同名セッションに自動でサフィックスが付く機能）と組み合わさることで、名前の衝突自体が起きにくくなり、この即時配信の恩恵を受けやすくなっています。
