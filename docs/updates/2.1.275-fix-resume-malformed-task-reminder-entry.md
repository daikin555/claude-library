## 原文（日本語に翻訳）

`--resume`、レジュームピッカーのプレビュー、レジュームされたバックグラウンドエージェント、およびトランスクリプトビューが、保存された履歴に不正なタスクリマインダーまたは@ファイル添付エントリを含むセッションで失敗してしまっていた問題を修正

## 原文（英語）

Fixed `--resume`, the resume picker preview, resumed background agents and the transcript view failing on a session whose saved history contains a malformed task-reminder or @-file attachment entry

## 概要

Claude Codeはセッションの履歴をローカルに保存し、後から `--resume` で再開したり、レジュームピッカーでプレビューしたりできます。これまで、保存された履歴の中にタスクリマインダーや `@` ファイル添付に関する不正な形式のエントリが含まれている場合、`--resume` コマンド自体や、レジュームピッカーのプレビュー、バックグラウンドエージェントのレジューム、トランスクリプトビューのすべてが失敗してしまう不具合がありました。今回の修正により、このような不正なエントリが含まれていてもこれらの機能が正常に動作するようになりました。

## 基本的な使い方

```bash
claude --resume
```

保存された履歴に問題のあるエントリが含まれていても、セッションを正常にレジュームできるようになりました。

## 実践例

### 修正前の挙動

過去のセッションで何らかの理由により不正な形式のタスクリマインダーや `@` ファイル添付エントリが履歴に保存されてしまった場合、そのセッションを `--resume` しようとするとエラーで失敗し、レジュームピッカーでのプレビューやトランスクリプトの表示もできなくなっていました。

### 修正後の挙動

不正なエントリが含まれていても、`--resume`、レジュームピッカーのプレビュー、バックグラウンドエージェントのレジューム、トランスクリプトビューのいずれも正常に動作するようになり、問題のあるエントリは適切にスキップまたは処理されます。

```bash
# 不正なエントリを含む可能性のある古いセッションでも
claude --resume
# → 正常にレジュームできる

# レジュームピッカーでのプレビューも同様に正常動作
claude --resume  # ピッカー画面でセッション一覧とプレビューを確認
```

## 注意点

- この不具合は履歴データが何らかの理由で破損・不正な形式になっている場合に限定して発生していました
- 通常の正常な履歴データを持つセッションでは、元々問題なくレジュームできていました
- 不正なエントリ自体が具体的にどのような内容だったかは、レジューム後のトランスクリプトで欠落・省略される場合があります
