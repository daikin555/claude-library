## 原文（日本語訳）

セッションあたり200件というサブエージェントの起動上限を撤廃しました。長時間実行セッションで新規エージェントの起動が拒否されることがなくなります（同時実行数制限と深さ制限は引き続き適用されます）。

## 原文（英語）

Removed the 200-subagent-per-session spawn cap; long-running sessions no longer refuse new agents (concurrency and depth limits still apply)

## 概要

Claude Codeのサブエージェント機能は、調査やファイル探索などのタスクを別のコンテキストウィンドウを持つ子エージェントに委譲できる仕組みです。これまではセッションあたり最大200件までしかサブエージェントを起動できないという上限があり、`CLAUDE_CODE_MAX_SUBAGENTS_PER_SESSION`環境変数で調整できるものの、長時間にわたって多数のサブエージェントを使い倒すセッションでは、この上限に達すると新規エージェントの起動が拒否されてしまう問題がありました。今回のアップデートでこのセッション累計の上限そのものが撤廃され、長時間セッションでも新しいサブエージェントの起動が拒否されなくなりました。ただし、同時に走らせられる数（同時実行数制限）と、サブエージェントがさらにサブエージェントを起動できる深さ（スポーン深さ制限）は引き続き適用されます。

## 基本的な使い方

特別な操作は不要です。通常どおりタスクをClaudeに依頼すれば、必要に応じて自動的にサブエージェントが起動されます。

```text
> このリポジトリ全体を対象に、未使用のexportを洗い出して調査して
```

同時実行数や深さの上限を調整したい場合は環境変数で設定します。

```bash
# 同時に実行できるサブエージェント数の上限(デフォルト20)
export CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS=20

# サブエージェントがさらにサブエージェントを起動できる深さの上限(デフォルト3)
export CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH=3
```

## 実践例

### 大規模モノレポの継続的な調査セッション

数百ファイルにまたがる大規模なモノレポで、Exploreエージェントやカスタムサブエージェントを使って何時間もかけて段階的に調査・リファクタリングを進めるようなワークフローでは、以前はセッションの後半で「200件の上限に達しました」といった形で新規エージェントの起動が拒否されることがありました。この上限撤廃により、セッションを`/clear`せずに長時間継続しても、サブエージェントの起動自体で頭打ちになることがなくなります。

### CI連携などで長時間の自動化タスクを回す場合

スケジュールタスクや長時間の自動化パイプラインの中でサブエージェントを多用する場合も、累計起動数によるブロックを気にせずに設計できるようになります。

### 並行度と深さの制限は引き続き意識する

上限が撤廃されたのはあくまで「セッションを通じた累計起動数」であり、ある瞬間に同時に走らせられる数(既定20)や、サブエージェントからサブエージェントを何段階まで起動できるか(既定3)は変わらず制限されています。大量のタスクを一気に並列化したい場合は、これらの環境変数で調整が必要です。

```bash
# 同時実行数の上限を引き上げる例
export CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS=40
```

## 注意点

- 撤廃されたのは「セッションあたりの累計スポーン数(旧デフォルト200件、`CLAUDE_CODE_MAX_SUBAGENTS_PER_SESSION`)」の上限です。同時実行数制限(`CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS`)とスポーン深さ制限(`CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH`)は完全に撤廃されたわけではなく、引き続き有効です。
- サブエージェントを大量かつ無制限に起動できるようになるため、トークン消費量やコストが意図せず増大する可能性があります。長時間セッションでは`/context`や`/usage`でコンテキスト・使用量を随時確認することをおすすめします。
- 同時実行数や深さの制限は組織のmanaged settingsで固定されている場合があり、その場合はユーザー側で緩和できません。
