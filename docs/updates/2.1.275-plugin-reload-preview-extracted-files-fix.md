## 原文（日本語訳）

プラグインが `--plugin-dir` または `--plugin-url` のアーカイブから読み込まれていた場合、プラグインのリロードプレビューが実行中セッションの展開済みプラグインファイルを置き換えてしまう不具合を修正しました。

## 原文（英語）

Fixed plugin reload previews replacing a running session's extracted plugin files when the plugin was loaded from a `--plugin-dir` or `--plugin-url` archive

## 概要

Claude Codeでは `--plugin-dir` や `--plugin-url` を使ってアーカイブ形式のプラグインを読み込むことができます。この場合、プラグインはセッション用に一時的な場所へ展開されて使用されます。プラグインの変更をプレビューするリロード機能を使うと、修正前は実行中のセッションがすでに使用している展開済みファイルまでもが意図せず置き換えられてしまい、実行中の動作に影響が及ぶ不具合がありました。今回の修正により、リロードプレビューは実行中セッションの展開済みファイルに影響を与えなくなりました。

## 基本的な使い方

```bash
claude --plugin-dir ./my-plugin
claude --plugin-url https://example.com/my-plugin.zip
```

プラグインの変更をプレビューする際も、実行中のセッションに影響を与えることなく安全に確認できます。

## 実践例

### プラグインをローカルディレクトリから読み込んで開発する

`--plugin-dir` でローカルのプラグインアーカイブを指定して開発中、変更内容をリロードプレビューで確認したいケースがあります。修正前は、実行中セッションがすでに参照している展開済みファイルまで書き換わってしまい、セッションの挙動が不安定になることがありました。修正後はプレビューと実行中セッションのファイルが分離され、安全に確認できます。

```bash
claude --plugin-dir ./my-plugin
# セッション実行中にプラグインを更新してリロードプレビューを確認しても、
# 実行中セッションの展開済みファイルは影響を受けない
```

### リモートURLから配布されたプラグインアーカイブの利用

`--plugin-url` で配布されたプラグインアーカイブを使っている場合も同様に、リロードプレビューが実行中セッションのファイルに干渉しないようになりました。

## 注意点

- この修正はプラグインの展開先の分離に関するものです。プラグイン自体のコード変更を反映させるには、依然としてセッションの再起動やリロードの明示的な操作が必要な場合があります。
- `--plugin-dir` や `--plugin-url` はローカル開発や社内配布など特定のワークフロー向けのオプションです。
