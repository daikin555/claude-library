## 原文（日本語訳）

[VSCode] 接続に失敗した後も拡張機能が Remote Control を「接続済み」と表示してしまう問題を修正しました。

## 原文（英語）

[VSCode] Fixed the extension showing Remote Control as connected after the connection failed

## 概要

この項目はClaude Code **VS Code拡張機能**に関する修正です。VS Code拡張機能では、プロンプト入力欄で `/remote-control`（または `/rc`）を実行すると、接続状態を示すバナーが表示されます。v2.1.224より前は、Remote Controlへの接続が実際には失敗していたにもかかわらず、拡張機能のバナーが「接続済み」と表示されてしまうことがありました。今回の修正により、接続に失敗した場合はその状態が正しくバナーに反映されるようになりました。

## 基本的な使い方

VS Code拡張機能でRemote Controlを開始する方法自体は変わりません。

```text
# VS Code拡張機能のプロンプト入力欄で実行
/remote-control
```

接続に成功すると、プロンプト入力欄の上にバナーが表示され、`claude.ai/code` へのリンクをクリックしてセッションへ直接アクセスできます。

## 実践例

### 接続失敗時にユーザーが誤認してしまうケース

```text
# ネットワーク不調やRemote Controlの一時的な障害などで接続に失敗した場合

# 修正前:
# バナーには「接続済み」と表示され続けるため、
# ユーザーはスマートフォンやブラウザから操作できると思い込んでしまう
# → claude.ai/code のセッション一覧を開いても該当セッションが見つからず混乱する

# 修正後:
# 接続失敗時はバナーが「接続済み」を示さなくなり、
# ユーザーは失敗に気づいてすぐに /remote-control を再実行できる
```

### 再接続を試みるワークフロー

接続状態が正しく表示されるようになったことで、失敗に気づいた時点で再試行するという通常のフローが機能するようになりました。

```text
# 1. /remote-control を実行 → 接続失敗（バナーは「接続済み」を表示しない）
/remote-control

# 2. ネットワークなどの問題を解消してから再度実行
/remote-control
# → 成功すればバナーに正しく「接続済み」と表示され、
#    claude.ai/code のリンクも有効になる
```

## 注意点

- この修正はVS Code拡張機能に固有のものです。CLI（ターミナル）版のRemote Controlインジケーター（`/rc active`）には元々この問題は影響していません。
- 接続に失敗した場合は、通知に失敗理由が表示されます。バナーの表示だけでなく通知内容も確認してください。
- 接続状態を再確認したい場合は、`/remote-control` を再実行するか、コマンドメニューから状態パネルを開いて確認できます。
