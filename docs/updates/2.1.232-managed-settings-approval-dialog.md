## 原文（日本語に翻訳）

管理対象設定（managed settings）の承認ダイアログを改善しました。エンドポイントURLを表示し、テレメトリのみの変更にはより分かりやすい文言を使用し、通常のOpenTelemetryオプションについては承認をスキップし、サーバー管理のサンドボックスバイナリの上書き（`sandbox.bwrapPath`、`sandbox.socatPath`、`sandbox.ripgrep`）については承認を必須とするようにしました

## 原文（英語）

Improved the managed settings approval dialog: shows endpoint URLs, uses clearer wording for telemetry-only changes, skips routine OpenTelemetry options, and requires approval for server-managed sandbox binary overrides (`sandbox.bwrapPath`, `sandbox.socatPath`, `sandbox.ripgrep`)

## 概要

企業や組織で管理されたポリシー（managed settings）がClaude Codeの設定を変更しようとする際、ユーザーに承認を求めるダイアログが表示されます。v2.1.232では、このダイアログが改善され、（1）変更対象のエンドポイントURLが表示されるようになり、（2）テレメトリのみに関わる変更の場合はより分かりやすい文言になり、（3）通常のOpenTelemetryオプションの変更では承認ダイアログ自体が省略されるようになり、（4）一方でセキュリティ上重要なサンドボックスバイナリのパス上書き（`sandbox.bwrapPath`、`sandbox.socatPath`、`sandbox.ripgrep`）については、必ずユーザーの承認が必要になるよう強化されました。

## 基本的な使い方

```bash
# 管理対象設定（例: 組織のポリシーファイル）によって
# Claude Codeの設定が変更されようとした場合、承認ダイアログが表示される

claude

# 修正前: どのエンドポイントに接続しようとしているか不明瞭だったり、
#         些細なOpenTelemetryの設定変更にも毎回承認が求められることがあった
# 修正後: エンドポイントURLが明示され、テレメトリ関連は文言が改善、
#         通常のOpenTelemetry設定変更は承認不要になった
```

## 実践例

### テレメトリ設定のみが変更される場合

```jsonc
// managed-settings.json 側でOpenTelemetリレーテッドのエンドポイントが変更された場合
{
  "otelEndpoint": "https://telemetry.example.com/v1/traces"
}
```

このような変更では、承認ダイアログに接続先のエンドポイントURLが明示され、「テレメトリ収集のみに関する変更です」といった分かりやすい文言で表示されるようになりました。通常のOpenTelemetryオプションであれば承認ダイアログ自体がスキップされ、業務効率が向上します。

### サンドボックスバイナリのパスが上書きされる場合

```jsonc
// managed-settings.json でサンドボックス関連バイナリのパスが上書きされるケース
{
  "sandbox": {
    "bwrapPath": "/custom/path/to/bwrap",
    "socatPath": "/custom/path/to/socat",
    "ripgrep": "/custom/path/to/rg"
  }
}
```

これらはセキュリティ上重要な設定であるため、v2.1.232以降は自動適用されず、必ずユーザーの明示的な承認が求められるようになりました。

### 管理者としてポリシーを配布する場合

```bash
# 組織の管理者がmanaged-settings.jsonを配布する際、
# エンドユーザー側の承認ダイアログにどの情報が表示されるかを踏まえて
# 設定内容を検討できる
```

## 注意点

- Claude Code v2.1.232で導入された改善です。
- `sandbox.bwrapPath`、`sandbox.socatPath`、`sandbox.ripgrep` はサンドボックス実行に使われるバイナリパスの上書き設定であり、任意のバイナリに差し替えられるとセキュリティリスクとなるため、承認必須化は意図的なセキュリティ強化です。
- 通常のOpenTelemetryオプション（何が「通常」に該当するかの詳細）については公式ドキュメントを参照してください。
