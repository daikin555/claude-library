## 原文（日本語訳）

出力が20MBの上限を超える検索において、Grep、Glob、および@ファイル候補がハングしたりメモリ不足になったりする不具合と、大量の警告が出た後にシステムのripgrepがエラーの代わりに「一致なし」と報告してしまう不具合を修正しました。

## 原文（英語）

Fixed Grep, Glob and @-file suggestions hanging or running out of memory on searches over the 20MB output cap, and system ripgrep reporting "no matches" instead of an error after a flood of warnings

## 概要

Claude CodeのGrep/Globツールや `@` によるファイル候補補完は、内部的にripgrepを利用して高速な検索を行っています。検索結果の出力が非常に大きく20MBの上限を超えるようなケースで、処理がハングしたりメモリを使い果たしたりする不具合がありました。また、システムにインストールされたripgrepを使う場合、大量の警告メッセージが出力されると、本来はエラーとして扱うべき状況を「一致なし（no matches）」と誤って報告してしまう問題もありました。今回の修正でこれらが解消され、大規模な検索でも安定して動作するようになりました。

## 基本的な使い方

通常どおりGrepツールやGlobツール、`@`によるファイル参照を使用するだけで、この修正の恩恵を受けられます。

```bash
# 大規模なリポジトリに対する検索でも安定して動作する
# (Claude Codeセッション内でGrepツールを使用)
```

## 実践例

### 巨大なリポジトリでのGrep検索

非常に多くのファイルやバイナリに近いテキストファイルを含む大規模モノレポでは、検索結果が20MBを超えることがあります。修正前はこのようなケースでツールがハングしたりメモリ不足でクラッシュしたりすることがありましたが、修正後は安全に上限で打ち切られ、処理が継続します。

### システムripgrep使用時の警告フラッド

システムにインストールされたripgrepを利用する設定で、権限エラーなどによる警告が大量に出力される状況では、修正前は本来のエラーが「一致なし」として握りつぶされていました。修正後は正しくエラーとして扱われるため、検索結果が0件だったのか、そもそも検索が失敗したのかを正しく区別できます。

## 注意点

- 20MBという出力上限そのものは変更されておらず、上限を超えるような巨大な結果セットは依然として切り詰められます。より絞り込んだ検索パターンやパスの指定を推奨します。
- システムripgrepを使うかバンドルされたripgrepを使うかは環境によって異なるため、動作に差異を感じる場合は設定を確認してください。
