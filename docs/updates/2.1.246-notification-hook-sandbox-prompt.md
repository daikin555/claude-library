## 原文（日本語訳）

サンドボックスの「Network request outside of sandbox」権限プロンプトが待機している間、`Notification` フックが発火しない問題を修正しました。

## 原文（英語）

Fixed the `Notification` hook not firing while the sandbox "Network request outside of sandbox" permission prompt is waiting

## 概要

Claude Codeのサンドボックス機能は、コマンド実行時のファイルアクセスやネットワークアクセスを制限し、サンドボックス外へのネットワークリクエストが発生した場合にはユーザーに確認を求めます。この確認プロンプトが表示されて応答待ちの状態になっている間、本来であればユーザーに知らせるための `Notification` フックが発火するはずでしたが、実際には発火しないという不具合がありました。これにより、通知を頼りに他の作業をしていたユーザーが、承認待ちの状態に気づくのが遅れる可能性がありました。今回の修正で、この待機中も `Notification` フックが正しく発火するようになりました。

## 基本的な使い方

`Notification` フックを設定している場合、サンドボックスのネットワーク許可確認が発生した際にも通知が届くようになります。

```json
{
  "hooks": {
    "Notification": [
      {
        "hooks": [
          { "type": "command", "command": "notify-send \"Claude Code\" \"$CLAUDE_NOTIFICATION\"" }
        ]
      }
    ]
  }
}
```

## 実践例

### サンドボックス下でのバックグラウンド作業の監視

サンドボックスを有効にした状態でClaude Codeをバックグラウンドで動かしている際、意図しないネットワークアクセスが発生して承認待ちになった場合でも、`Notification` フックによってすぐに気づくことができます。

### デスクトップ通知との連携

`Notification` フックからOS標準の通知機能（`notify-send` や `osascript` など）を呼び出す設定をしている場合、サンドボックスの確認プロンプトも他の通知と同様に確実に届くようになりました。

### 承認待ちによる作業停止の早期発見

サンドボックスの権限確認で処理が止まっていることに気づかないまま長時間放置してしまう、といった事態を避けやすくなります。

## 注意点

- この修正はサンドボックスの「Network request outside of sandbox」プロンプトに特有の通知欠落を解消するものです。他の権限プロンプトの通知動作には影響しません
- サンドボックス機能自体はオプトインの設定です。有効化していない場合はこの挙動は関係しません
