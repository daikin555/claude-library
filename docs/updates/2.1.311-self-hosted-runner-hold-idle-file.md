## 原文（日本語に翻訳）

`self-hosted-runner` に `--hold-idle-file` と `--max-hold-min` を追加。ホストが、セッションの残したプロセスが実行中であると報告している間、アイドル状態のセッションを維持できるようになりました。

## 原文（英語）

Added `--hold-idle-file` and `--max-hold-min` to `self-hosted-runner`, to keep an idle session while your host reports processes it left running

## 概要

`self-hosted-runner` に、アイドル状態のセッションを維持するための2つのオプションが追加されました。ホスト側が「セッションが残したプロセスがまだ動いている」と報告している間は、セッションがアイドルでも終了させずに保持できます。保持時間の上限は `--max-hold-min` で指定します。

## 基本的な使い方

```bash
claude self-hosted-runner \
  --hold-idle-file /var/run/runner/busy \
  --max-hold-min 30
```

- `--hold-idle-file`: ホストが管理するファイルのパス。ホストがプロセスの実行中であると報告している間、アイドルセッションを維持するために参照されます。
- `--max-hold-min`: 保持する最大時間（分）。

（ファイルの正確な形式や判定条件は、公式ドキュメントまたは `claude self-hosted-runner --help` で確認してください。）

## 実践例

### 開発サーバーを起動したままのセッションを保つ

Claudeがバックグラウンドで開発サーバーやテストウォッチャーを起動した場合、アイドル判定でセッションが終了するとそれらも止まってしまいます。ホスト側のラッパーが該当ファイルを管理することで、プロセスが動いている間だけセッションを保持できます。

### 無制限の保持を防ぐ

`--max-hold-min` に上限を設けることで、ホストの報告が更新されないままセッションが残り続けるのを防げます。

## 注意点

- 保持はあくまで `--max-hold-min` までの上限付きです。
- ファイルの内容形式などの詳細は本記事執筆時点で確認できていないため、`--help` を参照してください。
