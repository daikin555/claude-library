## 原文（日本語に翻訳）

`strictKnownMarketplaces` と `blockedMarketplaces` のmanaged settingsに、GitHub org配下のすべてのマーケットプレイスリポジトリを許可・ブロックするための、owner wildcardエントリ（`"owner/*"`）が追加された。

## 原文（英語）

Added owner wildcard entries (`"owner/*"`) to the `strictKnownMarketplaces` and `blockedMarketplaces` managed settings for allowing or blocking all marketplace repos under a GitHub org

## 概要

`strictKnownMarketplaces` と `blockedMarketplaces` は、組織の管理者が `managed-settings.json` で設定できるプラグインマーケットプレイスの許可・ブロックリストです。これまでは `{"source": "github", "repo": "acme-corp/approved-plugins"}` のようにリポジトリ単位で厳密一致（exact match）させる必要があり、GitHub org配下に多数のマーケットプレイスリポジトリが存在する場合、1つずつ列挙する必要がありました。今回のアップデートで、`repo` フィールドに `"owner/*"` という形式のowner wildcardを指定できるようになり、特定のGitHub org配下のリポジトリをまとめて許可・ブロックできるようになりました。

## 基本的な使い方

`managed-settings.json` に以下のように記述すると、`acme-corp` org配下のすべてのマーケットプレイスリポジトリが許可されます。

```json
{
  "strictKnownMarketplaces": [
    {
      "source": "github",
      "repo": "acme-corp/*"
    }
  ]
}
```

同様に `blockedMarketplaces` でも `"owner/*"` を指定すると、そのorg配下のリポジトリをまとめてブロックできます。

```json
{
  "blockedMarketplaces": [
    {
      "source": "github",
      "repo": "untrusted-org/*"
    }
  ]
}
```

## 実践例

### 社内orgのマーケットプレイスを一括許可する

複数チームがそれぞれ独自のプラグインマーケットプレイスリポジトリを社内GitHub org配下で運用している場合、org単位でまとめて許可できます。

```json
{
  "strictKnownMarketplaces": [
    {
      "source": "github",
      "repo": "acme-corp/*"
    }
  ],
  "extraKnownMarketplaces": [
    {
      "source": "github",
      "repo": "acme-corp/approved-plugins"
    }
  ]
}
```

`strictKnownMarketplaces` は「ユーザーが追加できるもの」を制限するだけなので、実際にデフォルトで登録しておきたいマーケットプレイスは別途 `extraKnownMarketplaces` に列挙します。

### 特定orgからのマーケットプレイスを一括ブロックする

セキュリティポリシー上、信頼していない外部orgのリポジトリをマーケットプレイスとして追加できないようにしたい場合に使用します。

```json
{
  "blockedMarketplaces": [
    {
      "source": "github",
      "repo": "random-github-user/*"
    }
  ]
}
```

これにより、そのユーザー/org配下のどのリポジトリをマーケットプレイスとして追加しようとしても拒否されます。

### 自社orgのみ許可し、それ以外は全面ブロックする組み合わせ

厳格なサプライチェーン管理をしたい組織では、`strictKnownMarketplaces` による許可リストと `blockedMarketplaces` を組み合わせることで、自社org以外を実質的にすべて排除できます。

```json
{
  "strictKnownMarketplaces": [
    {
      "source": "github",
      "repo": "acme-corp/*"
    }
  ]
}
```

`strictKnownMarketplaces` に許可リストを設定した時点で、そこに一致しないマーケットプレイスは自動的に追加不可になるため、多くの場合はこれだけで十分です。

## 注意点

- `strictKnownMarketplaces` と `blockedMarketplaces` はどちらもmanaged settings専用の項目であり、ユーザー設定やプロジェクト設定では上書きできません。
- ワイルドカードはowner（GitHub org/ユーザー）単位でのみサポートされており、リポジトリ名の一部分だけをワイルドカード化すること（例: `acme-corp/plugin-*`）は本アップデートの説明範囲では言及されていません。
- 制限チェックはマーケットプレイス追加時だけでなく、プラグインのインストール・更新・リフレッシュ・自動更新のたびに実行されます。ポリシー変更前に追加済みのマーケットプレイスも、新しいポリシーに一致しなければブロックされます。
- `strictKnownMarketplaces` は「ユーザーが追加できるもの」を制限するだけで、マーケットプレイスを自動登録するものではありません。デフォルトで使わせたいマーケットプレイスは `extraKnownMarketplaces` に別途追加する必要があります。
- 本記事作成時点で公式ドキュメントの `strictKnownMarketplaces`/`blockedMarketplaces` リファレンスページには、owner wildcardの完全な仕様（例えば `hostPattern`・`pathPattern` との組み合わせ可否など）についての詳細な記載がまだ反映されていない可能性があるため、記事の一部はchangelogの記述内容からの妥当な推測を含みます。
