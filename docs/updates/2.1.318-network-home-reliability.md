# 共有ネットワークホームでの設定・ログイン保存の信頼性向上

## 原文（日本語訳）

- `~/.claude.json`、設定ファイル、保存済みログインが共有ネットワークホームディレクトリでの保存時に、削除されたり、一時的に空になったり、ほぼ空・古いコピーに置き換わったりすることが減りました
- ネットワークファイルシステム上で、設定ファイルが誤って「存在しない」と報告された場合に再確認するようになり、MCPサーバーや信頼済みフォルダなしで起動するケースが減りました
- `/logout`、`claude auth logout`、`claude mcp remove` が、共有ネットワークホームで設定ファイルを更新できなかった場合に成功と報告したり、信頼・同意・MCP設定の変更が黙って破棄されたりする問題を修正しました

## 原文（英語）

- Improved how `~/.claude.json`, settings files and the stored login survive saves on shared network home directories: they are less often deleted, briefly emptied or replaced by a near-empty or older copy
- Improved sessions on network file systems to look again when the configuration file is wrongly reported as missing, so fewer start without your MCP servers and trusted folders
- Fixed `/logout`, `claude auth logout` and `claude mcp remove` reporting success, and changes to trust, consent or MCP settings being dropped with no word, when the config file could not be updated on a shared network home directory

## 概要

NFSなどの共有ホームディレクトリで、複数の端末やジョブから同時にClaude Codeを使う際の設定消失リスクが下がりました。更新失敗も正しく報告されます。

## 基本的な使い方

特別な操作は不要です。2.1.318へ更新するだけで適用されます。

```bash
claude --version
```

## 実践例

### HPC・共有サーバー環境

ホームを共有する研究クラスタなどで、MCPサーバー設定や信頼済みフォルダが消える問題が減ります。

### ログアウトの確認

`claude auth logout` が失敗した場合にエラーが表示されるため、ログアウトできたと誤認しなくなります。

## 注意点

- 同時書き込みの競合が完全になくなるわけではありません。
- 大切な設定は `~/.claude.json` のバックアップを取っておくと安心です。
