## 原文（日本語訳）

フックやバックグラウンドエージェントがメガバイト単位のエラー出力を出力した際に、それが会話コンテキストを溢れさせ、セッションが「Prompt is too long」で動かなくなってしまう不具合を修正しました。

## 原文（英語）

Fixed a hook or background agent that printed megabytes of error output being able to overflow the conversation and wedge the session on "Prompt is too long"

## 概要

フックスクリプトやバックグラウンドで動くエージェントが、想定外の理由でメガバイト規模の膨大なエラー出力を吐き出すことがあります。これまではこの出力がそのまま会話コンテキストに取り込まれてしまい、コンテキストの上限を超えて「Prompt is too long」エラーとなり、セッション自体が操作不能になってしまう（ユーザーが会話を続けられなくなる）ことがありました。今回の修正で、こうした大量出力によってセッションが完全に詰まってしまう問題が解消されています。

## 基本的な使い方

ユーザー側で特別な設定は不要です。フックやバックグラウンドエージェントの出力が異常に大きくなった場合でも、セッションが「Prompt is too long」で完全に固まることなく動作を継続できるようになりました。

```
（PostToolUseフックが誤って数MBのスタックトレースを標準エラーに出力してしまった場合）
→ 修正前: セッションが "Prompt is too long" で応答不能になる
→ 修正後: セッションは継続して動作する
```

## 実践例

### バグのあるフックスクリプトを実行してしまった場合

デバッグ中のフックスクリプトが無限ループやログの重複出力によって大量のエラーを出力してしまっても、セッション全体が使えなくなる事態を避けられます。

### バックグラウンドエージェントが暴走した場合

バックグラウンドで実行しているエージェントが何らかの理由で大量のエラーメッセージを出し続けても、親セッションのコンテキストがそれによって溢れて動作不能になるリスクが下がります。

### CI連携やカスタムツールからの予期しない出力

外部コマンドやカスタムツールが想定外に大きなエラー出力（例えば依存関係の解決エラーで数千行のログを出すなど）を返してきても、セッションの安定性が保たれます。

## 注意点

- この修正はあくまで「セッションが完全に詰まる」ことを防ぐものであり、フックやバックグラウンドエージェントが大量のエラー出力をそもそも出さないように直すことは、依然としてユーザー側の対応が必要です
- 非常に大きな出力は依然として一部が切り詰められたり要約されたりする可能性があるため、詳細なエラー内容を確認したい場合はログファイルなど別の手段も併用することが推奨されます
