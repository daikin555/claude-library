## 原文（日本語訳）

[VSCode] 実行中のセッションをリネームすると自動生成された名前に戻ってしまう問題を修正しました（2.1.269で発生した回帰バグ）。

## 原文（英語）

[VSCode] Fixed renaming a running session reverting to the generated name (regression in 2.1.269)

## 概要

Claude Codeでは、セッションに任意の名前を付けて管理できます。しかし、バージョン2.1.269で発生した回帰バグにより、実行中のセッションをリネームしても、しばらくすると自動生成された名前（Claudeが会話内容から自動でつけた名前）に上書きされて戻ってしまう不具合が発生していました。今回のリリースでこの回帰バグが修正され、リネームした名前が正しく維持されるようになりました。

## 基本的な使い方

セッション一覧またはセッションタイトル部分をクリックし、任意の名前に変更できます。

```
1. セッションのタイトルを右クリックまたはダブルクリック
2. 新しい名前を入力
3. Enterで確定
```

## 実践例

### セッションが実行中（タスク処理中）にリネームする場合

Claudeがまだタスクを処理している最中にセッション名を変更し、処理が進むにつれて自動生成名に上書きされていないか確認するケースです。

```
修正前（2.1.269〜）:
  1. 実行中セッションを「本番デプロイ対応」にリネーム
  2. Claudeの処理が進行 → 名前が自動生成名（例: "Fixing deployment script"）に戻ってしまう

修正後:
  1. 実行中セッションを「本番デプロイ対応」にリネーム
  2. Claudeの処理が進行しても「本番デプロイ対応」のまま維持される
```

### 複数の実行中セッションを整理・管理する場合

複数のタスクを並行して走らせている際、それぞれに分かりやすい名前を付けて管理したいユーザーにとって、リネームが確実に保持されることは作業効率に直結します。

## 注意点

- この不具合は2.1.269で導入された回帰バグであり、それ以前のバージョンでは発生していませんでした。
- リネームは実行中・完了済みいずれのセッションに対しても行えます。
