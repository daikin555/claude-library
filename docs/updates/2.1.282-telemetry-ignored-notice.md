## 原文（日本語訳）

プロジェクトの設定ファイルで無視された、またはテレメトリをオフにしたテレメトリ関連の環境変数を一覧表示する起動時通知と、`/status` および `claude doctor` のエントリを追加しました。

## 原文（英語）

Added a startup notice, and `/status` and `claude doctor` entries, listing telemetry variables in a project's settings files that were ignored or that turned telemetry off

## 概要

Claude Codeはセキュリティ上の理由から、プロジェクト単位の設定ファイル（`.claude/settings.json` など）に書かれた一部のOpenTelemetry関連の環境変数（`CLAUDE_CODE_ENABLE_TELEMETRY` や `OTEL_LOG_*` など）を無視する場合があります。これまでは、なぜテレメトリが有効にならないのかが分かりにくいという問題がありました。今回の変更で、起動時の通知、`/status`、`claude doctor` のいずれでも、無視された・または無効化されたテレメトリ変数を具体的に確認できるようになりました。

## 基本的な使い方

通常の操作は不要です。該当する変数がある場合、Claude Code起動時に自動で通知が表示されます。状態を後から確認したい場合は以下を実行します。

```bash
claude doctor
```

または対話セッション内で:

```
/status
```

## 実践例

### テレメトリが有効にならない原因の切り分け

組織のOpenTelemetry基盤にメトリクスが飛んでこない場合、まず `claude doctor` を実行し、どの変数がプロジェクト設定で無視されているかを確認します。

```bash
claude doctor
# → "OTEL_LOG_USER_PROMPTS is ignored in project settings" のような表示
```

### オンボーディング時の設定ミス検知

新しいプロジェクトに参加したメンバーが `.claude/settings.json` にテレメトリ変数を書いても反映されない場合、起動時通知を見ればすぐに原因（プロジェクト設定側での制限）に気づけます。

## 注意点

- これはテレメトリを有効にする機能ではなく、「なぜ有効にならないか」を可視化する診断表示です
- ユーザー設定・管理設定（managed settings）ではなく、プロジェクト設定ファイルに起因する制限が対象です
- 関連する制限自体は [変更: プロジェクト/ローカル設定でのOTEL変数無視](./2.1.282-change-settings-ignore-otel-vars.md) を参照してください
