## 原文（日本語に翻訳）

Claude appsゲートウェイのサインインにサインイン済みアカウント名を追加：ゲートウェイがアカウント名を返す場合、認証情報が保存される前にそのアカウントを確認できるようになり、`/status` でも表示されるようになりました

## 原文（英語）

Added the signed-in account to Claude apps gateway sign-in: when the gateway names it, you confirm it before the credential is saved, and `/status` shows it

## 概要

企業や組織が運用するClaude appsゲートウェイ経由でサインインする際、これまではどのアカウントで認証されるのかが分かりにくいことがありました。この変更により、ゲートウェイ側がアカウント名を通知してくる場合、認証情報を保存する前に画面上でそのアカウント名を確認できるようになり、誤ったアカウントでサインインしてしまうリスクを減らせます。また、サインイン後は `/status` コマンドでも現在サインインしているアカウントを確認できます。

## 基本的な使い方

ゲートウェイ経由でサインインを行うと、確認画面にアカウント名が表示されます。

```bash
claude
# サインインフローが開始され、ゲートウェイがアカウント名を返す場合
# 「このアカウントでサインインしますか？」といった確認が表示される
```

サインイン後、現在のアカウントを確認するには：

```
/status
```

## 実践例

### 複数アカウントを使い分けている場合の確認

組織のゲートウェイ経由で複数のアカウントを切り替えて利用しているケースでは、意図しないアカウントで認証情報が保存されるのを防げます。

```bash
claude
# サインイン確認画面で表示されたアカウント名が
# 想定しているものと一致するかを確認してから承認する
```

### サインイン後のアカウント確認

サインインが完了した後、どのアカウントが使われているかを `/status` で素早く確認できます。

```
/status
# 出力例:
# Account: user@example.com (via gateway)
```

## 注意点

- アカウント名の表示は、ゲートウェイ側がアカウント名を返却する構成になっている場合のみ機能します
- ゲートウェイがアカウント名を提供しない場合、従来通りの挙動になります
- 認証情報の保存前に確認ステップが挟まるため、自動化スクリプトなどでは影響がないか確認してください
