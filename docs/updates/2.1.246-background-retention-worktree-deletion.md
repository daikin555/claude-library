## 原文（日本語訳）

古いバックグラウンドセッションのレコードが指し示していた場合に、`.claude/worktrees/` 配下にあるユーザー自身が作成したgit worktreeを、バックグラウンド保持のクリーンアップ処理が削除してしまう問題を修正しました。

## 原文（英語）

Fixed the background retention sweep removing git worktrees under `.claude/worktrees/` that you created yourself when an old background-session record pointed at them

## 概要

Claude Codeはバックグラウンドセッションが使用したgit worktreeを `.claude/worktrees/` 配下に作成・管理し、一定期間が過ぎた古いセッションレコードとともに不要になったworktreeを自動的に削除する「保持クリーンアップ（retention sweep）」を行っています。しかし、古いバックグラウンドセッションのレコードが、たまたまユーザー自身が手動で作成し同じパスに配置したworktreeを指していた場合、そのクリーンアップ処理によってユーザーのworktreeまで誤って削除されてしまう問題がありました。この修正により、自分で作成したworktreeが意図せず消えてしまうことがなくなります。

## 基本的な使い方

この修正はバックグラウンドのクリーンアップ処理の内部ロジックに関するものです。ユーザーは特別な操作をする必要はありませんが、`.claude/worktrees/` 配下で独自にworktreeを管理している場合、以降はバックグラウンドセッションの保持期限切れによる自動削除の対象から正しく除外されます。

```
.claude/worktrees/
├── session-abc123/   # バックグラウンドセッションが作成したもの（保持期限で削除される）
└── my-manual-wt/     # ユーザーが自分で作成したもの（修正後は誤って削除されない）
```

## 実践例

### `.claude/worktrees/` 配下で独自のworktreeを運用しているチーム

CI連携や独自のブランチ管理のために `.claude/worktrees/` 配下に手動でworktreeを作成して運用している場合、古いバックグラウンドセッションの記録と衝突して意図せず削除されるリスクが解消されます。

### バックグラウンドセッションを頻繁に使うワークフロー

複数のバックグラウンドセッションを日常的に作成・破棄する運用では、保持期限切れのクリーンアップが定期的に走ります。この際に無関係な自作worktreeが巻き込まれて消えることがなくなり、安心してバックグラウンドセッションを活用できます。

### 長期間保持したいworktreeとの併用

実験用や長期検証用に残しておきたいworktreeを `.claude/worktrees/` に置いている場合でも、古いセッションレコードの誤参照によって消されるリスクがなくなり、安全に共存できます。

## 注意点

- この問題は、古いバックグラウンドセッションのレコードが偶然ユーザー作成のworktreeと同じパスを指していた場合に限って発生していました
- 修正後もClaude Codeが実際に作成・管理しているバックグラウンドセッション用worktreeは、通常の保持期限に従って削除されます
- 重要なworktreeについては、`.claude/worktrees/` 以外の場所に置くか、バックアップを取っておくことも安全な運用の一つです
