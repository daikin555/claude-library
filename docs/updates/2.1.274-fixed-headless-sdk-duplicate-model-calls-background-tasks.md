## 原文（日本語訳）
ヘッドレスおよびSDKセッションで、完了したバックグラウンドタスクごとに個別のモデル呼び出しを行っていた問題を修正。すでにキューに溜まっていた完了通知は、1回の呼び出しでまとめて応答されるようになった。

## 原文（英語）
Fixed headless and SDK sessions making a separate model call for every background task that finished; completions already queued are now answered by one call

## 概要
これまでヘッドレスモードやClaude Agent SDKを使ったセッションでは、複数のバックグラウンドタスクがほぼ同時に完了すると、それぞれに対して個別のモデル呼び出しが発生していました。このため、短時間に多数のバックグラウンドタスクが完了すると無駄なAPI呼び出しが積み重なり、レイテンシやコストの増加につながっていました。今回の修正により、すでにキューに溜まっている完了通知はまとめて1回のモデル呼び出しで処理されるようになり、効率が改善されました。

## 基本的な使い方
この修正はランタイム内部の挙動改善であり、ユーザーやSDK利用者側で明示的に有効化する設定はありません。ヘッドレスモード（`claude -p`など）やClaude Agent SDKでバックグラウンドタスク（Bashのバックグラウンド実行やサブエージェントなど）を利用している場合、自動的に恩恵を受けます。

```bash
# ヘッドレスモードでバックグラウンドタスクを伴うセッションを実行する例
claude -p "複数のバックグラウンドジョブを実行して結果をまとめて" --output-format stream-json
```

## 実践例

### 複数バックグラウンドタスクを同時実行するSDKセッション
SDKを使って複数の長時間実行タスク（ビルド、テスト、監視スクリプトなど）を並行してバックグラウンド起動した場合、以前はタスクが完了するたびに個別のモデル呼び出しが発生していました。修正後は、ほぼ同時に完了した複数タスクの結果が1回のモデル呼び出しにまとめられ、APIコール数が削減されます。

```python
# 例: Claude Agent SDKで複数のバックグラウンドタスクを起動するイメージ
# (擬似コード)
session.run_background("npm test")
session.run_background("npm run lint")
session.run_background("npm run build")
# -> 以前: 3回の完了通知でそれぞれモデル呼び出し
# -> 修正後: キューされた完了通知は1回の呼び出しでまとめて処理
```

### CI/CDパイプラインでのヘッドレス実行
CIジョブ内でClaude Codeをヘッドレスモードで動かし、複数のバックグラウンドチェックを走らせるケースでは、この修正によりAPI呼び出し回数が減り、実行コストとレイテンシが下がります。

## 注意点
- これは内部最適化であり、ユーザー側の設定変更は不要です。
- バックグラウンドタスクが1つしかない場合や、完了タイミングが大きくずれている場合は挙動に大きな違いは感じられません。
- SDKやヘッドレスモードのバージョンが古い場合はこの最適化の恩恵を受けられないため、最新版へのアップデートを推奨します。
