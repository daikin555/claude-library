## 原文（日本語に翻訳）

プロンプト内で「@」を入力すると、名前で他のClaudeセッションをメンションできるようになりました。Claudeはその後 `SendMessage` を使って、そのセッションに直接メッセージを送信します。

## 原文（英語）

Type `@` in the prompt to mention another Claude session by name; Claude then uses `SendMessage` to reach that session directly

## 概要

複数のClaude Codeセッションを同時に走らせている場合、これまでは対象セッションの名前を口頭で指示する必要がありました。v2.1.232からは、プロンプト入力欄で `@` を入力するだけで稼働中の他セッションを名前でメンションできるようになり、Claudeはそのメンションを解釈して `SendMessage` ツールで対象セッションに直接メッセージを届けます。

## 基本的な使い方

```
@backend-session このAPIの実装が終わったらフロントエンド側の作業を始めてほしい
```

プロンプト内で `@` に続けて対象セッションの名前を入力すると、Claudeがその名前を解決し、`SendMessage` で該当セッションへメッセージを送ります。

## 実践例

### 複数セッションでの共同作業を依頼する

```
@frontend-session このコンポーネントのpropsを変更したので、呼び出し側も更新して
```

バックエンドとフロントエンドなど、役割を分けて起動している複数セッション間で、作業の引き継ぎや依頼をその場で送れます。

### バックグラウンドで動いている別セッションに進捗を尋ねる

```
@migration-task 進捗はどう？エラーが出ていたら教えて
```

長時間実行中のバックグラウンドセッションに対して、状況確認のメッセージを直接送信できます。

### チーム編成したエージェントへ直接指示を送る

```
@qa-agent このプルリクエストのテストを実行して結果を報告して
```

エージェントチームの一員として動いている名前付きセッションに対しても、同様に `@` メンションで直接指示できます。

## 注意点

- Claude Code v2.1.232での変更です。
- メンション対象は「稼働中で名前が付いているセッション」に限られます。名前がない、または停止済みのセッションはメンションできません。
- 内部的には `SendMessage` ツールが使われるため、対象セッションが受信可否（accept/hold/refuse）をどう設定しているかによって届き方が変わります。
- セッション名の一覧確認には `ListAgents` 相当の機能が使われます。
