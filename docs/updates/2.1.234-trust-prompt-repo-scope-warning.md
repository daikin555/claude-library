## 原文（日本語訳）

ディレクトリがリポジトリ化される前から存在していた場合に、信頼プロンプトでリポジトリ全体スコープの警告が表示されていなかった不具合を修正しました。

## 原文（英語）

Fixed trust prompts omitting the repository-wide scope warning when the directory was first seen before the repository existed there

## 概要

Claude Codeは初めて開いたディレクトリで作業を始める際、そのディレクトリを信頼するかどうかを確認する信頼プロンプトを表示します。ディレクトリがgitリポジトリのルート（またはその配下）である場合、そこでの信頼判断はリポジトリ全体に適用される旨の警告が併記されます。しかし、そのディレクトリを最初にClaude Codeが認識した時点ではまだgitリポジトリが存在せず、後からそこにリポジトリが作成された場合には、この「リポジトリ全体スコープ」の警告が表示されないことがありました。今回の修正で、後からリポジトリ化されたディレクトリでも正しく警告が表示されるようになりました。

## 基本的な使い方

信頼プロンプトの動作自体に変更はありません。新しいディレクトリでClaude Codeを起動すると、次のような確認が表示されます。

```
Do you trust the files in this folder?

/path/to/project

This is a git repository. Trusting it grants access to the entire
repository, not just this directory.

❯ 1. Yes, proceed
  2. No, exit
```

## 実践例

### 空ディレクトリで作業開始後にgit initした場合

```bash
mkdir new-project
cd new-project
claude
# この時点ではgitリポジトリではないため、通常の信頼プロンプトが表示される
> /exit

git init
claude
# 修正前: リポジトリ化されたにもかかわらず、
#         「リポジトリ全体に適用される」という警告が表示されないことがあった
# 修正後: git initの後は正しくリポジトリ全体スコープの警告が表示される
```

### git clone前にディレクトリを事前に作っていた場合

CI環境やスクリプトで、あらかじめ空のワークディレクトリを用意しておき、後から `git clone` や `git init` でリポジトリ化する運用をしているケースでは、この修正により信頼判断のスコープが正しくユーザーに伝わるようになります。

### モノレポの一部ディレクトリで作業していた場合

サブディレクトリ単体で先にClaude Codeを使い始め、後になってリポジトリのルートに `.git` が追加された（あるいはサブモジュール化された）ようなケースでも、信頼スコープの警告漏れが起きなくなります。

## 注意点

- この修正はプロンプトの表示内容に関するものであり、信頼の判断ロジックや権限モデル自体を変更するものではありません
- リポジトリ全体スコープの警告は、そのディレクトリを信頼すると同一リポジトリ内の他のディレクトリにも信頼が及ぶことを示す重要な情報です。見落とさないようにしてください
- 既存の信頼設定（`.claude.json` などに保存された履歴）に影響はなく、今後新たに信頼判断を行う際の表示が改善されます
