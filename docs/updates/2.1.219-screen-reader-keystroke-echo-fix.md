## 原文（日本語に翻訳）

スクリーンリーダーモードにおいて、キー入力のたびに入力欄全体を読み上げ直してしまい、実際にタイプされた1文字だけがエコーされない不具合を修正しました。

## 原文（英語）

Fixed screen-reader mode rewriting the entire input line on every keystroke instead of echoing only the typed character

## 概要

Claude Codeには、視覚に障害のあるユーザー向けに `--ax-screen-reader` フラグで有効化できるスクリーンリーダーモードがあります。このモードでは、入力欄でのテキスト変更がVoiceOverやNVDAなどのスクリーンリーダーに通知され、音声で読み上げられます。従来はキーを1つ押すたびに入力欄全体が再読み上げされてしまい、タイピング中に冗長な音声フィードバックが発生していましたが、今回の修正により実際に入力した1文字のみがエコーされるようになりました。

## 基本的な使い方

スクリーンリーダーモードは、Claude Codeの起動時にフラグを付与することで有効になります。

```bash
claude --ax-screen-reader
```

有効化すると、プロンプト入力欄への文字入力やカーソル移動などの変更が、OSのアクセシビリティAPIを通じてスクリーンリーダーに通知されるようになります。修正後は、たとえば「h」「e」「l」「l」「o」と入力した場合、これまでは入力するたびに「hello」全体が読み上げられていたのに対し、修正後は打った文字（h、e、l、l、o）だけが順番に読み上げられます。

## 実践例

### VoiceOver（macOS）利用時のタイピング体験

macOSのVoiceOverを使っている場合、ターミナルでClaude Codeを起動し `--ax-screen-reader` を付けて起動します。

```bash
claude --ax-screen-reader
```

修正前は、長いプロンプトを入力している最中に1文字打つたびにそれまで入力した文章全体が読み上げられ、どこまで入力できているか把握しづらく、長文になるほど待ち時間も増えていました。修正後は打鍵ごとにその文字のみが読み上げられるため、タイプ音のフィードバックのように自然にタイピングの進捗を確認できます。

### NVDA（Windows）でのコードレビューコメント入力

NVDAユーザーがWindows上でClaude Codeを使い、PRへのレビューコメントなど長めのテキストを入力するケースです。

```bash
claude --ax-screen-reader
```

修正前は文中に誤字を見つけて途中を修正する際、1文字編集するたびに文全体が読み上げられてしまい、編集箇所の把握が困難でした。修正後は編集した文字だけが読み上げられるため、他のテキストエディタでの編集体験に近い形で快適に文章を修正できます。

### スクリプトやCI環境での動作確認

スクリーンリーダーを使わない開発者がアクセシビリティ対応を検証する場合にも、このフラグを使ってログ出力を確認できます。

```bash
claude --ax-screen-reader --verbose
```

このように起動し、実際にどのようなアクセシビリティ通知が発行されているかをログで確認することで、視覚障害のあるユーザーが体験するフィードバックの粒度が「1文字単位」になっていることを開発側でも検証できます。

## 注意点

- `--ax-screen-reader` フラグは、OS側でVoiceOverやNVDAなどのスクリーンリーダーが実際に有効になっていない環境では特に効果を体感できません。
- 貼り付け（ペースト）操作など、1文字ずつのキー入力ではない変更については、引き続き変更範囲全体が読み上げられる場合があります。
- 削除（Backspace/Delete）時の読み上げ挙動は、タイプ時のエコーとは別の扱いになっていることがあるため、環境によって聞こえ方が異なる可能性があります。
- 本修正はターミナル上のスクリーンリーダー連携に関するものであり、スクリーンリーダー自体の設定や音声エンジンの挙動はOS側の設定に依存します。
