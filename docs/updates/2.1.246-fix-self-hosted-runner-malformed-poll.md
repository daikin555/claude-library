## 原文（日本語訳）

ワークポーリングの応答が不正な形式だった場合（例えば、通信を横取りするプロキシが返すHTMLページなど）に、セルフホストランナーが実行中のライブセッションを終了させたり、プロセス自体が終了してしまう問題を修正しました。現在は不正な応答を受け取った場合、ポーリングをリトライするようになりました。

## 原文（英語）

Fixed the self-hosted runner ending its live sessions or exiting when a work-poll response is malformed (e.g. an intercepting proxy's HTML page); it now retries the poll

## 概要

セルフホストランナーは、実行すべき作業がないかを定期的にサーバーへポーリングして確認します。企業ネットワークなどでは、この通信が社内プロキシに横取りされ、期待するJSON応答の代わりにHTMLのログインページやエラーページが返ってくることがあります。これまではこうした不正な形式の応答を受け取ると、ランナーが実行中のライブセッションを強制終了したり、プロセス自体が異常終了したりしていました。今回の修正により、不正な応答は単純にリトライ対象として扱われ、ランナーは動作を継続します。

## 基本的な使い方

セルフホストランナーを通常通り起動しておくだけで、ネットワーク越しの一時的な不正応答があってもランナーは自動的にポーリングをリトライし、処理を継続します。

```
claude runner start   # セルフホストランナーの起動例
```

## 実践例

### プロキシ配下の企業ネットワークでの運用

社内プロキシが認証ページやエラーページをHTMLで返すような環境でセルフホストランナーを動かしている場合、これまでは通信のたびにランナーが落ちるリスクがありましたが、修正後はリトライにより安定して稼働を継続できます。

### 不安定なネットワーク環境でのCI連携

一時的な回線断や中間ネットワーク機器の不調によってポーリング応答が壊れることがある環境でも、ランナーが即座に終了せず、ネットワークが復旧すれば処理を継続できます。

### 長時間のライブセッションを保護

実行中の長時間セッションがある状態で一時的な不正応答が発生しても、セッションが強制終了されずに保護されるようになりました。

## 注意点

- リトライは不正な形式の応答に対する挙動であり、サーバーからの正当なエラー応答（認証エラーなど）に対する扱いは別です
- プロキシによる通信の横取り自体が続く場合は、根本的にはネットワーク設定側の見直しが必要です
