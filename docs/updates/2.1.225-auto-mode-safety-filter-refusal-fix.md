## 原文（日本語訳）

オートモードがセーフティフィルターによる自身のパーミッションチェック拒否を連続ブロック制限にカウントしていた問題を修正。アクションは依然として拒否されますが、モデルはリトライするのではなく次に進むよう指示されるようになりました。

## 原文（英語）

Fixed auto mode counting a safety-filter refusal of its own permission check toward the consecutive-block limit; the action is still denied, but the model is now told to move on rather than retry

## 概要

Claude Codeのオートモードでは、安全性を保つために連続ブロック制限という仕組みがあります。これは、3回の連続した拒否または20回の総拒否が同一セッション内で発生した場合に、エージェントを停止してユーザーのパーミッションが必要な状態に戻す保護機構です。この修正により、セーフティフィルター自体（ユーザーではなく）がパーミッションチェック要求を拒否した場合の処理が改善されました。これまでこのような拒否は誤って連続ブロック制限にカウントされていましたが、修正後はカウント対象外となり、モデルは適切に次のステップに進むよう指示されます。

## 基本的な使い方

オートモードはClaude Codeセッションで次のように有効にできます。

```bash
claude --permission-mode auto
```

VS Code、デスクトップアプリ、またはclaude.aiの場合は、UI内のモード選択パネルからオートモードを選択できます。オートモードを有効にすると、AIクラシファイアがすべてのアクション（ファイル編集やシェルコマンド実行など）の安全性を自動判定し、ユーザーのパーミッションプロンプトなしに実行が可能になります。

## 実践例

### 長時間の自動実行タスク

オートモードで複数ファイルの一括編集や大規模なリファクタリングを実行する場合、パーミッションプロンプトによる中断がなくなるため作業が効率化されます。ただし、ユーザーの意図を超えるスコープ拡大や疑わしい操作は依然としてセーフティフィルターによって遮断されます。

```bash
claude --permission-mode auto
# これ以降、複数ファイルの編集やコマンド実行がユーザーのパーミッションプロンプトなしで実行されます
```

### セーフティフィルターが拒否した場合の動作

セーフティフィルター（プロンプトインジェクション検出、スコープ逸脱検出など）がアクションを拒否した場合、修正前はモデルが同じアクションを何度もリトライしようとし、それが連続ブロック制限にカウントされて、最終的にオートモードが無効化されることがありました。修正後は、拒否されたアクションをリトライするのではなく、モデルに「このアクションは実行できないため別の方法を検討する」よう明確に指示されるため、不必要なリトライループを避けられます。

## 注意点

- **セーフティ機構は維持される**: この修正はセーフティフィルターを無効化するものではなく、フィルターによる拒否は依然として適切に行われます
- **連続ブロック制限は機能**: 実際のユーザーパーミッション拒否や重大なポリシー違反については、従来どおり3回の連続拒否または20回の総拒否で制限が発動します
- **エージェントの停止を防止**: この修正により、セーフティフィルターの正当な判定がオートモードの誤った停止を引き起こすことがなくなります
- **内部的な信頼性向上**: ユーザーが感じるパーミッションプロンプト削減と安全性の両立がより堅牢になります
