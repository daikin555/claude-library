## 原文（日本語訳）
worktreeで分離されたセッションが、特定のネストしたシェル展開を含むBashコマンドを受け付けてしまっていた問題を修正。現在はこれらのコマンドが拒否されるようになった。

## 原文（英語）
Fixed worktree-isolated sessions accepting Bash commands with certain nested shell expansions; these are now refused

## 概要
Claude Codeにはエージェントの作業をgitのworktreeで分離し、本来のリポジトリへの影響を制限する機能があります。この分離モードでは実行できるBashコマンドの範囲が制限されているはずですが、コマンド置換のネスト（例: `$(...)`の中にさらに`$(...)`を含むような構造）を使った特定のパターンでは、この制限をすり抜けて実行を許してしまう不具合がありました。今回の修正により、こうしたネストしたシェル展開を含むコマンドは正しく拒否されるようになり、worktree分離の安全性が強化されました。

## 基本的な使い方
worktree分離機能自体の使い方に変更はありません。分離されたセッションで制限対象のコマンドを実行しようとすると、以前は通っていた一部のパターンが拒否されるようになります。

```bash
# worktree分離セッションでの実行例
claude --worktree
```

## 実践例

### ネストしたコマンド置換を使った制限回避の防止
以前は、コマンド置換を入れ子にすることで分離モードの制約を回避できるケースがありました。

```bash
# ネストしたシェル展開の例
echo "$(cat $(echo /etc/passwd))"
# 修正前: worktree分離セッションでも実行が許可される場合があった
# 修正後: このようなネストした展開を含むコマンドは拒否される
```

### 通常のworktree分離ワークフローへの影響
シンプルなコマンド置換（ネストしていないもの）を使った通常のスクリプトは引き続き問題なく実行できます。ネストした展開を使う複雑なワンライナーを書く場合は、拒否されることを想定してより単純な形に書き直す必要があります。

## 注意点
- ネストしたシェル展開を多用する複雑なワンライナーは、worktree分離セッションでは拒否される可能性が高くなりました。分離モードを使う場合は、コマンドをより単純なステップに分割することを検討してください。
- この修正はセキュリティ強化を目的としたものであり、意図的な制限強化です。
