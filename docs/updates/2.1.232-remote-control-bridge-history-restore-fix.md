## 原文（日本語に翻訳）

セッションワーカーが再起動した際に、Remote Controlのブリッジセッションで会話履歴が復元されない問題を修正しました。

## 原文（英語）

Fixed Remote Control bridge sessions not restoring conversation history when the session worker restarts

## 概要

Remote Controlでは、クライアント（スマートフォンやブラウザ）とローカルで動くClaude Codeセッションを「ブリッジ」と呼ばれる仕組みで橋渡ししています。今回の修正前は、サーバー側のセッションワーカーが再起動した際に、このブリッジセッションの会話履歴が正しく復元されず、それまでのやり取りが見えなくなってしまうことがありました。本アップデートにより、ワーカー再起動後も会話履歴が正しく復元されるようになりました。

## 基本的な使い方

Remote Controlのブリッジセッションは、デスクトップ／VS Codeで実行中のセッションとリモートクライアントの間を仲介するバックエンド側の仕組みです。通常、この処理は利用者から意識されませんが、サーバー側のメンテナンスやデプロイでワーカーが再起動されるタイミングで影響を受けることがありました。

```bash
# デスクトップでRemote Controlセッションを開始
claude

# phone やブラウザから接続し、会話を継続
# サーバー側のセッションワーカーが再起動（メンテナンス等）
# 以前: 再接続時に会話履歴が空、または欠落して見えることがあった
# 修正後: 再起動後も会話履歴が正しく復元される
```

## 実践例

### メンテナンス中に接続していたRemote Controlセッションを再開する場合

Anthropic側のインフラでセッションワーカーの再起動を伴うメンテナンスやデプロイが行われるタイミングで、たまたまRemote Control経由で会話をしていたケースです。以前はこのタイミングでブリッジセッションの履歴が失われ、それまでの文脈が分からなくなることがありました。修正後は再起動をまたいでも履歴が保持され、途切れることなく続きから操作できます。

```bash
# Remote Control経由で会話を継続中
# ...サーバー側でワーカー再起動が発生...

# クライアントを再読み込み、または再接続
# 修正後: これまでの会話履歴がすべて表示される
```

### 長時間にわたるバックグラウンドセッションをリモートから監視する場合

長時間実行されるタスクをRemote Control経由で監視・操作している場合、その間にバックエンドのワーカーが再起動することがあります。以前はこのようなケースで履歴が欠落し、進捗の把握が難しくなることがありましたが、この修正によって履歴が確実に復元されるため、安心して長時間セッションをリモートから利用できます。

```bash
claude
# Remote Controlで接続し、長時間タスクを監視
# バックグラウンドでワーカー再起動が発生しても
# 会話履歴は正しく維持される
```

## 注意点

- Claude Code v2.1.232での修正です。バックエンド側（Anthropicのサーバーインフラ）の修正のため、クライアント・ホストを最新版にアップデートしていれば自動的に適用されます。
- 症状が再発した場合は、セッションを一度切断し、再接続を試してください。
- Remote Controlは Pro、Max、Team、Enterprise プランで利用可能です。
