## 原文（日本語訳）

Remote Control: このコンピューターを別のclaude.aiアカウントまたは組織にサインインさせると、数時間後に誤解を招くHTTP 404エラーが表示される代わりに、数秒以内に実行中のセッションが停止し、理由が表示されるようになりました。

## 原文（英語）

Remote Control: signing this computer in to a different claude.ai account or organization now stops the running session within seconds and says why, instead of a misleading HTTP 404 hours later

## 概要

Remote Controlを使ってPCのローカルセッションをスマートフォンやclaude.ai/codeから操作している最中に、そのPC自体を別のclaude.aiアカウントや組織にサインインし直すと、これまでは接続が裏側で壊れたまま気づかれず、数時間後に「HTTP 404」という意味の分かりにくいエラーが表示されるだけでした。今回の修正で、アカウント切り替えが発生した時点で実行中のRemote Controlセッションが数秒以内に停止し、「アカウントが切り替わったため停止した」という明確な理由が表示されるようになりました。

## 基本的な使い方

特別な操作は不要です。Remote Controlでセッションを実行している状態で、ローカルマシン側で `claude` の認証アカウントを別のclaude.aiアカウントや組織に切り替えると、自動的に以下が起こります。

1. 実行中のRemote Controlセッションが数秒以内に検知して停止する
2. 「アカウントまたは組織が変更されたため接続を終了しました」といった趣旨のメッセージが表示される
3. 元のアカウントでの接続が必要な場合は、再度サインインし直してセッションを開始する

## 実践例

### 複数アカウントを使い分けるチーム利用時

個人アカウントで会社のプロジェクトを進めながらRemote Controlでスマホから進捗確認をしていたところ、途中でチームの別アカウント（組織アカウント）にログインし直した場合、以前はスマホ側の表示が固まったまま数時間後に謎の404エラーになっていました。修正後は切り替えた瞬間にセッションが停止し、原因が明示されるため、混乱なく状況を把握できます。

### 誤って別アカウントでログインしてしまった場合の気づき方

Remote Control経由でセッションを操作中、ローカル端末で誤って別アカウントに `/login` してしまうと、即座にRemote Control側のセッションが停止メッセージとともに終了するため、「あれ、なぜか固まった」と悩む前に原因に気づけます。

## 注意点

- この変更はRemote Control（スマートフォンアプリまたはclaude.ai/codeからローカルセッションを操作する機能）に関するものです
- アカウントや組織を切り替えた場合、Remote Control経由の既存セッションは継続できないため、新しいアカウントで改めてセッションを開始する必要があります
- Claude Code on the Web（クラウド実行版）とは異なる機能である点に注意してください
