## 原文（日本語訳）

クロスセッション用の `SendMessage` に `notify_when_idle` オプションが追加されました。これにより、同じマシン上で動作している別のClaude Codeセッションに対して、そのセッションが次にアイドル状態になったタイミングで一度だけ通知を送るよう依頼できます。オプトイン方式のワンショット通知で、ポーリングは発生しません（macOSとLinuxで利用可能）。

## 原文（英語）

Added `notify_when_idle` to cross-session `SendMessage`: ask another Claude Code session on this machine to send one notice when it next goes idle — opt-in, one-shot, no polling (macOS and Linux)

## 概要

`SendMessage` は `ListAgents` と組み合わせて、同一マシン上の別のClaude Codeセッション同士でテキストメッセージをやり取りするための仕組みです。これまでは相手のセッションが今どういう状態かを知るには、こちらから何度もメッセージを送って確認する（実質的なポーリング）しかありませんでした。今回追加された `notify_when_idle` を使うと、相手セッションに「次にアイドル状態になったら一度だけ知らせて」と依頼でき、こちら側は無駄な確認を繰り返さずに済みます。

## 基本的な使い方

`notify_when_idle` はユーザーが直接指定するパラメータではなく、Claudeが状況に応じて `SendMessage` 呼び出し時に付与するオプションです。ユーザーは自然な言葉で依頼するだけで構いません。

```
別のターミナルで動いているセッションが今のタスクを終えてアイドルになったら、私に知らせて
```

Claudeはこの依頼を受けて、対象セッションに「アイドルになったら一度だけ通知してほしい」という意図を伝えます。対象セッションが次にアイドル状態に入ったタイミングで、依頼元に一度だけ通知が届きます。

## 実践例

### 長時間タスクの完了を待つ間、繰り返し確認しない

大規模なリファクタリングやビルドを別セッションで実行している場合、そのセッションに何度も「終わった？」と尋ねる代わりに、アイドルになった時点で一度だけ知らせてもらうよう依頼できます。

```
リファクタリング中のセッションが作業を終えて手が空いたら教えて
```

### 並行するworktreeでの作業調整

複数のworktreeでそれぞれ別のセッションが動いている構成で、片方のセッションが自分のタスクを終えたタイミングを、もう片方が知りたい場合に活用できます。ポーリングによる無駄なメッセージ往復が発生しません。

### バックグラウンドセッションの一段落を待つ

バックグラウンドで動かしている長時間セッションに対して、「作業が一段落してアイドルになったら知らせて」と依頼しておけば、手元の作業を進めながら通知を待つことができます。

## 注意点

- オプトインの仕組みであり、明示的に依頼した場合のみ通知が設定されます
- ワンショットです。一度通知が届くとその依頼は消費され、再度アイドルになっても自動では通知されません
- macOSとLinux（WSL2を含む）で利用できます。クロスセッションメッセージング自体がネイティブWindowsでは利用できません
- 対象セッションが `SendMessage`/`ListAgents` を拒否する権限設定になっている場合や、受信側の `crossSessionInbound` 設定によっては通知が保留・拒否されることがあります
