## 原文（日本語に翻訳）

- `claude -p` のテキスト出力で、ストリーミングの途中でAPIエラーが発生してターンが異常終了した際に、それまでに生成済みだった回答が失われてしまう不具合を修正

## 原文（英語）

- Fixed `claude -p` text output dropping the answer already produced when a turn dies on a mid-stream API error

## 概要

`claude -p` はプロンプトを1回だけ実行して結果を返すヘッドレス（非対話）モードで、CIやシェルスクリプト、自動化パイプラインへの組み込みによく使われます。従来は、Anthropic APIとのストリーミング応答の途中でネットワークエラーやAPI側のエラーが発生してターンが異常終了すると、それまでにストリームされて生成されていたテキストごと出力が失われ、標準出力が空、または不完全な状態になることがありました。v2.1.219では、ミッドストリームでエラーが発生しても、そこまでに生成済みのテキストを破棄せずに出力するよう修正され、部分的な回答であっても後続処理で活用できるようになりました。

## 基本的な使い方

```bash
# ヘッドレスモードでワンショット実行し、テキストのみを標準出力に出す
claude -p "このリポジトリのREADMEを要約して" --output-format text
```

修正前は、上記コマンドの実行中にAPI呼び出しがストリーミング途中で失敗すると、標準出力に何も返らない（あるいは崩れた出力になる）ことがありました。修正後は、エラーが起きた時点までに生成されていた文章がそのまま出力されます。

## 実践例

### CIパイプラインで部分的な回答でも後続ステップに渡す

```bash
#!/usr/bin/env bash
set -euo pipefail

output=$(claude -p "変更差分からリリースノートの下書きを作成して" \
  --output-format text || true)

if [ -n "$output" ]; then
  echo "生成された下書き（部分的な場合あり）:"
  echo "$output"
else
  echo "出力が空でした。ログを確認してください。" >&2
fi
```

以前はミッドストリームエラー時に `$output` が空文字になり、後続のリリースノート投稿ステップがスキップされていました。修正後は、エラー発生までに生成された文章が `$output` に格納されるため、たとえ回答が途中で切れていても人間がレビューして活用できます。

### `stream-json` 形式でエラー発生前後のイベントを確認する

```bash
claude -p "大きなコードベースの設計方針を説明して" \
  --output-format stream-json > events.jsonl

# 生成されたテキストイベントとエラーイベントを両方確認
cat events.jsonl | jq 'select(.type == "text" or .type == "error")'
```

`stream-json` 形式で出力すると、テキストの断片が個々のイベントとして書き出されるため、途中でエラーイベントが発生していても、それ以前に届いたテキストイベントを個別に確認・集計できます。今回の修正により、`--output-format text` を使う場合でも `stream-json` 相当の「エラー前に生成された分は残す」という挙動に揃いました。

### スクリプトでリトライ判断に活用する

```bash
result=$(claude -p "テストが失敗した原因を調査して修正案を出して" \
  --output-format text)

if echo "$result" | grep -qi "error"; then
  echo "エラーの兆候あり。部分的な結果を保存して手動確認します。"
  echo "$result" > partial-result.txt
fi
```

ミッドストリームエラーで回答が完全に消えなくなったため、「回答は途中までしか得られなかったが、次の調査の手がかりとしては十分」というケースを自動化スクリプト側で拾いやすくなります。

## 注意点

- この修正はあくまで「エラー発生時点までに生成済みのテキストを保持する」というものであり、エラー自体が解消されるわけではありません。ターンが異常終了した事実は変わらないため、終了コードやエラーメッセージのハンドリングは引き続き必要です。
- 出力されるテキストが「回答の途中」である可能性があるため、CIなどで機械的にパースする場合は、内容が文として完結しているかどうかを別途チェックすることが望まれます。
- `--output-format json` や `stream-json` を使う場合は、エラー情報とテキスト断片が別イベントとして分かれて出力されるため、部分的な回答か完全な回答かを判別しやすくなっています。用途に応じて出力フォーマットを使い分けることを推奨します。
- 本修正はv2.1.219以降で有効です。CIなどで挙動を前提とする場合は `claude --version` でバージョンを確認してください。
