## 原文（日本語訳）

実行途中で中断されたコマンドが、中断された形跡がないまま「シェルコマンドを1件実行しました」と表示されてしまう問題を修正しました。

## 原文（英語）

Fixed a command interrupted mid-run showing as "Ran 1 shell command" with no sign it was cut

## 概要

Bashツールでコマンドを実行している最中にユーザーが中断（Escキーなど）した場合、これまでは実行結果の表示が通常の完了時と同じ「シェルコマンドを1件実行しました」となっており、そのコマンドが最後まで実行されずに途中で切られたことが画面上からは分かりませんでした。これはユーザーがコマンドの結果を誤解し、実際には完了していない処理を完了したものとして扱ってしまうリスクがありました。この修正により、中断されたコマンドは中断されたことが明示的に表示されるようになります。

## 基本的な使い方

長時間かかるコマンドを実行中にEscキーなどで中断すると、以下のように表示が変わります。

```
修正前:
> Ran 1 shell command

修正後:
> Ran 1 shell command (interrupted)
```

ユーザー側で特別な操作は不要で、通常通りコマンドを中断するだけで正しい表示が得られます。

## 実践例

### 長時間のビルドやテストを途中で止めた場合

`npm run build` や大規模なテストスイートの実行を待っている間に方針を変えたくなり中断した場合、これまでは完了したように見えてビルド結果を誤って信用してしまう恐れがありましたが、修正後は中断された旨が表示に残るため、ビルドが未完了であることが一目で分かります。

### デバッグ中に誤って実行したコマンドの停止

意図せず重い処理やループするコマンドを実行してしまい、慌てて中断したケースでも、履歴を振り返った際にそのコマンドが正常終了したのか中断されたのかを区別できるようになります。

### エージェントが自動生成したコマンドの監督

Claudeが自動的に実行するコマンド（テスト実行やlintなど）をユーザーが監視しながら、想定外の挙動を見た時点で中断する運用において、中断の事実が記録として残ることで、後からセッションを振り返る際にも状況を正確に把握できます。

## 注意点

- この修正は表示上の問題の修正であり、コマンドの中断そのものの挙動（プロセスの停止方法など）を変更するものではありません
- 中断された旨はセッションの履歴・ログにも反映されるため、モデル自身も中断されたことを認識しやすくなります
- 中断のタイミングによっては、コマンドが一部の出力を既に生成している場合があります。その出力自体は引き続き表示されます
