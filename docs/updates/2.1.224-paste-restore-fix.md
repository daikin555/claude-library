## 原文（日本語訳）

再呼び出し（recall）または復元（restore）されたペースト内容が、ペーストの有効期限が切れていた場合やプレースホルダー番号が衝突していた場合に、誤ったデータに紐づいたり、テキストが静かに失われたりすることがある問題を修正しました。

## 原文（英語）

Fixed recalled or restored paste content occasionally attaching wrong data or silently losing text when the paste had aged out or placeholder numbers collided

## 概要

Claude Codeでは、長いテキストをターミナルに貼り付けると、入力欄が読みにくくならないように `[Pasted text #1]` のようなプレースホルダーに置き換えられ、実際の内容は内部的に保持されます。入力履歴を遡って過去のプロンプトを再呼び出ししたり、中断したセッションを復元したりすると、このプレースホルダーから元のペースト内容が復元される仕組みです。今回の修正では、ペースト内容が内部キャッシュから期限切れになっていた場合や、複数のペースト間でプレースホルダー番号（`#1`、`#2`など）が衝突していた場合に、誤ったペースト内容が紐づいたり、テキストが警告なく消えてしまったりする不具合が解消されました。

## 基本的な使い方

通常のペースト操作自体に変更はありません。大きなテキストブロックをターミナルに貼り付けると、これまで通りプレースホルダー表示になり、送信時に元の内容へ展開されます。

```bash
# 長いログやコードブロックをクリップボードからペースト
> [Pasted text #1 +120 lines]

# そのままEnterで送信すると、実際の内容がClaude Codeに渡される
```

## 実践例

### 修正前に起きていた問題

長時間のセッションで複数回ペーストを行い、上矢印キーで過去の入力を辿って同じプロンプトを再送信しようとすると、まれに以下のような問題が発生していました。

```bash
# 1回目のペースト（大きなエラーログ）
> [Pasted text #1 +200 lines]

# しばらく作業を続けた後、別の内容を再度ペースト
> [Pasted text #1 +15 lines]

# 履歴を上矢印で遡って最初のプロンプトを再送信すると…
# プレースホルダー番号 #1 が衝突しており、
# 最初のログではなく2回目にペーストした短い内容が
# 誤って送信されてしまうことがあった
```

また、ペーストしてから時間が経ちすぎてキャッシュから内容が期限切れ（aged out）になっていた場合、再呼び出し時にテキストがエラーも出ずに消えてしまうケースもありました。

### 修正後の挙動

同じシナリオでも、プレースホルダー番号の衝突や内容の期限切れが正しくハンドリングされるようになり、再呼び出し・復元時に意図しない内容にすり替わったり、テキストが黙って失われたりすることがなくなりました。

```bash
# 複数回ペーストしても、それぞれのペーストが
# 正しく元の内容と紐づいたまま履歴に保持される
> [Pasted text #1 +200 lines]
> [Pasted text #2 +15 lines]

# セッション復元後も、対応する内容が正しく復元される
```

## 注意点

- この修正は内部的な安定性の改善であり、ユーザー側で設定を変更する必要はありません
- 非常に長時間のセッションで大量のペーストを行う場合は、念のため送信前にプレースホルダーの内容（行数表示など）を確認することを推奨します
- セッション復元（`claude --resume` など）を多用するワークフローでも、貼り付けた内容の整合性が向上しています
