## 原文（日本語訳）

別のClaude Codeプロセスがちょうどnpmパッケージを再インストールしているタイミングで、「Couldn't start the background service … EACCES」というエラーが表示されバックグラウンドセッションが開けなくなる不具合を修正しました。

## 原文（英語）

Fixed background sessions failing to open with "Couldn't start the background service … EACCES" when another Claude Code process was re-installing the npm package at that moment

## 概要

Claude Codeは自動更新の際にnpmパッケージを再インストールすることがありますが、その最中に別のClaude Codeプロセスがバックグラウンドセッションを開こうとすると、パッケージファイルへの一時的なアクセス競合が発生し、「Couldn't start the background service … EACCES」というパーミッションエラーでセッションの起動に失敗することがありました。今回のアップデートでこの競合状態が解消され、再インストール中でもバックグラウンドセッションの起動が失敗しにくくなりました。

## 基本的な使い方

特別な操作は不要です。通常通りバックグラウンドセッションを開こうとするだけで、修正後の挙動が適用されます。

```
claude --background
```

以前は他のプロセスがパッケージを更新中だと `EACCES` エラーで失敗することがありましたが、修正後は再インストールと競合してもセッションが正常に起動します。

## 実践例

### 複数のターミナルでClaude Codeを同時に使っている場合

一つのターミナルで自動更新によるnpmパッケージの再インストールが走っている最中に、別のターミナルでバックグラウンドセッションを開こうとしても、以前は失敗することがありましたが、修正後は問題なく開けます。

### CI/CDやマルチセッション運用でClaude Codeを頻繁に起動する場合

多数のセッションを並行して起動・終了させる運用において、更新タイミングとの競合による予期しない失敗が減り、より安定してバックグラウンドセッションを利用できます。

### 自動更新が有効な環境で長期運用する場合

自動更新を有効にしたまま日常的にClaude Codeを使い続ける場合でも、更新処理とバックグラウンドセッションの起動が競合してエラーになるリスクが低減されます。

## 注意点

- このエラーはあくまで「別プロセスが再インストール中」という特定のタイミングで発生していたものであり、通常時のパーミッション設定の問題ではありません
- 環境によっては、npmパッケージのインストール先ディレクトリの権限設定自体が別の原因でEACCESを引き起こすこともあるため、修正後も同様のエラーが出る場合はインストール先の権限を確認してください
- この修正はバックグラウンドセッションの起動信頼性に関するものです
