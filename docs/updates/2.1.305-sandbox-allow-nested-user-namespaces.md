# sandbox.allowNestedUserNamespaces でサンドボックス内のユーザー名前空間を許可する

## 原文（日本語に翻訳）

- Linuxでサンドボックス化されたコマンドがユーザー名前空間を作成できるよう `sandbox.allowNestedUserNamespaces` を追加（Chromium、rootless podman など）。これによりサンドボックスのファイル保護を回避できてしまう

## 原文（英語）

- Added `sandbox.allowNestedUserNamespaces` so sandboxed commands on Linux can create user namespaces (Chromium, rootless podman); this lets them get around the sandbox's file protections

## 概要

新しい設定 `sandbox.allowNestedUserNamespaces` により、Linux上のサンドボックス内コマンドがユーザー名前空間を作成できるようになります。Chromiumやrootless podmanのように内部で名前空間を作るツールをサンドボックス下で動かせます。ただしサンドボックスのファイル保護を回避可能になるため、トレードオフがあります。

## 基本的な使い方

`settings.json` に次のように設定します。

```json
{
  "sandbox": {
    "enabled": true,
    "allowNestedUserNamespaces": true
  }
}
```

## 実践例

### ヘッドレスChromiumでE2Eテストを実行する

サンドボックス内でPlaywrightやPuppeteerのChromiumが起動に失敗する場合に有効化します。

### rootless podmanを使う

`podman run` などをサンドボックス下のコマンドから実行したい場合に設定します。

## 注意点

- 有効にするとサンドボックスのファイル保護を回避できる経路が生まれます。信頼できるリポジトリ・コマンドに限って使ってください。
- 必要なプロジェクトのみ、プロジェクト単位の設定で有効化するのが安全です。
