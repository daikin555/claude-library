## 原文（日本語訳）

`/cd` を改善しました。移動先ディレクトリのプロジェクト設定、hooks、`.mcp.json` に定義されたMCPサーバー（通常の承認プロンプトを経て）、skills、agentsが、`--resume` で再開したときではなく、ディレクトリ移動の直後から有効になるようになりました。

## 原文（英語）

Improved `/cd`: the new directory's project settings, hooks, `.mcp.json` servers (behind the usual approval prompt), skills, and agents now take effect right after the move instead of on `--resume`

## 概要

`/cd` はセッションを続けたまま作業対象のディレクトリを切り替えるコマンドです。これまでは移動先ディレクトリに固有のプロジェクト設定・hooks・MCPサーバー定義・skills・agentsが即座には反映されず、セッションを一度終了して `--resume` で再開するまで適用されないという制約がありました。今回の改善により、`/cd` でディレクトリを移動した直後からこれらすべてが有効になり、セッションを中断せずに新しいプロジェクトのコンテキストへスムーズに切り替えられるようになりました。

## 基本的な使い方

```
/cd ../another-project
```

移動が完了すると、`another-project` ディレクトリの `.claude/settings.json` によるプロジェクト設定、hooks、`.mcp.json` で定義されたMCPサーバー、`.claude/skills/` のskills、`.claude/agents/` のagentsがそのまま使えるようになります。MCPサーバーの起動時には通常通り承認プロンプトが表示されます。

## 実践例

### モノレポ内で複数プロジェクトを行き来する

一つのモノレポ内で複数のサブプロジェクトを順番に触っていくワークフローでは、`/cd` で移動するたびに各サブプロジェクト固有のhooksやskillsがすぐに使えるようになり、都度セッションを再起動する手間がなくなります。

### プロジェクト固有のMCPサーバーへすぐアクセス

データベース用MCPサーバーなど、プロジェクトごとに異なる `.mcp.json` を用意している場合、`/cd` で移動した直後から該当プロジェクトのMCPサーバーに（承認後）アクセスできます。

### サブエージェントやskillsを使い分ける

プロジェクトAとプロジェクトBでそれぞれ異なるカスタムagentsやskillsを用意している場合、`/cd` で切り替えた瞬間からそのプロジェクト向けのagentsやskillsが利用可能になります。

## 注意点

- MCPサーバーの起動には引き続き通常の承認プロンプトが表示されます。信頼できないディレクトリへの `/cd` には注意してください
- この改善以前は `--resume` によるセッション再開が必要でしたが、今後はその手順は不要です
- 移動先ディレクトリの設定内容自体（hooksの定義やMCPサーバーの構成など）に変更はなく、反映されるタイミングのみが改善されています
