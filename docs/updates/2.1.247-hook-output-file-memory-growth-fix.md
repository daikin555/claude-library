## 原文（日本語訳）

フックまたはバックグラウンドタスクの出力ファイルへの書き込みができなかった場合に発生していた無制限のメモリ増加を修正しました。現在はそのファイルに、出力がどこで失われたかを示す記録が書き込まれるようになりました。

## 原文（英語）

Fixed unbounded memory growth when a hook's or background task's output file could not be written; the file now notes where output was lost

## 概要

フックやバックグラウンドタスクの標準出力・標準エラー出力は、専用の出力ファイルに書き出されます。この修正前は、その出力ファイルへの書き込み自体が（ディスク容量不足や権限エラーなどの理由で）失敗した場合、出力データがどこにも捨てられずメモリ上に蓄積され続けてしまい、無制限にメモリ使用量が増加していく問題がありました。長時間動作するフックやバックグラウンドタスクでこの状態に陥ると、最終的にプロセス全体のメモリを圧迫するおそれがありました。修正後は、書き込みに失敗した場合でもメモリに溜め込み続けることなく、出力ファイル側に「どの時点で出力が失われたか」を示す記録が残るようになりました。

## 基本的な使い方

ユーザー側で特別な操作は不要です。フックやバックグラウンドタスクを実行している際に出力ファイルの書き込みが何らかの理由で失敗しても、Claude Code自体のメモリ使用量が肥大化することはなくなります。

```
# 出力ファイルに書き込めない状況が発生した場合、ファイルには
# 例えば以下のような趣旨の記録が残る
# [出力の一部がここで失われました: 書き込みエラーのため]
```

## 実践例

### ディスク容量が不足している環境での長時間タスク

ディスクの空き容量が少ない環境でバックグラウンドタスクや出力量の多いフックを動かしていると、出力ファイルへの書き込みが失敗することがあります。そのような状況でも、以前のようにメモリが際限なく増え続けることはありません。

### 権限設定が厳しいサンドボックス環境

出力先ディレクトリへの書き込み権限が制限されているサンドボックス環境で動かすフックでも、書き込み失敗によるメモリリークのリスクなく安全に運用できます。

### 大量のログを出力するカスタムフックの運用

大量の出力を生成するカスタムフックスクリプトを長時間動かす場合でも、書き込みに問題が発生した際は出力ファイルにその旨が記録されるため、後から調査してどこで出力が失われたかを特定できます。

## 注意点

- この修正はメモリ肥大化という安定性の問題を解消するものであり、出力ファイルへの書き込みが失敗する根本原因（ディスク容量、権限など）自体は解決しません
- 出力が失われた箇所は出力ファイル内の記録から確認できるため、原因調査時にはそのファイルを確認してください
