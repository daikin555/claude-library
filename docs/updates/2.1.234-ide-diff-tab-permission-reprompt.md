## 原文（日本語訳）

権限の再確認プロンプト表示中にIDEのdiffタブを閉じると、新しいプロンプトに対して前回の入力内容で回答してしまうことがある不具合を修正しました。

## 原文（英語）

Fixed a case where an IDE diff tab closing during a permission re-prompt could answer the new prompt with the previous input

## 概要

VS CodeなどのIDE統合では、Claudeがファイルを編集しようとするとdiffタブが開き、そこでの承認・却下操作が権限プロンプトへの回答として扱われます。今回修正された不具合は、ある権限プロンプトへの回答待ちの最中にdiffタブが閉じられ、直後に別の（新しい）権限の再確認プロンプトが表示されるという競合状態で発生していました。このタイミングでは、古いdiffタブのクローズイベントが新しいプロンプトへの回答として誤って適用されてしまうことがありました。修正後は、diffタブのクローズイベントが対応する権限プロンプトと正しく紐付けられ、意図しない自動承認・自動却下が起きなくなりました。

## 基本的な使い方

IDE統合を使った通常のワークフローに変更はありません。Claudeがファイル編集を提案すると、IDE上にdiffタブが開き、そこで変更内容を確認して承認（Accept）または却下（Reject）します。

```
Claude> ファイルXを編集します
[IDEにdiffタブが開く]
[変更内容を確認]
[Acceptをクリック、またはdiffタブを閉じて判断]
```

## 実践例

### 連続して複数ファイルを編集する場合

Claudeが複数のファイルを立て続けに編集しようとし、それぞれに権限プロンプト（diffタブ）が表示されるケースです。

```
1. ファイルA編集の権限プロンプト（diffタブA）が表示される
2. ユーザーがdiffタブAを閉じる（承認 or 却下の判断を下す）
3. ほぼ同時にファイルBの権限プロンプト（diffタブB）が表示される
# 修正前: タブAのクローズ操作が、タブBのプロンプトへの回答として
#          誤って適用されてしまうことがあった
# 修正後: タブAのクローズはタブAのプロンプトにのみ適用され、
#          タブBは独立して回答を待つ
```

### 権限が再確認（re-prompt）される場面

一度却下した操作についてClaudeが別のアプローチで再度同じような編集を提案し、権限が再確認される場合も、古いdiffタブの操作が新しいプロンプトに漏れ出さなくなります。

### すばやくdiffタブを閉じる操作をした場合

レビューを急いでdiffタブをすばやく閉じるような操作をしても、直後に出現する別ファイルの権限プロンプトに前回の判断（承認/却下）が誤って引き継がれることがなくなり、意図しない編集の適用や却下を防げます。

## 注意点

- この不具合はIDE統合（VS Code拡張機能など）を使用している場合にのみ関係します。ターミナルのみの利用では影響がありません
- 特に、複数ファイルの編集が短時間に連続する場面や、権限が再確認される場面で発生しやすい競合状態でした
- 重要な変更を承認・却下する際は、diffタブの内容とプロンプトの対象ファイルが一致していることを確認する習慣を持つとより安全です
