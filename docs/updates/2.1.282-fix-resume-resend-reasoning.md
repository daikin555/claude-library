## 原文（日本語訳）

`--continue`、`--resume` で継続・再開したセッションが以前のメッセージを異なる形式で再送信し、APIがClaudeの過去の推論（reasoning）内容を破棄してしまうケースをさらに修正しました。

## 原文（英語）

Fixed more cases of continued or resumed sessions (`--continue`, `--resume`) re-sending earlier messages in a changed form, which could make the API drop Claude's earlier reasoning

## 概要

`claude --continue` や `claude --resume` でセッションを再開すると、内部的には過去のメッセージ履歴がAPIに再送信されます。この際、メッセージの形式が元のターンと微妙に異なる形で再構築されてしまうケースがあり、その結果APIが「整合性が取れない」と判断してClaudeの過去の推論内容（extended thinkingのブロック）を破棄してしまうことがありました。今回の修正でこうしたケースの多くが解消され、再開後もClaudeの思考の連続性が保たれやすくなりました。

## 基本的な使い方

通常どおりセッションを継続・再開するだけで、修正の恩恵を受けられます。

```bash
claude --continue
# または
claude --resume
```

## 実践例

### 長時間の設計検討セッションの再開

前日にextended thinkingを使って複雑な設計を検討したセッションを翌日 `--resume` で再開しても、Claudeが以前の検討過程を踏まえた応答をしやすくなります。

### CI・自動化パイプラインでのセッション継続

`--continue` を使って複数ステップにまたがる自動化ワークフローを組んでいる場合、途中のステップで推論内容が失われることによる一貫性の低下が減ります。

## 注意点

- 「さらに修正」とあるように、この問題は段階的に修正が重ねられているものであり、非常に稀なケースでは依然として発生する可能性があります
- extended thinkingを有効にしていないセッションには直接関係しません
