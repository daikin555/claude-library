## 原文（日本語訳）

`-p` フラグ、SDK、クラウドセッションなどの非対話セッションが改善されました。サーバーエラー、接続断、またはストールによって応答が途中で切れた場合、エラーで終了するのではなく、自動的にその応答を継続するようになりました。

## 原文（英語）

Improved non-interactive sessions (`-p`, SDK, cloud sessions) to automatically continue a response cut off mid-stream by a server error, connection loss, or stall instead of ending with an error

## 概要

`-p` フラグを使ったヘッドレス実行やClaude Agent SDK経由の実行、クラウド上で動くセッションでは、人が対話的に再試行を判断できないため、ストリーミング中にサーバーエラーや接続断、応答の停滞（ストール）が発生すると、そのままエラー終了してしまい、パイプラインやCI/CD、自動化スクリプトが失敗するという問題がありました。今回の改善により、こうした中断が発生した場合はClaude Code側が自動的に応答の続きを取得し、処理を継続するようになりました。これにより非対話環境での実行の信頼性が向上します。

## 基本的な使い方

ユーザー側で特別な設定は不要です。`-p` で実行している最中にネットワークが一時的に切れたりサーバー側でエラーが発生したりしても、自動的にリトライ・継続が行われます。

```bash
claude -p "大きなリファクタリングを実行して結果をまとめて" --output-format json
```

途中でストリームが切断されても、これまでは非ゼロ終了コードで失敗していたケースが、今後は自動的に応答が継続され、最終的な出力が得られる可能性が高くなります。

## 実践例

### CI/CDパイプラインでのヘッドレス実行

CIジョブの中で `claude -p` を使ってコードレビューやテスト生成を行っている場合、ネットワークの一時的な不調やサーバー側の一時的なエラーによってジョブ全体が失敗するリスクが減ります。

### SDKを使った長時間バッチ処理

Claude Agent SDKで多数のタスクをバッチ処理している場合、個々のリクエストがストリーム中に切れても自動継続されるため、リトライロジックを自前で実装する必要が少なくなります。

### クラウド上でのバックグラウンドエージェント実行

クラウド環境で動くバックグラウンドセッション（`schedule` スキルなどで作成した定期実行エージェントを含む）では、人が張り付いて監視しているわけではないため、この自動継続によって一時的な障害からの回復力が高まります。

## 注意点

- 対話的なターミナルセッション（インタラクティブモード）でも同様の恩恵はありますが、この改善は特に非対話セッション（`-p`、SDK、クラウド）向けに強化されたものです
- あらゆる種類のエラーが継続対象になるわけではなく、サーバーエラー・接続断・ストールなど、応答が「途中で切れた」と判断されるケースが対象です
- 自動継続によって最終的な出力が得られるまでの時間が延びる場合があります
