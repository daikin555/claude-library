## 原文（日本語訳）

managed settings（組織管理設定）の挙動を変更しました。組織の設定が変わっていない場合、再ログインや組織切り替えのたびに承認プロンプトが再表示されることがなくなりました。

## 原文（英語）

Changed managed settings: the approval prompt no longer re-appears after re-login or org switching when the organization's settings are unchanged

## 概要

Claude Codeの「server-managed settings」は、組織のOwnerがclaude.aiの管理コンソールから、フックや権限ルールなどをメンバー全員に一括配布できる仕組みです。フックの実行やカスタム環境変数、CLAUDE.mdへの内容配布など、セキュリティ上リスクのある設定が含まれる場合、Claude Codeは起動時に「この設定を適用してよいか」というセキュリティ承認ダイアログをユーザーに表示します。これまでは、組織の設定内容自体が変わっていなくても、ユーザーが再ログインしたり別の組織アカウントに切り替えたりするたびにこの承認プロンプトが再度表示されることがありました。今回の変更により、組織側の設定内容が実際に変わっていない限り、再ログインや組織切り替えを行っても承認プロンプトは再表示されなくなりました。

## 基本的な使い方

エンドユーザー側で特別な操作は不要です。組織のOwnerがmanaged settingsを設定している状態で、通常どおりログインすれば、初回承認後は設定が変わらない限り再承認を求められません。

```bash
# 通常のログイン・再ログイン
/login
```

## 実践例

### 複数の組織アカウントを行き来する開発者

コンサルタントや複数プロジェクトを兼任するエンジニアなど、日常的に異なる組織アカウント間でログインを切り替える場合、以前はアカウントを切り替えるたびに同じmanaged settingsの承認プロンプトに何度も応答する必要がありました。設定内容が変わっていなければ、切り替え後も再承認を求められずスムーズに作業を再開できます。

### 認証トークンの期限切れによる再ログイン

セッションが長時間に及び認証トークンが失効して`/login`をやり直すようなケースでも、組織のmanaged settings自体が変更されていなければ、承認プロンプトが再度出現することはありません。

### 実際に組織側の設定が変更された場合

一方で、組織のOwnerがmanaged settingsのフックや権限ルールを実際に変更した場合は、内容が変わったことをClaude Codeが検知し、変更後の設定内容を説明する承認プロンプトが改めて表示されます。ユーザーは変更内容を確認したうえで承認・拒否を選択できます。

```text
# 組織側で managed settings を更新した場合、次回起動時に
# 「この設定を適用しますか？」という承認ダイアログが再表示される
```

## 注意点

- 承認プロンプトが表示されるのは、フックの実行やカスタム環境変数（プロキシ・ベースURLなど）、CLAUDE.mdへの配布内容など、リスクを伴う設定が含まれる場合のみです。モデル選択やコンパクション関連の設定など、一部の環境変数は承認なしに適用されます。
- ユーザーが承認プロンプトを拒否した場合、Claude Codeは終了します。
- `claude -p`のような非対話実行やAgent SDKのセッションでは承認ダイアログを表示できないため、その回内でのみ設定が適用され、次の対話セッションで改めて承認が求められます。
- 承認状態はローカルにキャッシュされますが、組織側で設定が更新されるとキャッシュは無効になり、再度承認が必要になります。
