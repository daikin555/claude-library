## 原文（日本語訳）
ファイルタブがClaudeタブとグループを共有している場合、New Session（新規セッション）を実行すると別のロックされたエディタグループが開かれてしまう不具合が修正されました。

## 原文（英語）
[VSCode] Fixed New session opening another locked editor group whenever a file tab shared the group with your Claude tab

## 概要
VSCode拡張機能では、Claudeタブが開かれているエディタグループがロックされる仕組みがあります。これまでは、そのロック済みグループ内にファイルタブが混在している状態で「New Session」を実行すると、既存のグループを使わずに新たなロック済みエディタグループが開かれてしまう不具合がありました。今回の修正により、そのようなケースでも余計なエディタグループが新規に作成されなくなりました。

## 基本的な使い方
特別な操作は不要です。新しいセッションを開始する際に通常通り「New Session」機能を使います。

```
VSCode: Claude Codeアイコン → New Session
```

## 実践例

### 修正前の挙動
Claudeタブと同じエディタグループにファイルタブ（例えば参照中のソースファイル）が開かれている状態で「New Session」を実行すると、既存のグループとは別に新しいロック済みエディタグループが作成され、画面レイアウトが乱雑になることがありました。

### 修正後の挙動
同じ状況で「New Session」を実行しても、余計なエディタグループが新規に開かれることなく、既存のレイアウトが保たれるようになりました。

## 注意点
- この修正も「エディタグループのロック機能」に関連する一連の不具合修正の一つです。`claudeCode.lockEditorGroups` を無効化している場合は影響を受けません。
- ファイルタブとClaudeタブを同じグループで頻繁に併用するワークフローのユーザーに特に有用です。
