## 原文（日本語訳）
Claudeがルーチン一覧の取得結果と同じ形式でルーチンを書き込んだ際、`/schedule` がルーチンのプロンプトをメッセージロール情報なしで保存してしまう問題を修正しました。

## 原文（英語）
Fixed `/schedule` saving a routine's prompt without its message role when Claude writes the routine in the shape that listing routines returns

## 概要
`/schedule` コマンドは定期実行するルーチン（スケジュールタスク）を作成・保存する機能です。Claudeがルーチンの一覧取得（listing routines）と同じデータ形状でルーチンを書き込んだ場合に限り、プロンプトに紐づくべきメッセージロール（userやassistantなどの役割情報）が欠落したまま保存されてしまう不具合がありました。今回の修正により、この経路で保存されるルーチンにも正しくメッセージロールが含まれるようになりました。

## 基本的な使い方
`/schedule` コマンドでルーチンを作成します。

```
/schedule 毎朝9時にリポジトリのオープンPRを要約して
```

## 実践例

### 修正前の挙動
ルーチン一覧の取得結果を基にClaudeがルーチンを再保存するような操作を行うと、保存されたプロンプトのメッセージロール情報が欠落し、実行時にプロンプトの解釈が崩れる可能性がありました。

### 修正後の挙動
どの経路でルーチンが保存されても、プロンプトのメッセージロールが正しく保持され、スケジュール実行時に意図通りの挙動になります。

## 注意点
- この不具合は主に内部データ形状の不整合によるものであり、通常の `/schedule` の直接作成フローでは顕在化しにくいものでした。
- ルーチンの内容が意図通り実行されているか、作成後に一度確認することをおすすめします。
