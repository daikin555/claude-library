## 原文（日本語訳）

macOSとLinuxのサンドボックスで、`git worktree add`、`move`、`remove` が読み取り専用で失敗するようになりました。セッションを開始した、または指定したworktree以外でのコミットも同様です（プロジェクト内でも対象です）。

## 原文（英語）

Changed the sandbox on macOS and Linux: `git worktree add`, `move` and `remove` now fail read-only, as do commits in a worktree the session wasn't started in or given, even one inside the project

## 概要

サンドボックス内からのgit worktree操作が制限されました。worktreeの作成・移動・削除と、開始時に指定されていないworktreeへのコミットは、読み取り専用エラーになります。

## 基本的な使い方

worktreeの管理はサンドボックスの外で行います。

```bash
git worktree add ../feature-x feature-x
cd ../feature-x
claude
```

## 実践例

### 並行作業用のworktree

先にサンドボックス外でworktreeを作成し、そのディレクトリでClaude Codeを起動します。

### 関連する変更

- 同バージョンで、`.git` がリンクや、ハードリンクを含むcheckout（git-new-workdirや `cp -al` のコピー）に対するworktree作成は拒否されるようになりました。通常のcloneを使ってください
- サンドボックスはシンボリックリンク経由の書き込み許可を無視します。実際のパスを許可してください

## 注意点

- 既存の自動化でworktreeをサンドボックス内から作成している場合は、手順の見直しが必要です
- `ExitWorktree` や `/resume` が、削除済みの元フォルダのせいで誤ったフォルダに戻る問題も修正されています
