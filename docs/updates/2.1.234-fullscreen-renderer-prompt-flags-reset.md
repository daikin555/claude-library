## 原文（日本語訳）

「新しいフルスクリーンレンダラーを試しますか？」というプロンプトを承諾すると、セッションが権限モード（例: `--dangerously-skip-permissions`）、ツールの許可/拒否ルール、モデルやeffortフラグを引き継がずに再起動してしまう問題を修正しました。

## 原文（英語）

Fixed accepting the "Try the new fullscreen renderer?" prompt restarting the session without its permission mode (e.g. `--dangerously-skip-permissions`), tool allow/deny rules, model or effort flags

## 概要

Claude Code起動時に表示される「新しいフルスクリーンレンダラーを試しますか？」という確認プロンプトを承諾すると、セッションが再起動される仕組みになっていますが、この再起動時に元のセッションで指定していた `--dangerously-skip-permissions` のような権限モード、ツールの許可/拒否ルール、モデル指定やeffort（推論の強さ）フラグが引き継がれずリセットされてしまう不具合がありました。今回の修正により、これらの起動オプションが再起動後も正しく維持されるようになりました。

## 基本的な使い方

特別な操作は不要です。フルスクリーンレンダラーの試用プロンプトが表示された際に「はい」を選択しても、元々指定していたコマンドラインフラグやツールの許可設定がそのまま引き継がれます。

```bash
claude --dangerously-skip-permissions
# 「新しいフルスクリーンレンダラーを試しますか？」→ 承諾
# 再起動後も --dangerously-skip-permissions が維持される
```

## 実践例

### 危険操作スキップフラグ付きで起動した場合

```bash
claude --dangerously-skip-permissions
```

修正前: フルスクリーンレンダラーのプロンプトを承諾すると再起動され、`--dangerously-skip-permissions` が外れた状態になり、以降のツール実行のたびに許可を求められるようになってしまいました（意図せず安全側に倒れる形ではあるものの、ユーザーの想定と異なる挙動でした）
修正後: 再起動後もフラグが維持され、指定した挙動のまま作業を継続できます

### モデルやeffortフラグを指定して起動した場合

```bash
claude --model opus --effort high
```

修正前: フルスクリーンレンダラー承諾後の再起動でモデルやeffort指定がデフォルトに戻ってしまうことがありました
修正後: 指定したモデル・effort設定が再起動後も保持されます

### 独自のツール許可/拒否ルールを設定していた場合

事前に設定した許可（allow）・拒否（deny）ルールがある状態でこのプロンプトを承諾しても、ルールがリセットされず維持されるため、意図しない権限確認や意図しないツール実行のリスクが減ります。

## 注意点

- 本修正前のバージョンでは、特に `--dangerously-skip-permissions` のような重要な権限フラグが再起動時に失われる点に注意が必要でした
- 再起動を伴う挙動自体（フルスクリーンレンダラーへの切り替え）は変わらず、引き継がれる設定内容が修正されています
