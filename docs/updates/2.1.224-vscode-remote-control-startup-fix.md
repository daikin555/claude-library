## 原文（日本語訳）

[VSCode] `remoteControlAtStartup` が明示的に有効化されている場合に、セッションがその設定に従わない問題を修正しました。

## 原文（英語）

[VSCode] Fixed sessions not honoring `remoteControlAtStartup` when explicitly enabled

## 概要

Claude Codeには、インタラクティブセッション開始時に自動でRemote Controlへ接続する `remoteControlAtStartup` という設定があります。ユーザー設定（`~/.claude/settings.json`）や管理設定でこれを `true` に明示的に設定すると、通常はセッション開始と同時にRemote Controlが自動接続されます。しかしv2.1.224より前は、**VS Code拡張機能**上でこの設定が正しく反映されず、`remoteControlAtStartup` を有効化していてもセッションが自動接続しないケースがありました。今回の修正で、VS Code拡張機能のセッションもこの設定を正しく尊重するようになりました。

## 基本的な使い方

`remoteControlAtStartup` はユーザー設定または管理設定の `settings.json` に記述します。

```json
{
  "remoteControlAtStartup": true
}
```

VS Code拡張機能では、コマンドメニューの設定セクションから **Enable Remote Control for all sessions** を有効にすることでも同様の効果が得られます。

## 実践例

### 設定ファイルで自動接続を有効化しているケース

```json
// ~/.claude/settings.json
{
  "remoteControlAtStartup": true
}
```

```text
# VS Code拡張機能で新しいClaude Codeセッションを開始

# 修正前: remoteControlAtStartup を true にしていても、
#         VS Code拡張機能のセッションでは自動接続されないことがあった
#         → 毎回手動で /remote-control を実行する必要があった

# 修正後: 設定どおりにセッション開始時から自動的にRemote Controlへ接続され、
#         バナーに接続状態が表示される
```

### コマンドメニューから有効化するケース

```text
# VS Code拡張機能のコマンドメニュー（/）を開く
# Settings セクションから
# 「Enable Remote Control for all sessions」を有効化

# 修正前: 設定を有効にしても、次回以降のセッションで反映されない場合があった
# 修正後: 設定した通り、以後のすべてのセッションで自動接続が機能する
```

### 複数プロジェクトを行き来するケース

複数のプロジェクトをVS Codeで開き直すような使い方でも、ユーザー設定に保存された `remoteControlAtStartup: true` が一貫して適用されるようになったため、プロジェクトを切り替えるたびに手動でRemote Controlを有効化し直す必要がなくなりました。

## 注意点

- プロジェクト・ローカル設定（`.claude/settings.json` や `.claude/settings.local.json`）では `false` は反映されますが、`true` は無視されます。これはリポジトリに含めた設定ファイルだけで他者のRemote Controlを勝手に有効化できないようにするための仕様であり、今回の修正対象ではありません。
- 組織のポリシーでRemote Control自体が無効化されている場合（`disableRemoteControl` や管理コンソールの設定）は、`remoteControlAtStartup` を有効にしても自動接続は行われません。
- CLI（ターミナル）ではこの問題は発生しておらず、今回の修正はVS Code拡張機能に固有のものです。
