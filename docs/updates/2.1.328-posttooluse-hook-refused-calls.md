# managed PostToolUse フックが拒否された呼び出しでは発火しないように変更

## 原文（日本語に翻訳）

managed の `PostToolUse` フックは、実行前に拒否された呼び出しでは発火しなくなりました。ログ記録、書き換え、ブロック、停止は行われません。`PostToolBatch` はそのほとんどを受け取りますが、拒否されたものとは区別されません。

## 原文（英語）

Changed managed `PostToolUse` hooks to no longer fire for calls refused before they ran: no log entry, rewrite, block or stop there; `PostToolBatch` gets most, not marked as refused

## 概要

実行されなかったツール呼び出しに対して PostToolUse フックが動く挙動が改められました。監査ログ用に PostToolUse を使っている場合、拒否された呼び出しは記録されなくなる点に注意が必要です。

## 基本的な使い方

```json
{
  "hooks": {
    "PostToolUse": [
      { "hooks": [{ "type": "command", "command": "./audit-log.sh" }] }
    ]
  }
}
```

## 実践例

### 監査ログの見直し

拒否された操作も記録したい場合は、PreToolUse や PermissionRequest 側でのログ取得を検討してください。

## 注意点

- 対象は managed な PostToolUse フックです
- `PostToolBatch` では拒否された呼び出しにその印が付きません
- Code Mode では UserPromptSubmit フックがスクリプト出力に実行されなくなり、出力の加工には `updatedToolOutput` を使う PostToolUse フックを使います
