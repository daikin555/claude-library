## 原文（日本語訳）

Bedrock、Vertex、Foundryのセッション（およびテレメトリが無効になっているすべてのセッション）が改善されました。設定されたMCPサーバーへの接続が失敗した場合、Claudeはそのツールが存在しないと誤って結論づけるのではなく、接続に失敗したことを通知されるようになりました。

## 原文（英語）

Improved Bedrock, Vertex, and Foundry sessions (and any with telemetry disabled): Claude is now told when a configured MCP server failed to connect, instead of concluding its tools don't exist

## 概要

これまでBedrock、Vertex、Foundryなどテレメトリが無効な環境では、MCPサーバーへの接続に失敗した場合でもClaudeにその情報が伝わらず、Claudeは単に「そのツールは存在しない」と誤解してしまうことがありました。今回の改善により、MCPサーバーの接続失敗という事実そのものがClaudeに伝えられるようになり、誤った推論や見当違いの回避策を提案してしまう問題が減ります。ユーザー側の設定変更は不要で、内部動作の改善です。

## 基本的な使い方

特別な操作は必要ありません。MCPサーバーの設定（`.mcp.json` や `claude mcp add` など）はこれまでと同じ方法で行います。

```bash
claude mcp add my-server -- npx -y my-mcp-server
```

Bedrock/Vertex/Foundry経由でClaude Codeを利用している場合や、テレメトリを無効化している場合でも、設定したMCPサーバーへの接続に失敗すると、Claudeはその失敗自体を認識できるようになりました。

## 実践例

### 社内ネットワークでMCPサーバーが一時的に到達不能な場合

社内プロキシやファイアウォールの都合でMCPサーバーに接続できないとき、以前は「そのツールは存在しない」という誤った前提で作業を進めてしまうことがありました。改善後は、Claudeが接続失敗を把握したうえで、ユーザーに状況を説明したり代替手段を提案したりできます。

### Bedrock/Vertex経由での企業導入時のトラブルシューティング

エンタープライズ環境でBedrockやVertex AI経由でClaude Codeを利用する場合、テレメトリが無効化されている構成が多く見られます。この構成でMCPサーバーの設定ミス（認証情報やエンドポイントの誤り）があった場合も、Claudeが「接続失敗」という正確な情報を得られるため、原因調査がしやすくなります。

### Foundry環境でのMCP連携診断

Azure AI Foundry経由の利用でMCPサーバーの起動に問題がある場合も、Claudeが誤解せずに接続失敗を前提としたやり取りができるようになります。

## 注意点

- この改善は内部的な挙動修正であり、ユーザーが明示的に有効化する設定はありません
- MCPサーバー自体の接続問題（認証情報、ネットワーク、起動コマンドの誤りなど）は引き続きユーザー側で解決する必要があります
- テレメトリが有効な標準環境でも同様の情報伝達は既に行われていましたが、今回の対応でBedrock/Vertex/Foundryやテレメトリ無効環境でも一貫した挙動になりました
