## 原文（日本語に翻訳）

Coworkセッションは、ユーザースコープのメモリファイル（CLAUDE.mdなど）に含まれる外部の `@` インポートを、もはやインラインで展開しないようになりました。

## 原文（英語）

Cowork sessions no longer inline external @-imports from user-scope memory files

## 概要

これはセキュリティ・プライバシー面での修正です。Claude CodeのCLAUDE.mdなどのメモリファイルでは、`@path/to/file` という記法で他のファイルの内容をインポート（インライン展開）できます。ユーザースコープ（`~/.claude/CLAUDE.md` など個人の設定として保存されているファイル）にこうした外部への `@` インポートが含まれている場合、これまでCoworkセッション（複数人・複数エージェントが関わるコラボレーション的なセッション）でもその内容がそのまま展開されてしまうことがありました。今回の修正により、Coworkセッションではユーザースコープのメモリファイルにある外部の `@` インポートが展開されなくなり、意図せず個人環境のファイル内容が共有コンテキストに取り込まれることを防げます。

## 基本的な使い方

この修正はCoworkセッションの内部的な安全対策であり、ユーザー側の操作は不要です。ユーザースコープのCLAUDE.mdなどに `@` インポートを記述していても、Coworkセッションではその外部ファイルの内容が自動展開されなくなります。

```markdown
<!-- ~/.claude/CLAUDE.md（ユーザースコープ） -->
# 個人設定
@~/notes/personal-context.md
```

Coworkセッションでは、上記のような外部ファイルへの `@` インポートはインライン展開されません。

## 実践例

### 個人用のメモファイルを誤って共有してしまうことを防ぐ

個人のユーザースコープ設定に、自分用のメモや作業ログなどを `@` インポートで参照させている場合、以前はCoworkセッションでもその内容が展開され、意図せず他の参加者やエージェントと共有されるコンテキストに含まれてしまう可能性がありました。修正後は、そうした個人用ファイルの内容がCoworkセッションに漏れ出ることがなくなります。

### チームでCoworkを使う際のスコープ分離

チームメンバーがそれぞれ自分のユーザースコープに個人的な設定や参照ファイルを持っている状況で、Coworkセッションを通じて共同作業を行う場合、各自の個人ファイルの中身がお互いに見えてしまうことを防げます。プロジェクトスコープ（リポジトリ内の `CLAUDE.md` など）で明示的に共有したい情報は、引き続き通常通り展開されます。

### 外部ファイルパスの取り扱いに関するセキュリティ強化

ユーザースコープのメモリファイルにローカル環境固有のパスを指す `@` インポートが含まれている場合、Coworkの共有コンテキストにおいてそれらが不用意に読み込まれることがなくなり、機密情報や環境依存情報の漏えいリスクを低減します。

## 注意点

- 本修正はユーザースコープのメモリファイルにおける外部への `@` インポートに関するものです。プロジェクトスコープなど他のスコープでのインポート挙動には影響しません。
- Coworkセッション以外の通常のClaude Codeセッションでの `@` インポートの挙動には変更はありません。
- メモリファイルの階層（ユーザースコープ／プロジェクトスコープなど）や `@` インポートの詳細な仕様は公式ドキュメントを参照してください。
