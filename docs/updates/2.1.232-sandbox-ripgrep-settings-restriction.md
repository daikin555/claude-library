## 原文（日本語に翻訳）

`sandbox.ripgrep` 設定を、ユーザー設定・管理者（managed）設定・`--settings` フラグ経由の設定からのみ有効になるように変更しました。プロジェクト設定では、もはやサンドボックスが使用するripgrepバイナリを上書きできません。

## 原文（英語）

Changed `sandbox.ripgrep` to be honored only from user, managed, and `--settings` settings; project settings can no longer override the sandbox's ripgrep binary.

## 概要

`sandbox.ripgrep` は、サンドボックス化されたBashツール内でGrepツールが使用するripgrepバイナリのパスを指定する設定です。これまではプロジェクト設定（リポジトリにコミットされる `.claude/settings.json` など）からもこの値を上書きできましたが、これはリポジトリを操作できる第三者が任意のバイナリをripgrepとして指し示すことを許してしまう、サプライチェーン上のリスクになり得ました。v2.1.232では、`sandbox.ripgrep` を指定できるスコープを「ユーザー設定」「管理者（managed）設定」「`--settings` フラグ」の3つに限定し、プロジェクト設定からの上書きを禁止しました。

## 基本的な使い方

`sandbox.ripgrep` を設定したい場合は、プロジェクトの `.claude/settings.json` ではなく、ユーザーレベルの設定ファイルや管理者設定、または `--settings` フラグを使う必要があります。

```json
// ~/.claude/settings.json （ユーザー設定 - 引き続き有効）
{
  "sandbox": {
    "ripgrep": "/usr/local/bin/rg"
  }
}
```

```bash
# --settings フラグ経由でも指定可能
claude --settings '{"sandbox": {"ripgrep": "/usr/local/bin/rg"}}'
```

```json
// .claude/settings.json （プロジェクト設定 - v2.1.232以降は無効化される）
{
  "sandbox": {
    "ripgrep": "/some/path/rg"
  }
}
// このようにプロジェクト設定に書いても、
// v2.1.232以降はサンドボックスのripgrepバイナリとしては使用されない
```

## 実践例

### 組織の管理者がripgrepバイナリを固定する

```json
// managed settings（IT管理者が配布する設定ファイル）
{
  "sandbox": {
    "ripgrep": "/opt/company-tools/rg"
  }
}
```

組織全体で検証済みのripgrepバイナリのみを使用させたい場合、managed設定から指定することで、各プロジェクトの設定に関わらず一貫して適用されます。

### 個人開発者がローカルのripgrepを指定する

```json
// ~/.claude/settings.json
{
  "sandbox": {
    "ripgrep": "/home/user/.local/bin/rg"
  }
}
```

自分のマシンにインストールした特定バージョンのripgrepを使いたい場合は、ユーザー設定に記述します。

### 信頼できないリポジトリをcloneして作業する場合

```bash
git clone https://github.com/someone/unknown-repo.git
cd unknown-repo
claude
# このリポジトリの .claude/settings.json に
# 悪意のある sandbox.ripgrep が設定されていても、
# v2.1.232以降は無視され、ユーザー/管理者設定の値が優先される
```

## 注意点

- Claude Code v2.1.232で導入された変更です
- 有効なスコープ: ユーザー設定（`~/.claude/settings.json`）、管理者（managed）設定、`--settings` CLIフラグ
- 無効化されたスコープ: プロジェクト設定（`.claude/settings.json` や `.claude/settings.local.json`）
- 既にプロジェクト設定に `sandbox.ripgrep` を記述している場合、v2.1.232以降はその値が無視され、ユーザー設定や管理者設定にフォールバックします
- この変更はセキュリティ強化が目的であり、信頼できないリポジトリから任意のバイナリをripgrepとして実行させられるリスクを低減します
- 一般的な設定の優先順位（managed > CLI引数 > project local > project > user）とは異なり、`sandbox.ripgrep` はこのルールの例外的な扱いになる点に注意してください
