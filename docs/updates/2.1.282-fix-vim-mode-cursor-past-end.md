## 原文（日本語訳）

履歴から呼び出した、またはキューから戻したプロンプトのノーマルモードで、カーソルが末尾を超えた位置に残ってしまい、`x` が何も削除しない不具合を修正しました。

## 原文（英語）

Fixed vim mode leaving the cursor past the end of a prompt recalled from history or pulled back from the queue in normal mode, so `x` did nothing

## 概要

vimモードのノーマルモードでは、カーソルは行の末尾の文字の上に位置するのが正しい挙動です。しかし、過去に入力したプロンプトを履歴から呼び出した場合や、キューに入れていたプロンプトを戻した場合に、カーソルが末尾を超えた「文字が存在しない位置」に置かれてしまうことがありました。この状態では `x`（1文字削除）を押しても何も起こらず、ユーザーが操作を誤解する原因になっていました。今回の修正でカーソルが正しく末尾の文字上に配置されるようになりました。

## 基本的な使い方

履歴から呼び出したプロンプトに対して、ノーマルモードで通常通り編集操作を行います。

```
↑       " 履歴からプロンプトを呼び出す
x       " 末尾の文字を削除 → 正しく機能するようになった
```

## 実践例

### 過去のプロンプトを微修正して再送信

似たようなプロンプトを何度も少しずつ変更しながら送る作業で、履歴から呼び出した直後に末尾の文字を削除・修正する操作が期待通りに機能するようになります。

### キューに溜めたプロンプトの編集

複数のプロンプトをキューに入れて順次実行するような使い方をしている場合、キューから戻したプロンプトに対する編集操作の信頼性が向上します。

## 注意点

- 新規に入力したプロンプトでは元々この不具合は発生していませんでした。履歴やキューから復元したプロンプトに特有の問題でした
- vimの標準的な挙動に合わせて、ノーマルモードのカーソルは常に何らかの文字の上に位置するようになります
