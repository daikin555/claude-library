## 原文（日本語訳）
サブモジュールのチェックアウトを含むエージェントworktreeを削除する前の安全確認を改善。

## 原文（英語）
Improved safety checks before removing an agent worktree that contains submodule checkouts

## 概要
Claude Codeはエージェントの作業をgitのworktreeで分離して実行できますが、作業完了後や不要になった際にこのworktreeを削除する処理が行われます。対象のリポジトリがgitサブモジュールを含んでいる場合、worktreeの削除処理がサブモジュールのチェックアウト内容を意図せず巻き込んでしまうリスクがありました。今回の改善により、サブモジュールを含むworktreeを削除する前の安全確認が強化され、意図しないデータ損失のリスクが低減されました。

## 基本的な使い方
特別な操作は不要です。サブモジュールを含むリポジトリでエージェントのworktreeを使った作業を行い、それを削除する際に、より安全なチェックが自動的に行われます。

```bash
# サブモジュールを含むリポジトリでworktreeを使った作業例
git submodule status
claude --worktree
```

## 実践例

### サブモジュール内に未コミットの変更がある状態でworktreeを削除しようとした場合
サブモジュール内で作業中の変更が残っている状態でエージェントworktreeを削除しようとすると、以前は十分な確認なしに削除が進んでしまう可能性がありました。改善後は、こうした状態を検知してより慎重な確認が行われるようになり、意図しない変更の消失を防ぎやすくなります。

```bash
# サブモジュール内に変更がある状態
cd my-repo/vendor/some-submodule
git status  # 未コミットの変更あり
# -> worktree削除時に安全確認が強化されている
```

### 複数のサブモジュールを持つ大規模モノレポでの運用
複数のサブモジュールを含む大規模なリポジトリでエージェントを頻繁に使う開発チームにとって、この改善はworktreeのクリーンアップ処理をより安心して自動化できるようにします。

## 注意点
- この改善は安全確認の強化であり、サブモジュール自体の扱い方（追加・更新方法など）を変更するものではありません。
- サブモジュールを含まないリポジトリでは、この変更による挙動の違いはほとんど感じられません。
