## 原文（日本語訳）
Artifact公開機能を改善：古いバージョンをもとに構築された公開処理は送信前に停止され、マージすべき新しいバージョンのページが提示されるようになった。

## 原文（英語）
Improved artifact publishing: a publish built on an older version is stopped before it is sent, with the newer page to merge

## 概要
Artifactは複数回の編集を経て更新されていくことがあり、その間にclaude.ai側で新しいバージョンが存在する状態になることがあります。これまでは、古いバージョンをベースにした公開（パブリッシュ）処理がそのまま送信されてしまい、意図せず新しい変更を上書きしてしまうリスクがありました。今回の改善により、古いバージョンに基づく公開は送信前に検知されて停止され、代わりにマージすべき新しいバージョンのページが提示されるようになりました。

## 基本的な使い方
Artifactを公開する際の基本操作に変更はありませんが、公開しようとしている内容が古いバージョンに基づいている場合、送信前に警告とともに最新バージョンへの参照が提示されます。

```bash
# Artifactを更新して公開する例
"このArtifactにグラフを追加して、更新版を公開して"
```

## 実践例

### 複数人・複数セッションでArtifactを編集している場合
チームや複数のセッションで同じArtifactを並行して編集していると、片方が古いバージョンをベースに公開しようとするケースが起こり得ます。以前はそのまま古い内容で上書き公開されてしまうことがありましたが、改善後は公開前に停止され、最新版とのマージが必要であることが提示されます。

```text
# 公開しようとした際の挙動イメージ
"公開に進もうとしています..."
-> 検出: このArtifactにはより新しいバージョンが存在します
-> 最新版のページを確認し、変更をマージしてから再度公開してください
```

### 長時間放置していたセッションから再開してArtifactを公開する場合
しばらく操作していなかったセッションから作業を再開し、Artifactを公開しようとする場合も、この改善によって最新の状態を見落として古い内容を上書きしてしまう事故を防げます。

## 注意点
- この機能は自動でマージを行うわけではなく、ユーザー（またはClaude）が最新バージョンの内容を確認し、必要な変更を反映してから改めて公開する必要があります。
- 頻繁に同じArtifactを複数箇所から編集する運用をしている場合、この改善により公開のたびにバージョン確認が挟まる可能性があります。
