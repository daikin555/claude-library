## 原文（日本語に翻訳）

同一マシン上の対話型セッションは、一意な名前を保持するようになりました。あるセッションを起動またはリネームする際に、既に稼働中の別セッションと同じ名前を使おうとすると、`name-word-word` 形式のバリアント名が付与され、その旨が通知されます。

## 原文（英語）

Interactive sessions on one machine now keep unique names: starting or renaming a session to a name another live session already uses gives it a `name-word-word` variant and tells you

## 概要

複数のClaude Codeセッションを同一マシン上で並行して動かす運用が増える中、同じ名前のセッションが複数存在すると `SendMessage` や `@` メンションで送信先を誤る可能性がありました。v2.1.232からは、セッションの起動時またはリネーム時に名前が既存の稼働中セッションと重複すると、自動的に `name-word-word` という形式のユニークな名前に変換され、変換されたことがユーザーに通知されます。

## 基本的な使い方

```
claude --name backend
# 既に "backend" という名前のセッションが稼働中の場合:
# -> "backend-swift-otter" のような名前に自動変換され、通知される
```

セッション名を指定する際、重複があれば自動でユニークな名前に調整されるため、ユーザー側で衝突を意識する必要がなくなりました。

## 実践例

### 同じ名前のセッションを複数起動しようとした場合

```
claude --name worker
# -> "worker" が既に使用中
# -> 自動的に "worker-bold-fox" として起動、その旨を通知
```

同名での起動を試みても失敗せず、自動的に区別可能な名前で起動します。

### セッションを手動でリネームする場合

```
/rename worker
# -> 既に稼働中の "worker" と衝突
# -> "worker-calm-hawk" にリネームされ、通知が表示される
```

対話中に `/rename` などでセッション名を変更する場合も、同様の衝突回避が適用されます。

### 一意な名前でSendMessageや@メンションを確実にする

セッション名が常に一意であることで、`SendMessage` の完全一致配信や `@` メンションが迷いなく対象セッションに届くようになります。

## 注意点

- Claude Code v2.1.232での変更です。
- 対象は「同一マシン上の対話型セッション」です。
- 自動生成されるバリアント名は `name-word-word` という形式（例: `worker-bold-fox`）です。
- 名前が変換された場合はその旨がユーザーに通知されるため、意図した名前と異なる点に気付きやすくなっています。
