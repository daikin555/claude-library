## 原文（日本語に翻訳）

Anthropicのモデルidではない `modelOverrides` のキーが、セッションの正規モデルIDとして扱われてしまう不具合を修正しました。仕様通り、未知のキーは無視されるようになりました。

## 原文（英語）

Fixed `modelOverrides` keys that aren't Anthropic model IDs being treated as the session's canonical model ID; unknown keys are now ignored as documented

## 概要

`modelOverrides` は、設定ファイル（`settings.json` など）で個々のAnthropicモデルID（例: `claude-opus-4-7`）を、Amazon BedrockのインファレンスプロファイルARNやGoogle Cloud's Agent Platformのバージョン名、Microsoft Foundryのデプロイ名といったプロバイダ固有の文字列にマッピングするための設定です。エンタープライズ管理者が、モデルバージョンごとにガバナンスやコスト配分、リージョンルーティングの都合で異なるプロバイダ側モデルへ振り分けたい場合に使われます。ドキュメント上、`modelOverrides` のキーは「[Models overview](https://platform.claude.com/docs/en/about-claude/models/overview) に列挙されているAnthropicモデルID」でなければならず、それ以外の未知のキーは無視される仕様でした。しかし修正前のバージョンには、Anthropicモデルidではない不正なキー（タイプミスや旧形式のIDなど）を指定した場合に、それがそのままセッションの「正規のモデルID」として扱われてしまうバグがありました。v2.1.223でこの不具合が修正され、仕様通り不正なキーは静かに無視され、セッションの実際のモデルIDに影響を与えなくなりました。

## 基本的な使い方

`modelOverrides` は設定ファイルの `modelOverrides` キーに、Anthropicモデルidをキー、プロバイダ側の値をバリューとして指定します。

```json
{
  "modelOverrides": {
    "claude-opus-4-7": "arn:aws:bedrock:us-east-2:123456789012:application-inference-profile/opus-prod",
    "claude-sonnet-4-6": "arn:aws:bedrock:us-east-2:123456789012:application-inference-profile/sonnet-prod"
  }
}
```

`/model` ピッカーでユーザーがこれらのモデルを選択すると、Claude Codeは組み込みのモデルIDの代わりに、ここで指定した値をプロバイダAPIへ送信します。

## 実践例

### Bedrockのインファレンスプロファイルへ各バージョンをマッピングする

日付付きのモデルIDも、Models overviewに記載されている表記のまま正確に指定する必要があります。

```json
{
  "modelOverrides": {
    "claude-opus-4-6": "arn:aws:bedrock:us-east-2:123456789012:application-inference-profile/opus-46-prod",
    "claude-opus-4-7": "arn:aws:bedrock:us-east-2:123456789012:application-inference-profile/opus-47-prod"
  }
}
```

このとき、`claude-opus-4-6-20260115` のように存在しない/誤った日付サフィックスを付けたキーを紛れ込ませても、v2.1.223以降ではそのキーは単に無視され、セッションの正規モデルIDが誤って書き換えられることはありません。

### タイプミスによる意図しない挙動を避ける

管理者が誤って `"claue-opus-4-7"` のようにキー名をタイプミスした場合を考えます。

```json
{
  "modelOverrides": {
    "claue-opus-4-7": "arn:aws:bedrock:us-east-2:123456789012:application-inference-profile/opus-prod"
  }
}
```

修正前は、このような不正なキーが原因でセッションのモデルID解決に予期しない影響が出ることがありましたが、修正後はドキュメント通り単に無視されるため、`claude-opus-4-7` を選択した場合は組み込みのデフォルトIDのまま動作し、意図しないモデルへ切り替わることはありません。

### `availableModels` と組み合わせて運用する

`modelOverrides` は `availableModels` による許可リストと併用できます。許可リストの評価はAnthropicモデルIDに対して行われるため、Opusのバージョンがすべて独自のARNへマッピングされていても、`"opus"` のようなエントリはそのまま一致し続けます。

```json
{
  "availableModels": ["opus", "sonnet"],
  "modelOverrides": {
    "claude-opus-4-8": "arn:aws:bedrock:us-east-2:123456789012:application-inference-profile/opus-latest"
  }
}
```

## 注意点

- `modelOverrides` のキーは、[Models overview](https://platform.claude.com/docs/en/about-claude/models/overview) に列挙されている正確なAnthropicモデルIDである必要があります。日付付きIDの場合は日付サフィックスまで一致させてください。
- Amazon Bedrock環境では、`modelOverrides` のエントリは、Claude Codeが起動時に自動検出するインファレンスプロファイルよりも優先されます。
- `--model` フラグや `ANTHROPIC_MODEL` 環境変数、`ANTHROPIC_DEFAULT_*_MODEL` 系の環境変数でAnthropicモデルIDを直接指定した場合も、`modelOverrides` の変換が適用されます（v2.1.200以降）。
- `availableModels` が管理設定（managed settings）で指定されている場合、`--model` や環境変数で渡されたIDに対しては、その管理設定と同じソースの `modelOverrides` のみが適用され、ユーザー設定やプロジェクト設定の `modelOverrides` は無視されます（v2.1.200以降）。
- 本修正はv2.1.223以降で有効です。それ以前のバージョンで不正なキーを含む `modelOverrides` を設定していた場合は、意図しないモデルID解決が起きていないか、アップデート後に `/model` やセッションログで確認することをおすすめします。
