## 原文（日本語に翻訳）

サンドボックス化されたコマンドが allowlist に登録されていないホストへアクセスしようとした際に、プロンプトで確認を求めることなく拒否できる `sandbox.network.strictAllowlist` 設定を追加しました。

## 原文（英語）

Added `sandbox.network.strictAllowlist` setting to deny non-allowlisted hosts for sandboxed commands without prompting

## 概要

Claude Codeのサンドボックス機能では、コマンド実行時のネットワークアクセスを `sandbox.network.allowedDomains` で制御できますが、従来は allowlist に無いホストへのアクセスが発生すると、その都度ユーザーに許可を求めるプロンプトが表示されていました。`sandbox.network.strictAllowlist` を有効にすると、この確認プロンプトをスキップし、allowlist 外のホストへの通信を即座に拒否するようになります。CI環境や無人実行など、対話的な承認ができない場面でのセキュリティ強化に役立ちます。

## 基本的な使い方

`.claude/settings.json` に以下を追加します。

```json
{
  "sandbox": {
    "network": {
      "strictAllowlist": true,
      "allowedDomains": ["github.com", "registry.npmjs.org"]
    }
  }
}
```

この設定により、`github.com` と `registry.npmjs.org` 以外へのネットワークアクセスは、プロンプトなしで即座にブロックされます。

## 実践例

### CI/CDパイプラインでの無人実行

対話的な承認ができないCI環境では、想定外のホストへのアクセスをすべて拒否しつつ、必要な通信のみを明示的に許可します。

```json
{
  "sandbox": {
    "network": {
      "strictAllowlist": true,
      "allowedDomains": [
        "github.com",
        "*.githubusercontent.com",
        "registry.npmjs.org",
        "pypi.org"
      ]
    }
  }
}
```

### 依存関係インストールを伴う自動化タスクの保護

パッケージマネージャーがアクセスするレジストリのみを許可し、それ以外の外部通信（データ持ち出しの疑いがあるものなど）を機械的に遮断します。

```json
{
  "sandbox": {
    "network": {
      "strictAllowlist": true,
      "allowedDomains": [
        "*.npmjs.org",
        "*.pythonhosted.org",
        "crates.io",
        "static.crates.io"
      ]
    }
  }
}
```

### 組織全体でのポリシー強制（managed settings）

管理者用のmanaged settingsに設定して、プロジェクトやユーザーの設定で緩められないネットワーク境界を敷きます。

```json
{
  "sandbox": {
    "network": {
      "strictAllowlist": true,
      "allowedDomains": ["internal-registry.example.com"]
    }
  }
}
```

## 注意点

- `strictAllowlist` を有効にした状態で `allowedDomains` に必要なホストを登録し忘れると、正当な通信まで無言でブロックされ、コマンドが原因不明に失敗しているように見えることがあります。導入時はログや失敗内容を確認しながら allowlist を拡充してください。
- この設定はサンドボックス化されたコマンド実行（Bashツールなど）のネットワーク層に対するものであり、ファイルシステムアクセスの制御（`sandbox.filesystem` 系設定）とは独立しています。
- ユーザー設定・プロジェクト設定・managed settings の `allowedDomains` は基本的にマージされますが、`strictAllowlist` を組織のmanaged settingsで有効化しておくことで、プロジェクト側の緩い設定に関わらずプロンプトなしの拒否ポリシーを強制できます。
- ワイルドカード（例: `*.npmjs.org`）でサブドメインをまとめて許可できますが、想定より広い範囲を許可してしまわないか確認することを推奨します。
