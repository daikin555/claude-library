## 原文（日本語訳）

不正な形式の閉じタグによってメッセージ本文がsummaryフィールド側に混入してしまい、`SendMessage` の呼び出しが拒否されてしまう問題を修正しました。

## 原文（英語）

Fixed `SendMessage` calls being rejected when a malformed closing tag left the message text inside the summary field

## 概要

`SendMessage` はセッション間（サブエージェント、永続サブエージェント、エージェントチーム、ローカルとクラウドのセッション間など）でテキストメッセージをやり取りするためのツールで、送信内容には要約（summary）用のフィールドと本文用のフィールドが分かれて渡されます。これまでは、Claudeが生成したツール呼び出しの中で閉じタグが不正な形式になっていた場合、本来メッセージ本文に入るべきテキストがsummaryフィールド側に混入してしまい、その結果 `SendMessage` の呼び出し自体がバリデーションエラーとして拒否されてしまうことがありました。今回の修正でこのパース処理が改善され、閉じタグの記述が多少崩れていても正しくフィールドが分離され、呼び出しが不要に拒否されなくなりました。

## 基本的な使い方

`SendMessage` はユーザーが直接呼び出すものではなく、Claudeが `ListAgents` で宛先を確認したうえで自動的に発行するツールです。ユーザーは「このセッションに◯◯を伝えて」と依頼するだけで構いません。

```
サブエージェントの作業結果をmain-sessionに報告して
```

修正前は、内部的なタグの整形がわずかに崩れただけで送信全体が失敗し、Claudeが気づかないまま処理を続けてしまうことがありました。修正後はそうした軽微な整形の乱れがあってもメッセージが正しく解釈され、送信が成功しやすくなっています。

## 実践例

### サブエージェントからの長い報告メッセージ送信

サブエージェントが作業結果の要約と詳細を含む長めのメッセージを親セッションに送ろうとした際、生成されたツール呼び出しの閉じタグの形式がわずかに崩れていると、以前は本文がsummary側に混ざり込みバリデーションエラーで送信が拒否されていました。修正後はこのようなケースでも正しく分離され、送信が通ります。

### エージェントチームでのメンバー間連絡

複数のサブエージェントが連携して作業するエージェントチーム構成で、あるメンバーが次のメンバーに状況を伝える際にも同様のパース処理が使われます。閉じタグの記述に軽微な乱れがあっても、以前のように呼び出し全体が拒否されることはなくなりました。

## 注意点

- この修正はメッセージのパース・バリデーション処理に関するものであり、`SendMessage` の基本的な使い方や宛先の指定方法自体は変わりません。
- summaryフィールドと本文フィールドが正しく分離されるようになったことで、受信側に表示される要約や通知の内容もより正確になります。
