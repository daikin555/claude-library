## 原文（日本語訳）

`/config` から「Default teammate model（デフォルトのチームメイトモデル）」設定を削除しました。エージェントチームのチームメイトは、スポーン時にモデルが指定されていない限り、リーダーのモデルを使用するようになります

## 原文（英語）

Removed the "Default teammate model" setting from `/config`; agent-team teammates now use the leader's model unless the spawn names one

## 概要

Agent Teams（エージェントチーム）機能では、リーダーが複数のチームメイト（サブエージェント）を起動して並行作業を行います。これまでは `/config` に「Default teammate model」という個別の設定項目があり、チームメイトが使用するモデルを別途指定できましたが、この設定が廃止されました。今後はチームメイトをスポーンする際にモデルが明示的に指定されていない限り、リーダー自身が使用しているモデルがそのまま引き継がれるようになります。

## 基本的な使い方

特別な設定は不要です。エージェントチームを起動すると、チームメイトはデフォルトでリーダーと同じモデルを使用します。

```
/agent-team あるタスクを複数のチームメイトに分担させて進めて
```

モデルを明示的に指定したい場合は、スポーン時にモデルを指名します。

```
チームメイトAをHaikuモデルで起動して簡単な調査を任せて
```

## 実践例

### 既存の設定を使っていた場合の移行

以前 `/config` で「Default teammate model」をOpusなどに設定していたユーザーは、この設定項目自体がなくなるため、今後はリーダーのモデルがそのままチームメイトに使われます。特定モデルを使わせたい場合は、チーム起動やスポーン指示のたびにモデルを明示する必要があります。

### 高性能モデルでリーダーを起動し、チーム全体を統一

```bash
claude --model opus
```

このようにリーダーをOpusで起動すれば、モデルを個別指定しない限りチームメイト全員がOpusを使用するようになり、チーム全体で一貫したモデル方針を保ちやすくなります。

### タスクごとに軽量モデルを個別指定

重い調査タスクはリーダーのモデルを継承させつつ、簡単な確認作業だけ軽量モデルのチームメイトに任せたい場合は、スポーン時に個別にモデル名を指定します。

## 注意点

- `/config` に「Default teammate model」という項目が表示されなくなります。以前この設定を利用していた場合は、リーダーのモデルに置き換わる点に注意してください
- スポーン時にモデルを名指しした場合は、その指定が優先されます
- リーダーのモデルを変更すれば、以降新たに起動するチームメイトのデフォルトモデルも変わります
