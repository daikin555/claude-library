## 原文（日本語訳）

Bedrock、Vertex、またはFoundry上で `model: "opus"` と指定されたサブエージェントが、そのモデルIDが認識可能なモデルファミリーに該当しない場合（`ANTHROPIC_DEFAULT_OPUS_MODEL` が設定されている場合を除く）、セッションのモデルのまま動作してしまう問題を修正しました。

## 原文（英語）

Fixed subagents with `model: "opus"` on Bedrock, Vertex or Foundry leaving the session's model when its id has no recognizable model family (unless `ANTHROPIC_DEFAULT_OPUS_MODEL` is set)

## 概要

Amazon Bedrock、Google Vertex AI、Microsoft Foundryといったサードパーティ基盤上でClaude Codeを利用する場合、モデルIDの形式がプロバイダー固有のものになることがあります。サブエージェントの設定で `model: "opus"` のようなエイリアスを指定しても、そのモデルIDから「Opusファミリー」であることを自動認識できない場合、これまではサブエージェントがセッション全体で使われているモデルにフォールバックしてしまい、意図したモデルファミリーで実行されないことがありました。今回の修正により、モデルIDからファミリーを認識できないケースでも、`ANTHROPIC_DEFAULT_OPUS_MODEL` が設定されていればそれを使ってOpusとして正しく解決されるようになりました（設定されていない場合の挙動改善も含まれます）。

## 基本的な使い方

```yaml
# サブエージェント定義の例
---
name: reviewer
model: opus
---
```

Bedrock/Vertex/Foundry環境で、モデルIDからファミリーが自動認識できない場合に備えて、環境変数でデフォルトのOpusモデルIDを明示しておきます。

```bash
export ANTHROPIC_DEFAULT_OPUS_MODEL="anthropic.claude-opus-4-6-v1:0"
```

## 実践例

### Amazon Bedrock環境でOpusサブエージェントを使う

Bedrock経由でClaude Codeを利用しつつ、`model: "opus"` を指定したサブエージェントを定義している場合、モデルIDの命名規則によってはファミリーが自動認識されないことがあります。`ANTHROPIC_DEFAULT_OPUS_MODEL` にBedrock上の正確なモデルIDを設定しておくことで、確実にOpusとして実行されます。

```bash
export ANTHROPIC_DEFAULT_OPUS_MODEL="anthropic.claude-opus-4-6-v1:0"
claude
```

### Vertex AIやFoundryでのマルチエージェント構成

VertexやFoundry上で、レビュー用など重い処理を担うサブエージェントにOpusを割り当てたい場合も、同様に `ANTHROPIC_DEFAULT_OPUS_MODEL` を設定しておくことで、意図したモデルファミリーでの実行を保証できます。

## 注意点

- `ANTHROPIC_DEFAULT_OPUS_MODEL` が未設定で、かつモデルIDからファミリーが自動認識できない場合は、引き続き期待通りに動作しないことがあります。該当する基盤を利用している場合は明示的に設定することを推奨します。
- モデルIDの命名規則はBedrock、Vertex、Foundryそれぞれで異なるため、利用している基盤のドキュメントを確認して正確なIDを指定してください。
