## 原文（日本語に翻訳）

サブエージェントのフォーキングがデフォルトで有効になりました。`subagent_type: "fork"` のサブエージェントは、会話全体とプロンプトキャッシュを引き継ぎます。また、対話型セッションにおいて、チームメイトではないエージェントの起動は、デフォルトでバックグラウンド実行されるようになりました。

## 原文（英語）

Subagent forking is now on by default: a `subagent_type: "fork"` subagent inherits the full conversation and prompt cache, and non-teammate agent spawns in interactive sessions now run in the background by default

## 概要

これまで `subagent_type: "fork"` を使ったサブエージェントの起動は明示的なオプトインが必要でしたが、v2.1.232からはデフォルトで有効になりました。フォークされたサブエージェントは、通常のサブエージェントのように新規のコンテキストから始まるのではなく、親セッションの会話履歴とプロンプトキャッシュをそのまま引き継ぐため、これまでの経緯を再説明する必要がありません。加えて、対話型セッションでチームメイト以外のエージェントを起動した場合、既定でバックグラウンド実行となり、メインの作業を止めずに並行してタスクを進められるようになりました。

## 基本的な使い方

```
Agent({
  description: "既存の会話を踏まえてコードレビュー",
  subagent_type: "fork",
  prompt: "ここまでの変更内容を踏まえて、追加した認証処理のセキュリティ観点でレビューして"
})
```

`subagent_type: "fork"` を指定するだけで、親セッションの会話全体とプロンプトキャッシュを引き継いだ状態でサブエージェントが起動します。

## 実践例

### 会話全体を引き継いだ状態でレビューを依頼する

長時間の実装セッションの途中で、ここまでの文脈を踏まえたレビューを別エージェントに任せたい場合に有効です。

```
Agent({
  description: "実装済みコードのレビュー",
  subagent_type: "fork",
  prompt: "これまでのやり取りを踏まえ、実装したAPIエンドポイントのエラーハンドリングをレビューして"
})
```

フォークされたサブエージェントは会話履歴を最初から読み込む必要がなく、プロンプトキャッシュも共有されるため、起動が速くコストも抑えられます。

### 長時間セッションの途中で専門タスクだけ分岐させる

```
Agent({
  description: "テストケースの追加",
  subagent_type: "fork",
  prompt: "これまでの設計方針に沿って、未カバーのエッジケースに対するテストを追加して"
})
```

親の文脈（設計方針や既存の決定事項）を再送する必要がないため、指示文をシンプルに保てます。

### バックグラウンド実行でメインの作業を止めない

```
Agent({
  description: "ドキュメント更新",
  prompt: "README の変更点を反映して",
  run_in_background: true
})
```

v2.1.232からは、対話型セッションでチームメイトではないエージェントを起動すると、指定しなくても既定でバックグラウンド実行になります。結果をすぐに使いたい場合は `run_in_background: false` を明示的に指定してください。

## 注意点

- Claude Code v2.1.232での変更です。
- フォークは会話全体とプロンプトキャッシュを引き継ぐため、通常のサブエージェント（新規コンテキストから開始）とは挙動が異なります。
- 親の会話量が多いほど、フォーク先のサブエージェントも同じだけコンテキストを消費する点に注意してください。
- バックグラウンド実行がデフォルトになったのは「非チームメイト」のエージェント起動に限られます。チームメイト（エージェントチーム）の起動挙動は別扱いです。
- 次のアクションが結果に依存する場合は、`run_in_background: false` を指定してフォアグラウンド実行に切り替えられます。
