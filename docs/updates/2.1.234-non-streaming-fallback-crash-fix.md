## 原文（日本語訳）

非ストリーミングのフォールバックパス（多くの場合サードパーティのゲートウェイ経由）でAPIレスポンスに thinking フィールドが欠落した thinking ブロック、または text フィールドが欠落した text ブロックが含まれていた場合にクラッシュしていた不具合を修正しました。

## 原文（英語）

Fixed a crash when an API response on the non-streaming fallback path (typically via third-party gateways) contained a thinking block missing its thinking field or a text block missing its text field

## 概要

Claude Codeはストリーミング接続が利用できない環境や失敗した場合に、非ストリーミング（non-streaming）のフォールバックパスでAPIリクエストを行うことがあります。この経路は特にサードパーティ製のAPIゲートウェイ経由で使われることが多く、レスポンスの形式が公式APIと微妙に異なる場合があります。今回の修正前は、レスポンス内の `thinking` ブロックに `thinking` フィールドが無い、または `text` ブロックに `text` フィールドが無いといった不完全なレスポンスを受け取るとクラッシュしていましたが、修正後はこうした欠落フィールドを許容し、クラッシュせずに処理を継続できるようになりました。

## 基本的な使い方

この修正はバグフィックスであり、ユーザー操作は不要です。サードパーティのLLMゲートウェイ（社内プロキシや互換APIサーバーなど）を経由してClaude Codeを利用している場合、レスポンスの形式が完全に仕様通りでなくてもクラッシュしにくくなります。

## 実践例

### 社内プロキシ経由でClaude Codeを利用している場合

```bash
# 例: 独自のAPIゲートウェイ経由でANTHROPIC_BASE_URLを設定
export ANTHROPIC_BASE_URL="https://internal-gateway.example.com/v1"
claude
```

ゲートウェイがストリーミングに完全対応していない、あるいは一部レスポンスでフィールドを省略してしまうケースでも、修正後はクラッシュせずにセッションが継続します。

### ネットワーク不安定時に非ストリーミングへ自動フォールバックするケース

ストリーミング接続が途中で切断されて非ストリーミングにフォールバックした際、ゲートウェイ側の変換処理でレスポンスの一部フィールドが欠落することがありますが、そうした場合でもクラッシュせずに動作を継続できます。

## 注意点

- この修正は「クラッシュしない」ようにするものであり、欠落したフィールドの内容自体を補完・推測するものではありません。ゲートウェイ側のレスポンス品質に問題がある場合、表示内容が空になるなどの影響は残る可能性があります
- 公式のAnthropic APIを直接利用している場合はこの不具合の影響を受けにくいですが、サードパーティゲートウェイ経由の利用ではアップデートを推奨します
