## 原文（日本語訳）

セルフホスト環境を追加：`claude self-hosted-runner` により、自分のマシンやコンテナをClaude CodeのWeb・モバイル・デスクトップセッションの実行場所にできます（Team・Enterpriseプラン向け）。

## 原文（英語）

Added self-hosted environments: `claude self-hosted-runner` turns your own machines or containers into a place Claude Code web, mobile, and desktop sessions can run, on Team and Enterprise plans

## 概要

セルフホスト環境は、Claude Codeの「クラウドセッション」（claude.aiやモバイル・デスクトップアプリ、`claude --cloud`、スケジュール実行される routine から開始される、開発者自身のマシン以外で動くセッション）を、Anthropicのインフラではなく組織が管理するインフラ上で実行できるようにする機能です。ネットワーク要件やコンプライアンス要件により、コードの実行環境を自社で管理したいチーム向けに、Team・Enterpriseプランでパブリックベータとして提供されます。デフォルトでは無効になっており、組織の管理者が明示的に有効化する必要があります。

## 基本的な使い方

セルフホスト環境は「environment（環境）」「runner（ランナー）」「session（セッション）」の3つの要素で構成されます。まず、claude.aiの管理画面（**Cloud environments**ページ）で環境を作成し、次に自分のインフラ上でランナープロセスを起動して、その環境に登録します。

```bash
# ランナーを起動して環境に登録する（イメージ）
claude self-hosted-runner start \
  --environment-secret <環境作成時に発行されるシークレット> \
  --capacity 2
```

ランナーがセッションを受信すると、リポジトリをクローンし、その中で子プロセスとしてClaude Codeを起動して実行します。開発者がセッション開始時に環境ピッカーからこのセルフホスト環境を選べば、以降はAnthropicホスト環境と同じ操作感でセッションを利用できます。

## 実践例

### 社内ネットワーク内のサービスにアクセスする

社内APIやデータベースなど、インターネットに公開していないサービスにClaude Codeからアクセスしたい場合に有効です。

```bash
# ランナーは社内ネットワーク内で動作するため、
# 社内APIやプライベートなDBに直接到達できる
claude self-hosted-runner start \
  --environment-secret $ENV_SECRET \
  --capacity 4
```

### 事前にツールをインストールしたランナーイメージを使う

コンパイラや社内CLIなど、セッションが毎回使う依存関係をあらかじめランナーのイメージに含めておくことで、セッション開始のたびにセットアップする手間を省けます。

```dockerfile
FROM ubuntu:24.04
RUN apt-get update && apt-get install -y build-essential internal-cli
# ランナーのセットアップコマンドをここに追加
```

### オンデマンドでランナーをスケールさせる

固定数のランナーを常時起動しておく代わりに、オートスケーリング・オーケストレーターを使うと、セッションがキューに入ったタイミングでランナーを起動し、処理が終われば自動的に停止できます。

```bash
# セッションのキューを監視し、必要に応じてランナーを起動/停止する
# オーケストレーターを別プロセスとしてホストする
claude self-hosted-runner orchestrator start --environment-secret $ENV_SECRET
```

## 注意点

- 2026年8月時点でTeam・Enterpriseプランのパブリックベータで、デフォルトでは無効です。有効化にはClaude Code on the webが組織で有効になっている必要があります。
- Zero Data Retention（ゼロデータリテンション）を有効にしている組織では利用できません。
- モデル推論はAnthropic API経由のみで、Amazon Bedrock・Google Cloud・Microsoft Foundryやカスタムのllmゲートウェイ経由にはルーティングできません。
- リポジトリのチェックアウトはGitHubからのみ対応しています。
- 1台のランナーは一度に1ユーザーのセッションのみを処理し、最初に受け取ったセッションのユーザーにロックされます（ユーザー間でチェックアウト済みコードが混ざらないようにするため）。
- Claude Tag、Claude Security、Code Reviewのセッションはまだセルフホスト環境にルーティングされません。
- セルフホスト環境で実行したセッションも、通常のClaude Code利用量として組織の使用量にカウントされます。
