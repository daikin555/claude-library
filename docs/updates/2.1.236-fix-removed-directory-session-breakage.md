## 原文（日本語訳）

セッションが `cd` などで移動した先のディレクトリが後から削除された場合に、クリップボードへのコピー、バックグラウンドのハウスキーピング処理、バックグラウンドセッション、ローカルMCPのログが壊れてしまう不具合を修正しました（2.1.229以降で発生していました）。

## 原文（英語）

Fixed clipboard copy, background housekeeping, background sessions, and local MCP logs breaking after the directory a session had switched into was removed (since 2.1.229)

## 概要

Claude Codeのセッションが作業中に別のディレクトリへ移動し、その後そのディレクトリが（一時ディレクトリの掃除やworktreeの削除などによって）ファイルシステムから消えてしまうと、内部的にカレントディレクトリの取得に失敗し、クリップボードコピーやバックグラウンドの定期処理、バックグラウンドセッションの実行、ローカルMCPサーバーのログ出力といった複数の機能が連鎖的に壊れる不具合がありました。2.1.229で入った変更以降に発生していたリグレッションで、今回の修正で解消されています。

## 基本的な使い方

ユーザー側で特別な操作は不要です。今回の修正はランタイムの内部的な不具合対応であり、アップデート後は自動的に解消されます。

## 実践例

### 一時ディレクトリで作業した後にそのディレクトリが削除されるケース

Bashツールで一時ディレクトリに `cd` して作業し、その後別のプロセスやスクリプトがそのディレクトリを削除してしまうような場面で、修正前はクリップボードコピーなどの機能が以後動作しなくなることがありました。修正後はディレクトリが消えても他の機能に影響しません。

### git worktreeを使った作業でworktreeを削除するケース

セッションがworktree内のディレクトリに移動して作業した後、そのworktreeを `git worktree remove` などで削除すると、修正前はバックグラウンドのハウスキーピング処理やバックグラウンドセッションが壊れてしまうことがありました。

### ローカルMCPサーバーを利用している長時間セッション

ローカルMCPサーバーのログを利用しているセッションで、作業ディレクトリの削除後にログ出力が止まってしまう問題も、今回の修正対象に含まれます。

## 注意点

- 2.1.229以降のバージョンで発生していたリグレッションです。2.1.236以降ではこの問題は発生しません
- 影響していたのはクリップボードコピー、バックグラウンドのハウスキーピング処理、バックグラウンドセッション、ローカルMCPのログの4点です
- ディレクトリが削除されること自体を防ぐものではなく、削除された後も他の機能が正常に動作し続けるようにする修正です
