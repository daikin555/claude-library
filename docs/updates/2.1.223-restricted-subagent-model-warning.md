## 原文（日本語に翻訳）

workflowエージェント、forkされたskill、スラッシュコマンド、または再開されたbackground agentが要求したサブエージェントモデルが制限されており、代わりに親（parent）モデルが実行される場合に、警告が表示されるようになった。

## 原文（英語）

Added a warning when workflow agents, forked skills, slash commands, or resumed background agents' requested subagent model is restricted and the parent model runs instead

## 概要

Claude Codeでは、組織の管理者が `availableModels`（managed settingsやpolicy settings）でユーザーが選択できるモデルを制限できます。サブエージェントのモデルは、環境変数 `CLAUDE_CODE_SUBAGENT_MODEL`、呼び出し時の `model` パラメータ、サブエージェント定義のfrontmatterの `model` フィールド、という優先順で解決されますが、この解決結果が組織の許可リストに反していた場合、Claude Codeはそのモデルの利用を拒否し、代わりに親会話（呼び出し元）のモデルでサブエージェントを実行します。今回のアップデートでは、workflowエージェント・forkされたskill・スラッシュコマンド・再開されたbackground agentがこの状況に陥った際に、要求されたモデルが使えず親モデルにフォールバックしたことをユーザーに知らせる警告が追加されました。従来はこの置き換えがサイレントに行われていたため、意図したモデル（例えば低コストなHaikuでの実行を想定していた処理）が実際には別のモデルで実行されていることに気づきにくいという問題がありました。

## 基本的な使い方

たとえば、組織のmanaged settingsで利用可能なモデルが制限されているとします。

```json
{
  "availableModels": ["sonnet"]
}
```

この状態で、`model: haiku` を指定したworkflowエージェントやカスタムスラッシュコマンドを実行すると、`haiku` が許可リストに含まれていないため、Claude Codeは親会話のモデル（例: `sonnet`）でサブエージェントを実行し、次のような警告が表示されます（文言はイメージです）。

```text
Warning: requested subagent model "haiku" is restricted by your organization.
Running with the parent model instead.
```

## 実践例

### workflowエージェントで安価なモデルを指定していた場合

コスト最適化のために、特定のworkflowステップだけ軽量モデルで動かす設定にしていても、組織ポリシーでそのモデルが許可されていなければ、意図せず高コストな親モデルで実行されます。今回の警告により、この乖離にワークフロー実行時点で気づけるようになりました。

```yaml
---
name: log-summarizer
model: haiku
---
```

上記のようなworkflowエージェント定義がある環境で `availableModels` が `haiku` を許可していない場合、実行時に警告が表示され、実際には親モデルで処理されたことが分かります。

### forkされたskill内でモデルを指定していた場合

`context: fork` を使うskillでモデルを指定するケースでも同様に、制限されたモデルが要求されると警告付きで親モデルにフォールバックします。想定外のモデルでskillが実行されていないかを、警告の有無で確認できます。

### 再開したbackground agentのモデルが制限されている場合

`--agent` などで指定したbackground agentを後から再開（resume）する際、そのagentのモデル指定が組織のモデル制限に抵触していると、再開後の会話も親モデルにフォールバックします。長時間実行しているbackground agentを再開する運用では、この警告を見て意図通りのモデルで再開できているかを確認できます。

## 注意点

- この警告はあくまで通知であり、モデル制限そのものの挙動（親モデルへのフォールバック）を変更するものではありません。制限の仕組み自体は `availableModels` によるものです。
- モデルのブロック値がopusなどのファミリーエイリアスの場合、Claude Codeはそのファミリー内で許可リストが認める最新バージョンに自動的に切り替えます（v2.1.222以降）。この場合は親モデルへのフォールバックが発生しないため、今回の警告の対象にはなりません。警告が出るのは、ファミリー内に許可されたバージョンが存在しない場合や、ファミリーエイリアス以外の値がブロックされた場合です。
- 対象となるのはworkflowエージェント、forkされたskill、スラッシュコマンド、再開されたbackground agentであり、通常のTaskツール経由のサブエージェント呼び出し全般について、警告の適用範囲が完全に同一かどうかは公式ドキュメントに本記事作成時点で明記が見当たりませんでした。
- `availableModels` はmanaged settingsまたはpolicy settingsで設定する組織向けの制限機能であり、個人設定やプロジェクト設定では上書きできません。
