## 原文（日本語訳）

auto modeを改善しました: `Monitor` のallowルールは、auto modeが有効な間は一時的に無効化されるようになり、`Monitor` コマンドもBashコマンドと同じように審査されるようになりました。

## 原文（英語）

Improved auto mode: `Monitor` allow rules are now set aside while auto mode is active, so Monitor commands are reviewed the same way Bash commands are

## 概要

auto modeは、ツール呼び出しをclassifier（分類モデル）に通し、破壊的・不可逆的・環境外への操作を自動的にブロックする仕組みです。バックグラウンドプロセスの出力を監視する `Monitor` ツールはシェルコマンドを実行して標準出力をイベントとして流す仕組みのため、Bashと同様に任意のコマンドを実行しうるツールです。これまでauto mode中でも `Monitor(...)` に対する広いallowルールがそのまま有効になってしまうケースがあり、classifierによる審査をすり抜けてコマンドが実行される可能性がありました。今回の改善で、auto modeが有効な間は `Monitor` の広いallowルールも一時的に無効化され、Bashの広いallowルール（`Bash(*)` など）と同様に、実行前にclassifierの審査を受けるようになりました。

## 基本的な使い方

ユーザー側で明示的な設定変更は不要です。auto modeが有効な状態でClaudeが `Monitor` ツールを使ってバックグラウンドプロセスを監視しようとすると、コマンド内容に応じてclassifierが安全性を審査し、問題があれば承認を求めるか拒否します。

```json
{
  "permissions": {
    "allow": [
      "Monitor(*)"
    ]
  }
}
```

上記のような広いallowルールを設定していても、auto mode中はこのルールが一時的に無効化され、`Monitor` で実行しようとするコマンドの内容がBashコマンドと同じ基準で審査されます。

## 実践例

### 長時間ビルドをMonitorで見守っているセッション

`npm run build` や `docker build` のような時間のかかる処理をMonitorで監視させている場合、auto mode下では監視対象のコマンド自体（および出力に応じてClaudeが追加実行しようとする操作）がclassifierによってチェックされ、意図しない破壊的な操作が紛れ込むのを防ぎます。

### `Monitor(*)` のような広いallowルールを設定している開発者

自動化を優先して `Monitor` に対して広い許可ルールを設定していたチームでも、auto modeが有効な間はそのルールに関わらずclassifierが個々のコマンドを審査するため、Bashの場合と同様に「広いallowルールで安全チェックが素通りしてしまう」抜け穴が塞がれます。

## 注意点

- `autoMode.classifyAllShell` を `true` に設定すると、Bashに加えてMonitorも含め、すべてのシェルコマンドがauto mode中は無条件にclassifierを通るようになります
- この挙動はauto modeが有効なときのみ適用され、他のパーミッションモードではMonitorのallowルールは通常どおり機能します
- classifierによる審査はレイテンシを伴うため、頻繁にMonitorを使うワークフローではわずかに応答が遅くなる場合があります
