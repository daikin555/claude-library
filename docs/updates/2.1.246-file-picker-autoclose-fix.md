## 原文（日本語訳）

入力したテキストが実在するパスに一致しなくなった後も、`@` ファイルピッカーが開いたままになる不具合を修正しました。

## 原文（英語）

Fixed the `@` file picker staying open after the typed text stopped matching a real path

## 概要

Claude Codeでは `@` を入力するとファイルパスの補完候補を表示するファイルピッカーが起動します。しかし、候補を絞り込むために文字を入力していく途中で、実在するどのファイルパスにも一致しなくなった場合でも、ピッカーが自動的に閉じずに開いたままになる不具合がありました。今回の修正により、入力テキストが実在パスに一致しなくなった時点でファイルピッカーが正しく閉じるようになりました。

## 基本的な使い方

`@` を入力してファイルを参照する際、候補と一致しなくなった時点でピッカーが自動的に閉じます。

```
@src/components/App
```

例えば `App` の後にタイプミスの文字を続けて実在しないパスになった場合、修正前はピッカーが表示され続けていましたが、修正後は自動的に閉じ、通常のテキスト入力として扱われます。

## 実践例

### ファイルパスを手入力しながら絞り込む

`@src/utils/` まで入力してディレクトリ内の候補を確認し、そこから存在しないファイル名を続けて入力してしまった場合、ピッカーが自動で閉じるため誤った候補選択を防げます。

### `@` をメンションや強調表現として使う

ファイル参照ではなく、単に `@` を使った通常の文章（例: SNS風のメンションや強調）を書く場合も、実在パスに一致しない入力を続けるとピッカーが閉じ、通常のテキスト編集に戻ります。

### タイプミスからの復帰

パスの一部を打ち間違えてピッカーの候補がなくなった際、以前は手動でピッカーを閉じる操作が必要でしたが、今後は自動的に閉じるためスムーズに入力を続けられます。

## 注意点

- この修正はUIの表示挙動に関するものであり、実際のファイル参照解決ロジックには影響しません
- 一致する候補が復活する入力（バックスペースで正しいパスに戻すなど）を行えば、ピッカーは再度表示されます
