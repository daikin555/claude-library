## 原文（日本語訳）

claude.aiの使用量制限がリセットされると、Claude Codeが自動的にセッションを継続するようになりました。この動作は `/config` の「Continue automatically at usage limit（使用量制限で自動継続する）」からオフにできます。

## 原文（英語）

Claude Code now continues your session automatically when a claude.ai usage limit resets; turn it off in `/config` ("Continue automatically at usage limit")

## 概要

claude.aiアカウントの使用量制限（プランごとのメッセージ数・時間あたりの上限など）に達すると、これまではリセット時刻が来ても手動でセッションを再開する必要がありました。今回の更新により、使用量制限に達して待機状態になっていたセッションは、制限がリセットされたタイミングでClaude Codeが自動的に処理を再開します。この挙動が不要な場合は `/config` からいつでも無効化できます。

## 基本的な使い方

デフォルトで有効になっているため、特別な操作は不要です。使用量制限に達すると、リセット時刻まで待機し、リセット後に自動で作業を継続します。

```bash
claude

> 大規模なリファクタリングを実行して

# 途中で使用量制限に到達
Usage limit reached. Resuming automatically at 14:00...

# 14:00になると自動的に処理を再開
```

## 実践例

### 長時間の自律的タスクを制限をまたいで実行する

夜間や外出中に長時間タスクを走らせている場合、使用量制限に一度引っかかっても、リセット後に自動で続きから再開されます。

```bash
claude -p "リポジトリ全体のテストカバレッジを80%まで引き上げて" &

# 制限リセットをまたいでも、明示的な再実行なしに作業が継続する
```

### 自動継続を無効化して手動制御したい場合

制限に達したタイミングで作業内容を確認してから再開したい場合は、`/config` で無効化します。

```bash
claude
/config
# "Continue automatically at usage limit" をオフに変更
```

以降は使用量制限に達すると、リセット後も自動再開せず、ユーザーの操作を待つようになります。

### チームで運用ポリシーを統一する

自動継続の可否をチームで統一したい場合、設定ファイルで管理することも検討できます（詳細は設定ドキュメントを参照）。

## 注意点

- 対象はclaude.aiアカウントの使用量制限であり、API従量課金のレート制限とは異なる場合があります
- 自動継続はデフォルトで有効です。意図せず長時間タスクが再開してほしくない場合は、事前に `/config` で無効化しておくことを推奨します
- リセット時刻を待っている間、セッションはアイドル状態になりますが、ターミナル自体は開いたままにしておく必要があります
- 自動継続後の挙動は、制限に達する直前まで実行していたタスクの続きからになります
