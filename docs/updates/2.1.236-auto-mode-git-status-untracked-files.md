## 原文（日本語訳）

auto modeを改善しました: gitのステータスチェックが、リポジトリの `status.showUntrackedFiles=no` 設定によって「ワーキングツリーはクリーンである」と誤って報告されることがなくなりました。

## 原文（英語）

Improved auto mode: the git status check can no longer be fooled by a repo's `status.showUntrackedFiles=no` setting into reporting a clean tree

## 概要

auto modeのclassifierは、破壊的な操作（強制プッシュや履歴の書き換えなど）を許可するかどうかを判断する材料として、ワーキングツリーの状態（変更や未追跡ファイルの有無）を `git status` などのコマンドで確認することがあります。しかしgitには `status.showUntrackedFiles=no` という設定があり、これを有効にしたリポジトリでは `git status` の出力から未追跡ファイルが除外されるため、実際には未追跡の変更が存在するにもかかわらず「クリーンなツリーである」と誤認識されてしまう可能性がありました。今回の修正で、この設定が有効なリポジトリでもauto modeのgitステータスチェックが未追跡ファイルの存在を正しく検出できるようになり、判定を欺くことができなくなりました。

## 基本的な使い方

ユーザー側で対応が必要な操作はありません。リポジトリの `.gitconfig` や `.git/config` に `status.showUntrackedFiles=no` が設定されている場合でも、auto modeのclassifierは未追跡ファイルの有無を正しく把握したうえで安全性を判断するようになります。

```ini
# .git/config の例
[status]
    showUntrackedFiles = no
```

このような設定があるリポジトリでも、classifierは実際のワーキングツリーの状態を正確に評価します。

## 実践例

### `status.showUntrackedFiles=no` を運用ルールとして採用しているリポジトリ

出力を簡潔にする目的でこの設定を有効化している大規模リポジトリでauto modeを使っている場合、これまでは意図せず「ツリーはクリーン」と誤判定され、本来であれば慎重に扱うべき操作（未追跡の重要ファイルが残った状態での破壊的な操作など）がチェックをすり抜けるリスクがありました。修正後は、この設定の有無にかかわらず正確な状態でclassifierが判断します。

### ブランチ切り替えや強制操作の前提条件をauto modeが確認する場面

Claudeが `git checkout` や `git clean` のような操作を行う前に「ワーキングツリーがクリーンかどうか」を確認する場面では、未追跡ファイルの見落としによって不用意にファイルが失われるリスクが排除され、より安全にauto modeを利用できます。

## 注意点

- この修正はauto modeのclassifierによるgit状態の判定ロジックに関する内部的な安全性強化であり、gitコマンド自体の出力仕様（`status.showUntrackedFiles` の挙動）は変わりません
- `soft_deny` や `hard_deny` のカスタムルールで独自にgit操作を制御している場合でも、ベースとなるツリー状態の判定が正確になることで全体の安全性が向上します
