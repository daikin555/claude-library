## 原文（日本語訳）

`--agent` フラグを付けて起動したセッションで `/compact` や「Summarize from here」を実行すると、会話本来のシステムプロンプトではなくデフォルトのシステムプロンプトを使って要約してしまう問題を修正しました。

## 原文（英語）

Fixed `/compact` and "Summarize from here" in sessions started with `--agent` summarizing under the default system prompt instead of the conversation's own

## 概要

`claude --agent <name>` のように特定のエージェントを指定して起動したセッションは、そのエージェント固有のシステムプロンプトのもとで動作します。`/compact`（コンテキストの要約・圧縮）や会話中の「Summarize from here」機能も、本来はそのセッションが使っているシステムプロンプトに沿って要約を行うべきものです。しかしこの修正前は、`--agent` で起動したセッションであっても要約処理がデフォルトのシステムプロンプトを使ってしまい、そのエージェントの役割や指示が要約の観点に反映されていませんでした。修正後は、会話本来のシステムプロンプトのもとで正しく要約が行われます。

## 基本的な使い方

特定のエージェントを指定してセッションを起動し、通常どおり `/compact` を実行します。

```
claude --agent code-reviewer
```

セッション内で

```
/compact
```

を実行すると、`code-reviewer` エージェント自身のシステムプロンプトを踏まえた要約が生成されます。

## 実践例

### カスタムエージェントで長時間のレビュー作業をする場合

特定の役割（コードレビュー、セキュリティ監査など）に特化したエージェントで長時間作業し、コンテキストが大きくなって `/compact` を使う場合、そのエージェントの観点（何を重視すべきか）が要約に反映されるようになります。

### 会話中の「Summarize from here」の活用

会話の途中から要約したい場合に使う「Summarize from here」も同様に、指定したエージェントのシステムプロンプトに基づいて要約されるため、エージェントの意図から外れた要約になるリスクが減ります。

### 複数のカスタムエージェントを使い分ける運用

プロジェクトごとに異なる役割のエージェントを `--agent` で使い分けている場合、それぞれのセッションでの要約が一貫してそのエージェントの文脈に沿ったものになります。

## 注意点

- この問題は `--agent` フラグでセッションを起動した場合に限られます。デフォルトのシステムプロンプトで起動した通常のセッションには影響しません
- 要約の品質はエージェントのシステムプロンプトの内容にも依存します
