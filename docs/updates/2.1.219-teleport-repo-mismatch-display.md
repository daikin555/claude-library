## 原文（日本語に翻訳）

`claude --teleport` を改善し、現在のチェックアウトがセッションのリポジトリと一致しない場合に、現在のチェックアウトがどのリポジトリを指しているかを表示するようにしました。

## 原文（英語）

Improved `claude --teleport` to show which repo your current checkout points at when it doesn't match the session's repo

## 概要

`claude --teleport` は、Web版Claude CodeやRemote環境、バックグラウンドタスクなどクラウド上で実行していたセッションを、手元のターミナルに引き継いで続きの作業を行うための機能です。teleportは実行時にリポジトリの整合性を検証しており、これまではセッションの紐づくリポジトリとローカルのカレントディレクトリのリポジトリが一致しない場合、エラーにはなるものの原因が分かりにくいことがありました。今回の改善により、不一致が起きた際に「今どのリポジトリのチェックアウト上にいるのか」を具体的に表示するようになり、ユーザーが問題箇所を素早く特定して正しいディレクトリに移動できるようになりました。

## 基本的な使い方

`claude --teleport` を引数なしで実行すると、クラウド上に存在するセッションの一覧（インタラクティブなセレクター）が表示され、その中から引き継ぎたいセッションを選択できます。

```bash
# 対話的にセッションを選んでteleportする
claude --teleport
```

特定のセッションIDが分かっている場合は、それを直接指定して再開することもできます。

```bash
# セッションIDを指定してteleportする
claude --teleport <session-id>
```

すでにgitリポジトリ内でこのコマンドを実行している場合、セッション一覧はそのリポジトリに紐づくものだけに自動的に絞り込まれるため、意図しない別プロジェクトのセッションを誤って引き継いでしまうことを防げます。

## 実践例

### リポジトリ不一致時のエラー表示を確認する

例えば `project-a` のセッションをteleportしようとしているのに、カレントディレクトリが `project-b` のチェックアウトだった場合、今回の改善後は次のようにローカルのチェックアウト先が具体的に示されます。

```bash
$ cd ~/work/project-b
$ claude --teleport <session-id-for-project-a>

Error: This session belongs to repo "github.com/your-org/project-a",
but your current checkout at /home/you/work/project-b points to
"github.com/your-org/project-b".

Move to the correct checkout and try again.
```

以前は単に「リポジトリが一致しません」という趣旨のエラーだけでしたが、改善後は「今いる場所がどのリポジトリのチェックアウトなのか」まで表示されるため、どこに移動すればよいかがその場で判断できます。

### 正しいディレクトリに移動してteleportをやり直す

エラーメッセージに表示されたローカルパスやリポジトリ名を手がかりに、対象リポジトリのチェックアウトへ移動してから再実行します。

```bash
# エラーで示されたリポジトリのチェックアウトへ移動
cd ~/work/project-a

# 再度teleportを実行
claude --teleport <session-id-for-project-a>
```

複数のチェックアウトを並行して使っている場合（例えば `git worktree` で複数ブランチを同時に作業しているケース）は、どのworktreeがどのリポジトリ・ブランチに対応しているか忘れがちです。エラーメッセージにリポジトリ情報が出るようになったことで、`git remote -v` などで確認する手間を減らせます。

```bash
# 複数worktreeを使っている場合、念のため紐づくリポジトリを確認
git remote -v

# 該当するworktreeへ移動してteleportをやり直す
cd ~/work/project-a-worktree
claude --teleport <session-id-for-project-a>
```

### CIやスクリプトからteleportを呼び出す際の事前チェック

自動化スクリプトなどで `claude --teleport` を呼び出す場合、事前にカレントディレクトリのリポジトリを確認しておくと、今回改善されたエラーメッセージを待たずに早期に失敗を検知できます。

```bash
#!/usr/bin/env bash
set -e

expected_repo="github.com/your-org/project-a"
current_repo=$(git remote get-url origin | sed -E 's#(git@|https://)([^/:]+)[:/](.+)\.git#\2/\3#')

if [ "$current_repo" != "$expected_repo" ]; then
  echo "警告: カレントディレクトリのリポジトリ($current_repo)が期待値($expected_repo)と一致しません"
  exit 1
fi

claude --teleport "$1"
```

## 注意点

- この改善はエラーメッセージの分かりやすさを向上させるものであり、リポジトリが一致しない場合にteleportが成功するようになるわけではありません。引き続き、セッションのリポジトリとカレントディレクトリのリポジトリを一致させる必要があります。
- リポジトリの一致判定はgitのリモートURLなどのメタデータに基づいて行われるため、同じコードベースをフォークやミラーとして複数のリモートURLで管理している場合は、意図せず不一致と判定されることがあります。
- `git worktree` を使って同一リポジトリの複数ブランチを別ディレクトリにチェックアウトしている場合でも、リポジトリ自体は一致するため通常はteleportできますが、ブランチが異なる場合は別途ブランチの切り替えが必要になることがあります。
- Remote環境やバックグラウンドタスクとの連携については、事前に対象アカウントでのOAuth認証が必要です。
