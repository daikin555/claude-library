## 原文（日本語訳）

保存された履歴に、Anthropic APIが受け付けないツールブロック（通常はサードパーティのAPIプロキシによって書き込まれたもの）が含まれている場合、再開したセッションが毎ターン400エラーで失敗する問題を修正しました。

## 原文（英語）

Fixed resumed sessions failing every turn with a 400 when the saved history contains tool blocks the Anthropic API does not accept (typically written by a third-party API proxy)

## 概要

Claude Codeはセッションを終了・再開する際に、会話履歴をディスクに保存し、次回起動時にそれを読み込んで会話を続行します。サードパーティのAPIプロキシ（例えばAnthropic API互換のゲートウェイなど）を経由して利用している場合、そのプロキシが独自形式のツールブロックを履歴に書き込むことがあり、それをそのままAnthropic APIへ送信すると形式不正として400エラーが返されていました。この問題があると、セッションを再開した瞬間から全てのターンでエラーになり、実質的にセッションが使えなくなっていました。今回の修正でこうした不正なツールブロックが適切に処理され、再開後も正常に会話を継続できるようになりました。

## 基本的な使い方

修正の適用によりユーザー側で特別な操作は不要です。サードパーティプロキシ経由で作業していたセッションを、通常通り再開するだけです。

```bash
claude --resume
# 以前: 保存履歴に不正なツールブロックがあると毎ターン400エラー
# 修正後: 正常に会話が継続する
```

## 実践例

### サードパーティのAPIゲートウェイ利用時のセッション再開

`ANTHROPIC_BASE_URL` などでサードパーティのプロキシ/ゲートウェイを経由してClaude Codeを使っている環境では、そのプロキシが独自のツール呼び出し情報を履歴に混入させることがありました。この修正により、そうした環境でもセッションの再開が安定して機能します。

### 長時間にわたる開発セッションの継続

一度セッションを終了して翌日に `--continue` や `--resume` で作業を再開するようなワークフローで、プロキシ経由の履歴が原因で作業が継続できなくなる事態を回避できます。

### チーム環境でのプロキシ設定の切り替え

プロキシ設定を変更した後に既存セッションを再開する場合でも、履歴内の不正なツールブロックによってブロックされることなく作業を続けられます。

## 注意点

- この問題は主にサードパーティのAPIプロキシを経由している場合に発生していました。Anthropic APIを直接利用している場合は影響が小さい可能性があります
- プロキシ自体が不正な形式のデータを書き込む挙動を修正するものではなく、Claude Code側でそれを受け入れられるようにする対応です
