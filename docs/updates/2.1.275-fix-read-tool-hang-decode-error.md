## 原文（日本語に翻訳）

大きなファイルの一部がメモリ不足によりデコードできなかった場合に、Readツールがエラーを報告せずハングしてしまっていた問題を修正

## 原文（英語）

Fixed the Read tool hanging instead of reporting an error when part of a large file could not be decoded under memory pressure

## 概要

Readツールは大きなファイルを読み込む際、内容をデコードして処理します。これまで、メモリが逼迫している状況下で、ファイルの一部が正常にデコードできない場合に、エラーを返さずにツールがハング（応答不能）してしまう不具合がありました。この状態になるとセッションが実質的に停止してしまいます。今回の修正により、デコードに失敗した場合は適切にエラーが報告されるようになり、ハングを回避できます。

## 基本的な使い方

この修正は内部的なエラーハンドリングの改善であり、通常のRead操作に特別な変更はありません。

```bash
# 大きなファイルを読み込む場合
# メモリが逼迫していても、デコードに失敗した際は
# ハングせずエラーが報告されるようになった
```

## 実践例

### 修正前の挙動

非常に大きなファイル（例えば巨大なログファイルやバイナリに近いテキストファイル）を読み込む際、システムのメモリが逼迫していると、一部のデコード処理が失敗してもツールが応答を返さずハングし、ユーザーはセッションを中断せざるを得ませんでした。

### 修正後の挙動

同様の状況でも、デコードに失敗した場合はハングせずにエラーメッセージが返されるようになり、ユーザーは原因（メモリ不足やファイルのエンコーディング問題）を把握して対処できます。

```bash
# メモリ逼迫時に大きなファイルを読み込んだ場合
# → ハングせず、デコードエラーが明確に報告される
```

## 注意点

- この不具合はシステムのメモリが逼迫している状況下で、かつ非常に大きなファイルを読み込む場合に発生しやすい問題でした
- エラーが報告されるようになった後も、根本的なメモリ不足自体を解消するには、システムリソースの確保やファイルサイズの分割読み込みなどを検討してください
- 通常サイズのファイルやメモリに余裕がある環境では、元々この問題は発生していませんでした
