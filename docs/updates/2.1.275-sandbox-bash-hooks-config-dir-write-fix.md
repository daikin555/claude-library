## 原文（日本語訳）

サンドボックス化されたBashコマンドが、`hooks/` や `config/` という名前のプロジェクトディレクトリに書き込めない不具合を修正しました。

## 原文（英語）

Fixed sandboxed Bash commands being unable to write to project directories named `hooks/` or `config/`

## 概要

Claude Codeのサンドボックス機能は、Bashコマンドの実行範囲を制限してファイルシステムへの意図しない変更を防ぎます。しかし、このサンドボックスの内部実装が、プロジェクト内に `hooks/` や `config/` という名前のディレクトリが存在する場合に、それらをClaude Code自身の内部ディレクトリと混同してしまい、正当なプロジェクトファイルへの書き込みまでブロックしてしまう不具合がありました。今回の修正により、プロジェクト内に同名のディレクトリがあっても正しく書き込みができるようになりました。

## 基本的な使い方

特別な操作は不要です。サンドボックスが有効な状態で、プロジェクト内の `hooks/` や `config/` ディレクトリに対する書き込みを伴うコマンドを実行するだけです。

```bash
mkdir -p hooks
echo "#!/bin/bash" > hooks/pre-commit.sh
```

## 実践例

### プロジェクト内にhooks/ディレクトリを持つリポジトリ

Gitフックやカスタムスクリプトを管理するために `hooks/` という名前のディレクトリを持つプロジェクトでは、修正前はサンドボックス経由のBashコマンドがこのディレクトリへの書き込みを拒否されることがありました。修正後は通常のプロジェクトディレクトリと同様に書き込めます。

```bash
# サンドボックス有効時でも正しく書き込める
cat > hooks/post-checkout.sh << 'EOF'
#!/bin/bash
echo "checked out"
EOF
```

### config/ディレクトリにアプリケーション設定を生成するプロジェクト

Webアプリケーションなどで `config/` ディレクトリに設定ファイルを生成・更新するようなワークフローでも、同様の書き込み拒否が発生していましたが、この修正で解消されています。

```bash
mkdir -p config
echo "APP_ENV=development" > config/app.env
```

## 注意点

- サンドボックスは引き続きプロジェクト外や機密性の高いパスへの書き込みを制限します。今回の修正はあくまでプロジェクト内の正当なディレクトリ名との誤判定を解消するものです。
- サンドボックスの詳細な挙動や設定は、環境やOSによって異なる場合があります。
