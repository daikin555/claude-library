## 原文（日本語訳）

管理設定 `allowManagedPermissionRulesOnly` が有効な場合でも、リポジトリ・ユーザー・`--add-dir` で追加されたスキルやコマンド、スキルディレクトリ型プラグインのマニフェストが、`allowed-tools` を通じて自身のツールを事前承認できてしまっていた不具合を修正しました。

## 原文（英語）

Fixed repository, user and `--add-dir` skills, commands and skills-directory plugin manifests pre-approving their own tools via `allowed-tools` under managed `allowManagedPermissionRulesOnly`

## 概要

これはセキュリティに関わる修正です。管理者が `allowManagedPermissionRulesOnly` を有効にして、権限ルールを管理設定のみに限定しているつもりでも、リポジトリに含まれるスキルやカスタムコマンド、`--add-dir` で追加したディレクトリ内のスキル、あるいはスキルディレクトリ型のプラグインマニフェストが、それぞれのファイル内の `allowed-tools` フィールドを使って自分自身のツール利用を事前承認できてしまう抜け穴がありました。これにより、管理者の意図に反してリポジトリ側が権限を拡張できる可能性がありました。今回の修正でこの抜け穴が塞がれました。

## 基本的な使い方

ユーザー側の対応は不要です。`allowManagedPermissionRulesOnly` を有効にしている環境では、この修正によって権限制限がより厳格に適用されるようになります。

## 実践例

### 信頼できないリポジトリのスキル・コマンドの安全な実行

外部から取得したリポジトリに、意図的にツールを事前承認するよう仕組まれたスキルやコマンドが含まれていても、管理者の権限ポリシーが優先されるようになります。

### プラグインマーケットプレイスからのインストール時の安全性向上

スキルディレクトリ型のプラグインをインストールする際も、`allowManagedPermissionRulesOnly` が有効な組織では、プラグイン側のマニフェストで勝手に権限が拡張されることを防げます。

## 注意点

- この修正は `allowManagedPermissionRulesOnly` を有効にしている組織にのみ関係します。有効にしていない環境では従来通り `allowed-tools` によるスキル・コマンド単位の権限設定が機能します
- 既存のスキルやコマンドが、この修正によって想定していたツール利用が制限されるようになる場合があります。管理者側の許可リストへの追加を検討してください
