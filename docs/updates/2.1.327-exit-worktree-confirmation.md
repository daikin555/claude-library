# ExitWorktree が未保存の作業がある worktree の削除前に確認

## 原文（日本語に翻訳）

`ExitWorktree` が、未保存の作業を含む可能性のある worktree を削除する前に確認するようになりました。確認する相手がいない場合や don't-ask モードでは拒否されます。ただし、allow ルール、auto モード、bypass permissions モードが許可している場合を除きます。

## 原文（英語）

Changed `ExitWorktree` to ask before removing a worktree that may hold unsaved work; refused in don't-ask mode or with nobody to answer, unless an allow rule, auto or bypass permissions mode allows it

## 概要

worktree 内の未コミット変更を誤って失わないよう、削除前に確認が入ります。関連して、Remote Control の worktree モードでサーバー停止時に git-ignored ファイル（`.env` など）が消える問題や、終了時に worktree が残ったことを表示しない問題も修正されました。

## 基本的な使い方

```bash
claude --worktree feature-x
```

作業後に worktree から抜ける際、未保存の変更があれば削除の確認が表示されます。

## 実践例

### 自動化で削除を許可したい場合

```json
{
  "permissions": {
    "allow": ["ExitWorktree"]
  }
}
```

### 変更を残す

確認で拒否し、先にコミットまたは push してから終了します。

## 注意点

- `claude -p` など応答者がいない実行では、allow ルール等がない限り削除は拒否されます。
- 無人運用では、事前に変更をコミットしておくか許可ルールを明示してください。
