## 原文（日本語訳）

一部のUnicodeの特殊な文字列を含むメッセージで、Markdownのレンダリングが極端に遅くなる不具合を修正しました。

## 原文（英語）

Fixed markdown rendering becoming extremely slow for some messages containing unusual Unicode sequences

## 概要

Claude Codeのターミナル出力ではメッセージ内容がMarkdownとして描画されますが、絵文字の結合文字列やゼロ幅文字、特殊な結合文字（Zero Width Joiner）など一部の特殊なUnicodeシーケンスが含まれるメッセージで、Markdownのパース・描画処理が極端に遅延する不具合がありました。この修正により、そうした特殊な文字列を含むメッセージでも描画パフォーマンスが正常な速度に改善されています。

## 基本的な使い方

この修正はパフォーマンス改善であり、特別な操作は不要です。絵文字を多用する応答や、多言語の結合文字を含むコード・テキストをClaudeが出力した場合でも、ターミナルの描画が固まったり極端に遅くなったりしなくなります。

## 実践例

### 絵文字を多用した応答を受け取る場合

```
> プロジェクトの進捗を絵文字たっぷりで教えて
```

以前のバージョンでは複雑な絵文字の組み合わせ（家族の絵文字や国旗の結合絵文字など）を含む応答でターミナルの表示が固まったように見えることがありましたが、修正後はスムーズに描画されます。

### 多言語混在のドキュメントやコードコメントを扱う場合

アラビア語・タイ語などの結合文字を含むテキストや、ゼロ幅文字が混入したコピー&ペースト由来のテキストをClaudeが処理・出力する際も、描画速度への影響が解消されています。

## 注意点

- この不具合はごく一部の特殊な文字列パターンでのみ発生していたため、通常の日本語・英語のやり取りでは体感しにくかった可能性があります
- 大量の絵文字やコピー&ペーストで混入した不可視文字（ゼロ幅スペースなど）を含むログやレビューコメントを扱う場合に、特に改善を実感しやすいです
