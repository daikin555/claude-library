# ~/.claude.json 破損時の起動と復旧の改善

## 原文（日本語訳）

- 非対話起動で、有効なJSONではない `~/.claude.json` をデフォルト値で置き換えてしまう問題を修正しました。起動は失敗し、復元方法が表示され、ファイルはそのまま残ります（anthropics/claude-code#87551）
- バックアップのない空の `~/.claude.json` が破損と報告される問題を修正しました。ファイルがない場合と同様に起動します
- 破損・欠損時に表示される復元コマンドが、空や途中で切れたバックアップを指したり、読み取り専用ファイルで失敗したりする問題を修正しました

## 原文（英語）

- Fixed non-interactive launches replacing a `~/.claude.json` that isn't valid JSON with defaults; the start now fails, says how to restore the file, and leaves it as is (anthropics/claude-code#87551)
- Fixed an empty `~/.claude.json` with no backup being reported as corrupted; Claude Code now starts as it does when the file is missing
- Fixed the restore command printed for a damaged or missing `~/.claude.json` naming an empty or cut-off backup, or failing on a read-only file

## 概要

`~/.claude.json` には信頼済みフォルダやMCPサーバー設定が保存されています。壊れたファイルを黙ってデフォルトで上書きして設定が失われていた挙動が、安全側に改められました。

## 基本的な使い方

壊れたファイルで `claude -p` を実行すると、起動が失敗して復元手順が表示されます。

```bash
claude -p "hello"
# → エラーと復元方法が表示され、~/.claude.json は変更されない
```

## 実践例

### 復旧手順

1. 表示された復元コマンドの内容を確認する
2. バックアップが空でないことを確認してから実行する
3. 再度 `claude -p` を実行して起動を確認する

### CI環境での扱い

自動化環境では、設定が黙って初期化されるより明示的に失敗するほうが原因を追いやすくなります。終了コードを監視してください。

## 注意点

- 破損ファイルは上書きされないため、手動で修正・復元するまで非対話起動は失敗し続けます。
- 復元前にバックアップの中身が正常か確認してください。
