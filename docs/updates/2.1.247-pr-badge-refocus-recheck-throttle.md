## 原文（日本語訳）

プロンプトフッターに表示されるPRバッジについて、直前のチェックから1分未満しか経過していない場合は、ターミナルへのフォーカス復帰時に行われるGitHubの再チェックをスキップするように変更されました。

## 原文（英語）

Changed the prompt-footer PR badge to skip its GitHub re-check on terminal refocus when the last check is under a minute old

## 概要

Claude Codeはプロンプトフッターにプルリクエストの状態（レビュー状況やCIの結果など）をバッジとして表示しており、ターミナルウィンドウにフォーカスが戻るたびにGitHub上の最新状態を再チェックしていました。エディタとターミナルを頻繁に切り替える使い方をしていると、この再チェックが短時間に何度も実行され、不要なAPI呼び出しが発生していました。今回の変更で、直前のチェックから1分未満であれば再チェックをスキップするようになり、無駄なリクエストを減らせます。

## 基本的な使い方

ユーザーが操作することはありません。PRバッジが表示されている状態で、エディタなど他のウィンドウとターミナルを切り替えると、以下のように挙動します。

```
# 1分以内に再度ターミナルへフォーカスを戻した場合
→ GitHubへの再チェックはスキップされ、直前の表示状態が維持される

# 1分以上経過してからフォーカスを戻した場合
→ 通常どおりGitHubへ再チェックが行われ、バッジが更新される
```

## 実践例

### エディタとターミナルを頻繁に切り替える開発フロー

VS CodeなどのエディタとClaude Codeのターミナルを何度も往復しながら作業していると、以前は毎回GitHub APIへのリクエストが発生していました。今回の変更で、短時間の切り替えでは再チェックがスキップされ、不要な通信が抑えられます。

### レート制限が気になるGitHub Enterprise環境

社内のGitHub Enterprise環境などでAPIレート制限がタイトな場合、頻繁なフォーカス切り替えによる再チェックの積み重ねが問題になることがありました。1分間隔のスロットリングにより、この種の負荷が軽減されます。

### 長時間ターミナルを開いたままPRの状態を確認する

PRのCI結果待ちで何度もターミナルとブラウザを切り替えて確認する場面でも、直前のチェック結果が1分以内であればそのまま表示され、更新が必要なタイミングでのみ実際のチェックが行われます。

## 注意点

- 完全にチェックを止めるわけではなく、1分間隔のスロットリングです。1分以上経過すればフォーカス復帰時に通常どおり再チェックされます
- PRバッジ機能自体を無効化する設定ではありません
- 表示中のバッジがわずかに古い情報（最大で約1分前の状態）になる可能性があります
