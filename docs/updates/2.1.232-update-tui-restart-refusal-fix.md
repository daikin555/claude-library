## 原文（日本語に翻訳）

再起動をまたいで継続する処理が実行中の場合に、`/update` と `/tui` が再起動を拒否してしまう不具合を修正しました

## 原文（英語）

Fixed `/update` and `/tui` refusing to restart while work that survives the relaunch was running

## 概要

`/update` コマンドはClaude Code自体を最新版に更新して再起動し、`/tui` はターミナルUIモードを切り替えて再起動します。これまで、バックグラウンドタスクなど再起動後も継続される種類の処理が実行中の場合、これらのコマンドが「作業中なので再起動できない」と誤って判断し、再起動を拒否してしまうことがありました。v2.1.232では、再起動をまたいで安全に継続できる処理であれば、それを実行中でも `/update` や `/tui` が正常に再起動できるように修正されました。

## 基本的な使い方

```bash
# バックグラウンドタスクなどが実行中の状態で更新を実行
> /update

# 修正前: 「作業が実行中です」といったメッセージで再起動が拒否されることがあった
# 修正後: 再起動後も継続可能な処理であれば、そのまま再起動・更新が行われる
```

```bash
# TUIモードを切り替え
> /tui
```

## 実践例

### バックグラウンドタスク実行中にアップデートする

```bash
# 長時間かかるバックグラウンドタスクを起動した直後にアップデートを試みる
> Run the test suite in the background
> /update

# 修正前: バックグラウンドタスクが「実行中の作業」とみなされ再起動が拒否された
# 修正後: バックグラウンドタスクの状態を維持したまま再起動・アップデートが完了する
```

### 作業中にTUIモードを切り替える

```bash
# 何らかの継続処理が動いている状態でUIモードを変更
> /tui

# 修正前: 再起動が必要な /tui コマンドが「作業中」として拒否されるケースがあった
# 修正後: 継続可能な処理はそのまま維持されつつ、TUIモードが切り替わる
```

## 注意点

- Claude Code v2.1.232で修正されたバグ修正です。
- 「再起動後も継続する処理」とは、バックグラウンドタスクなど再起動をまたいで状態を保持できる処理を指し、対話中の応答生成そのものなど再起動で失われる処理はこれまで通り注意が必要です。
- `/update` や `/tui` が理由もなく拒否される場合は、v2.1.232以降へのアップデートで改善が見込めます。
