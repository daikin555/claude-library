## 原文（日本語訳）
`--strict-mcp-config` を空の `--mcp-config` とともに使用すると、関係のないMCPサーバーのために非対話セッションの最初のターンが `MCP_TIMEOUT` の時間まで待たされてしまう問題を修正しました。

## 原文（英語）
Fixed `--strict-mcp-config` with an empty `--mcp-config` holding the first non-interactive turn for up to `MCP_TIMEOUT` on incidental MCP servers

## 概要
`--strict-mcp-config` は、コマンドラインで指定したMCP設定のみを厳密に使用するためのフラグです。このフラグを空の `--mcp-config` と組み合わせて使用した場合、本来は接続すべきMCPサーバーが存在しないはずですが、実際には無関係なMCPサーバーへの接続を試みてしまい、その結果が返るまで最初のターンが `MCP_TIMEOUT` で指定された時間だけ待たされてしまう不具合がありました。今回の修正により、このケースで不要な待機が発生しないようになりました。

## 基本的な使い方
厳密なMCP設定を使いたい場合は、以下のように空の設定と組み合わせて実行します。

```bash
claude -p "タスクを実行" --strict-mcp-config --mcp-config '{}'
```

## 実践例

### 修正前の挙動
`--strict-mcp-config` と空の `--mcp-config` を指定して非対話モードでタスクを実行すると、本来接続すべきでない無関係なMCPサーバーへの接続試行によって、`MCP_TIMEOUT` に設定された時間（デフォルトなど）だけ最初のターンの開始が遅延していました。

### 修正後の挙動
同じ設定で実行すると、無関係なMCPサーバーへの不要な接続待ちが発生せず、最初のターンが速やかに開始されるようになりました。

## 注意点
- `MCP_TIMEOUT` 環境変数はMCPサーバーへの接続タイムアウトを制御します。この値が大きく設定されている環境ほど、修正前の不具合による影響が大きくなっていました。
- CI/CDなど非対話モードでClaude Codeを頻繁に呼び出すパイプラインでは、この修正によって実行時間の短縮が期待できます。
