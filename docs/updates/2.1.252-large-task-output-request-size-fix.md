# 大きな失敗出力を持つバックグラウンドタスク通知がAPIリクエストサイズ上限を超える不具合を修正

## 原文（日本語訳）

非常に大きな失敗出力（例: ディスクフル時のgitエラーなど）を伴うバックグラウンドタスクの通知が、会話をAPIリクエストサイズ上限を超えさせてしまう問題を修正しました。

## 原文（英語）

Fixed background task notifications with very large failure output (for example git errors on a full disk) making the conversation exceed the API request size limit

## 概要

Claude Codeのバックグラウンドタスクが失敗すると、その失敗内容（エラー出力）が会話に通知として挿入されます。しかし、ディスクフルによるgitエラーのように、失敗時の出力が異常に大きくなるケースでは、その通知だけで会話全体がAPIのリクエストサイズ上限を超えてしまい、以降のやり取りができなくなる不具合がありました。2.1.252では、このような巨大な失敗出力が適切に切り詰められる（またはサイズ超過を回避する形で処理される）ようになり、会話が破綻しなくなりました。

## 基本的な使い方

この修正はバックグラウンドタスクの失敗通知処理に関する内部的な修正であり、ユーザーが明示的に操作する項目はありません。通常通りバックグラウンドタスクを実行するだけで、修正の恩恵を受けられます。

```bash
# バックグラウンドでタスクを実行（例: 長時間かかるgit操作）
# Claude Codeに「このコマンドをバックグラウンドで実行して」と依頼
git gc --aggressive
```

タスクが失敗した場合も、会話が壊れることなく失敗内容が通知されます。

```bash
# バックグラウンドタスクの一覧・状態確認
/tasks
```

## 実践例

### 1. ディスク容量が逼迫した環境でのgit操作

CIランナーやローカル開発環境でディスク容量が不足している状態でバックグラウンドのgit操作（`git gc`、大きなリポジトリの`git clone`など）が失敗すると、大量のエラーメッセージが出力されることがあります。今回の修正により、こうした状況でも会話が継続できるようになりました。

```bash
# ディスク容量を確認しておくことでそもそもの失敗を予防
df -h
```

### 2. 大量のログを出力するビルド・テストタスク

ビルドやテストがバックグラウンドで失敗し、大量のスタックトレースやログを標準エラー出力に吐き出すケースでも、通知が会話全体を破綻させることなく処理されます。

```bash
# バックグラウンドでテストを実行
npm test -- --verbose
```

### 3. 長時間実行タスクの失敗を安心して監視できる

出力サイズを気にせずバックグラウンドタスクに大きな処理を任せられるようになるため、開発サーバーの監視やビルドパイプラインの実行など、失敗時に大量ログを出しがちなワークフローでも安心して利用できます。

## 注意点

- 失敗出力が非常に大きい場合、通知内では出力が切り詰められて表示されることがあります。完全なログを確認したい場合は、タスクの詳細表示やログファイルを直接参照してください。
- この修正はAPIリクエストサイズ上限（リクエスト全体のバイトサイズ制限）に起因する問題への対処であり、通常のトークン数ベースのコンテキスト超過（会話が長くなった場合の自動コンパクション）とは別の問題です。
- 根本原因（例: ディスクフル）そのものは解消されないため、繰り返しタスクが失敗する場合は環境側の問題（ディスク容量など）も確認してください。
