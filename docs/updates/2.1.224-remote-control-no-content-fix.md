## 原文（日本語訳）

`/clear` などの出力を伴わないコマンドの実行後に、Remote ControlおよびSDKクライアントで空の「(no content)」メッセージが表示される問題を修正しました。

## 原文（英語）

Fixed Remote Control and SDK clients showing a blank "(no content)" message after `/clear` and other output-less commands

## 概要

`/clear` のように、実行してもチャット欄に何もテキストを返さないコマンドがあります。ローカルのターミナルUIではこれらのコマンドは違和感なく処理されますが、Remote Control経由で接続したモバイル・Webクライアントや、Claude Agent SDKを使ったクライアントでは、出力が存在しないメッセージに対して空の「(no content)」という表示が出てしまい、あたかもエラーや不具合が起きたかのように見えることがありました。今回の修正で、出力を伴わないコマンドの結果が正しく扱われるようになり、この不要な表示が解消されました。

## 基本的な使い方

Remote Controlで接続したクライアントやSDK経由のクライアントから、通常通りスラッシュコマンドを実行できます。

```bash
# Remote Control経由で接続したモバイルアプリ・Webクライアントから
/clear

# SDKクライアントからも同様にコマンドを送信可能
```

## 実践例

### 修正前に起きていた問題

Remote Controlでスマートフォンやブラウザから接続し、コンテキストをリセットするために `/clear` を実行すると、会話履歴のクリア自体は正しく行われるものの、クライアントの画面には以下のような空のメッセージが1件表示されていました。

```text
> /clear

(no content)
```

これは `/clear` に限らず、目に見える出力を返さない他のコマンドでも同様に発生しており、SDKを使ってカスタムクライアントを構築している場合も、レスポンスの一部として意味のない「(no content)」を含むメッセージを受け取る形になっていました。

### 修正後の挙動

出力を伴わないコマンドの実行結果が正しくハンドリングされるようになり、Remote Controlのクライアントやチャット欄に不要な「(no content)」メッセージが表示されなくなりました。

```text
> /clear

# 会話履歴がクリアされるのみで、
# 無意味な「(no content)」メッセージは表示されない
```

SDKを利用している場合も、出力のないコマンド実行時に空のコンテンツを持つメッセージオブジェクトが返されることがなくなり、クライアント側での不要なハンドリングが不要になります。

## 注意点

- この修正はRemote Control経由のクライアントおよびClaude Agent SDKを利用するクライアントに影響します。ローカルターミナルUIの表示自体は元々問題ありませんでした
- SDKでカスタムクライアントを実装している場合、以前は「(no content)」のような空メッセージを画面に表示しないようフィルタリングする実装をしていたケースがあるかもしれません。アップデート後はそうした回避策が不要になります
- 併せて、Remote Controlでは `/clear` によるリセットが接続中のクライアントにも正しく伝播するよう改善されています
