## 原文（日本語訳）

管理設定（managed settings）の取得元とポリシーヘルパーの状態を記録する `claude_code.managed_settings_resolved` OTelイベントを追加しました。`OTEL_LOG_MANAGED_SETTINGS=1` を指定すると、マスクされた設定値とそのダイジェストも記録されます。

## 原文（英語）

Added `claude_code.managed_settings_resolved` OTel event: managed-settings sources and policy helper state; redacted settings and digests with `OTEL_LOG_MANAGED_SETTINGS=1`

## 概要

企業のIT部門はmanaged settings（管理設定）を通じてClaude Codeの挙動を組織全体で統制しています。新しい `claude_code.managed_settings_resolved` イベントにより、どの設定ソースが実際に適用されたか、ポリシーヘルパーの状態がどうなっているかをOpenTelemetry経由で可視化できるようになりました。`OTEL_LOG_MANAGED_SETTINGS=1` を設定すれば、マスク済みの設定内容とそのダイジェスト（ハッシュ値）も併せて記録され、設定の一貫性を監査できます。

## 基本的な使い方

```bash
export CLAUDE_CODE_ENABLE_TELEMETRY=1
export OTEL_LOGS_EXPORTER=otlp
export OTEL_LOG_MANAGED_SETTINGS=1
claude
```

これにより、`claude_code.managed_settings_resolved` イベントに管理設定のソース一覧、ポリシーヘルパーの状態、マスク済み設定値とダイジェストが含まれるようになります。

## 実践例

### 管理設定の適用状況の監査

IT管理者は、社内の複数の設定ソース（グローバルポリシー、組織デフォルトなど）のうち、どれが実際にエンドユーザーの環境で有効になっているかをOTelログで確認し、意図しない設定の欠落がないかを検証できます。

### 設定変更のドリフト検知

`OTEL_LOG_MANAGED_SETTINGS=1` で記録されるダイジェストを定期的に収集し、以前の値と比較することで、意図しない管理設定の変更（ドリフト）を検知するパイプラインを構築できます。

## 注意点

- `OTEL_LOG_MANAGED_SETTINGS=1` を指定しない場合、設定の中身は記録されず、ソースとポリシーヘルパーの状態のみが記録されます。
- 設定値はマスク（redacted）された形で記録されるため、機密情報がそのままログに出力されるわけではありませんが、社内のログ取り扱いポリシーに従って保管してください。
- このイベントは主にEnterprise環境でmanaged settingsを利用している組織向けの機能です。
