## 原文（日本語訳）

SendMessageで別マシンのリモートコントロールセッションに名前を指定して会話を開始できるようになりました（ListAgentsに`name [ref]`として表示されます）。従来は相手から最初にメッセージを受け取った後にしか返信できませんでしたが、これで主動的に会話を開始できます。

## 原文（英語）

SendMessage can now start a conversation with your Remote Control sessions on other machines by name (`ListAgents` shows them as `name [ref]`), instead of only replying after they message you first

## 概要

Claude Code 2.1.225では、クロスセッションメッセージング機能が拡張されました。別マシンで動作しているリモートコントロールセッションに対して、名前を指定して主動的にメッセージを送信できるようになった重要なアップデートです。従来は別マシンのセッションから最初にメッセージを受け取った後に返信することしかできませんでしたが、これからは任意のタイミングで会話を開始できます。これにより、マシン間での協調作業がより柔軟で効率的になります。

## 基本的な使い方

別マシンで動作中のセッションに主動的にメッセージを送信する場合、まず`/list-agents`（または`/peers`）コマンドで利用可能なセッション一覧を確認します。

```text
/list-agents
```

このコマンド実行時に、Remote Controlで接続されている別マシンのセッションが`name [ref]`という形式で表示されます。例えば以下のように表示される場合があります：

```
Local sessions:
  myapp-3f (~/projects/myapp)
  data-pipeline-1a (~/projects/data)

Remote Control sessions:
  work-laptop [ref-abc123]
  gaming-pc [ref-def456]
```

表示されたセッション名に対して、Claude にメッセージを送るよう指示します：

```text
別のマシンで動作中の work-laptop セッションに、現在のデータベーススキーマの変更状況を知らせてほしい
```

Claude がメッセージ内容を判断し、自動的に該当セッションに送信します。

## 実践例

### ノートパソコンでの作業中に、デスクトップマシンのセッションに進捗確認を送信

複数マシンで異なるプロジェクトを並行開発している場合、ノートパソコンのセッションからデスクトップマシン上の長時間実行タスク（大規模なテスト、データ処理など）の進捗を確認できます。

```text
desk-ubuntu セッションに、データマイグレーションが完了したかどうか確認してほしい
```

デスクトップマシンで動作中のセッションが、その時点での状態を返答します。これにより、別のマシンで作業を続けながら、進捗確認を非同期で行えます。

### 関連タスクを処理している2台のマシン間で結果を共有

複数マシンの git worktree で同じリポジトリを開発している場合、一方のマシンで重要な決定事項や変更内容をもう一方のマシンで動作中のセッションに直接通知できます。

```text
work-laptop セッションに、スキーママイグレーションが完了したこと、新しいカラム名が tenant_id であること、main ブランチへのリベースが安全であることを伝えてほしい
```

このように主動的にメッセージを送信することで、マシン間での協調開発がより効率的になり、重要な情報の伝達遅延を防げます。

## 注意点

- **リモートコントロール接続が必須**: 別マシンのセッションにメッセージを送信するには、送信元のマシンで Remote Control 接続が確立されている必要があります
- **対応OS**: macOS と Linux でのみ利用可能です。Windows での cross-session messaging はサポートされていません
- **セッション識別**: 複数マシンで同じ名前のセッションがある場合、`[ref]` サフィックスで識別されます。メッセージ送信時は Claude が適切なセッションに送信します
- **プレーンテキストのみ**: セッション間で送信されるのはプレーンテキストのみです。会話履歴やファイルは含まれません
- **権限の独立性**: リモートセッション間のメッセージ送信も権限チェックの対象となります。受信側セッションの権限設定により、メッセージの配信が制限される場合があります
- **セキュリティ**: `isolatePeerMachines` 設定で、別マシンへのメッセージ送信を承認制にすることができます
