## 原文（日本語訳）

Claude appsゲートウェイの設定に `store.connect_timeout_seconds` を追加し、Postgresへの接続タイムアウト（デフォルト5秒）を延長できるようにしました。また、データベースに接続できない場合の起動エラーメッセージを改善し、`store.postgres_url` と設定されているタイムアウト値を案内するようにしました。

## 原文（英語）

Added `store.connect_timeout_seconds` to the Claude apps gateway config to lengthen the Postgres connect timeout (default 5 seconds), and improved the boot error when the database is unreachable to point to `store.postgres_url` and the configured timeout

## 概要

Claude appsゲートウェイはバックエンドストアとしてPostgresを利用しており、ネットワーク遅延の大きい環境やレイテンシの高いマネージドDBに接続する場合、デフォルトの5秒という接続タイムアウトでは不十分なことがありました。今回追加された `store.connect_timeout_seconds` 設定により、この接続タイムアウトを環境に応じて延長できるようになり、あわせてデータベースに接続できなかった場合の起動時エラーメッセージも、原因箇所（`store.postgres_url` と設定中のタイムアウト値）を明示するように改善されました。

## 基本的な使い方

```yaml
# claude apps gateway の設定ファイル例
store:
  postgres_url: "postgres://user:pass@db.internal:5432/claude_apps"
  connect_timeout_seconds: 15
```

## 実践例

### レイテンシの高いマネージドPostgresへの接続

クラウドプロバイダーのマネージドPostgres（特にリージョンをまたぐ構成）では、デフォルトの5秒でタイムアウトしてしまうことがあります。`connect_timeout_seconds` を15〜30秒程度に延長することで、起動時の接続失敗を回避できます。

```yaml
store:
  connect_timeout_seconds: 30
```

### 接続失敗時のトラブルシューティング

データベースに到達できない場合、起動エラーに `store.postgres_url` と現在設定されているタイムアウト値が表示されるようになったため、設定ミスなのかネットワーク到達性の問題なのかを迅速に切り分けられます。

## 注意点

- タイムアウトを長く設定しすぎると、データベースが本当に到達不能な場合にゲートウェイの起動失敗を検知するまでの時間が延びます。環境に応じて妥当な値を設定してください。
- この設定はClaude appsゲートウェイ（自己ホスト型のエンタープライズ構成）向けであり、通常のCLI利用には影響しません。
