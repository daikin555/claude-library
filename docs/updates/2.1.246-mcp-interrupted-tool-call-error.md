## 原文（日本語訳）

ヘッドレス／リモートセッションにおいて、着信メッセージによって中断されたMCPツール呼び出しが、モデルに対して明示的な中断エラーではなく「出力なしで完了」と報告されてしまう問題を修正しました。

## 原文（英語）

Fixed MCP tool calls interrupted by an incoming message in headless/remote sessions being reported to the model as "completed with no output" instead of an explicit interrupted error

## 概要

ヘッドレスモードやリモートセッションでClaude Codeを運用している際、実行中のMCPツール呼び出しに新しいメッセージが割り込んで中断されるケースがあります。従来はこの中断が正しく検知されず、モデルには「ツールは正常に完了したが出力がなかった」という誤解を招く情報が渡されていました。この修正により、中断が発生した場合はその旨が明示的なエラーとしてモデルに伝わるようになり、モデルが誤った前提（ツールが成功した）で以降の判断を続けてしまう問題が解消されます。

## 基本的な使い方

この修正はランタイムの内部挙動に関するもので、ユーザー側で有効化する設定はありません。ヘッドレス/リモートセッションでMCPツールを呼び出している最中に別のメッセージが割り込んだ場合、以降は次のような動作になります。

```
[ツール実行前] MCPツール "search_database" を呼び出し中...
[割り込みメッセージ受信]
[修正後] エラー: ツール呼び出しは着信メッセージにより中断されました
[修正前] （誤り）ツールは完了しましたが出力はありませんでした
```

## 実践例

### CI/CDパイプラインでのヘッドレス実行

CIジョブの中でClaude Codeをヘッドレスモードで実行し、MCP経由で外部APIやデータベースにアクセスするワークフローでは、途中で別のトリガー（新しいコミットや通知）によりセッションにメッセージが割り込むことがあります。この修正により、中断が発生した箇所を正確に特定でき、誤って「成功した」と判断されたまま処理が進むことを防げます。

### リモートエージェントの並行タスク管理

複数のリモートセッションを並行して動かし、必要に応じて追加の指示を送るような運用では、MCPツール呼び出し中に指示メッセージが届くことがあります。中断が明示的に報告されるため、モデルは中断されたツール呼び出しをリトライするか、状況を踏まえて別のアプローチを取るかを正しく判断できます。

### 長時間実行するMCPツールのデバッグ

外部システムへの問い合わせなど時間のかかるMCPツール呼び出しが途中で中断された場合、これまでは「出力なし」という不透明な結果しか得られませんでしたが、修正後は中断であることが明示されるため、デバッグ時にツール自体の不具合と中断による影響を区別しやすくなります。

## 注意点

- この修正はヘッドレス／リモートセッションでのMCPツール呼び出しに関するものです。通常の対話型セッションには直接影響しません
- ユーザー側での設定変更は不要で、Claude Codeのアップデートにより自動的に適用されます
- モデルが中断を認識できるようになったことで、リトライや代替手段の提案といった振る舞いが改善されます
