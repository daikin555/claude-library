## 原文（日本語訳）

権限プレビューが、受信トラストゲートで許可されたチャンネルサーバーにのみ中継されるように修正しました。また、サーバーが明示的に権限機能をオプトアウトしている場合は、それが尊重されるようになりました。

## 原文（英語）

Fixed: permission previews now relay only to channel servers admitted by the inbound trust gate, and a server's explicit permission-capability opt-out is honored

## 概要

Claude CodeのChannels機能では、Telegram・Discord・iMessageなどのMCPサーバー（チャンネル）を通じて、ターミナルから離れた場所でも権限プロンプトを確認・承認できる「権限リレー（permission relay）」機能があります。今回の修正前は、権限プレビュー（プロンプトの内容）が、本来は受信を許可されていないはずのチャンネルサーバーにも中継されてしまうことがあり、また一部のサーバーが権限機能を明示的に無効化（オプトアウト）していても、その設定が無視されることがありました。修正後は、`--channels` で有効化され、かつ送信者の許可リスト（トラストゲート）を通過したサーバーにのみ権限プレビューが中継されるようになり、サーバー側のオプトアウト設定も正しく尊重されます。

## 基本的な使い方

Channels経由での権限リレー自体の使い方に変更はありません。`--channels` でチャンネルを有効にしたセッションでは、ターミナルから離れていても、権限プロンプトが許可済みのチャンネル経由で届きます。

```bash
claude --channels plugin:telegram@claude-plugins-official
```

Claudeが権限を要求する操作を行おうとすると、許可済みチャンネル（送信者の許可リストを通過したもの）にプレビューが中継され、そこから承認・却下できます。

## 実践例

### 許可されていないチャンネルサーバーが接続されている場合

複数のチャンネルプラグインを同時に有効化しているが、一部のプラグインの送信者がまだ許可リスト（ペアリング）を完了していないケースです。

```bash
claude --channels plugin:telegram@claude-plugins-official plugin:discord@claude-plugins-official
```

```
# 修正前: Telegram側の送信者がまだペアリング未完了でも、
#         権限プレビューの内容がそのサーバーへ漏れて中継されることがあった
# 修正後: トラストゲート（許可リスト）を通過したサーバーにのみ
#         権限プレビューが中継される
```

### 権限リレーをオプトアウトしているサーバーを使う場合

自作、またはサードパーティのチャンネルサーバーが、権限機能（permission-capability）を明示的にオプトアウトしている場合です。

```
# サーバー側でpermission relay capabilityを無効化している
# 修正前: オプトアウト設定にもかかわらず権限プレビューが送られてしまうことがあった
# 修正後: サーバーのオプトアウト設定が尊重され、権限プレビューは中継されない
```

### 社内向けチャンネルプラグインを運用している場合

組織が `allowedChannelPlugins` で独自のチャンネルプラグインを許可リストに追加して運用しているケースでは、この修正により、意図しないサーバーへ権限プロンプトの内容（コマンドやファイルパスなど機微な情報を含みうる）が流出するリスクが減少します。

## 注意点

- 権限リレーは、チャンネルがその機能（permission relay capability）を宣言している場合にのみ有効です
- 送信者の許可リストは、権限リレーの可否にも影響します。信頼できる送信者のみを許可リストに追加してください
- `--channels` に指定するプラグインは、Anthropicが管理する許可リスト、または組織の `allowedChannelPlugins` 設定に含まれるものに限られます
- 本機能はリサーチプレビュー段階であり、今後仕様が変更される可能性があります
