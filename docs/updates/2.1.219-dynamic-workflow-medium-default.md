## 原文（日本語に翻訳）

Dynamic workflow（動的ワークフロー）のデフォルトを「medium」サイズのガイドラインに変更しました（目安としてエージェント数15未満を目指します）。`/config` の「Dynamic workflow size」から、別のサイズや制限なし（unrestricted）を選択することもできます。

## 原文（英語）

Changed dynamic workflows to default to a medium size guideline (aim for fewer than 15 agents); pick another size or unrestricted with Dynamic workflow size in `/config`

## 概要

Claude CodeのDynamic Workflow機能は、複雑なタスクを複数のサブエージェントに分割してオーケストレーションする仕組みです。今回のアップデートでは、生成されるワークフローの規模を制御する「Dynamic workflow size」ガイドラインのデフォルト値が「medium」（エージェント数15未満を目安とする）に変更されました。これにより、特に設定を変更していないユーザーでも、過度に肥大化したワークフローが生成されにくくなり、トークン消費量やレビューのしやすさとのバランスが取れたオーケストレーションがデフォルトの挙動になります。

## 基本的な使い方

デフォルトでは何も設定する必要はありません。Dynamic Workflowを使うタスク（例えば複数の調査・実装・検証ステップを含む大きめの依頼）をClaude Codeに投げると、自動的に「medium」ガイドライン（目安15エージェント未満）に沿ったワークフローが計画・実行されます。

サイズを変更したい場合は `/config` を開き、「Dynamic workflow size」の項目から選択します。

```
/config
> Dynamic workflow size
  - small
  - medium (default)
  - large
  - unrestricted
```

選択するとその場でセッションに反映され、以降のDynamic Workflow生成に適用されます。

## 実践例

### medium（デフォルト）を使う: 通常規模の複数ステップタスク

特に設定変更は不要です。例えば「複数ファイルにまたがるリファクタリングを行い、テストを実行し、変更点をレビューしてほしい」といった依頼では、mediumガイドラインのもとで15エージェント未満を目安に、調査・実装・検証といった役割に応じたサブエージェントが適度な粒度で構成されます。トークン消費とオーケストレーションの網羅性のバランスが取れており、多くのタスクではデフォルトのままで十分です。

### small に切り替える: 素早く軽量に済ませたいタスク

`/config` から「Dynamic workflow size」を `small` に変更すると、生成されるエージェント数がさらに絞り込まれます。

```
/config
> Dynamic workflow size
  - small を選択
```

小規模な修正や、レビューのしやすさ・実行速度・トークンコストを優先したい場面（CI上での軽量タスクや、単純なバグ修正など）に向いています。エージェント数が少ない分、オーケストレーションの網羅性は下がりますが、意図を追いやすく無駄なコストを抑えられます。

### unrestricted に切り替える: 大規模・網羅的な調査やマイグレーション

大規模なモノレポ全体の調査、広範なマイグレーション作業、多数のサブシステムを横断する複雑なタスクでは、15エージェント未満という目安が制約になることがあります。この場合は `/config` から「Dynamic workflow size」を `unrestricted` に変更します。

```
/config
> Dynamic workflow size
  - unrestricted を選択
```

エージェント数の目安上限がなくなるため、タスクの複雑さに応じてより多くのサブエージェントを動員した網羅的なオーケストレーションが可能になります。ただし、トークン消費量やレビューの負荷は増える点に注意してください。

## 注意点

- 「medium」の「15エージェント未満」はあくまで目安（guideline）であり、厳密な上限として強制されるものではありません。
- サイズ設定は `/config` から変更した後、同じ値を設定ファイルの `workflowSizeGuideline` キーで指定することも可能です（`/config` からの変更はこのキーに反映されます）。
- サイズを大きく（`unrestricted` など）すると、生成されるサブエージェントが増えるためトークン消費量とレビュー負荷が増加します。タスクの規模に見合った設定を選ぶことが推奨されます。
- 設定はセッションまたはプロジェクト単位で保持されるため、頻繁に大規模タスクを扱う場合は事前に `unrestricted` や `large` に切り替えておくと、毎回 `/config` を開く手間を省けます。
