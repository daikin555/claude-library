## 原文（日本語訳）

Claudeが作業中であっても `/permissions` を開けるようになりました。変更したルールは、現在進行中のターン（残りの処理）から即座に適用されます。

## 原文（英語）

`/permissions` can now be opened while Claude is working — rule changes apply to the rest of the current turn

## 概要

これまで `/permissions` コマンドはClaudeが処理を終えて入力待ちの状態でないと開けませんでした。今回の変更により、Claudeがツールを実行するなどして作業中でも `/permissions` を開いてパーミッションルールを確認・変更できるようになりました。変更したルールは、現在実行中のターンの残りの処理からすぐに反映されます。

## 基本的な使い方

Claudeが作業中（ツール実行中など）でも、いつでも `/permissions` と入力してパーミッション設定画面を開けます。

```
> /permissions
```

画面上でallow/deny/askルールを追加・編集し、閉じると、現在のターンの以降の処理から新しいルールが適用されます。

## 実践例

### 想定外のコマンド実行を途中で制限する

Claudeが長時間のタスクを実行中に、特定のディレクトリへの書き込みを許可したくないことに気づいた場合、作業を中断せずに `/permissions` を開いて `deny` ルールを追加すれば、その場から新しいルールが適用されます。

```
/permissions
> Bash(rm -rf:*) を deny に追加
```

### 作業中に安全な操作の許可を先回りして追加する

Claudeが一連のリファクタリングタスクを進めている最中、この先必要になりそうな `npm test` の実行を都度確認されるのが煩わしい場合、作業を止めずに `/permissions` からallowルールを追加しておけば、以降の確認プロンプトを減らせます。

### 長時間タスクの途中でルールを見直す

`/goal` などで長時間の自律タスクを実行させている際、進行状況を見ながら必要に応じてパーミッションを調整でき、タスク完了までルール変更のためだけに作業を止める必要がなくなりました。

## 注意点

- ルール変更が適用されるのは「現在のターンの残りの処理」からです。すでに実行済みのツール呼び出しには遡って適用されません
- 恒久的なルール変更（`.claude/settings.json` などへの保存）を行う場合は、保存の挙動は従来と同様です
- 誤ってルールを変更すると、実行中のタスクの挙動に影響する可能性があるため、特にdenyルールの追加は内容をよく確認してから行ってください
