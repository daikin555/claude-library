## 原文（日本語訳）

トランスクリプトに破損したメッセージエントリが含まれる会話を再開したときのクラッシュ、およびそのような会話が上にスクロールした状態で新しいメッセージを受信したときのフルスクリーンクラッシュを修正しました。

## 原文（英語）

Fixed a crash when resuming a conversation whose transcript contains a malformed message entry, and a fullscreen crash when such a conversation received new messages while scrolled up

## 概要

Claude Codeは会話履歴（トランスクリプト）をローカルファイルとして保存し、`--resume` や `--continue` で以前のセッションを再開できます。しかし、何らかの理由でトランスクリプトファイル内のメッセージエントリが破損していると、再開処理がクラッシュしてしまう不具合がありました。さらに、フルスクリーン表示でスクロールバックした状態のまま新しいメッセージを受け取った場合にも同様のクラッシュが発生していました。今回の修正により、破損したエントリがあってもクラッシュせずに会話を再開できるようになりました。

## 基本的な使い方

この修正はバグ修正であり、ユーザー側で特別な操作は不要です。通常どおりセッションを再開するだけで、修正の恩恵を受けられます。

```bash
claude --resume
```

## 実践例

### 破損したトランスクリプトでの再開

以前は、途中でクラッシュしたセッションなどが原因でトランスクリプトファイルに不完全なメッセージエントリが残ることがあり、そのセッションを再開しようとするとClaude Code自体がクラッシュしていました。

```bash
# 修正前: 破損したエントリを含むセッションを再開するとクラッシュすることがあった
claude --resume <session-id>

# 修正後: 破損したエントリがあっても安全に再開できる
claude --resume <session-id>
```

### フルスクリーンでスクロール中に新規メッセージを受信

フルスクリーンモードで過去の会話をスクロールして見ている最中に、バックグラウンドで新しいメッセージ（サブエージェントの出力など）が到着すると、修正前はクラッシュが発生することがありました。修正後はスクロール位置を保ったまま安全にメッセージを受信できます。

## 注意点

- 破損したメッセージエントリ自体が自動的に修復されるわけではなく、あくまで「クラッシュしない」ようになった点に注意してください。
- 万一再開時に異常な動作を感じた場合は、`claude --resume` で別のセッションを選び直すことも検討してください。
