## 原文（日本語訳）

`listChanged` を宣言していないMCPサーバーが変更通知（list-changed notifications）を送信しても、MCPのプロンプトやリソースが更新されない問題を修正しました。

## 原文（英語）

Fixed MCP prompts and resources not refreshing when a server sends list-changed notifications without declaring `listChanged`

## 概要

MCPプロトコルでは、サーバーが自身のcapabilities（機能）として `listChanged` をサポートしていることを宣言した上で、プロンプトやリソースの一覧が変化した際に通知を送る仕組みになっています。しかし一部のMCPサーバーは、capabilitiesとして `listChanged` を明示的に宣言していないにもかかわらず、実際には変更通知を送信してくることがあり、これまではその通知が無視されてしまい、Claude Code側のプロンプト・リソース一覧が古いまま更新されませんでした。今回の修正で、このようなケースでも通知を正しく処理し、一覧が最新の状態にリフレッシュされるようになりました。

## 基本的な使い方

この修正はMCPクライアント側（Claude Code）の内部動作の修正であり、ユーザー側での設定変更は不要です。対象のMCPサーバーに接続していれば、自動的に恩恵を受けられます。

```
/mcp
```

上記のコマンドで、接続中のMCPサーバーが提供するプロンプトやリソースの一覧を確認できます。

## 実践例

### サーバー側でプロンプトが動的に追加・削除される場合

開発中のMCPサーバーで、`listChanged` の宣言が漏れたまま通知だけを送信しているようなケースでも、Claude Code側のプロンプト一覧が自動的に更新されるようになりました。

### リソース一覧が動的に変わるMCPサーバーとの連携

ファイルシステムやデータベースの状態に応じてリソース一覧が変化するMCPサーバーを利用している場合、修正後はその変化がより確実にClaude Code側の一覧へ反映されます。

## 注意点

- サーバー側が変更通知自体を一切送信しない場合は、引き続き一覧が自動更新されません。その場合はセッションの再接続などが必要になることがあります。
- MCPサーバーを自作する場合は、本来は capabilities で `listChanged` を正しく宣言することが推奨されます。
