## 原文（日本語に翻訳）

セッションの履歴に不正な形式のdiagnostics（診断情報）添付ファイルが含まれていた場合、resumeしたセッションのすべてのターンが失敗したり、対話型アプリが応答しないエラー画面のまま固まったりする不具合を修正しました。

## 原文（英語）

Fixed a resumed session failing every turn, or leaving the interactive app on an unresponsive error screen, when its history held a malformed diagnostics attachment

## 概要

Claude Codeは、エラー発生時などにdiagnostics（診断情報）をメッセージへの添付ファイルとして会話履歴に保存することがあります。これまで、この添付ファイルの形式が何らかの理由で壊れている（malformed）と、そのセッションを `--resume` や `--continue` で再開した際に、以降のすべてのターンでリクエストが失敗する、またはインタラクティブなTUIアプリが応答しないエラー画面のまま操作不能になるという問題がありました。今回の修正により、不正なdiagnostics添付ファイルが履歴に含まれていても、セッションを正常にresumeできるようになりました。

## 基本的な使い方

過去のセッションを再開する際は、`--continue` または `--resume` を使います。

```bash
# 直近のセッションをそのまま再開
claude --continue
```

```bash
# セッション一覧から選んで再開
claude --resume
```

resumeがうまくいかない場合は、デバッグログを取得して原因を確認できます。

```bash
claude --resume --debug > debug-resume.log 2>&1
```

## 実践例

### エラーが発生した過去のセッションを再開して調査を続ける

以前のセッションでエラーが発生し、その内容がdiagnosticsとして履歴に保存されているケースで、続きの作業を行いたい場合です。

```bash
claude --continue
```

修正前は、このdiagnostics添付ファイルの形式が壊れていると、resume後のすべてのターンが失敗し、作業を続行できませんでした。修正後は正常にresumeでき、履歴を踏まえた続きのやり取りが可能になります。

### 対話型アプリが固まった場合の復旧手順

resume直後にTUIアプリが応答しなくなった場合、まずアプリを終了し、`--debug` フラグ付きで再度起動してログを確認します。

```bash
claude --resume --debug > debug-2.1.223.log 2>&1
```

ログに `diagnostics` や `attachment` 関連のパースエラーが出力されていないか確認し、出力されていれば本修正の対象だった可能性が高いといえます。

### 複数の古いセッションを棚卸しして問題がないか確認する

過去に不安定だったセッションがいくつかある場合、アップデート後にそれぞれ再開して問題なく動作するかをまとめて確認します。

```bash
claude --resume
# セッション一覧から順番に選択して動作確認
```

## 注意点

- 本修正はセッション履歴に不正なdiagnostics添付ファイルが「すでに含まれている」場合の復旧に関するものです。今後diagnosticsが生成される過程自体の不具合を修正するものではない可能性があります。
- resume後も同様の問題が再発する場合は、`claude --debug` で取得したログを添えてGitHub Issuesに報告することが推奨されます。
- 重要なセッション履歴がある場合は、アップデート前に `~/.claude` 配下のセッションデータをバックアップしておくと安心です。
