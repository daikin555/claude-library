## 原文（日本語に翻訳）

stream-jsonにネストしたサブエージェントの転送機能を追加しました。`--forward-subagent-text` を設定している場合、depth-2以降で生成されたサブエージェントの出力も表示されるようになり、それぞれの出力はそれを生成した親のAgentツール呼び出し（`tool_use` id）をキーとして紐づけられます。

## 原文（英語）

Added nested subagent forwarding in stream-json: subagents spawned at depth-2+ now appear when `--forward-subagent-text` is set, keyed by their spawning Agent `tool_use` id

## 概要

Claude Codeのサブエージェント機能では、サブエージェントがさらに別のサブエージェントを呼び出す「ネスト」が可能です。ヘッドレスモードで `--output-format stream-json` と `--forward-subagent-text` を併用すると、サブエージェントのテキスト出力をストリームに転送できますが、これまではdepth 1（親から直接呼ばれたサブエージェント）の出力しか転送されませんでした。今回のアップデートにより、depth 2以降のネストしたサブエージェントの出力も転送されるようになり、各出力イベントを生成した親のAgentツール呼び出しIDに紐づけて識別できるようになりました。

## 基本的な使い方

```bash
claude -p "大規模なリファクタリングを計画して各サブエージェントに委任して" \
  --output-format stream-json \
  --forward-subagent-text
```

これだけで、depth 1だけでなく、depth 2以降でスポーンされたネストしたサブエージェントのテキスト出力もJSONストリームに含まれるようになります。

## 実践例

### 深くネストしたマルチエージェントのオーケストレーションを追跡する

たとえば「調査エージェント」が「実装エージェント」を呼び出し、その実装エージェントがさらに「テストエージェント」を呼び出すような3階層構成の場合、以下のようなイベントがストリームに流れます。

```bash
claude -p "調査してから実装し、テストまで行って" \
  --output-format stream-json \
  --forward-subagent-text \
  --verbose > run.jsonl
```

出力の一部（depth 2のサブエージェントの出力）は次のようになります。

```json
{
  "type": "assistant",
  "subagent_depth": 2,
  "parent_tool_use_id": "toolu_01Agent7f3kQZ9mN2xVh",
  "message": {
    "role": "assistant",
    "content": [
      {
        "type": "text",
        "text": "テストスイートを実行しています。失敗した3件を修正しました。"
      }
    ]
  },
  "session_id": "sess_9f2a"
}
```

`parent_tool_use_id` が、このdepth-2サブエージェントを生成した親（depth-1の実装エージェント）側の `Agent` ツール呼び出しの `tool_use` idと一致しているため、どの親がどの子を生成したかを正確に追跡できます。

### `jq` で特定の親サブエージェントの子出力だけを抽出する

CIログや監査目的で、特定のAgentツール呼び出しから派生した子サブエージェントの出力だけを絞り込みたい場合は、`parent_tool_use_id` でフィルタします。

```bash
cat run.jsonl | jq -c \
  'select(.parent_tool_use_id == "toolu_01Agent7f3kQZ9mN2xVh")'
```

さらに、depthごとにグルーピングして階層構造を可視化することもできます。

```bash
cat run.jsonl | jq -s '
  group_by(.parent_tool_use_id) |
  map({parent: .[0].parent_tool_use_id, count: length})
'
```

### オーケストレーションのデバッグ用にツリー表示する

深いネストで問題が起きた際、どのdepthのどのサブエージェントが何を出力したかをまとめて確認したい場合は、`subagent_depth` と `parent_tool_use_id` を組み合わせて表示すると見通しが良くなります。

```bash
cat run.jsonl | jq -r '
  select(.type == "assistant" and .subagent_depth != null) |
  "[depth=\(.subagent_depth)] parent=\(.parent_tool_use_id // "root"): \(.message.content[0].text // "")"
'
```

```
[depth=1] parent=toolu_01Orch3str8aRootXY: 実装エージェントを起動しました。
[depth=2] parent=toolu_01Agent7f3kQZ9mN2xVh: テストスイートを実行しています。失敗した3件を修正しました。
[depth=3] parent=toolu_01Agent7f3kQZ9mN2xVh: サブテストAgentを呼び出してカバレッジを検証中です。
```

## 注意点

- この機能は `--output-format stream-json` と `--forward-subagent-text` を**両方**指定した場合にのみ有効です。片方だけでは従来通りdepth 1のみ、あるいは転送自体が行われません。
- 従来はdepth 1のサブエージェント出力しか転送されなかったため、既存のパース処理がdepth 1のみを前提にしている場合、depth 2以降のイベントが混在することで想定外の件数・構造になる可能性があります。フィルタ条件を見直してください。
- ネストが深いオーケストレーションでは出力イベント数が大きく増えるため、ログサイズやパイプ先の処理コストに注意してください。
- `parent_tool_use_id` は、そのサブエージェントを起動した親側の `Agent` ツール呼び出しの `tool_use` idです。ルート（トップレベルのメインエージェント）から直接呼ばれたdepth 1サブエージェントの場合、親IDはメインの会話のツール呼び出しIDになります。
- 本機能はヘッドレスモード（`-p` / `--print`）での利用が前提です。対話型セッションのUI表示挙動には影響しません。
