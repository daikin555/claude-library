## 原文（日本語訳）

サーバー側のセッションが期限切れになった後にRemote Controlセッションが再作成される際、以前のローカル会話履歴が新しいセッションにアップロードされてしまう問題を修正しました。

## 原文（英語）

Fixed a Remote Control session recreated after its server session expired uploading prior local conversation history into the new session

## 概要

Remote Controlは、ローカルのClaude Codeセッションとリモートクライアント（モバイルアプリやWebクライアント）を紐づけるために、サーバー側にもセッション情報を保持しています。このサーバー側セッションには有効期限があり、期限切れになると新しいセッションが自動的に再作成される仕組みです。これまでは、この再作成のタイミングで、期限切れになる前のローカルの会話履歴が丸ごと新しいセッションにアップロードされてしまう不具合がありました。今回の修正により、セッション再作成時に過去の会話履歴が意図せずアップロードされることがなくなりました。

## 基本的な使い方

Remote Controlのセッション管理はバックグラウンドで自動的に行われるため、ユーザーが明示的に操作する必要はありません。

```bash
# Remote Controlを起動して長時間セッションを維持
claude remote-control

# サーバー側セッションが期限切れになった場合、
# バックグラウンドで新しいセッションが自動的に作成される
```

## 実践例

### 修正前に起きていた問題

Remote Controlを有効にしたまま長時間Claude Codeを起動し続けていると、サーバー側のセッションが期限切れになるタイミングがありました。この際、内部的に新しいセッションが再作成されるのですが、期限切れ前のローカルの会話履歴（それまでのやり取りすべて）が、意図せず新しいセッションへまとめてアップロードされてしまうことがありました。

```text
# 長時間のセッション中にサーバー側セッションが期限切れに
[内部] Server session expired, recreating remote session...

# 再作成時に、期限切れ前のローカル会話履歴が
# 新しいセッションへ丸ごとアップロードされてしまっていた
```

これにより、意図しないタイミングで過去の会話内容がサーバーへ送信されてしまう可能性がありました。

### 修正後の挙動

セッションが再作成される際に、以前のローカル会話履歴が新しいセッションへアップロードされることはなくなりました。サーバー側セッションの期限切れとローカルの会話履歴の扱いが正しく分離され、リモート接続の再確立のみが行われます。

```text
[内部] Server session expired, recreating remote session...

# 新しいセッションが作成されるのみで、
# 以前の会話履歴が誤ってアップロードされることはない
```

## 注意点

- この修正は主に長時間にわたってRemote Controlを有効にしたまま利用しているワークフローに影響します
- サーバー側セッションが再作成されても、ローカルのターミナル上での会話自体は継続されます。影響を受けるのはリモートクライアントとの同期処理のみです
- 会話履歴のアップロード全般に関するデータの取り扱いについては、Claude Codeのデータ利用ポリシーも合わせて確認してください
