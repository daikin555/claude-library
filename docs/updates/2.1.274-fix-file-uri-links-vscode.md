## 原文（日本語訳）

VS Codeやその他 `file://` URIを要求するターミナルにおいて、ローカルファイルパスへのクリック可能なリンクをクリックしても何も起こらなかった問題を修正しました。

## 原文（英語）

Fixed clickable links to local file paths doing nothing in VS Code and other terminals that require a `file://` URI

## 概要

Claude Codeはターミナル上でローカルファイルへのパスをクリック可能なリンクとして表示しますが、ターミナルの実装によってはリンクとして正しく機能するために `file://` 形式のURIを必要とするものがあります。VS Codeの統合ターミナルなど、この形式を要求する環境では、これまで生成されるリンクの形式が合っておらず、クリックしても何も反応しないという問題がありました。今回の修正で、そうしたターミナルでも正しく `file://` URI形式でリンクが生成されるようになり、クリックでファイルを開けるようになりました。

## 基本的な使い方

この修正は内部的なリンク生成ロジックの改善であり、ユーザー側での操作は不要です。VS Codeの統合ターミナルなどでClaude Codeを使い、会話中にファイルパスがリンクとして表示されたら、そのままクリックしてください。

## 実践例

### VS Codeの統合ターミナルからファイルを開く

VS Code内のターミナルでClaude Codeを実行し、エラーメッセージや検索結果に含まれるファイルパスのリンクをクリックすると、修正後は正しく該当ファイルがエディタで開かれるようになります。

### file:// URIを要求するその他のターミナルエミュレータ

VS Code以外にも、`file://` 形式のURIでなければファイルリンクを認識しないターミナルエミュレータを使っている場合、同様にリンクが正しく機能するようになります。

## 注意点

- ターミナルによっては、そもそもクリック可能なリンク機能自体をサポートしていない場合があります。その場合は表示されたパスを手動でコピーして開く必要があります。
- 修正の効果はターミナルエミュレータの実装に依存するため、利用している環境によっては挙動が異なる場合があります。
