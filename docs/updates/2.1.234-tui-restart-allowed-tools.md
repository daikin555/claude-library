## 原文（日本語訳）

`/tui` が再起動時に起動オプションの `--allowed-tools`/`--disallowed-tools` ルールを失っていた不具合を修正しました。セッションに再起動では引き継げない制限がある場合、`/tui` は理由を示した上で切り替えを拒否するようになりました。

## 原文（英語）

Fixed `/tui` dropping launch `--allowed-tools`/`--disallowed-tools` rules when it restarts; it now declines to switch, with the reason, when the session has restrictions a restart can't carry over

## 概要

`/tui` はClaude Codeをフルスクリーンのターミナルユーザーインターフェース（TUI）レンダラーへ切り替えるコマンドで、内部的にはプロセスを再起動する形で実装されています。これまでは、`claude --allowed-tools ...` や `--disallowed-tools ...` を指定して起動したセッションで `/tui` を実行すると、再起動後にこれらのツール制限ルールが失われてしまうことがありました。今回の修正により、再起動では引き継げない制限がセッションに存在する場合、Claude Codeは切り替え自体を理由付きで拒否するようになり、意図しない権限昇格を防ぎます。

## 基本的な使い方

`/tui` コマンドの使い方自体に変更はありません。通常のセッションでは、コマンドを実行するとフルスクリーンTUIモードに切り替わります。

```bash
claude
> /tui
```

`--allowed-tools`/`--disallowed-tools` を指定せずに起動したセッションでは、これまで通りシームレスに切り替わります。

## 実践例

### 制限付きセッションで/tuiを実行した場合

`--disallowed-tools` を指定して起動したセッションで `/tui` を実行すると、修正後は以下のように切り替えが拒否されます。

```bash
claude --disallowed-tools "Bash(rm:*)" "WebFetch"
> /tui
# 修正前: 再起動後にBash(rm:*)やWebFetchの禁止ルールが消えてしまう恐れがあった
# 修正後:
# Cannot switch to /tui: this session has launch-time tool restrictions
# (--disallowed-tools) that cannot be preserved across a restart.
```

この場合、TUIモードを使いたければ、最初から `claude --tui --disallowed-tools ...` のように起動時オプションとしてTUIを指定する必要があります。

### CI/自動化環境での安全性確認

`--allowed-tools` で許可ツールを絞り込んだ自動化スクリプトが、途中で `/tui` を呼び出すコマンドを誤って実行してしまっても、権限ルールが失われたまま緩い状態で再起動されることがなくなりました。制限が保持できないことに気づいた時点で処理が止まるため、意図しないツール実行の温床になりません。

### 制限なしセッションとの比較

制限なしで起動した通常セッションでは、引き続き `/tui` によるシームレスな切り替えが可能です。

```bash
claude
> /tui
# 通常通りTUIモードへ切り替わる
```

## 注意点

- この修正はセキュリティ上のリグレッションを防ぐためのものです。ツール制限は再起動をまたいで保証されない場合、機能を犠牲にしてでも安全側に倒します
- TUIモードを使いたい場合は、`--allowed-tools`/`--disallowed-tools` と同時に起動時から `--tui` 相当のオプションを指定することを検討してください
- 拒否メッセージには理由が明示されるため、なぜ切り替えられないかをその場で確認できます
