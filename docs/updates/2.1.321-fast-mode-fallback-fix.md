# ファストモード障害時にまず同じモデルの標準速度を試すよう改善

## 原文（日本語に翻訳）

- ファストモードの提供がレート制限・過負荷・障害のときに、返信が失われたり、モデルが切り替わったり、数分間リトライしたりする問題を修正。まず同じモデルの標準速度を試すようになった
- ファストモードのラベルを、現在のモデルがファストモードに対応している場合はそのモデル名で表示するよう変更（`/fast`、`/config`、`/model`）。VS Codeの行から「(Opus only)」を削除

## 原文（英語）

- Fixed fast mode losing replies, switching models or retrying for minutes when fast serving is rate-limited, overloaded or failing; it now tries standard speed on the same model first
- Changed the fast mode labels in `/fast`, `/config` and `/model` to name your current model when it supports fast mode, and removed "(Opus only)" from the VS Code row

## 概要

ファストモードの提供側に問題があっても、同じモデルのまま標準速度で処理を続けるようになりました。以前はモデルの切り替わりや長時間のリトライが発生することがありました。

## 基本的な使い方

```text
> /fast
```

ラベルには、現在のモデル名が表示されます。

## 実践例

### 混雑時間帯での作業

ファストモードがレート制限されても、モデルが変わらないため、出力の傾向が一貫したまま作業を続けられます。

## 注意点

- フォールバックすると速度は標準に戻ります。
- 現在のモデルがファストモードに対応していない場合、ラベルにモデル名は表示されません。
