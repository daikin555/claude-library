## 原文（日本語に翻訳）

共有 `/tmp` 上に自動生成されるクロスセッションメッセージング用ソケットディレクトリを強化しました。事前に仕込まれたシンボリックリンクや、別ユーザーが所有するディレクトリを使用せず、拒否するようになりました。

## 原文（英語）

Hardened the auto-generated cross-session messaging socket directory on shared `/tmp` against a pre-planted symlink or another user's directory: it is now refused instead of used.

## 概要

Claude Codeはセッション間でメッセージをやり取りするために、共有の `/tmp` ディレクトリ配下にソケット用のディレクトリを自動生成して利用しています。複数ユーザーが共有する `/tmp` は誰でも書き込める領域であるため、悪意のあるユーザーが事前にシンボリックリンクや自分名義のディレクトリを仕込んでおくことで、他ユーザーのClaude Codeプロセスにそれを使わせてしまう「事前仕込み（pre-planting）」攻撃のリスクがありました。v2.1.232では、このディレクトリの所有者やタイプ（シンボリックリンクかどうか）を検証し、想定と異なる場合はそのディレクトリの使用を拒否するように変更されました。

## この変更が影響する場面

これは内部的なセキュリティ強化であり、ユーザーが明示的に呼び出す機能ではありません。以下のような場面で挙動に影響します。

- 複数ユーザーが同じマシン（サーバーやCI環境など）を共有し、`/tmp` に対する書き込み権限を持っている場合
- Claude Codeのクロスセッションメッセージング機能（`SendMessage` など、エージェント間・セッション間でのメッセージ送受信）を利用する場合
- 何らかの理由で `/tmp` 上のソケット用ディレクトリが既に存在し、かつそれが現在のユーザーの所有物でない、またはシンボリックリンクになっている場合、Claude Codeはそのディレクトリを使わず、エラーとして扱うようになります

## 実践例

### 共有サーバー上での複数ユーザー利用

```bash
# 複数人が同じLinuxサーバーにログインし、それぞれClaude Codeを使うケース
# ユーザーAが /tmp/claude-xxxx のようなディレクトリを事前に作成・シンボリックリンク化していても
# ユーザーBのClaude Codeプロセスはそのディレクトリを検証し、
# 所有者不一致やシンボリックリンクを検知した場合は使用を拒否する

claude
# セッション間メッセージング用ディレクトリの所有権・種別が検証される
# 想定外の場合はディレクトリを新規作成し直すか、エラーを返す
```

### CI環境でのサンドボックス実行

```bash
# CIランナーのように一時的なコンテナ/VM上で複数ジョブが
# 同じ /tmp を共有する可能性がある環境
# → 事前に仕込まれた不正なディレクトリ/シンボリックリンクを
#   利用してしまうリスクが排除される
```

## 注意点

- Claude Code v2.1.232で導入された変更です
- この修正はセッション間メッセージング（クロスセッション通信）に使われる `/tmp` 配下のソケットディレクトリに関するものです
- ユーザー側で設定を変更する必要はなく、自動的に安全側の挙動になります
- 該当するディレクトリが不正と判定された場合、機能が一時的に利用できないことがあります。その場合は `/tmp` 内の該当ディレクトリを手動で確認・削除することを検討してください
