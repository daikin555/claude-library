## 原文（日本語訳）

`/status` に、このセッションのauto mode分類器がサーバー側で実行されているかどうかを示す `Auto mode server` の行を追加。

## 原文（英語）

Added an `Auto mode server` row to `/status` showing whether this session's auto mode classifier runs on the server

## 概要

auto modeの分類器がサーバーサイドで課金なしに実行されるようになったのに合わせて（[関連記事](/updates/2.1.278-auto-mode-server-classifier-billing)）、`/status` コマンドの出力に `Auto mode server` という行が追加されました。この行を見るだけで、現在のセッションが非課金のサーバーサイド分類器で動いているのか、それとも従来の課金対象の分類器にフォールバックしているのかを一目で確認できます。

## 基本的な使い方

セッション中にいつでも `/status` を実行するだけです。

```bash
/status
```

出力の中に以下のような行が表示されます。

```text
Auto mode server: Enabled
```

- `Enabled`: サーバー側の安全チェックが有効で、分類器のオーバーヘッドは課金されません。
- `Disabled`: セッションが従来の（課金対象の）自前の分類器にフォールバックしています。

## 実践例

### auto modeで課金状況を確認する

Claude APIやEnterpriseプランでauto modeを使っていて、想定より使用量が多いと感じた場合、まず `/status` で `Auto mode server` の状態を確認します。`Disabled` になっていれば、分類器のリクエストがトークンとして課金されている可能性があります。

```bash
/status
# ...
# Auto mode server: Disabled
```

### 社内ゲートウェイ導入後の動作確認

社内のLLMゲートウェイをサーバーサイド分類器に対応させる改修を行った後、実際に反映されているかを `/status` で検証します。新しいセッションを開始し、`Auto mode server` が `Enabled` に変わっていれば、ゲートウェイがリクエスト/レスポンスを正しくパススルーできていると確認できます。

### トラブルシューティング時の切り分け

auto modeの挙動やコストについて `/feedback` で報告する前に、`/status` の出力を添えることで、Anthropicサポート側がプラットフォームやリージョンの対応状況を切り分けやすくなります。

## 注意点

- この行はセッション開始時点の状態ではなく、リアルタイムの状態を表示するため、セッション中にサーバー側チェックが到達できなくなった場合は `Disabled` に変わります。
- Pro、Max、Teamプランではそもそもフォールバック通知の対象外ですが、`/status` 自体は他プランと同様に確認可能です。
- 個々のアクションが一時的にサーバー側チェックに到達できなかっただけでは `Disabled` にはならず、フォールバック状態はセッション全体に対して確定した場合に反映されます。
