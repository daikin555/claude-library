## 原文（日本語訳）

権限モードが設定されていない場合、プランモードで終了したセッションが、VS Code拡張機能で再開する際、および `claude -p --continue`/`--resume` で権限プロンプトを使うツールとともに再開する際に、プランモード外の状態で再開してしまう問題を修正しました。

## 原文（英語）

Fixed sessions that ended in plan mode resuming outside plan mode in the VS Code extension, and in `claude -p --continue`/`--resume` with a permission prompt tool, when no permission mode was set

## 概要

プランモードは、Claude Codeが実際にファイルを変更する前に計画を提示し、承認を得てから実行に移る安全な作業モードです。プランモードのままセッションを終了した場合、次にそのセッションを再開したときも同じプランモードが維持されることが期待されます。しかし、明示的な権限モードが設定されていない状態でVS Code拡張機能から再開したり、`claude -p --continue`/`--resume` を権限プロンプト付きのツールと組み合わせて使ったりすると、プランモードが維持されずに通常モード（実行可能な状態）で再開してしまう不具合がありました。これは意図せずファイルが変更されてしまうリスクにつながるため、今回修正されました。

## 基本的な使い方

修正後は、プランモードで終了したセッションを再開すると、そのままプランモードの状態で再開されます。

```bash
# プランモードのままセッションを終了した後
claude --continue
# 修正後: プランモードが維持された状態で再開される
```

## 実践例

### VS Code拡張機能での作業継続

VS Code内でプランモードにして計画レビュー中にセッションを閉じ、後で再開した場合、以前は通常モードに戻ってしまい、計画の承認前に変更が実行されてしまう可能性がありました。修正後は安全にプランモードのまま再開できます。

### 非対話モードでのパイプライン再開

`claude -p --continue` や `claude -p --resume` を使ったスクリプトやパイプラインで、権限プロンプトを伴うツールを利用している場合、プランモードのセッションが誤って実行モードで再開されることがなくなりました。

### レビュー待ちの計画を安全に持ち越す

大きな変更の計画を立てたあと、一旦セッションを離れて後日レビューを継続するようなワークフローでも、承認前に意図せず変更が適用されてしまう心配がなくなります。

## 注意点

- この問題は権限モードが明示的に設定されていない場合に発生していました。`--permission-mode` などで明示的にモードを指定していた場合は影響が異なります
- プランモードの目的はレビュー前の変更適用を防ぐことなので、この修正はセキュリティ・安全性の観点でも重要です
