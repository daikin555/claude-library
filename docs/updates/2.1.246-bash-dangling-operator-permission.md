## 原文（日本語訳）

末尾に `&&` または `||` 演算子が中途半端に残っている不正な形式のコマンドについて、Bashの権限チェックが常に承認を要求するように修正しました。

## 原文（英語）

Fixed Bash permission checks to always require approval for malformed commands with a dangling `&&` or `||` operator

## 概要

Claude CodeはBashコマンドを実行する前に、設定された許可リストと照らし合わせてそのコマンドが安全かどうかを判断します。コマンド文字列の末尾に `&&` や `||` が中途半端に残っている（後続のコマンドが欠けている）ような不正な形式のコマンドは、パーサーによる解析が本来意図した形と異なる結果になり、権限チェックをすり抜けてしまう可能性がありました。今回の修正により、こうした不完全な形式のコマンドは常に承認プロンプトの対象となり、意図しないコマンドが許可リストの判定をバイパスして実行されることを防ぎます。

## 基本的な使い方

末尾に演算子が残るような不完全なコマンドを渡すと、許可リストの設定にかかわらず承認プロンプトが表示されるようになります。

```bash
# 例: 末尾の && の後にコマンドがない不正な形式
echo hello &&
```

このようなコマンドは、`echo` が許可リストに含まれていても、修正後は必ず承認確認の対象になります。

## 実践例

### 許可リストのバイパスを防ぐ

`Bash(echo:*)` のような許可ルールを設定している環境で、末尾に `&&` を付けた不完全なコマンド文字列を使って意図しないコマンド実行を誘発しようとするケースがあっても、常に承認プロンプトが表示されるため安全性が保たれます。

### 自動生成コマンドの安全性確保

何らかのテンプレートやスクリプトからコマンド文字列が組み立てられる際に、演算子だけが末尾に残ってしまうような不完全な生成結果になったとしても、権限チェックの観点で危険側に倒れて承認を要求します。

### セキュリティレビューでの想定動作の明確化

Bashの許可リスト設計をレビューする際、「不完全な形式のコマンドは常に承認対象になる」という明確な挙動が保証されるため、権限モデルの検証がしやすくなります。

## 注意点

- この修正は権限チェックをより厳格にするものであり、正常な形式のコマンド（末尾に演算子が残らないもの）の挙動には影響しません
- 許可リストで自動承認を広く設定している場合でも、不正な形式のコマンドは例外的に承認プロンプトが挟まる点に留意してください
