## 原文（日本語訳）

フルスクリーン表示およびCtrl+Oのトランスクリプト表示で、セッションが長くなるにつれてメモリ使用量が増大する問題を修正しました。各メッセージ行のレンダリング結果が、トランスクリプト全体のツール参照情報の完全なコピーを保持しなくなりました。

## 原文（英語）

Fixed memory growing with session length in the fullscreen and Ctrl+O transcript views: each rendered message row no longer retains a full copy of the transcript-wide tool lookups

## 概要

Claude Codeのフルスクリーン表示や `Ctrl+O` によるトランスクリプト表示は、これまでメッセージ行ごとにトランスクリプト全体のツール呼び出し参照情報のコピーを保持していました。セッションが長くなり表示行数が増えるほど、この重複したコピーが積み重なってメモリ使用量が線形に増大していました。今回の修正でこの重複保持がなくなり、長時間・大量ツール呼び出しのセッションでも安定したメモリ使用量で動作するようになります。

## 基本的な使い方

修正はClaude Code内部の表示ロジックに対するものなので、ユーザー側で特別な操作は不要です。通常通りフルスクリーンモードやトランスクリプト表示を使うだけで、改善されたメモリ動作の恩恵を受けられます。

```
Ctrl+O  # トランスクリプト表示を開く/閉じる
```

## 実践例

### 長時間にわたる開発セッション

一日中同じセッションでコーディングを続けるようなワークフローでは、ツール呼び出しの回数が数百〜数千に達することがあります。今回の修正により、そうした長時間セッションでもフルスクリーン表示を開いたままにしてもメモリ消費が抑えられます。

### 大量のツール出力を含むセッションのレビュー

ビルドログの確認やテスト結果の解析など、ツール出力が大量に発生するタスクの後で `Ctrl+O` を使ってトランスクリプトを見返す場合でも、メモリ使用量の急増を心配せずに利用できます。

### 低メモリ環境やリソースが限られた端末での利用

CIランナーや軽量なコンテナ環境など、メモリに制約のある環境でClaude Codeを長時間動かすケースでも、今回の修正によって安定性が向上します。

## 注意点

- この修正は内部実装の最適化であり、ユーザーが設定を変更する必要はありません
- 表示内容や機能自体に変更はなく、メモリ効率のみが改善されています
- 非常に長いセッションでは依然として一定のメモリ増加が見込まれますが、増加率が改善されています
