## 原文（日本語訳）

フルスクリーンレンダラーが一度でも起動に失敗すると、以後の起動すべてで失敗し続けてしまう不具合を修正しました。今回の修正により、起動に失敗した場合はそのたびに終了してしまうのではなく、クラシックレンダラーへ自動的にフォールバックするようになりました。

## 原文（英語）

Fixed the fullscreen renderer failing permanently after a single failed start: it now falls back to the classic renderer instead of exiting on every subsequent launch

## 概要

Claude Codeの端末UIには、画面全体を使う「フルスクリーンレンダラー」と、従来型の「クラシックレンダラー」があります。これまでは、何らかの理由（対応していない端末環境や特殊な設定など）でフルスクリーンレンダラーの起動が一度失敗すると、その状態が記録されてしまい、以後Claude Codeを起動するたびに同じ理由で終了してしまう不具合がありました。今回の修正で、起動に失敗した場合はクラシックレンダラーに自動的にフォールバックするようになり、以後の起動が毎回失敗し続けることがなくなりました。

## 基本的な使い方

ユーザー側で特別な操作は不要です。フルスクリーンレンダラーの起動に失敗するような環境でも、Claude Codeはクラシックレンダラーで正常に起動するようになります。

```bash
claude
```

以前はこのような環境で起動自体ができなくなっていましたが、修正後はクラシックレンダラーの画面でそのまま使い続けられます。

## 実践例

### フルスクリーンレンダラーに対応していない端末を使っている場合

一部のターミナルエミュレータや特殊な設定の端末では、フルスクリーンレンダラーの初期化に失敗することがあります。修正前はその1回の失敗以降、Claude Codeの起動自体が毎回失敗するようになっていましたが、修正後はクラシックレンダラーに切り替わって使用を継続できます。

### tmuxやscreenなど多重化ターミナル環境での起動

tmuxやscreen経由でClaude Codeを使っている場合など、フルスクリーン描画がうまく機能しない環境でも、今回の修正によって都度クラシックレンダラーへフォールバックするため、起動不能な状態に陥りにくくなりました。

### SSH経由のリモート端末での利用

SSH越しの端末で端末機能の検出が不安定な場合も、フルスクリーンレンダラーの起動失敗が永続化しなくなったことで、以後の接続でも問題なく起動できます。

## 注意点

- この修正は起動失敗時のフォールバック挙動に関するものであり、フルスクリーンレンダラー自体の描画品質を変更するものではありません
- クラシックレンダラーにフォールバックした場合、フルスクリーンレンダラー特有の表示は利用できません
- 端末環境が改善されれば、次回以降のセッションで再びフルスクリーンレンダラーが利用される可能性があります
