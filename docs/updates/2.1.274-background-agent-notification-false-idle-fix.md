## 原文（日本語訳）
バックグラウンドエージェントが自身のバックグラウンドタスクの完了待ちで再開予定であるにもかかわらず、通知が「アクティブなバックグラウンド作業がない」と誤って主張してしまう問題を修正しました。

## 原文（英語）
Fixed background agent notifications claiming the agent had no live background work when it was still waiting on its own background task and would resume

## 概要
バックグラウンドエージェントが自分自身のバックグラウンドタスクの完了を待機している状態は、まだ「稼働中」とみなされるべきです。しかし通知システムがこの状態を正しく認識できず、実際には後で再開する予定があるにもかかわらず「バックグラウンド作業なし」という誤った通知を出してしまう不具合がありました。今回の修正により、待機中でも再開予定があるエージェントは正しく「稼働中」として扱われるようになりました。

## 基本的な使い方
バックグラウンドエージェントを起動し、通知設定を有効にしておくだけで、正しいステータスが通知されるようになります。

```bash
claude --agent my-background-task
```

## 実践例

### 修正前の挙動
エージェントが内部のバックグラウンドタスクの完了を待っている間に、通知だけを見ると「作業が完了した、または存在しない」ように見えてしまい、ユーザーが誤って作業が終わったと誤解する可能性がありました。

### 修正後の挙動
エージェントが自身のバックグラウンドタスクを待機中で、後で再開する予定がある場合は、通知にもその状態が正しく反映されるようになりました。

## 注意点
- 通知だけに頼らず、実際のセッション状態も併せて確認することが引き続き有用です。
- この修正は通知の表示ロジックに関するものであり、バックグラウンドタスク自体の実行速度には影響しません。
