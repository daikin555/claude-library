## 原文（日本語訳）
`OTEL_LOG_RAW_API_BODIES=file:<dir>`の出力を改善：新たに`index.jsonl`が追加され、`request_body_id`と`message.id`のイベント属性によって、各レスポンスをリクエストファイルとトランスクリプトのメッセージに紐付けられるようになった。

## 原文（英語）
Improved `OTEL_LOG_RAW_API_BODIES=file:<dir>` output: a new `index.jsonl` and `request_body_id` / `message.id` event attributes link each response to its request file and transcript message

## 概要
`OTEL_LOG_RAW_API_BODIES`は、Claude Codeが送受信する生のAPIリクエスト/レスポンスボディをファイルとして記録するための環境変数です。デバッグや監査に有用ですが、これまでは出力されたリクエスト/レスポンスファイルと実際のトランスクリプト上のメッセージとの対応関係を追うのが手間でした。今回の改善により、`index.jsonl`という索引ファイルが新たに出力され、`request_body_id`や`message.id`といった属性を通じて、各レスポンスがどのリクエストファイル・どのトランスクリプトメッセージに対応するかを簡単に辿れるようになりました。

## 基本的な使い方
```bash
# 生のAPIリクエスト/レスポンスボディを指定ディレクトリに記録する
export OTEL_LOG_RAW_API_BODIES=file:/tmp/claude-api-logs
claude
```

実行後、指定ディレクトリに各リクエスト/レスポンスのファイルに加え、`index.jsonl`が生成されます。

## 実践例

### APIリクエストとトランスクリプトメッセージを突き合わせてデバッグする場合
特定のトランスクリプト上のメッセージがどのAPIリクエスト/レスポンスに対応するかを調査したい場合、`index.jsonl`を`message.id`でフィルタすることで、対応する`request_body_id`とファイルパスを特定できます。

```bash
# message.idを使ってindex.jsonlから該当エントリを検索
grep '"message.id":"msg_abc123"' /tmp/claude-api-logs/index.jsonl
```

### 監査・コンプライアンス目的でのリクエスト履歴の追跡
企業内でClaude Codeの利用を監査する際、どのユーザーのどの操作がどのAPIリクエストに対応するかをまとめて追跡したい場合、`index.jsonl`を使って一括で紐付けを行い、レポートを生成できます。

```bash
# request_body_idごとに件数を集計する例
cat /tmp/claude-api-logs/index.jsonl | jq -r '.request_body_id' | sort | uniq -c
```

## 注意点
- `OTEL_LOG_RAW_API_BODIES`はAPIの生データ（プロンプトや応答内容を含む）をファイルに保存するため、機密情報が含まれる可能性があります。保存先ディレクトリのアクセス権限管理に注意してください。
- 長時間の利用では出力ファイルが増え続けるため、ログのローテーションや定期的なクリーンアップを検討してください。
