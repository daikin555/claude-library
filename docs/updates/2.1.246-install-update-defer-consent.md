## 原文（日本語訳）

`claude install` と `claude update` が変更されました。保留中のmanaged-settings（管理設定）の同意プロンプトが、コマンド実行中に表示されるのではなく、次の対話セッションに先送りされるようになりました。

## 原文（英語）

Changed `claude install` and `claude update` to defer a pending managed-settings consent prompt to the next interactive session instead of prompting mid-command

## 概要

組織によって管理設定（managed settings）が構成されている環境では、設定内容についてユーザーの同意を求めるプロンプトが表示されることがあります。これまでは `claude install` や `claude update` を実行している最中にこの同意プロンプトが割り込んで表示されることがあり、インストールやアップデートを自動化しているスクリプトが同意入力待ちで止まってしまう問題がありました。今回の変更により、こうした同意プロンプトはコマンド実行中には表示されず、次に対話的なセッションを開始したタイミングに先送りされるようになりました。

## 基本的な使い方

ユーザーが操作を変える必要はありません。通常どおりインストールやアップデートを実行します。

```bash
claude update
```

管理設定の同意が保留中であっても、このコマンド自体は同意待ちで止まることなく完了します。同意プロンプトは、次に `claude` を対話的に起動したときに表示されます。

## 実践例

### CI/CDやプロビジョニングスクリプトでの自動アップデート

社内の管理設定が構成された環境で、CIパイプラインやマシンのプロビジョニングスクリプトから `claude update` を自動実行している場合、同意プロンプトによって処理がハングするリスクがなくなります。

### 管理設定が新しく展開された直後のインストール

組織が新しい管理設定を展開した直後に `claude install` を実行するようなケースでも、コマンドは中断せずに完了し、実際の同意確認は開発者が対話的にClaude Codeを使い始めるタイミングで行われます。

### 複数マシンへの一括デプロイ

複数の開発者マシンに対してインストール・アップデートを一括で行うスクリプトを運用している場合、各マシンでの同意プロンプトの割り込みを気にせずにコマンドを実行できます。

## 注意点

- 同意プロンプト自体がなくなるわけではありません。表示されるタイミングが「コマンド実行中」から「次の対話セッション開始時」に変わるだけです
- 管理設定の同意が必要な組織の環境でのみ関係する変更です。managed-settingsを使っていない場合はこの変更の影響を受けません
