## 原文（日本語訳）
- テレメトリまたはフィーチャーフラグが無効（LLMゲートウェイ配下を含む）の場合のオートモードを変更：サーバーが確認できない呼び出しは確認または拒否され、組み込み分類器へのフォールバックは行われません。引き続き使うには `CLAUDE_CODE_AUTO_MODE_SERVER=0` を設定します（Bedrock、Vertex、Foundryは変更なし）。
- LLMゲートウェイ配下のオートモードを変更：`CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS` 設定時でも `CLAUDE_CODE_AUTO_MODE_SERVER=1` でサーバー側チェックを有効にできます。後者を管理設定で設定している場合は `1` も設定が必要です。
- 変更：プロジェクトの設定ファイルやプラグインは、プロジェクト外で無効にしたサーバー側チェックを再び有効にできなくなりました。

## 原文（英語）
- Changed auto mode with telemetry or feature flags off, including behind LLM gateways: calls the server can't check are asked about or denied, with no fallback to the built-in classifier; set `CLAUDE_CODE_AUTO_MODE_SERVER=0` to keep using it (Bedrock, Vertex and Foundry are unchanged)
- Changed auto mode behind an LLM gateway: `CLAUDE_CODE_AUTO_MODE_SERVER=1` turns on the server-side check even with `CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS` set; if managed settings set the latter, they must set the `1` too
- Changed auto mode so that a project's settings files or a plugin can no longer switch its server-side check back on once you have switched it off outside the project

## 概要
オートモードのサーバー側安全チェックの扱いが、ゲートウェイ環境やテレメトリ無効環境で厳格になりました。チェックできない呼び出しは、組み込み分類器に頼らず確認または拒否されます。

## 基本的な使い方
```bash
# 従来どおり組み込み分類器を使い続ける
export CLAUDE_CODE_AUTO_MODE_SERVER=0

# ゲートウェイ配下でサーバー側チェックを有効化
export CLAUDE_CODE_AUTO_MODE_SERVER=1
```

## 実践例

### ゲートウェイ配下で従来挙動を維持
更新後に確認が増えた場合、`CLAUDE_CODE_AUTO_MODE_SERVER=0` で組み込み分類器を使い続けられます。

### 管理設定での統一
`CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS` を管理設定で使っている組織は、`CLAUDE_CODE_AUTO_MODE_SERVER=1` も併せて設定します。

## 注意点
- Bedrock、Vertex、Foundryは変更ありません。
- 一度プロジェクト外で無効にした設定は、プロジェクト側の設定やプラグインから再有効化できません。
