## 原文（日本語訳）

管理対象設定（managed settings）の承認プロンプトが起動時に表示されないことがあるにもかかわらず、最初のキー入力を承認として扱ってしまう問題を修正しました。

## 原文（英語）

Fixed the managed-settings approval prompt sometimes not appearing at startup while still capturing the first keypress as approval

## 概要

組織や管理者が配布する管理対象設定（managed settings）がClaude Codeの挙動を変更しようとする場合、起動時にユーザーへ承認を求めるプロンプトが表示される仕組みになっています。これまでは、何らかの理由でこのプロンプトが画面上に表示されないことがあるにもかかわらず、内部的には最初のキー入力を「承認」として処理してしまうというタイミングの不具合がありました。これにより、ユーザーが承認を意図していない操作（例えば通常の入力を始めようとした最初のキー入力）が、意図せず管理対象設定への承認として扱われてしまう恐れがありました。今回の修正で、プロンプトの表示と最初のキー入力の受け付けタイミングが正しく同期され、表示されていないプロンプトが勝手に承認されることはなくなりました。

## 基本的な使い方

特別な操作は不要です。管理対象設定が適用される環境でClaude Codeを起動すると、承認が必要な変更がある場合には承認プロンプトが確実に表示されるようになり、ユーザーが明示的に操作するまで承認は行われません。

```bash
claude
# 管理対象設定（managed-settings.json）による変更がある場合、
# 起動時に承認プロンプトが表示される
# 修正前: プロンプトが表示されないまま、最初のキー入力が承認扱いになることがあった
# 修正後: プロンプトが確実に表示されてから、ユーザーの入力を承認として受け付ける
```

## 実践例

### 起動直後にすぐ入力を始めてしまった場合

Claude Codeを起動してすぐにプロンプトへ質問や指示を入力し始めるユーザーは多いですが、以前はこのタイミングでたまたま管理対象設定の承認プロンプトが裏側で処理待ちになっていると、最初のキー入力が意図せず承認として扱われてしまうことがありました。修正後は、承認プロンプトが実際に画面へ表示されてから初めて入力が承認として扱われるため、意図しない承認を防げます。

### 組織のポリシーで機密性の高い設定変更を配布する場合

管理者がサンドボックス設定やエンドポイントの変更など、慎重な確認を要する設定を `managed-settings.json` 経由で配布しているケースでは、この修正によりユーザーが実際にプロンプトの内容を確認したうえで承認するというフローがより確実に保証されます。

## 注意点

- この修正はセキュリティに関わるタイミングの不具合の修正であり、承認プロンプトが表示された後の操作方法自体は変わりません。
- 管理対象設定を配布していない一般的な利用環境（managed-settings.jsonが存在しない環境）では、この問題自体が発生しないため影響はありません。
