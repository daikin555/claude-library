## 原文（日本語に翻訳）

Linuxファイルシステムサンドボックスにおける、保護対象パス（protected path）のバイパスに対する耐性を強化しました。

## 原文（英語）

Hardened the Linux filesystem sandbox against a protected-path bypass.

## 概要

Claude Codeのサンドボックス機能（`sandbox.enabled` などで有効化されるBashツール用のファイルシステム分離）は、Linux上でOSレベルの仕組みを使って、`~/.bashrc` やSSHキーなど機微なパスへのアクセスを制限しています。v2.1.232では、こうした「保護対象パス」への制限を何らかの方法で回避（バイパス）できる可能性のある問題が修正され、サンドボックスの分離がより厳密に機能するようになりました。具体的な攻撃手法の詳細は公開されていませんが、サンドボックス内で実行されたコマンドが保護対象のファイルやディレクトリに意図せずアクセスできてしまう可能性を防ぐための強化です。

## この変更が影響する場面

これはセキュリティバグ修正であり、ユーザーが明示的に呼び出す新機能ではありません。以下のような場面で影響があります。

- Linux上で `sandbox.enabled: true` を設定し、Bashツールをサンドボックス化して利用している場合
- サンドボックスの保護対象パス（例: `~/.ssh`、`~/.bashrc`、システムディレクトリなど）へのアクセスを制限する目的で運用している場合
- 信頼できないコードやスクリプト（npmパッケージのインストールスクリプトなど）をサンドボックス内で実行している場合

修正後は、これまでバイパスが可能だった経路が塞がれるため、サンドボックスの保護がより確実に機能するようになります。

## 実践例

### サンドボックスを有効化した開発環境

```json
// ~/.claude/settings.json
{
  "sandbox": {
    "enabled": true,
    "failIfUnavailable": true
  }
}
```

```bash
claude
# サンドボックス化されたBashツールを使ってコマンドを実行
# 保護対象パス（~/.ssh, ~/.bashrc など）への
# 意図しないアクセスがより確実にブロックされる
```

### 信頼できないスクリプトの実行時の安心材料

```bash
# 例: 未検証のnpmパッケージのpostinstallスクリプトなど
npm install some-untrusted-package

# サンドボックス内で実行されるコマンドが
# 保護対象パスへアクセスしようとしても拒否される
```

## 注意点

- Claude Code v2.1.232で修正された、Linux固有のサンドボックス強化です
- サンドボックス機能自体は `sandbox.enabled` の設定が必要です。詳細は公式ドキュメントの sandboxing ページを参照してください
- `sandbox` プロパティが適用されるのはBashツールのみで、Read/Write/WebSearch/WebFetch/MCP・hooks・内部コマンドには適用されません
- 具体的なバイパス手法の詳細は公開されていないため、影響範囲を正確に把握したい場合は公式のセキュリティアドバイザリやリリースノートを確認してください
- 常に最新バージョンのClaude Codeを利用することが推奨されます
