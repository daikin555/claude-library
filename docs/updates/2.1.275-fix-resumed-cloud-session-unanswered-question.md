## 原文（日本語に翻訳）

レジュームしたクラウドセッションで、キューに入っていたメッセージが質問を置き換えたにもかかわらず、トランスクリプト上に未回答の質問が残ったままになっていた問題を修正

## 原文（英語）

Fixed a resumed cloud session leaving an unanswered question open in the transcript after a queued message superseded it

## 概要

クラウド上で実行しているClaude Codeセッションをレジューム（再開）する際、Claudeがユーザーに質問を投げかけた後、別のキューに入っていたメッセージによってその質問が実質的に置き換えられるケースがあります。これまでは、このような状況でトランスクリプト上に未回答のままの質問が表示され続けてしまう不具合がありました。今回の修正で、置き換えられた質問は適切にクローズされ、トランスクリプトの表示が整合性を持つようになりました。

## 基本的な使い方

クラウドセッションのレジュームは通常通り行います。

```bash
claude --resume
```

質問がキューメッセージによって置き換えられた場合でも、トランスクリプトは正しい状態で表示されます。

## 実践例

### 修正前の挙動

Claudeが確認の質問（例：「このファイルを削除してよいですか？」）を投げた直後に、別の指示メッセージがキューに入っていて質問を実質的に上書きした場合、セッションをレジュームするとトランスクリプト上にその未回答の質問がそのまま残って表示されてしまい、混乱を招いていました。

### 修正後の挙動

キューメッセージによって置き換えられた質問は、トランスクリプト上でも適切にクローズされた状態で表示されるようになり、レジューム後の会話履歴がより正確になりました。

```bash
# クラウドセッションをレジュームした際に
# 過去のトランスクリプトに矛盾した未回答質問が残らない
claude --resume
```

## 注意点

- この修正はクラウドセッションのレジューム時の表示整合性に関するものです
- キューメッセージの送信タイミングによっては、依然として質問への回答を明示的に求められる場合があります
- ローカルセッションでも同様の状況が起こり得る場合は、挙動を確認してください
