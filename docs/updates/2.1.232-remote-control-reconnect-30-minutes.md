## 原文（日本語に翻訳）

Remote Controlは、ネットワークの瞬断（一時的な切断）が発生した後も約30分間再接続を試み続けるようになり、1時間の間に複数回の瞬断が散発しても接続が切れなくなりました。

## 原文（英語）

Remote Control now keeps reconnecting for about 30 minutes after a network blip and no longer drops after a few blips spread across an hour

## 概要

これは安定性の改善です。従来のRemote Controlは、Wi-Fiの切り替えやモバイル回線の一時的な不調などによるネットワークの瞬断が短時間に何度か発生すると、再接続の試行回数や時間の制限に達してしまい、セッションの接続が完全に切断されてしまうことがありました。今回の改善により、1回の瞬断からは約30分間再接続を試み続けるようになり、また1時間程度の間隔で複数回の瞬断が散発的に発生しても、それだけでは接続がドロップしなくなりました。

## 基本的な使い方

ユーザー側で特別な操作は不要です。Remote Controlで接続したセッションが一時的にネットワークを失っても、自動的に再接続が試みられます。

```bash
# ローカル環境でRemote Controlを有効化
claude remote-control
```

または既存セッションから:

```
/remote-control
```

外出先などで電波状況が不安定になっても、Claudeアプリやclaude.ai/codeとの接続は裏側で自動的に再確立が試みられます。

## 実践例

### 移動中の電車やバスでモバイル回線が不安定な場合

トンネルや電波の弱いエリアを通過する際に何度も瞬断が発生しても、以前は接続が完全に切れてしまうことがありました。改善後は約30分間再接続の試行が継続されるため、電波が回復すればセッションが自動的に復帰し、再度QRコードをスキャンし直す手間が減ります。

### オフィスと自宅でWi-Fiを切り替える場合

ノートPCをスリープから復帰させたり、Wi-Fiネットワークを切り替えたりする際に短い瞬断が発生することがあります。1時間のうちに複数回そうした切り替えが発生しても、それだけを理由に接続がドロップしなくなったため、モバイルアプリ側での再接続操作が不要になるケースが増えます。

### 長時間のバックグラウンドタスクを監視している場合

長時間かかるビルドやテストの進捗をRemote Control経由でスマートフォンから監視している際、途中でネットワークが数回不安定になっても、セッションとの接続が維持されやすくなり、タスク完了の通知を見逃しにくくなります。

## 注意点

- 再接続の試行は約30分間を目安に継続されますが、それを超えて長時間ネットワークが失われた場合は、改めて手動での再接続が必要になることがあります。
- この改善はネットワークの瞬断に対する耐性を高めるものであり、Remote Control自体が別デバイスに引き継がれた場合やセッションが明示的に終了された場合の挙動には影響しません。
- Remote Controlの利用には対象プランでの有効化や `claude.ai` アカウントでの認証などの前提条件があります。
