## 原文（日本語に翻訳）

エージェント定義の `bypassPermissions` モードが、組織のbypass-permissions無効化ポリシーを無視してしまう権限ギャップを修正しました。

## 原文（英語）

Fixed a permission gap where an agent definition's `bypassPermissions` mode ignored the org bypass-permissions disable policy

## 概要

Claude Codeでは、組織の管理者が管理設定（managed settings）を通じて、`bypassPermissions`（権限確認を省略するモード）の使用を組織全体で無効化できます。これは、`--dangerously-skip-permissions` のような危険なモードが意図せず有効化されることを防ぐためのガバナンス機能です。今回修正された問題は、サブエージェントやカスタムエージェントの定義ファイル内で `bypassPermissions` モードを指定した場合、この組織レベルの無効化ポリシーが適用されず、本来禁止されているはずの権限スキップ動作が実行されてしまうというものでした。v2.1.223では、エージェント定義由来の `bypassPermissions` 指定に対しても組織ポリシーが正しく適用され、無効化設定が確実に反映されるように修正されています。

## 基本的な使い方

組織で `bypassPermissions` の使用を禁止する場合、管理設定ファイルでポリシーを設定します。

```json
{
  "permissions": {
    "disableBypassPermissionsMode": "disable"
  }
}
```

エージェント定義側で `bypassPermissions` を指定していても、修正後はこの組織ポリシーが優先されます。

```yaml
# .claude/agents/my-agent.md のfrontmatter例
---
name: my-agent
permission-mode: bypassPermissions
---
```

## 実践例

### 組織ポリシーが適用されているかを確認する

管理設定でbypass-permissionsを無効化している組織では、`bypassPermissions` を指定したエージェント定義を実行しても権限確認が省略されないことを確認します。

```bash
# エージェント定義を利用してタスクを実行
claude -p "my-agentサブエージェントを使ってファイルを整理して"
# → 組織ポリシーが有効な場合、権限プロンプトが引き続き表示されることを確認する
```

### 管理設定ファイルの内容を監査する

管理者は、配布している managed-settings.json の内容が意図どおりであるかを定期的に確認することが推奨されます。

```bash
cat /etc/claude-code/managed-settings.json 2>/dev/null \
  || cat /Library/Application\ Support/ClaudeCode/managed-settings.json 2>/dev/null
```

### サードパーティ製エージェント定義を導入する際の確認

Marketplaceなどから取得したエージェント定義に `permission-mode: bypassPermissions` が指定されていないか事前に確認し、組織ポリシーと合わせて安全性を検証します。

```bash
grep -r "bypassPermissions" .claude/agents/ 2>/dev/null
```

## 注意点

- 本修正はセキュリティ・ガバナンス上重要な変更のため、組織で権限ポリシーを運用している場合はv2.1.223以降への速やかなアップデートを推奨します。
- 組織ポリシーを設定していない環境では、そもそも `bypassPermissions` の使用が許可されているため、本修正による挙動の変化はありません。
- エージェント定義ファイルは外部から取得・共有されることがあるため、`permission-mode` の指定内容を事前に確認する習慣が推奨されます。
- 管理設定の反映にはClaude Codeの再起動やセッションの再読み込みが必要な場合があるため、ポリシー変更後は動作確認を行ってください。
