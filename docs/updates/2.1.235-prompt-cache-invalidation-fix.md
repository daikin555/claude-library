## 原文（日本語訳）

セッション中に言語サーバー（LSP）が切断または再接続した際、プロンプトキャッシュ全体が無効化されてしまう不具合を修正しました。

## 原文（英語）

Fixed whole-prompt-cache invalidation when a language server disconnected or reconnected mid-session

## 概要

Claude Codeはリクエストのプレフィックス（システムプロンプトやプロジェクトコンテキストなど、毎ターン変化しない部分）をサーバー側のキャッシュに保持することで、処理速度とコストを大幅に改善しています。今回の修正前は、セッション中にLSPサーバー（コード補完や定義ジャンプなどに使われる言語サーバー）がプロセス終了や一時的な通信障害で切断・再接続すると、本来キャッシュを保持できるはずの部分まで含めてプロンプトキャッシュ全体が無効化されてしまうことがありました。これにより、長時間のセッションで不要にキャッシュが再構築され、レスポンスが遅くなったり、コストが増加したりする問題が発生していました。

## 基本的な使い方

この修正は内部的な挙動の改善であり、ユーザーが明示的に操作する項目はありません。LSPサーバーを利用する言語（TypeScript、Python、Goなど）のプロジェクトで長時間のセッションを行っていると、以下のような状況で自動的に恩恵を受けられます。

```bash
claude
# TypeScriptプロジェクトを長時間編集
# → LSPサーバーが一時的にクラッシュ・再起動しても、
#   会話全体のキャッシュが無駄に破棄されなくなった
```

## 実践例

### 大規模プロジェクトで長時間セッションを継続する

LSPサーバーはメモリ不足やタイムアウトなどで稀に再起動することがあります。修正前はこのタイミングでキャッシュが全損し、次のターンの応答が遅く・高コストになっていましたが、修正後はキャッシュヒット率が維持されやすくなります。

```bash
claude
> 数時間にわたってリファクタリング作業を継続
# LSPが裏側で再接続しても、応答速度への影響が小さくなる
```

### キャッシュヒット率をモニタリングして確認する

ステータスライン等で `cache_read_input_tokens` と `cache_creation_input_tokens` を監視している場合、LSPの再接続タイミングで `cache_creation_input_tokens` が急増していないかを確認できます。修正後は、LSPの切断・再接続だけでは大きなキャッシュ再構築が発生しにくくなります。

```bash
# 例: OpenTelemetryやstatuslineスクリプトでキャッシュ関連メトリクスを可視化し、
# LSP再接続前後のキャッシュ挙動を比較する
```

### 不安定なネットワーク環境での開発

リモート開発環境やコンテナ内でLSPサーバーの接続が不安定になりやすい場合でも、今回の修正によりプロンプトキャッシュへの悪影響が抑えられ、セッション全体のレスポンス性能が安定しやすくなります。

## 注意点

- 本修正はLSPサーバーの切断・再接続に起因する「不要な」キャッシュ全損を防ぐものであり、MCPサーバーの接続・切断（プレフィックスに読み込まれるツール定義が変化する場合）によるキャッシュ無効化とは別の話です
- モデルの切り替えやeffortレベルの変更、`/compact`によるキャッシュ無効化など、他の要因によるキャッシュ再構築は引き続き発生します
- キャッシュの挙動を詳しく確認したい場合は、公式ドキュメントの「Actions that invalidate the cache」セクションを参照してください
