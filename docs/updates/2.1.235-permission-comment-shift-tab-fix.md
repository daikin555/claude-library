## 原文（日本語訳）

権限プロンプトのコメント欄で Shift+Tab を押すと、コメント欄を閉じるのではなく、誤って編集を承認し、さらにセッション全体に対する編集権限まで付与してしまう不具合を修正しました。

## 原文（英語）

Fixed Shift+Tab inside the permission prompt's comment field approving the edit and granting session-wide edit permission instead of closing the field

## 概要

Claude Codeの権限プロンプトでは、ファイル編集などの操作を承認・拒否する際にコメント（フィードバック）を添えることができます。通常、Claude Codeでは Shift+Tab は権限モード（Manual／auto-accept editsなど）を切り替えるためのショートカットとして使われますが、権限プロンプトのコメント入力欄がアクティブな状態で Shift+Tab を押すと、本来はコメント欄を閉じるだけの操作であるべきところ、誤って編集そのものを承認し、さらにセッション全体で以後の編集を無条件に許可する状態（auto-accept edits相当）まで有効にしてしまう不具合がありました。ユーザーがコメントを入力・確認しているだけのつもりが、意図せずセッション全体の編集権限を渡してしまう可能性があったため、今回の修正でこの誤動作が解消されました。

## 基本的な使い方

この修正はユーザー操作を必要とせず、権限プロンプトの挙動が自動的に正しくなります。修正後は、コメント欄で Shift+Tab を押すとコメント欄が閉じるだけになり、編集の承認やセッション全体の権限変更は行われません。

```
Claude wants to edit src/app.ts
> コメントを入力... (Shift+Tab で閉じる)
```

## 実践例

### 編集内容にフィードバックを添えてから判断する

権限プロンプトが表示された際、承認・拒否の前にコメントを書きたい場合に、Shift+Tabで意図せず承認されてしまう心配がなくなりました。

```
Claude wants to edit src/components/Form.tsx
> このバリデーション条件は要確認、と一旦コメントしてから
  Shift+Tab でコメント欄を閉じ、改めて承認/拒否を選ぶ
```

### 誤操作によるセッション全体の権限付与を防ぐ

修正前は、コメント欄でうっかりShift+Tabを押しただけで、以後のすべての編集が確認なしで実行される状態（auto-accept edits）になってしまうことがありました。修正後はコメント欄でのShift+Tabがこの権限変更を引き起こさないため、意図しない範囲でのファイル書き換えを防ぎやすくなります。

```
# 修正前: コメント欄でShift+Tab → 誤って「今後は編集を毎回自動承認」状態になっていた
# 修正後: コメント欄でShift+Tab → コメント欄が閉じるだけ
```

### 通常の権限モード切り替えは引き続き利用する

コメント欄以外の場面では、Shift+Tabは従来通り権限モードの切り替え（Manual → auto-accept edits → plan modeなど）として機能します。

```
claude
# プロンプト入力欄（コメント欄ではない状態）でShift+Tab
# → 権限モードが順に切り替わる
```

## 注意点

- 本修正はコメント欄がアクティブな状態でのShift+Tabの挙動に限定した修正です。通常のプロンプト入力欄における権限モード切り替えとしてのShift+Tabの動作は変わりません
- 修正前のバージョンで意図せずセッション全体の編集権限が付与されてしまった場合は、`/config` や権限モードの切り替えで元のモードに戻すことができます
- 権限プロンプトやコメント機能の詳細な挙動は、バージョンによって細部が変わる可能性があるため、最新のドキュメントも合わせて確認してください
