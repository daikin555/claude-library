## 原文（日本語訳）

ワークロードアイデンティティフェデレーション（WIF）を使ったセッション、起動時に実行される `apiKeyHelper` によって送信されるイベント、そしてアイドル中にログイントークンが失効した後に送信されるイベントについて、利用状況テレメトリを組織に正しく帰属させる精度が改善されました。

## 原文（英語）

Improved attribution of usage telemetry to your organization for workload identity federation sessions, events sent while `apiKeyHelper` runs at startup, and after a login token expired while idle

## 概要

Claude Codeは組織単位で利用状況（トークン消費量やイベント数など）を集計するためのテレメトリを送信していますが、一部の特殊な認証経路や認証状態ではイベントが正しい組織に帰属されないケースがありました。今回の改善では、クラウドプロバイダーのワークロードアイデンティティフェデレーション（WIF）を使う認証方式、起動時に `apiKeyHelper` スクリプトが実行されている間のイベント、そしてアイドル状態のままログイントークンが失効した後のイベントについて、組織への帰属が正しく行われるようになりました。これにより、組織の管理者がコストや利用状況をより正確に把握できます。

## 基本的な使い方

この改善は内部的なテレメトリ処理の修正であり、ユーザーが操作を変える必要はありません。WIFやAPIキーヘルパーを使った認証構成のまま、通常どおりClaude Codeを利用するだけで、テレメトリの帰属が自動的に改善されます。

```bash
# apiKeyHelperを使った構成の例（settings.json）
{
  "apiKeyHelper": "/path/to/get-api-key.sh"
}
```

## 実践例

### クラウドのワークロードアイデンティティフェデレーションを使う企業環境

BedrockやVertex AIなどでWIFを用いてAWS/GCPの認証情報を取得している組織では、これまでセッションによってはテレメトリが正しい組織IDに紐づかないことがありましたが、今後はより正確に集計されるようになります。

### `apiKeyHelper` でAPIキーを動的取得している構成

起動時に外部スクリプトでAPIキーを取得する構成を使っているチームでは、そのスクリプト実行中に発生した使用量イベントも正しく組織に帰属されるようになり、利用状況ダッシュボードの数値の欠落や誤帰属が減ります。

### 長時間アイドル状態のセッションを再開する場合

ログイントークンが失効した状態でしばらく放置されていたセッションを再開したとき、失効後に送信されたイベントも正しい組織に紐づくようになるため、コスト管理や利用状況分析の精度が向上します。

## 注意点

- この改善はテレメトリの「帰属先」の正確性に関するものであり、収集されるデータの内容自体を変更するものではありません
- 組織の利用状況ダッシュボードやOpenTelemetryエクスポート先で数値を確認・監査している管理者にとって特に関係のある改善です
