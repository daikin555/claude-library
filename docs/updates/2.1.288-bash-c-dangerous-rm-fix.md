## 原文（日本語訳）

`bash -c` や `sh -c` のスクリプト内にある危険な `rm`（`/` やホームディレクトリ対象など）が、bypassPermissionsモードやシェル許可ルールの下で確認なしに実行される問題を修正した（anthropics/claude-code#96300）。

## 原文（英語）

Fixed a dangerous `rm` (such as one on `/` or the home directory) inside a `bash -c` or `sh -c` script running without a prompt in bypassPermissions mode or under a shell allow rule (anthropics/claude-code#96300)

## 概要

`rm -rf /` のような危険な削除は通常、確認が求められます。しかし `bash -c "..."` の中に包まれると、bypassPermissionsモードや許可ルールがある場合に確認なしで実行されてしまうことがありました。この修正でスクリプト内部の危険な `rm` も検出されます。

## 基本的な使い方

利用者側の操作は不要です。更新するだけで保護が有効になります。

```bash
claude --version
```

## 実践例

### 許可ルールを広めに設定している場合

```json
{
  "permissions": {
    "allow": ["Bash(bash:*)"]
  }
}
```

このようなルールがあっても、`bash -c 'rm -rf ~'` のような内部の危険操作では確認が入ります。

### bypassPermissionsの利用

隔離環境で使う場合でも、ホームやルートを対象にした削除は保護されます。

## 注意点

- bypassPermissionsは隔離された環境でのみ使うことが前提です。この修正は保険であり、完全な防御ではありません。
- 広いシェル許可ルールは避け、必要なコマンドに絞ってください。
