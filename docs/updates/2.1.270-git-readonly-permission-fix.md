## 原文（日本語訳）

長時間セッションを実行していると、読み取り専用のgitコマンドがBashツールで予期せず許可確認を求めるようになる不具合を修正しました（2.1.269で発生した回帰）。

## 原文（英語）

Fixed read-only git commands in Bash unexpectedly asking for permission after a session had been running for a while (regression in 2.1.269)

## 概要

Claude Codeは、`git status` や `git diff` のような読み取り専用のgitコマンドについて、通常は許可確認なしで実行できるようになっています。しかし2.1.269で、セッションを長時間動かし続けていると、この読み取り専用コマンドの自動許可が効かなくなり、毎回確認ダイアログが表示されてしまう回帰(リグレッション)が発生していました。2.1.270ではこの問題が修正され、セッションの経過時間に関わらず、読み取り専用のgitコマンドは想定通り確認なしで実行されるようになりました。

## 基本的な使い方

この修正は自動的に適用されるため、ユーザー側で追加の設定は不要です。2.1.270以降にアップデートするだけで、以下のような読み取り専用コマンドが長時間セッションでもスムーズに実行できます。

```bash
# セッションを長く使っていても、これらは確認なしで実行される
git status
git diff
git log --oneline -10
git show HEAD
```

アップデートは通常のClaude Codeの更新手順で行います。

```bash
claude update
```

## 実践例

### 長時間の対話的セッションでのコードレビュー

長時間にわたって同じセッションでコードベースを調査・修正していく場合、以前は時間が経つと `git status` や `git diff` のたびに確認を求められ、作業のテンポが崩れていました。2.1.270ではこの中断がなくなり、最初から最後まで一貫した挙動で作業を進められます。

```bash
> このセッションで数時間かけてリファクタリングを進めてください
# 序盤: git diff は確認なしで実行される
# 数時間後: 以前は確認が再度求められていたが、2.1.270では引き続き確認なしで実行される
```

### CI連携やバッチ処理での長時間セッション

自動化されたワークフローの中でClaude Codeを長時間稼働させ、定期的に `git log` や `git show` で変更履歴を参照させるようなケースでも、途中で確認待ちのために処理が止まってしまう心配がなくなります。

```bash
# 長時間稼働するエージェントが定期的に履歴を確認する処理
git log --since="1 hour ago" --oneline
git diff HEAD~1
```

### settings.jsonで独自の読み取り専用ルールを併用している場合

`permissions.allow` に `Bash(git status:*)` のような読み取り専用ルールを追加で定義している場合も、今回の修正でビルトインの読み取り専用コマンド判定とあわせて長時間セッションでの安定性が向上します。

```json
{
  "permissions": {
    "allow": [
      "Bash(git status:*)",
      "Bash(git diff:*)",
      "Bash(git log:*)"
    ]
  }
}
```

## 注意点

- この修正は2.1.269で発生した回帰の是正であり、2.1.268以前から使っていたユーザーへの影響はありません。2.1.269を使っていた場合は2.1.270へのアップデートを推奨します。
- 読み取り専用として自動許可されるのはgitの参照系コマンド（`status`、`diff`、`log`、`show` など）であり、`git commit` や `git push` のような変更を伴うコマンドは引き続き通常の許可確認の対象です。
- 独自に `permissions.deny` でgitコマンドを制限している場合、その設定が優先されるため、今回の修正後も意図通りに制限が効いているか確認しておくと安心です。
- 挙動に差異を感じる場合は `claude --version` で2.1.270以降になっているかを確認してください。
