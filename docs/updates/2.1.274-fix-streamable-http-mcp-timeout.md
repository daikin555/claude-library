## 原文（日本語訳）

長めの `timeout` をサーバーごとに設定していても、Streamable HTTPのMCPツール呼び出しが約5分でタイムアウトしてしまう問題を修正しました。

## 原文（英語）

Fixed Streamable HTTP MCP tool calls timing out after about 5 minutes even when a longer per-server `timeout` was set

## 概要

MCPサーバーの設定では、サーバーごとにツール呼び出しのタイムアウト時間（`timeout`）を指定できます。しかし、Streamable HTTPトランスポートを使うMCPサーバーでは、この設定値に関わらず内部的な上限によって約5分でツール呼び出しが強制的にタイムアウトしてしまうバグがありました。今回の修正により、設定した `timeout` の値が正しく尊重されるようになり、長時間かかる処理を行うMCPツールも最後まで完了できるようになりました。

## 基本的な使い方

```json
{
  "mcpServers": {
    "slow-tool-server": {
      "type": "http",
      "url": "https://example.com/mcp",
      "timeout": 600000
    }
  }
}
```

上記のように `timeout` をミリ秒単位で指定すると、その時間までツール呼び出しの完了を待つようになります。

## 実践例

### 長時間かかるデータ処理ツールの呼び出し

大規模なデータセットの分析や、時間のかかるバッチ処理を行うMCPツールをStreamable HTTPサーバー経由で呼び出す場合、以前は約5分で強制終了していましたが、修正後は `timeout` に設定した時間（例: 10分）まで正しく待機します。

```json
{
  "timeout": 600000
}
```

### 外部APIのレイテンシが大きいツール

外部の重いAPIをラップしたMCPツールなど、応答に数分かかることがあるケースでも、サーバーごとの `timeout` 設定に応じて適切に待機できるようになりました。

## 注意点

- `timeout` を過度に長く設定すると、実際に問題が発生してハングしているツール呼び出しの検知が遅れる可能性があります。想定される処理時間に見合った値を設定してください。
- この修正はStreamable HTTPトランスポートを使うMCPサーバーに関するものです。他のトランスポート（stdio、レガシーSSEなど）の挙動には影響しません。
