## 原文（日本語訳）

`plugin.json` がUTF-8のバイトオーダーマーク（BOM）付きで保存されている場合に、プラグインのインストールが失敗する不具合を修正しました。

## 原文（英語）

Fixed plugin installation failing when `plugin.json` was saved with a UTF-8 byte-order mark (BOM)

## 概要

一部のエディタやOS（特にWindows環境のメモ帳など）は、UTF-8ファイルを保存する際に先頭に不可視のバイトオーダーマーク（BOM, `EF BB BF`）を付与します。これまでのClaude Codeのプラグインローダーは、`plugin.json` の先頭にBOMが存在するとJSONのパースに失敗し、プラグインのインストールがエラーになってしまいました。今回の修正でBOMを自動的に無視してパースできるようになり、ファイルの保存方法にかかわらずプラグインをインストールできます。

## 基本的な使い方

特別な操作は不要です。BOM付きで保存された `plugin.json` を含むプラグインでも、通常通りインストールできるようになりました。

```bash
claude plugin install ./my-plugin
```

修正前はBOMが含まれている場合に `Unexpected token` のようなJSON解析エラーが発生していましたが、修正後は問題なくインストールが完了します。

## 実践例

### Windows環境で作成したプラグインの配布

Windowsのメモ帳や一部のIDEでファイルを保存すると、意図せずBOMが付与されることがあります。そうしたファイルをそのままコミット・配布してもインストールエラーが発生しなくなりました。

### 複数のエディタ・OSを併用するチームでの開発

チームメンバーが異なるOSやエディタで `plugin.json` を編集しても、BOMの有無によってプラグインの動作に差異が出なくなります。

### 既存プラグインのトラブルシューティング

これまで原因不明のインストール失敗に遭遇していた場合、`plugin.json` にBOMが含まれていたことが原因だったケースも今回の修正で解消されます。

## 注意点

- この修正は `plugin.json` のパース処理に関するものです。他の設定ファイル（`SKILL.md` のfrontmatterなど）でBOMが問題になる場合は別途確認が必要です
- BOMを手動で除去しなくても動作するようになりましたが、可能であればBOMなしのUTF-8で保存することが一般的な推奨事項です
