## 原文（日本語訳）

`strictKnownMarketplaces` の許可リストが、実際にgitが接続するホストとは異なるホストを持つSCP形式のgitマーケットプレイスソースを許可してしまっていた不具合を修正しました。

## 原文（英語）

Fixed `strictKnownMarketplaces` allowlists accepting SCP-style git marketplace sources whose host differs from the one git would actually connect to

## 概要

`strictKnownMarketplaces` は、Claude Codeがプラグインをインストールできるマーケットプレイスのソースを許可リスト（信頼済みホスト）に制限するセキュリティ設定です。gitのリモートURLには `https://` 形式のほかに `git@host:org/repo.git` のようなSCP形式があり、修正前のバージョンではこのSCP形式のURLを解析する際に、許可リストのチェックで使われるホスト文字列と、実際にgitコマンドが接続に使うホストが食い違ってしまうケースがありました。その結果、本来は許可リストに含まれていない（信頼できない）ホストへのマーケットプレイスソースが、チェックをすり抜けて許可されてしまう可能性がありました。今回の修正でSCP形式URLのホスト判定が、gitの実際の接続先と一致するよう修正されています。

## 基本的な使い方

この修正はセキュリティ関連のバグフィックスであり、`strictKnownMarketplaces` を設定して運用している組織・チームは特別な操作なしで恩恵を受けられます。

```jsonc
// managed settings や settings.json の例
{
  "strictKnownMarketplaces": [
    "github.com",
    "gitlab.internal.example.com"
  ]
}
```

## 実践例

### SCP形式のURLを使ったマーケットプレイス追加を試みる場合

```bash
# 許可リストに含まれていないホストへのSCP形式URL
claude plugin marketplace add "git@evil-host.example.com:some/marketplace.git"
```

修正前は、URLのホスト部分の解析が不正確だったために、このような許可リスト外のホストであっても条件によっては許可されてしまう可能性がありましたが、修正後は正しく拒否されます。

### 組織で許可ホストを厳格に運用しているケース

社内ポリシーとして `strictKnownMarketplaces` に自社のGitLabホストのみを許可している組織では、この修正によりSCP形式URLの抜け道を悪用した未許可マーケットプレイスからのプラグインインストールを防止できます。

## 注意点

- `strictKnownMarketplaces` を設定していない環境ではこの修正の直接的な影響はありません
- SCP形式（`user@host:path` 形式）のgit URLを使ってマーケットプレイスを登録している場合、修正後のバージョンでは許可リストとホストが厳密に一致している必要があります。意図した正規のホストが許可リストに正しく登録されているか確認してください
