## 原文（日本語訳）
[Code Review] Claudeによるレビューが100件を超えるプルリクエストで、ベースブランチからのクリーンなマージが行われるたびに、軽量なマージ対応レビューではなくフルレビューが実行されてしまう不具合を修正。

## 原文（英語）
[Code Review] Fixed pull requests with more than 100 Claude reviews getting a full re-review on every clean merge from the base branch instead of the lighter merge-focused review

## 概要
Claude Codeのコードレビュー機能は、ベースブランチをプルリクエストにマージした際、コンフリクトのないクリーンなマージであれば軽量な「マージ対応レビュー」のみを行うよう最適化されています。しかし、そのプルリクエストに対するClaudeのレビュー回数が100件を超えると、この最適化が効かなくなり、クリーンなマージのたびに毎回フルレビューが実行されてしまう不具合がありました。今回の修正により、レビュー件数が100件を超えていても、クリーンなマージ時には正しく軽量なマージ対応レビューが実行されるようになり、無駄な処理時間やコストが削減されます。

## 基本的な使い方
特別な操作は不要です。通常通りPull Requestを作成・更新し、Claudeによるコードレビューを利用するだけで、内部的にクリーンマージ時の処理が最適化されます。

## 実践例

### 長期間にわたり頻繁にレビューが行われているPRの場合
大規模な機能開発などで長期間オープンになっているPRでは、レビュー回数が100件を超えることがあります。修正前は、そのようなPRでベースブランチをマージするたびに、変更点全体を対象としたフルレビューが毎回走り、時間がかかっていました。

```
Before: レビュー回数 >100件のPR
        → ベースブランチをクリーンマージ → フルレビューが実行される（低速）
After:  レビュー回数 >100件のPR
        → ベースブランチをクリーンマージ → 軽量なマージ対応レビューのみ実行（高速）
```

### コンフリクトを伴うマージの場合
なお、マージ時にコンフリクトが発生した場合は、引き続き必要な範囲でより踏み込んだレビューが行われる可能性があります。この修正はあくまで「クリーンな」マージに関するものです。

## 注意点
- 本修正はレビュー件数が100件を超える大規模・長期間のPRに主に影響します。通常規模のPRでは元々問題は発生していませんでした。
- マージ対応レビューと通常のフルレビューでは、チェックする範囲や粒度が異なる場合があります。
