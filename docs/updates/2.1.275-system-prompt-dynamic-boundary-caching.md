## 原文（日本語訳）

`__SYSTEM_PROMPT_DYNAMIC_BOUNDARY__` という行を含む `--system-prompt` に対するプロンプトキャッシュを改善しました。この行より上のテキストは、SDKの配列形式ですでにそうなっているように、グローバルにキャッシュされるようになりました。

## 原文（英語）

Improved prompt caching for a `--system-prompt` that contains a `__SYSTEM_PROMPT_DYNAMIC_BOUNDARY__` line: the text above it is now cached globally, as the SDK's array form already is

## 概要

Claude Codeの `--system-prompt` オプションを使うと、CLI起動時にカスタムのシステムプロンプトを文字列として渡せます。プロンプトの一部にセッションごとに変化しない「静的な」部分と、実行のたびに変化する「動的な」部分が混在している場合、`__SYSTEM_PROMPT_DYNAMIC_BOUNDARY__` という特別な行を境界として挿入することで、その行より上のテキストをプロンプトキャッシュの対象として扱えます。これまでこの挙動はSDK側で配列形式のシステムプロンプトを渡した場合のみグローバルキャッシュの対象でしたが、今回の改善でCLIの文字列形式の `--system-prompt` でも同様にグローバルキャッシュされるようになり、キャッシュヒット率の向上によるコストとレイテンシの削減が期待できます。

## 基本的な使い方

```bash
claude --system-prompt "$(cat <<'EOF'
あなたは有能なコーディングアシスタントです。
常に日本語で回答してください。
__SYSTEM_PROMPT_DYNAMIC_BOUNDARY__
現在の作業ディレクトリ: /home/user/project
EOF
)"
```

`__SYSTEM_PROMPT_DYNAMIC_BOUNDARY__` より上の静的な指示部分がキャッシュ対象になります。

## 実践例

### 固定の役割指示とセッションごとに変わるコンテキストを分離する

チーム全体で共通のルールを `--system-prompt` の先頭に置き、セッションごとに異なる情報（日時やプロジェクト名など）を境界の下に置くことで、共通部分のキャッシュ効率を高められます。

```bash
claude --system-prompt "$(cat <<'EOF'
社内コーディング規約に従ってください。
テストを必ず書いてください。
__SYSTEM_PROMPT_DYNAMIC_BOUNDARY__
本日の日付: 2026-09-17
EOF
)"
```

### 自動化スクリプトから繰り返し呼び出す場合

CIパイプラインなどで `claude --system-prompt` を使ってシステムプロンプトの静的部分を固定したまま繰り返し呼び出すと、今回の改善によりグローバルキャッシュがより効果的に働き、レイテンシとコストの削減が見込めます。

## 注意点

- `__SYSTEM_PROMPT_DYNAMIC_BOUNDARY__` という行はキャッシュの境界を示す特別なマーカーであり、この行自体はプロンプトの内容として送信されません。
- プロンプトキャッシュの挙動やキャッシュ有効期限は、利用しているモデルやAPIプランによって異なります。
