## 原文（日本語訳）

修正: パーミッションプレビューでマスクされるプロバイダーAPIトークンが、シェルの区切り文字（デリミタ）が直後に続く場合でも正しくマスクされるようになりました。

## 原文（英語）

Fixed: provider API tokens that mask on permission previews now mask even when directly followed by shell delimiters

## 概要

Claude Codeがコマンド実行前に表示するパーミッションプレビューでは、プロバイダーのAPIトークンなどの機密情報が自動的にマスクされる仕組みがあります。今回の修正により、トークン文字列の直後に `;` や `&&`、`|` といったシェルの区切り文字が続く場合でも、マスク処理が正しく適用されるようになりました。これまではこのようなケースでトークンがマスクされずにそのまま画面に表示されてしまう可能性がありました。

## 基本的な使い方

この修正は内部的なパーミッションプレビュー表示ロジックに対するものであり、ユーザー側で特別な操作は不要です。Claudeがシェルコマンドを実行する前の確認画面で、APIトークンを含むコマンドが提示された場合、トークン部分は自動的に `***` のような形にマスクされます。

```
Bash(export ANTHROPIC_API_KEY=sk-ant-***;npm run deploy)
```

上記のように、トークンの直後にセミコロンなどの区切り文字が続く場合でも、トークン自体は正しく隠されます。

## 実践例

### 環境変数設定とコマンドを1行で実行する場合

```bash
export OPENAI_API_KEY=sk-xxxxxxxxxxxxxxxx && python script.py
```

このようなコマンドをClaudeが実行しようとした際、以前は `&&` が直後にあることでマスク処理が正しく働かないケースがありましたが、修正後はトークン部分が確実にマスクされてプレビューに表示されます。

### パイプを使ったワンライナー

```bash
curl -H "Authorization: Bearer sk-ant-api03-xxxxxxxx" https://api.example.com | jq .
```

トークンの後に `|` が続く場合でも、パーミッションプレビュー上ではトークン文字列がマスクされた状態で表示されます。

### CI/CDスクリプト実行時の確認

複数のコマンドをセミコロンで連結してデプロイスクリプトを実行させる際も、各トークンが個別に正しくマスクされるため、スクリーンショットや画面共有時に機密情報が露出するリスクが減ります。

## 注意点

- これはパーミューション「プレビュー表示」上のマスク処理の修正であり、実際のコマンド実行内容や環境変数の値自体には影響しません
- マスク処理はあくまで画面表示上の保護であり、ログファイルや履歴に別途トークンが残る可能性がある点は引き続き注意が必要です
- 機密情報を含むコマンドは、可能な限り環境変数ファイル（`.env`など）経由で扱うことが推奨されます
