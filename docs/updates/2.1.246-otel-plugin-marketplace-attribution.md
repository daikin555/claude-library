## 原文（日本語訳）

claude.aiから同期されたプラグインに関するOpenTelemetryプラグインイベントが変更されました。`plugin_id_hash` はプラグインの実際のマーケットプレイスを反映するようになり、管理者によってインストールされたプラグインの場合は `enabled_via` が `admin-install` になります。

## 原文（英語）

Changed OpenTelemetry plugin events for plugins synced from claude.ai: `plugin_id_hash` now reflects the plugin's real marketplace, and `enabled_via` is `admin-install` for admin-installed plugins

## 概要

Claude Codeのプラグインの中には、claude.ai側で管理・同期されているものがあります。これらのプラグインに関するOpenTelemetryのイベントでは、これまで `plugin_id_hash`（プラグインを識別するハッシュ値）が実際のマーケットプレイスの情報を正しく反映しておらず、また管理者によってインストールされたプラグインであっても `enabled_via`（有効化された経路）フィールドがそれを示していないケースがありました。今回の変更でこれらのフィールドが修正され、テレメトリを分析する組織がプラグインの出所や導入経路をより正確に把握できるようになりました。

## 基本的な使い方

この変更はテレメトリのフィールド内容に関する修正であり、ユーザーやプラグイン開発者が何かを設定する必要はありません。OpenTelemetryのエクスポートを有効にしている環境で、プラグイン関連のイベントを確認すると、修正後の値が反映されます。

```json
{
  "event": "plugin_used",
  "plugin_id_hash": "<プラグインの実際のマーケットプレイスを反映したハッシュ>",
  "enabled_via": "admin-install"
}
```

## 実践例

### 組織内で使われているプラグインの出所を監査する

OpenTelemetryのダッシュボードでプラグイン利用状況を分析している管理者は、`plugin_id_hash` が正しいマーケットプレイスを反映するようになったことで、どのマーケットプレイス由来のプラグインがどれだけ使われているかを正確に集計できます。

### 管理者インストールと個人インストールを区別する

`enabled_via` が `admin-install` として正しく記録されるようになったため、組織のポリシーとして展開したプラグインと、個々の開発者が自分でインストールしたプラグインの利用状況を区別して分析できます。

### claude.ai経由で同期されたプラグインのコンプライアンス確認

claude.aiで管理しているプラグイン構成が実際の利用状況と一致しているかを確認する際、修正後の属性情報によって、意図したマーケットプレイスのプラグインが使われているかを検証しやすくなります。

## 注意点

- この修正はclaude.aiから同期されたプラグインのイベントに関するものです。ローカルで開発・インストールしたプラグインのイベントには直接関係しません
- OpenTelemetryによるテレメトリ収集を有効化していない環境では、この変更の影響を目にすることはありません
