## 原文（日本語に翻訳）

Remote Controlクライアントにおいて、モデルの切り替え、再接続、または組織（org）チェックの失敗が発生した際に、古いfast-modeステータスがそのまま残ってしまう不具合を修正しました。

## 原文（英語）

Fixed Remote Control clients keeping a stale fast-mode status after a model switch, reconnect, or failed org check

## 概要

Claude CodeのRemote Control機能を使うと、スマートフォンやブラウザなどの別クライアントからセッションをリモートで操作・閲覧できます。この際、`/fast`コマンドで切り替えるfast mode（高速応答モード）のオン/オフ状態もクライアント側に表示されますが、モデルの切り替えや再接続、組織チェックの失敗といったイベントが発生すると、クライアント側の表示だけが古い状態のままキャッシュされ、実際のセッション状態と食い違ってしまう問題がありました。バージョン2.1.219では、こうしたケースでもRemote Controlクライアントのfast-modeステータス表示が正しく最新の状態に同期されるよう修正されています。

## 基本的な使い方

Remote Controlを有効化してセッションをリモートクライアントと接続する基本的な流れは以下の通りです。

```bash
# Claude Codeのセッション内でRemote Controlを有効化
/remote
```

`/remote`を実行すると、接続用のリンクまたはQRコードが表示されます。これをスマートフォンやブラウザで開くことで、そのセッションの入出力をリモートから閲覧・操作できるようになります。

fast modeの切り替えは通常通り以下のコマンドで行います。

```bash
/fast
```

この状態変更は、接続中のRemote Controlクライアント側にもリアルタイムで反映される想定です。

## 実践例

### モデル切り替え後にリモート側の表示を確認する

fast modeが有効な状態からfast modeに対応しないモデルへ切り替えた場合、以前はリモートクライアント側で「fast mode: ON」の表示が残ってしまうことがありました。修正後は、モデル切り替えのタイミングでリモートクライアントに最新のステータスがプッシュされ、表示が正しく更新されます。

```bash
# fast modeを有効化した状態でモデルを切り替える
/fast
/model claude-opus-5
```

手元での確認手順としては、以下のように操作すると分かりやすいです。

1. `/remote` でRemote Controlを有効化し、スマートフォン等で接続する
2. `/fast` でfast modeをONにし、リモート側の表示がONになることを確認する
3. `/model` で別のモデルに切り替える
4. リモート側の表示が古いままONで固定されていないか、正しく更新されているかを確認する

### 再接続時にステータスがリセットされることを確認する

ネットワークの瞬断などでRemote Controlクライアントが一度切断され、再接続するケースでも、以前は切断前のfast-modeステータスがキャッシュされたまま表示されることがありました。

```bash
# セッション側でfast modeを一時的に切り替えておく
/fast

# クライアント側のネットワークを切断→再接続
# （例: 機内モードのON/OFFなど）

# → 再接続後、リモートクライアントは
#   セッションの現在のfast-mode状態を取得し直して表示する
```

再接続後は、クライアント側が保持していた古いキャッシュではなく、サーバー側の最新状態が改めて同期されるようになりました。

### 組織チェック失敗時の挙動を確認する

組織（org）に紐づく設定の検証が何らかの理由で失敗した場合にも、fast-modeステータスが不整合な表示のまま止まってしまうケースがありました。この修正により、組織チェックが失敗した場合でも、リモートクライアント側の表示が古いキャッシュに固定されず、正しい状態（またはエラー状態）に更新されるようになっています。運用上は、組織チェックのエラーが表示された際にリモート側の画面を再読み込みする必要がなくなり、そのまま最新状態を確認できます。

## 注意点

- 本修正はRemote Controlクライアント側の「表示」の同期に関するバグ修正であり、fast mode自体の動作ロジックを変更するものではありません。
- fast modeに対応していないモデルに切り替えた場合、fast modeは自動的に無効化されるため、リモート側の表示もそれに合わせて「OFF」に更新されます。
- 複数のRemote Controlクライアントを同時に接続している場合、すべてのクライアントに対して同期が行われることが期待されますが、ネットワーク状況によっては反映に多少のタイムラグが生じる可能性があります。
- 組織チェックの失敗が継続する場合は、fast-modeの表示だけでなく組織側の設定・権限も合わせて確認してください。
