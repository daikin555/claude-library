## 原文（日本語に翻訳）

エンタープライズポリシーにおいて、素のリポジトリURLに対する `url` 型の `blockedMarketplaces` エントリは、CLIがそのURLを git clone として分類した場合でも、引き続きそのURLをブロックし続けるようになりました。

## 原文（英語）

Enterprise policy: a url-typed `blockedMarketplaces` entry for a bare repo URL keeps blocking that URL when the CLI classifies it as a git clone

## 概要

組織の管理設定（managed settings）では、`blockedMarketplaces` によって特定のマーケットプレイス供給元をブロックできます。従来、`url` 型で素のリポジトリURL（例: `https://gitlab.com/some-org/some-repo`）を指定してブロックしていても、CLI内部でそのURLが「git clone」として分類された場合には、ブロック判定がすり抜けてしまう可能性がありました。v2.1.232では、この分類の違いによらず、`url` 型で指定されたブロック対象URLが一貫してブロックされ続けるよう修正されました。

## この変更が影響する場面

これは管理者が設定する組織ポリシーの適用範囲に関するバグ修正であり、ユーザーが直接操作する機能ではありません。以下のような場面で効果を発揮します。

- 管理者がmanaged settingsで特定のリポジトリURLを `blockedMarketplaces` に登録している場合、そのURLに対するマーケットプレイス追加やプラグインのインストール・更新の試みが、CLI内部の分類方法に関わらず確実にブロックされるようになります。

## 実践例

### 特定のリポジトリURLを組織全体でブロックする

```json
{
  "blockedMarketplaces": [
    { "type": "url", "url": "https://gitlab.com/untrusted-org/untrusted-repo" }
  ]
}
```

managed settingsにこのように設定しておくと、該当のリポジトリURLをマーケットプレイスとして追加しようとした際にブロックされます。

### git cloneとして分類されるURLでもブロックが有効に働くことを確認する

```
/plugin marketplace add https://gitlab.com/untrusted-org/untrusted-repo
# -> ポリシーにより追加がブロックされる
```

CLIがこのURLを内部的に「git clone」経由として扱うケースでも、v2.1.232からはブロック設定が正しく効くようになりました。

### 他のsource形式（github等）と併用する

```json
{
  "blockedMarketplaces": [
    { "type": "url", "url": "https://gitlab.com/untrusted-org/untrusted-repo" },
    { "source": "github", "repo": "untrusted-org/*" }
  ]
}
```

`url` 型のエントリと、`source`/`repo` を使った他形式のエントリを組み合わせて、GitHub・GitLabなど複数のホストにまたがるブロックポリシーを構成できます。

## 注意点

- Claude Code v2.1.232での修正です。
- `blockedMarketplaces` はmanaged settings（組織の管理者向け設定）専用の機能です。
- ブロック判定は、マーケットプレイスの追加時だけでなく、プラグインのインストール・更新・リフレッシュ・自動更新の際にも、ネットワークやファイルシステム操作の前にチェックされます。
- ポリシー設定後に追加されたマーケットプレイスだけでなく、ポリシー設定前から登録されていたマーケットプレイスの供給元が許可リストに一致しなくなった場合も、インストールや更新が拒否されます。
