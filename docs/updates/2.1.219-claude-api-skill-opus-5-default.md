## 原文（日本語に翻訳）

`claude-api` スキルが更新され、デフォルトで推奨するモデルがClaude Opus 5になりました。あわせて、Opus 4.8を利用中のユーザー向けにOpus 5への移行パスに関する情報も追加されています。

## 原文（英語）

Updated the claude-api skill to default to Claude Opus 5, with a migration path from Opus 4.8

## 概要

Claude Codeにはビルトインのスキルとして、Claude API（Anthropic SDK）の利用方法を案内する `claude-api` スキルが用意されています。今回のアップデートでは、このスキルがデフォルトで案内するモデルがClaude Opus 5に切り替わり、これまでOpus 4.8を利用していたユーザーが迷わず移行できるよう、モデルIDの変更点や注意点を含む移行ガイダンスが組み込まれました。開発者がAPIやSDKでどのモデルを使うべきか尋ねたとき、Claude Codeは常に最新の推奨構成を提示できるようになります。

## 基本的な使い方

`claude-api` スキルは明示的に呼び出す必要はなく、Claude API・Anthropic SDKに関する話題（モデルID、料金、パラメータ、ストリーミング、Tool use、MCP、プロンプトキャッシュなど）が会話に含まれると自動的に参照されます。

```bash
claude "Claude APIで使うべき最新のモデルIDを教えて"
```

このように尋ねると、Claude Codeは `claude-api` スキルを参照し、現時点で推奨されるモデル（Claude Opus 5）とそのモデルIDを回答します。

## 実践例

### 新規プロジェクトで推奨モデルを確認する

新しくAnthropic SDKを使ったプロジェクトを始める際に、モデル選定をClaude Codeに相談すると、スキルの更新内容に基づいてOpus 5がデフォルトの推奨モデルとして提示されます。

```python
import anthropic

client = anthropic.Anthropic()

message = client.messages.create(
    model="claude-opus-5",  # claude-apiスキルが提示する最新の推奨モデル
    max_tokens=1024,
    messages=[
        {"role": "user", "content": "このコードのリファクタリング案を教えて"}
    ],
)
print(message.content)
```

### 既存のOpus 4.8実装をOpus 5へ移行する

すでにOpus 4.8でコードを書いている場合、Claude Codeに「Opus 4.8からOpus 5に移行したい」と伝えると、スキルに追加された移行パス情報を使って、モデルIDの置き換え箇所や挙動差分の確認ポイントを含む移行チェックリストを提示してくれます。

```diff
- model="claude-opus-4-8",
+ model="claude-opus-5",
```

```bash
claude "Opus 4.8からOpus 5への移行で確認すべき点をリストアップして"
```

Claude Codeはこの質問に対し、`claude-api` スキルの移行ガイダンスを参照し、モデルIDの変更・料金差・出力傾向の変化などを整理して回答します。

### ストリーミングやTool useの互換性を確認する

Opus 5移行時にストリーミング処理やTool use（関数呼び出し）の実装を変更する必要があるかを尋ねると、スキルの知識に基づいて、APIレスポンス形式やパラメータの互換性についても案内されます。

```bash
claude "Opus 5に移行した場合、既存のtool useの実装はそのまま使える？"
```

## 注意点

- モデルIDが `claude-opus-4-8` から `claude-opus-5` 系のIDへ変わるため、コード内でモデルIDをハードコーディングしている箇所は洗い出して置き換える必要があります。
- Opus 5とOpus 4.8では料金体系（入力・出力トークン単価、プロンプトキャッシュの割引率など）が異なる可能性があるため、移行前に最新の料金ページで確認することが推奨されます。
- スキルが提示する情報はあくまでClaude Codeの内部ナレッジに基づくものであり、本番導入前には必ずAnthropic公式ドキュメントの最新情報も併せて確認してください。
- 既存のプロンプト設計やレスポンス品質がモデル変更によって変わる可能性があるため、移行後は評価用のテストセットで出力品質を再検証することが望ましいです。
- コンテキストウィンドウやレート制限など、モデルごとの仕様差がある場合は、大量リクエストを行う本番システムでは事前に負荷試験を行うことを推奨します。
