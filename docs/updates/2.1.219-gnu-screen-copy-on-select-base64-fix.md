## 原文（日本語に翻訳）

GNU screen内でcopy-on-select（選択範囲の自動コピー）を行うと、選択したテキストがクリップボードにコピーされる代わりに、base64エンコードされた文字列がそのままターミナルに表示されてしまう不具合を修正しました。

## 原文（英語）

Fixed copy-on-select inside GNU screen printing base64 into the terminal instead of copying the selection

## 概要

Claude CodeのターミナルUIは、マウスでテキストを選択すると自動的にクリップボードへ内容を送る「copy-on-select」機能を備えています。これはOSC 52などのターミナルエスケープシーケンスを使ってターミナルエミュレータのクリップボードにアクセスする仕組みですが、GNU screen配下で実行すると、screen側のエスケープシーケンス処理とかみ合わず、送信したはずのエスケープシーケンスがそのままテキストとして画面に「印字」されてしまうことがありました。結果として、選択操作のたびに大量のbase64文字列が端末に表示され、作業の妨げになっていました。バージョン2.1.219でこの問題が修正され、GNU screen環境でも余計な文字列を表示せずに選択範囲を正しくクリップボードへコピーできるようになりました。

## 基本的な使い方

修正の適用を確認するには、まずClaude Codeのバージョンを確認します。

```bash
claude --version
# 2.1.219以降であればこの修正が含まれています
```

GNU screenのセッション内でClaude Codeを起動し、通常どおりマウスでテキストをドラッグ選択するだけです。追加の設定変更やコマンド操作は不要です。

```bash
screen -S claude-session
claude
# セッション内でテキストを選択 → クリップボードにコピーされる
```

## 実践例

### リモートサーバー上のscreenセッションでの動作確認

SSH接続先のサーバーでscreenを起動し、Claude Codeの出力の一部を選択してみます。修正前は選択のたびにエスケープシーケンスがそのまま画面に流れ込んでいましたが、修正後はターミナル側で正しく処理され、画面には何も表示されずクリップボードだけが更新されます。

```bash
ssh myserver
screen -R work
claude
# Claudeの応答テキストを選択
# → ローカル端末のクリップボードに反映される（余計な文字列は出ない）
```

ローカルのターミナルエミュレータ側でOSC 52によるクリップボード書き込みが許可されている必要があるため、iTerm2やWindows Terminal、Alacrittyなどを使用している場合は、設定でOSC 52（クリップボードへの書き込み）を許可しているか確認してください。

### `.screenrc` でOSC 52パススルーを明示的に設定する

GNU screenは内部的にOSC 52シーケンスを解釈・中継するため、`termcapinfo` で `Ms`（クリップボード書き込み）ケーパビリティを明示しておくと、screen経由でも確実にホスト端末までシーケンスが届きやすくなります。

```bash
# ~/.screenrc
termcapinfo xterm*|screen*|tmux* 'Ms=\E]52;%p1%s;%p2%s\007'
```

設定後は一度screenセッションを終了して再起動し、Claude Codeでの選択コピーが期待通り動くかを確認してください。

### ネストしたscreen/tmux環境での注意確認

screenをtmux内で使う、あるいはscreenを多重にネストして使う構成では、OSC 52シーケンスが複数回ラップされて正しく透過しないことがあります。この修正はClaude Code単体でのGNU screen対応を改善するものであり、screenとtmuxを二重に挟むような複雑な構成では、各ツール側のパススルー設定（screenの `termcapinfo`、tmuxの `set-clipboard` や `allow-passthrough`）も併せて見直すことを推奨します。

```bash
# tmux側の設定例（~/.tmux.conf）
set -g set-clipboard on
set -g allow-passthrough on
```

## 注意点

- この修正はClaude Code側の対応であり、GNU screen自体のバージョンによっては挙動が異なる場合があります。可能であればscreen 4.8系以降など比較的新しいバージョンを使用することを推奨します（`screen --version` で確認できます）。
- OSC 52によるクリップボード連携は、最終的に使用しているターミナルエミュレータがOSC 52の受信・クリップボード書き込みに対応している必要があります。対応していない、または設定でブロックしている端末では、修正後も選択コピーが機能しない場合があります。
- tmux配下でscreenを使う、あるいはSSHを多段で経由するなど、経路が複雑になるほどエスケープシーケンスが途中で欠落・変質しやすくなります。うまく動作しない場合は、まずネストのない単純なscreenセッションで動作確認することを勧めます。
- 修正後も画面にbase64文字列らしきものが表示される場合は、Claude Codeのバージョンが2.1.219未満のままになっていないか、`claude update` などで最新化されているかを確認してください。
