## 原文（日本語訳）

既にリポジトリを持つ実行中のクラウドセッションに、フォーク元のような別のGitHubオーナーのリポジトリをアタッチできるようになりました。Slackから開始したセッションも対象です。

## 原文（英語）

[Cloud sessions] Added attaching a repository from a different GitHub owner, such as a fork's upstream, to a running cloud session that already has one, including sessions started from Slack

## 概要

GitHubでフォークしたリポジトリを使ってクラウドセッションを開始した場合、フォーク元（upstream）のリポジトリの情報も参照したくなることがあります。これまでは、実行中のクラウドセッションに後から別のオーナーのリポジトリを追加でアタッチすることができませんでした。今回の変更で、既にリポジトリがアタッチされている実行中のクラウドセッションに対して、フォーク元のような別のGitHubオーナーのリポジトリを追加でアタッチできるようになりました。これはClaude Tag（Slack連携）から開始したセッションでも利用できます。

## 基本的な使い方

実行中のクラウドセッションの画面またはSlackのスレッドから、リポジトリのアタッチ操作を行い、別のオーナーのリポジトリ（フォーク元など）を指定します。

## 実践例

### フォークしたOSSプロジェクトへの貢献作業

自分のフォークで作業を進めているクラウドセッションに、途中からupstreamのリポジトリをアタッチして、最新の変更内容と比較しながら作業を続けられます。

### Slackから開始したセッションでの複数リポジトリ参照

Slackで `@Claude` にメンションして開始したセッションでも、後から関連する別オーナーのリポジトリを追加し、複数リポジトリにまたがる調査や作業を行えます。

## 注意点

- アタッチする別オーナーのリポジトリへのアクセス権限が、クラウドセッションの実行アカウントに付与されている必要があります
- この機能はクラウドセッション（ローカル実行ではない）に関するものです
