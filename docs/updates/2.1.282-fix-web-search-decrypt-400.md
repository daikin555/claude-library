## 原文（日本語訳）

APIが復号できないWeb検索結果を会話履歴に含む場合（例えば、サードパーティ製ゲートウェイ経由で回答されたターンからのものなど）に、すべてのリクエストが400エラーで失敗していた不具合を修正しました。

## 原文（英語）

Fixed every request failing with a 400 error in conversations whose history holds web search results the API cannot decrypt (for example, from a turn answered through a third-party gateway)

## 概要

Claude Codeの会話履歴にWeb検索結果が含まれる場合、そのデータは暗号化された形で保持されます。しかし、サードパーティ製のAPIゲートウェイなどを経由して生成されたWeb検索結果が履歴に混ざっていると、Anthropic APIがその内容を復号できず、以降のすべてのリクエストが400エラーで失敗するようになっていました。今回の修正により、この状態が解消され、該当する会話でも通常どおりやり取りを継続できます。

## 基本的な使い方

ユーザー側で特別な操作は不要です。修正はClaude Code本体側で行われており、該当条件に当てはまる会話でも自動的に正常なリクエストが送られるようになります。

## 実践例

### サードパーティゲートウェイ併用環境での継続利用

一部のターンをサードパーティ製ゲートウェイ経由のモデルで処理し、別のターンを直接Anthropic APIで処理するようなハイブリッド構成でも、Web検索結果を含むターンをまたいで会話を継続できます。

### 長時間セッションの安定性向上

Web検索を多用する長時間の調査セッションで、途中から突然すべてのリクエストが失敗するという現象がなくなり、作業を中断せずに続けられます。

## 注意点

- この修正は過去に発生したエラー状態を防ぐものであり、既に破損した会話履歴自体を修復するものではありません。エラーが再発する場合は新しいセッションの開始を検討してください
- サードパーティゲートウェイ経由の利用構成に特有の問題であり、直接Anthropic APIのみを利用している場合は影響を受けにくい不具合です
