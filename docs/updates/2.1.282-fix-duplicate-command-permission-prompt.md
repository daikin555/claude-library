## 原文（日本語訳）

リモートセッションのワーカーが再起動した際に、復元された権限プロンプトで承認済みだったコマンドが二重に実行されていた不具合を修正しました。

## 原文（英語）

Fixed a command approved on a restored permission prompt running twice when a remote session's worker restarted

## 概要

Remote Controlなどでリモートのワーカー上でセッションを実行している際、ワーカーが再起動すると、以前表示されていた権限プロンプト（コマンド実行の承認待ち）が復元されることがあります。このとき、既に承認していたはずのコマンドが再度実行され、結果として同じコマンドが二重に走ってしまう不具合がありました。ファイル変更や外部APIの呼び出しを伴うコマンドの場合、これは意図しない重複実行につながる可能性があります。今回の修正でこの問題が解消されました。

## 基本的な使い方

ユーザー側の対応は不要です。Remote Controlなどでリモートワーカーを利用する通常のフローの中で、この修正が自動的に適用されます。

## 実践例

### 外部APIを呼び出すコマンドの安全な実行

デプロイスクリプトや外部サービスへの通知など、副作用のあるコマンドを承認した直後にワーカーが再起動しても、意図せず二重実行されるリスクがなくなります。

### 長時間のリモートセッション運用

ネットワークの瞬断などでワーカーが再起動しやすい環境でリモートセッションを長時間運用する場合でも、承認したコマンドの実行回数について安心して任せられます。

## 注意点

- この不具合はリモートセッションのワーカー再起動というタイミングに特有のものです。ローカルセッションのみを使う場合は影響を受けません
- 冪等性のない（繰り返し実行すると結果が変わる）コマンドを承認する際は、引き続き内容を確認してから承認することをおすすめします
