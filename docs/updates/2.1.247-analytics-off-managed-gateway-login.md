## 原文（日本語訳）

管理設定によってゲートウェイ経由のログインが強制されている場合、またはカスタムOAuthデプロイメントが設定されている場合、アナリティクスがログイン後だけでなく起動時から一貫してオフになるように変更されました。

## 原文（英語）

Changed analytics to stay off from startup, not only after login, when managed settings force gateway login or a custom OAuth deployment is configured

## 概要

企業のIT管理者が管理設定でゲートウェイ経由のログインを強制している場合や、カスタムOAuthデプロイメントを利用している場合、以前はログインが完了するまでの起動直後の期間にアナリティクスが送信されてしまう可能性がありました。今回の変更で、こうした構成ではログイン前の起動時点からアナリティクスが一貫してオフになり、意図しないデータ送信の隙間がなくなります。

## 基本的な使い方

エンドユーザーが操作する項目はありません。管理者が管理設定（managed settings）でゲートウェイログインを強制する構成、またはカスタムOAuthデプロイメントを設定している場合、Claude Codeは起動直後からアナリティクス送信を行いません。

```json
// 管理者向けmanaged-settings.jsonの例（イメージ）
{
  "forceLoginMethod": "gateway"
}
```

このような設定が有効な環境では、Claude Codeの起動からログイン完了までの間も含めて、アナリティクスは常にオフの状態になります。

## 実践例

### 厳格なプライバシー要件を持つ企業でのゲートウェイログイン運用

社内ゲートウェイ経由のログインを必須としている企業では、ログイン前の短い期間であってもアナリティクスデータが外部に送信されることを避けたいケースがあります。今回の変更により、起動時点から一貫してオフになるため、こうした要件に合致します。

### カスタムOAuthデプロイメントを利用する組織

独自のOAuthプロバイダーと連携したデプロイメントを構築している組織では、ログインフロー自体が特殊であるため、ログイン完了前のタイミングでの挙動が特に重要になります。起動時からアナリティクスがオフになることで、より予測可能な挙動になります。

### コンプライアンス監査でのデータフロー確認

セキュリティやコンプライアンスの監査担当者が、Claude Codeがどのタイミングでどのようなデータを送信するかを確認する際、「管理設定でゲートウェイログインを強制している環境では起動時から一貫してオフ」という明確な挙動になったことで、監査がしやすくなります。

## 注意点

- この挙動は管理設定（managed settings）でゲートウェイログインが強制されている場合、またはカスタムOAuthデプロイメントが設定されている場合に適用されます
- 通常のログイン方式（Anthropic Consoleやサブスクリプションログインなど）を使う一般的な構成には影響しません
- アナリティクスのオン/オフ自体を個別に切り替える設定ではなく、特定の管理者構成における起動直後の挙動を一貫させるための変更です
