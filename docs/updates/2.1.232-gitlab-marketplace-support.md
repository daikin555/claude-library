## 原文（日本語に翻訳）

プラグインマーケットプレイスにGitLabサポートが追加されました。素の（bare）`gitlab.com` リポジトリURL（ネストしたサブグループを含む）が `github.com` のURLと同様にクローンできるようになり、クローン時の認証失敗ヒントには実際に使用しているgitホスト名が表示されるようになりました。

## 原文（英語）

Added GitLab support to plugin marketplaces: bare `gitlab.com` repo URLs (including nested subgroups) now clone like `github.com` URLs, and clone auth-failure hints name your actual git host

## 概要

これまでプラグインマーケットプレイスの追加は主にGitHubリポジトリを前提としていましたが、v2.1.232からはGitLabリポジトリも同様にサポートされるようになりました。素の `gitlab.com` のリポジトリURLを指定するだけで、`github.com` のURLと同じ感覚でマーケットプレイスとしてクローンできます。GitLab特有のネストしたサブグループ構成（例: `gitlab.com/group/subgroup/project`）にも対応しています。また、クローンに失敗して認証エラーが発生した場合のヒントメッセージも改善され、GitHubかGitLabかを問わず実際に使用しているgitホストの名前が表示されるようになりました。

## 基本的な使い方

```
/plugin marketplace add gitlab.com/my-group/my-marketplace
```

素の `gitlab.com` リポジトリURLを指定するだけで、GitHubの場合と同じ手順でマーケットプレイスを追加できます。

## 実践例

### GitLabのネストしたサブグループにあるマーケットプレイスを追加する

```
/plugin marketplace add gitlab.com/my-org/team-a/subteam/plugin-marketplace
```

深い階層のサブグループにあるリポジトリでも、`github.com` の場合と同様にそのままクローンできます。

### 認証エラー時のヒントメッセージを確認する

```
/plugin marketplace add gitlab.com/private-org/private-marketplace
# -> 認証に失敗した場合、GitLabへの認証設定を促すヒントが表示される
```

以前はGitHub前提のヒント文言が表示されることがありましたが、v2.1.232からは実際に使用しているgitホスト（この場合はGitLab）に応じたヒントが表示されます。

### GitHubとGitLab両方のマーケットプレイスを併用する

```
/plugin marketplace add github.com/org-a/marketplace-a
/plugin marketplace add gitlab.com/org-b/marketplace-b
```

社内でGitHubとGitLabが混在している環境でも、それぞれのホストに対応したマーケットプレイスを違和感なく併用できます。

## 注意点

- Claude Code v2.1.232での変更です。
- 対応するのは素の `gitlab.com` リポジトリURL（ネストしたサブグループを含む）です。
- 認証失敗時のヒントメッセージは、GitHub/GitLabなど実際に使用しているgitホストに応じて内容が変わります。
- 組織で `strictKnownMarketplaces`（`allowedMarketplaces`）や `blockedMarketplaces` を設定している場合、GitLabのURLについても同様にポリシーの対象となります。
