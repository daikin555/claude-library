## 原文（日本語訳）

`claude self-hosted-runner` が `--base-dir` を作成または書き込みできない場合に登録してもセッションが毎回失敗する問題を修正しました。スタートアップ時に明確なエラーメッセージを表示して終了するようになりました。

## 原文（英語）

Fixed `claude self-hosted-runner` registering and then failing every session when `--base-dir` cannot be created or written; it now exits at startup with a clear error

## 概要

セルフホストランナーは、`--base-dir` フラグで指定したディレクトリに git チェックアウト、セッションデータなどの作業ファイルを保存します。このアップデートにより、起動時にそのディレクトリを作成または書き込みできない場合（ディスク容量不足、権限問題、無効なパスなど）、ランナーはスタートアップ直後に明確なエラーメッセージを表示して終了するようになりました。以前は登録だけは成功して、その後のセッションすべてが失敗する無言のエラーが発生していました。

## 基本的な使い方

セルフホストランナーを起動する際に `--base-dir` を指定します：

```bash
claude self-hosted-runner --base-dir /var/lib/claude --environment-secret-file /etc/claude/secret
```

`--base-dir` ディレクトリが作成または書き込みできない場合、起動時に以下のようなエラーメッセージが表示されます：

```
Error: cannot create or write to base directory '/var/lib/claude': permission denied
```

スタートアップ時にエラーメッセージが表示されるため、セッションが失敗する前に問題を特定して対応できます。

## 実践例

### ディレクトリ権限が不足しているケース（セットアップ前の診断）

新しいサーバーにセルフホストランナーをセットアップする際、初めから権限を誤って設定してしまった場合：

```bash
# ランナーユーザーが /var/lib/claude に書き込み権限がない場合
$ sudo useradd -m claude-runner
$ sudo mkdir -p /var/lib/claude
$ sudo chown root:root /var/lib/claude  # ← 権限が間違っている
$ sudo chmod 700 /var/lib/claude

# ランナー起動時にスタートアップエラーが発生
$ claude self-hosted-runner --base-dir /var/lib/claude \
    --environment-secret-file /etc/claude/secret
Error: cannot create or write to base directory '/var/lib/claude': permission denied

# 権限を修正
$ sudo chown claude-runner:claude-runner /var/lib/claude
$ sudo chmod 700 /var/lib/claude

# 再度起動（成功）
$ claude self-hosted-runner --base-dir /var/lib/claude \
    --environment-secret-file /etc/claude/secret
```

### CI/CD パイプラインでフリート展開時の問題を素早く発見

複数のランナーインスタンスを自動展開する場合、ディスク容量やマウント設定に問題があると、展開直後に判明します：

```bash
# Kubernetes Job または Docker Compose で起動
docker run -e SELF_HOSTED_RUNNER_ENVIRONMENT_SECRET=$SECRET \
  ghcr.io/anthropic/claude-code-runner:latest \
  self-hosted-runner --base-dir /invalid/path/that/does/not/exist

# 新しい動作：スタートアップ時にエラーで即座に失敗
# → ロードバランサーにホストが登録される前に失敗
# → 健全なホストだけが本番環境に投入される

# 以前の動作：登録は成功してセッション開始時に失敗
# → ロードバランサーにホストが登録される
# → 数十のセッションがそれぞれ失敗する
# → 無言のエラーで原因特定に時間がかかった
```

## 注意点

- **基本的な使い方：** ランナーを起動する前に、`--base-dir` に指定するディレクトリが ランナー実行ユーザーによって作成および書き込み可能であることを確認してください
- **オーナーシップ確認：** ディレクトリのオーナーシップとパーミッション（例：`chown claude-runner:claude-runner`, `chmod 700`）を確認し、実行ユーザーに適切な権限があることを保証してください
- **ディスク容量：** `--base-dir` が配置されるストレージに十分な空き容量があることを確認してください。セッションが多い場合、複数の git チェックアウトが同時に保存されます
- **マウント確認：** コンテナ化された環境では、`--base-dir` が所属するマウントポイントが正しくマウントされていることを確認してください
- **フリート運用者向け：** 複数のランナーを展開する際は、スタートアップエラーを監視し、ランナーが正常に起動したことを確認してからセッション実行を開始してください
- **サイレント登録失敗の防止：** このアップデートにより、ディレクトリ権限の問題でランナーが無言で登録だけ成功して後続セッションが失敗する問題が排除されました
