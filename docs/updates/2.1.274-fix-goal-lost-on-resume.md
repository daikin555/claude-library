## 原文（日本語訳）

コンテキスト圧縮（compaction）が行われたセッションを `--continue` や `--resume` で再開した際に、アクティブな `/goal` が失われてしまう問題を修正しました。

## 原文（英語）

Fixed an active `/goal` being lost when resuming (`--continue` / `--resume`) a session that had compacted

## 概要

`/goal` コマンドで設定した自律的な目標は、セッションを通じて維持されるべき状態ですが、これまではコンテキスト圧縮が発生したセッションを `--continue` や `--resume` で再開すると、その `/goal` の情報が失われてしまい、意図せず自律実行が止まってしまう不具合がありました。今回の修正により、圧縮後のセッションを再開してもアクティブな `/goal` が正しく引き継がれるようになりました。

## 基本的な使い方

```bash
# 目標を設定してセッションを開始
claude
> /goal このリポジトリの型エラーをすべて修正する

# 何らかの理由で中断した後、セッションを再開
claude --continue
```

修正後は、圧縮を経たセッションであっても `/goal` の状態が保持されたまま再開されます。

## 実践例

### 長時間タスクを分割して再開する場合

大きなゴールを設定して作業させ、途中で意図的にセッションを終了し、後で `--continue` や `--resume` を使って作業を再開するようなワークフローでも、修正後は `/goal` が失われずに再開後も自律的な作業が継続されます。

```bash
claude --resume <session-id>
```

### 予期しない中断からの復旧

ネットワーク断や端末の再起動などでセッションが予期せず中断した場合でも、`--resume` で再開すればアクティブな `/goal` が保持されたままタスクを再開できます。

## 注意点

- この修正はコンテキスト圧縮が発生していたセッションを再開するケースに関するものです。圧縮が発生していないセッションの再開には影響しません。
- `/goal` を使った自律実行では、意図しない挙動を避けるため、再開後にゴールの内容が想定通りかを確認することをおすすめします。
