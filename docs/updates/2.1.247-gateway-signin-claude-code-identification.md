## 原文（日本語訳）

Claudeアプリのゲートウェイへのサインインリクエストが、Claude Codeであることを識別できるように変更されました。デバイス認可パラメータに `surface=claude_code` が付与され、User-Agentも `claude-code/<バージョン>` の形式になります。

## 原文（英語）

Changed Claude apps gateway sign-in requests to identify Claude Code (a `surface=claude_code` device-authorization parameter and a `claude-code/<version>` User-Agent)

## 概要

Claude Codeは内部的にClaudeアプリ向けの認証ゲートウェイを利用してサインインを行いますが、これまでのリクエストにはどのクライアント（Claude CodeなのかWeb版なのかなど）から送られたものかを区別する情報が明確に含まれていませんでした。今回の変更で、デバイス認可フローのパラメータに `surface=claude_code` が追加され、User-Agentヘッダーも `claude-code/<バージョン>` という形式になり、ゲートウェイ側でリクエスト元がClaude Codeであることを正確に識別できるようになりました。

## 基本的な使い方

ユーザーが特別に操作する項目はありません。通常のログインフロー（`/login` やブラウザ経由の認証フロー）を実行するだけで、内部的に送信されるリクエストに識別情報が自動的に付与されます。

```bash
claude /login
```

この際、デバイス認可リクエストには `surface=claude_code` パラメータが含まれ、HTTPリクエストのUser-Agentは `claude-code/2.1.247` のような形式になります。

## 実践例

### 企業のIT部門によるアクセス監視・分析

企業のIT部門やセキュリティチームがゲートウェイ側のログを分析する際、どのリクエストがClaude Code由来かを正確に区別できるようになり、クライアント種別ごとの利用状況把握やトラブルシューティングが容易になります。

### バージョン別の問題調査

サポート対応時に、User-Agentに含まれるバージョン情報（`claude-code/<version>`）を使って、特定バージョンのClaude Codeで発生している認証関連の問題を特定しやすくなります。

### 複数のClaudeクライアントを併用する組織でのアクセス管理

Web版やモバイル版などの他のClaudeクライアントとClaude Codeを併用している組織では、ゲートウェイ側でクライアントごとにアクセスポリシーやレート制限を分けて管理する際の判別材料として活用できます。

## 注意点

- ユーザーから見える認証フローの操作方法自体に変更はありません
- この識別情報はゲートウェイ側でのログ・分析・アクセス制御のために付与されるものであり、エンドユーザーが直接参照する項目ではありません
- カスタムOAuthデプロイメントやゲートウェイ構成によっては、識別情報の扱いが管理者側の設定に依存する場合があります
