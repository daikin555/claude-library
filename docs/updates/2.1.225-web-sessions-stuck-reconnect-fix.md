## 原文（日本語訳）

Claude Codeウェブセッションがスタック状態として誤報告され、再接続のたびに増加し続けるイベントバックログが再送信される問題が修正されました。

## 原文（英語）

Fixed Claude Code on the web sessions being misreported as stuck, re-sending a growing event backlog on every reconnect

## 概要

Claude Code on the web（claude.ai/code）のセッションが、スタック状態にないにもかかわらず「スタック」と誤検出される問題が修正されました。同時に、再接続時にこれまでのすべてのイベントを繰り返し送信していた非効率な動作も改善されました。これにより、ウェブセッションの信頼性が向上し、特に不安定なネットワーク環境での使用体験が改善されます。

## 基本的な使い方

Claude Code on the webは、claude.ai/codeのブラウザインターフェース上で、Anthropicのクラウドインフラストラクチャ内でセッションを実行します。セッションは接続が一時的に失われても持続し、再接続時に自動的に復旧します。

この修正により、以下の動作が改善されました：

1. **スタック検出の精度向上** - セッションが実際に動作している場合、それを正確に認識し、誤った「スタック」表示がされなくなりました。
2. **イベント送信の効率化** - 再接続時に過去のすべてのイベントを再送信するのではなく、必要なものだけを送信するようになりました。
3. **ネットワーク負荷の軽減** - 成長し続けるバックログを送信しないため、低速またはロストのある接続での動作が改善されました。

## 実践例

### 長時間実行タスクと不安定な接続

大規模なリポジトリのテスト実行やデータ処理など、数十分以上かかるタスクをウェブセッションで実行する場合があります。このとき、ネットワークが一時的に遮断されても、セッションは自動的に再接続を試みます。修正前は再接続時に膨大なイベントバックログが送信され、UIでセッションが「スタック」と表示されることがありました。修正後は、正確に実行中の状態が反映されるようになりました。

```bash
# ウェブセッションから長時間実行タスクを開始
claude --cloud "Run the full test suite and generate coverage report"
```

このタイプのタスクは、実行中に一時的な接続喪失が起こりやすく、この修正の恩恵を最も受けます。

### ネットワークスイッチング中のセッション継続

モバイルデバイスからセッションを監視しており、WiFiから携帯電話ネットワークに切り替わる場合があります。または、タブをバックグラウンドに移して、後で戻す場合もあります。修正前は、こうした一時的な接続喪失のたびに、過去のすべてのイベントが再度送信され、セッションの状態表示が混乱することがありました。修正後は、再接続がスムーズになり、セッションの状態が正確に維持されます。

```bash
# Claude Code On Webでセッションをリアルタイムで監視
# ネットワーク切り替えが発生してもセッションは適切に復旧
```

複数のデバイスから同じセッションを監視する場合（デスクトップ、モバイルアプリなど）も同様に改善されます。

## 注意点

- **ブラウザベースの特性** - Claude Code on the webはブラウザで実行されるため、ブラウザウィンドウを完全に閉じるとセッションは停止します。ただしセッションデータはサーバー側に保持され、再度開くことで復旧できます。
- **接続の自動復旧** - 短時間の接続喪失（数秒～数分）は自動的に復旧されます。長時間（数時間以上）セッションが利用されない場合、環境が期限切れになることがあります。
- **パフォーマンスの向上** - この修正により、特に不安定なネットワーク環境での再接続速度が向上します。
- **セッションがスタック表示される場合** - まれにセッションが実際にスタック状態になる場合があります。その場合は、セッションメニューから手動でリセットするか、新しいセッションを開始してください。
