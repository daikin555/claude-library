# /code-review の出力形式を変更（Important / Pre-existing / Nit と修正案）

## 原文（日本語に翻訳）

ほとんどのモデルで `/code-review` はバグと CLAUDE.md 違反のみを報告するようになりました。再利用・簡素化・効率化の提案は `/simplify` で行います。また各指摘に Important / Pre-existing / Nit のマークが付き、要約の最後に修正案が付きます。問題がない場合は "Code review found no issues." と表示されます。

## 原文（英語）

Changed `/code-review` on most models to report only bugs and CLAUDE.md violations; run `/simplify` for reuse, simplification and efficiency cleanups
Changed `/code-review` to mark each finding Important, Pre-existing or Nit on most models, and to end each summary with a suggested fix; a clean review's list now reads "Code review found no issues."

## 概要

レビューの役割が整理されました。`/code-review` は正しさに関わる指摘に集中し、コード品質の改善は `/simplify` が担当します。各指摘の重要度が分かるため、対応の優先順位を付けやすくなりました。

## 基本的な使い方

```bash
/code-review
/simplify
```

## 実践例

### 変更のレビューから整理まで

まず `/code-review` でバグを確認し、修正後に `/simplify` で重複や冗長な処理を整理します。

### 指摘の優先順位付け

- **Important**: 変更で入ったバグ
- **Pre-existing**: 以前からあった問題
- **Nit**: 軽微な指摘

## 注意点

- 「ほとんどのモデルで」の変更です
- 従来 `/code-review` で得ていた整理系の提案は `/simplify` を使ってください
