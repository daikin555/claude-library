## 原文（日本語訳）
MCPの接続エラーメッセージと、MCPログインツールの説明文に、MCP設定の`${VAR}`プレースホルダーから解決されたシークレットがそのまま表示されていた問題を修正。

## 原文（英語）
Fixed MCP connection errors and the MCP login tool's description showing secrets resolved from `${VAR}` placeholders in MCP configs

## 概要
MCP（Model Context Protocol）サーバーの設定では、APIキーなどの機密情報を直接書き込む代わりに`${VAR}`形式の環境変数プレースホルダーを使うことが推奨されています。しかし、これまでは接続エラーの表示やMCPログインツールの説明文において、このプレースホルダーが解決された後の実際のシークレット値がそのまま画面やログに露出してしまう不具合がありました。今回の修正により、こうした箇所でシークレットが平文表示されなくなり、セキュリティ面の懸念が解消されました。

## 基本的な使い方
MCP設定で環境変数プレースホルダーを使った機密情報の受け渡しは引き続き同じ方法で行えます。

```json
{
  "mcpServers": {
    "my-server": {
      "command": "npx",
      "args": ["my-mcp-server"],
      "env": {
        "API_KEY": "${MY_SERVICE_API_KEY}"
      }
    }
  }
}
```

## 実践例

### MCPサーバーへの接続に失敗した場合
接続に失敗した際のエラーメッセージにおいて、以前は`${MY_SERVICE_API_KEY}`が解決された実際の値（シークレット）がそのまま表示されることがありましたが、修正後は機密情報が画面に露出しません。

```bash
# MCPサーバー接続エラー発生時
claude mcp list
# 修正前: エラーメッセージに実際のAPIキーの値が含まれる場合があった
# 修正後: シークレットはマスクされ、プレースホルダー名などの安全な情報のみ表示
```

### MCPログインツールを使う場合
OAuthなどの認証を伴うMCPサーバーでログインツールを使う際、ツールの説明文にシークレットが混入することがなくなり、ターミナル履歴やログに機密情報が残るリスクが減少します。

## 注意点
- 過去のセッションログやターミナル履歴に既にシークレットが記録されている場合、この修正だけでは過去の露出は消えません。心当たりがある場合は該当のAPIキー等をローテーションすることを推奨します。
- `${VAR}`プレースホルダーを使わず設定ファイルに直接シークレットを書き込んでいる場合は、引き続き設定ファイル自体の管理に注意が必要です。
