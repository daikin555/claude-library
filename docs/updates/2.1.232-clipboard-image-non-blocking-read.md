## 原文（日本語に翻訳）

貼り付けられた画像やクリップボード画像の読み込みが、イベントループをブロックしないようになりました。

## 原文（英語）

Pasted and clipboard images are read without blocking the event loop

## 概要

これはパフォーマンス改善です。これまでClaude Codeでは、画像をターミナルに貼り付けたりクリップボードから取り込んだりする際、その読み込み処理が同期的に行われ、処理中はアプリ全体のイベントループがブロックされていました。特に大きな画像やクリップボード内のデータサイズが大きい場合、CLIの入力やレンダリングが一瞬フリーズしたように見えることがありました。今回の修正により、画像読み込みが非ブロッキングで行われるようになり、貼り付け中も操作性が損なわれなくなりました。

## 基本的な使い方

この変更はユーザー側での設定不要で、既存の画像貼り付け操作がそのまま速く・滑らかになります。

```bash
claude
# ターミナルにスクリーンショットを貼り付ける（Ctrl+V / Cmd+V など）
```

貼り付け直後にClaude Codeの応答性が落ちることなく、そのまま入力や他の操作を続けられます。

## 実践例

### 大きめのスクリーンショットを貼り付ける

デバッグ中にフルスクリーンの大きなスクリーンショットを撮ってそのままターミナルに貼り付けるケースです。修正前は画像の読み込み中にCLI全体が一時的に固まったように感じられることがありましたが、修正後はイベントループがブロックされないため、貼り付け直後でも他のキー入力やUIの更新が滞りません。

```bash
claude
# 大きなPNGスクリーンショットをクリップボードから貼り付け
```

### 複数の画像を連続して貼り付ける

UIの複数の状態（Before/Afterなど）を一度に見せたい場合、複数の画像を立て続けに貼り付けることがあります。非ブロッキング化により、1枚目の読み込み中でも操作がフリーズせず、テンポよく複数枚を貼り付けられます。

```bash
claude
# 画像1を貼り付け → 画像2を貼り付け → コメントを入力
```

### バックグラウンドタスクと並行して画像を貼り付ける

バックグラウンドでコマンドが実行されている最中に、確認のためのスクリーンショットを貼り付ける場合も、イベントループが専有されないため、バックグラウンド処理と貼り付け操作が互いに干渉しにくくなります。

## 注意点

- この変更は内部的なパフォーマンス改善であり、見た目や操作方法自体に変化はありません。
- 非常に大きな画像ファイルを貼り付けた場合、読み込み自体にかかる時間はサイズに応じて残りますが、その間もCLIの応答性は維持されます。
- 画像貼り付け機能全般の詳細（対応フォーマットや制限など）は公式ドキュメントを参照してください。
