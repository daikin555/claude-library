## 原文（日本語訳）
[Claude Tag] Slackスレッド内で切り替えたモデルが、そのスレッドのセッションが再起動または更新された後、無言のままチャンネルのデフォルトモデルに戻ってしまう不具合を修正。

## 原文（英語）
[Claude Tag] Fixed the model you switched to in a Slack thread silently reverting to the channel's default after that thread's session was restarted or refreshed

## 概要
Claude Tagでは、Slackスレッド内で使用するAIモデルをチャンネルのデフォルトとは別のものに切り替えることができます。しかし、そのスレッドを支えるセッションが再起動または更新されると、ユーザーが明示的に選択したモデルが何の通知もなくチャンネルのデフォルトモデルに戻ってしまう不具合がありました。これにより、ユーザーが気づかないうちに意図したモデルと異なるモデルでタスクが処理されるリスクがありました。今回の修正で、スレッド内で選択したモデルはセッションの再起動・更新後も維持されるようになりました。

## 基本的な使い方
Slackスレッド内でモデルを切り替えるコマンドや操作を行うと、そのスレッドでは以降そのモデルが使用され続けます。セッションが再起動・更新されても、選択したモデルの設定が保持されます。

```
スレッド内: 「Opusモデルに切り替えて」
→ 以降、このスレッドではOpusモデルが使用され続ける（再起動後も維持）
```

## 実践例

### 高精度なモデルで長時間の分析タスクを行っている場合
特定のスレッドでOpusのような高精度モデルに切り替えて複雑な分析を依頼している最中にセッションが再起動されても、修正後は引き続き選択したモデルで処理が継続されます。

```
Before: セッション再起動後、無言でチャンネルのデフォルトモデルに戻る
After:  再起動後もユーザーが選択したモデルのまま維持される
```

### コスト重視で軽量モデルに切り替えている場合
逆に、コストを抑えるために軽量なモデルに切り替えているスレッドでも、意図せずデフォルト（より高コストな）モデルに戻ってしまうことがなくなり、想定外のコスト増加を防げます。

## 注意点
- モデルの切り替えはスレッド単位で有効です。チャンネル全体のデフォルトモデルを変更したい場合は別途チャンネル設定を変更する必要があります。
- 選択可能なモデルは組織のプランや管理者設定によって制限される場合があります。
