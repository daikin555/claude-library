## 原文（日本語訳）

[Code Review] 新しいレビューが修正済みの指摘のスレッド下に、より重要度の低い指摘を投稿した場合に、そのスレッドが誤って開いたままになることがあった不具合を修正しました。

## 原文（英語）

[Code Review] Fixed re-reviews occasionally leaving a fixed finding's thread open when the new review also filed a lower-severity note under it

## 概要

Code Reviewは、プルリクエストに対して指摘（finding）をコメントスレッドとして投稿し、指摘が修正されるとそのスレッドを解決（クローズ）します。これまで、再レビュー時にすでに修正された指摘のスレッドの下に、新たに重要度の低い別の指摘が追加投稿されるケースで、そのスレッドがクローズされずに開いたままになってしまう不具合がありました。今回の修正により、修正済みの指摘は新しい低重要度の注記が同じスレッドに追加された場合でも正しくクローズされるようになりました。

## 基本的な使い方

通常どおりCode Reviewを実行し、指摘に対応してコミットをプッシュすると、再レビュー時に修正済みのスレッドが自動的にクローズされます。

```
# PRにコミットをプッシュすると自動的に再レビューが走る
git push origin feature-branch
```

## 実践例

### 修正後に低重要度の指摘が追加されるケース

あるコード行に対して重大な指摘がされ、開発者がそれを修正してプッシュしたとします。再レビュー時に、その同じ箇所に軽微なスタイル上の注記が新たに追加されることがありますが、修正後は元の重大な指摘のスレッドは正しくクローズされ、新しい軽微な注記だけが残ります。

### 修正前後の挙動比較

- 修正前: 重大な指摘が修正されていても、同じスレッドに軽微な注記が追加されると、スレッド全体が「未解決」のまま残ってしまう
- 修正後: 修正済みの指摘は正しくクローズされ、レビュースレッドの状態がコードの実際の状態を正確に反映する

## 注意点

- この修正はGitHub上でのCode Reviewのスレッド管理に関するものです
- 指摘の重要度判定ロジック自体に変更はありません
