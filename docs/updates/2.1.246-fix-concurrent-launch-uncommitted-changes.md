## 原文（日本語訳）

同じリポジトリから同時に起動された `/ultrareview` の実行とクラウドセッション（例えば複数のworktreeから同時起動した場合）が、それぞれ別の起動元の未コミット変更を取り込んでしまうことがある問題を修正しました。

## 原文（英語）

Fixed `/ultrareview` runs and cloud sessions launched at the same time from one repository (e.g. from several worktrees) sometimes starting with another launch's uncommitted changes

## 概要

`/ultrareview` やクラウドセッションは起動時に、リポジトリの現在の状態（未コミットの変更を含む）をスナップショットとして取り込みます。同一リポジトリから複数のworktreeを使って複数の起動を同時に行った場合、スナップショット取得のタイミングが競合し、あるセッションが本来意図していない別の起動元の未コミット変更を取り込んでしまうことがありました。今回の修正により、同時起動時でも各セッションが正しく自分自身の変更のみを取り込むようになります。

## 基本的な使い方

修正は内部のスナップショット取得処理に対するものです。ユーザーは通常通り各worktreeで `/ultrareview` を実行したり、クラウドセッションを起動したりするだけです。

```
/ultrareview
```

## 実践例

### 複数worktreeでの並行レビュー

同じリポジトリを複数のworktreeにチェックアウトし、それぞれで異なる変更を加えた状態から同時に `/ultrareview` を実行するケースです。修正後は、各worktreeのレビューがそのworktree自身の未コミット変更のみを対象にするようになります。

### 複数のクラウドセッションを一斉起動

複数の機能を並行して進めるために、同じリポジトリの異なるworktreeから複数のクラウドセッションを同時に起動するワークフローでも、各セッションが正しい差分だけを引き継ぎます。

### CI的な一括レビューフロー

複数のブランチ・worktreeに対してまとめて `/ultrareview` やクラウドセッションをキックするスクリプトを組んでいる場合、意図しない変更の混入によるレビュー結果の誤りを避けられます。

## 注意点

- 単一のworktreeで順番に起動する場合はこれまでも問題なく動作していました。影響があったのは同時起動のケースです
- レビューやクラウドセッションの結果に心当たりのない変更が含まれていた場合は、このバージョン以降で再現しないか確認してください
