## 原文（日本語訳）

最初の非対話的なターン（non-interactive turn）がMCPサーバーの接続を待つ時間の上限を指定する `CLAUDE_CODE_MCP_STARTUP_WAIT_MS` を追加しました（`0` を指定すると待機しません）。

## 原文（英語）

Added `CLAUDE_CODE_MCP_STARTUP_WAIT_MS` to bound how long the first non-interactive turn waits for connecting MCP servers (`0` = don't wait)

## 概要

`claude -p` などの非対話モードでClaude Codeを起動すると、最初のターンの前にMCPサーバーの接続が完了するまで待機することがあり、これがスクリプトやCIパイプラインの起動遅延の原因になっていました。新しい環境変数 `CLAUDE_CODE_MCP_STARTUP_WAIT_MS` を使うと、この待機時間の上限をミリ秒単位で指定でき、`0` を指定すればMCPサーバーの接続を待たずに即座に処理を開始できます。

## 基本的な使い方

```bash
# 最初の非対話ターンでMCPサーバーの接続を最大2秒だけ待つ
CLAUDE_CODE_MCP_STARTUP_WAIT_MS=2000 claude -p "このリポジトリの概要を教えて"
```

```bash
# MCPサーバーの接続をまったく待たずに即座に開始する
CLAUDE_CODE_MCP_STARTUP_WAIT_MS=0 claude -p "簡単な質問に答えて"
```

## 実践例

### CIパイプラインでの起動高速化

MCPツールを使わない単純なプロンプトをCI上で実行する場合、MCPサーバーの接続を待つ必要はありません。`0` を指定することで、ジョブの起動を高速化できます。

```bash
CLAUDE_CODE_MCP_STARTUP_WAIT_MS=0 claude -p "テスト結果を要約して" < test-output.log
```

### 遅いMCPサーバーが混在する環境でのタイムアウト調整

社内のMCPサーバーの起動が遅く、非対話コマンドの実行が毎回長時間ブロックされてしまう場合、待機上限を短く設定することで、MCPツールが使えなくてもタスクを継続させることができます。

```bash
CLAUDE_CODE_MCP_STARTUP_WAIT_MS=500 claude -p "現在のブランチの差分を確認して" 
```

## 注意点

- この設定は「最初の非対話的なターン」にのみ影響します。対話セッションの挙動は変わりません。
- 待機時間を短くしすぎると、MCPサーバーの接続が完了する前にターンが開始され、MCPツールが利用できない状態でタスクが進む可能性があります。
- MCPサーバーが実際に必要なワークフローでは、サーバーの起動時間を考慮した値を設定してください。
