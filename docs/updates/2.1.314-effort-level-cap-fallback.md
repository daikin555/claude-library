# 管理者が effort を制限した際の「Invalid effort level」エラーを自動回避

## 原文（日本語訳）

組織の管理者がモデルの effort に上限を設けている場合に、セッションが毎ターン「Invalid effort level」で失敗する問題を修正しました。Claude Code は effort を下げて再試行し、使用したレベルを通知します。

## 原文（英語）

Fixed sessions failing turn after turn with "Invalid effort level" when an organization's admin caps a model's effort: Claude Code now lowers the effort, retries, and says which level it uses

## 概要

管理者が許可する effort の上限を超える設定でセッションを使うと、これまではリクエストが毎回失敗していました。修正後は上限に合わせて自動的に effort を下げて再試行し、実際に使ったレベルを表示します。

## 基本的な使い方

特別な設定は不要です。高い effort を選んでいても、上限があれば自動調整されます。

```bash
claude --model opus
# 組織の上限を超える effort が選ばれていても、自動で引き下げられる
```

## 実践例

### 組織で effort を制限している場合

個々の開発者が高い effort を選んでいてもエラーで止まらず、通知されたレベルで作業を続行できます。

### CI やヘッドレス実行

`claude -p` のバッチ処理が、effort 超過で全ターン失敗する事態を避けられます。ログで実際のレベルを確認しましょう。

## 注意点

- 実際の effort は指定値より低い場合があります。品質が重要なタスクでは表示されたレベルを確認してください。
- 上限そのものを変えたい場合は管理者に相談してください。
