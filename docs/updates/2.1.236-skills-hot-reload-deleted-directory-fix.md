## 原文（日本語訳）

SDK/VS Codeセッションにおいて、セッションの作業ディレクトリが削除された後、Skillsの変更のたびにホットリロード処理がエラーを発生させ続けていた問題を修正しました（2.1.229以降で発生）。

## 原文（英語）

Fixed skills hot-reload in SDK/VS Code sessions raising an error on every skills change after the session's working directory was deleted (2.1.229+)

## 概要

Claude CodeのSkillsは、`~/.claude/skills/` やプロジェクトの `.claude/skills/` を監視し、ファイルの追加・編集・削除をセッションを再起動せずに即座に反映するホットリロード機能を持っています。バージョン2.1.229以降、SDKやVS Code拡張から起動したセッションで、セッションの作業ディレクトリが（一時ディレクトリの削除など何らかの理由で）存在しなくなった状態になると、Skillsの変更を検知するたびにホットリロード処理がエラーを発生させ続けるようになっていました。今回の修正により、作業ディレクトリが失われた状態でもこのエラーが発生しなくなりました。

## 基本的な使い方

この修正はSkillsのホットリロードに関する内部的な安定性の改善であり、Skillsそのものの使い方は変わりません。プロジェクトやユーザーのスキルディレクトリにファイルを追加・編集すれば、セッションを再起動せずに反映されます。

```
.claude/skills/my-skill/SKILL.md を編集して保存
```

修正前は、Claude Agent SDKで一時的な作業ディレクトリを使うセッションや、VS Code拡張から開始したセッションで、そのディレクトリが途中で削除されると、以降Skillsファイルを変更するたびにバックグラウンドでエラーが発生し続けていました。修正後は、作業ディレクトリが存在しなくなっていてもホットリロードの監視処理が安全に扱われ、エラーが繰り返し発生することはなくなります。

## 実践例

### SDKで一時ディレクトリを使ってセッションを実行する場合

Claude Agent SDKを使って一時的な作業ディレクトリ上でセッションを実行し、処理完了後にそのディレクトリをクリーンアップするようなワークフローでは、修正前はクリーンアップ後もセッションが生きている限りSkillsの変更検知がエラーを吐き続けることがありました。修正後はこの問題が解消されています。

### VS Code拡張でプロジェクトフォルダを閉じたり移動したりした場合

VS Code上でClaude Code拡張を使っているときに、開いていたプロジェクトフォルダが削除されたり別の場所に移動したりした場合でも、修正前はSkillsのファイル変更監視がその都度エラーを出していましたが、修正後はエラーが発生しなくなります。

## 注意点

- この問題は2.1.229以降のバージョンで発生していたものです。それ以前のバージョンには該当しません。
- 作業ディレクトリ自体が削除された状態でSkillsを正しく参照・実行できるとは限らないため、根本的にはセッションの作業ディレクトリを維持することが推奨されます。この修正はあくまでエラーの繰り返し発生を防ぐものです。
