# Grep の head_limit / offset ページングで結果が重複・欠落しないよう修正

## 原文（日本語に翻訳）

`head_limit` と `offset` でページングする際に、Grep が結果を重複させたり飛ばしたりする問題を修正しました。内容とカウントの結果はファイルパス順にソートされます。

## 原文（英語）

Fixed Grep repeating or skipping results when paging with `head_limit` and `offset`; content and count results are now sorted by file path

## 概要

Grep の結果順が実行ごとに変わり得たため、`offset` で続きを取得すると重複や欠落が起きていました。結果がファイルパス順に固定され、ページングが安定します。

## 基本的な使い方

```text
Grep pattern="TODO" output_mode="content" head_limit=50 offset=0
Grep pattern="TODO" output_mode="content" head_limit=50 offset=50
```

## 実践例

### 大量ヒットの網羅的レビュー

TODO が数百件ある場合も、50 件ずつ `offset` を進めれば漏れなく確認できます。

### 件数の集計

`output_mode="count"` でもファイルパス順になるため、再実行しても比較しやすくなります。

## 注意点

- 並び順がパス順に変わるため、従来の順序に依存した手順は見直してください。
- 同じ更新で、Read の巨大ファイルのサイズ表示や NotebookEdit の末尾改行消失なども修正されています。
