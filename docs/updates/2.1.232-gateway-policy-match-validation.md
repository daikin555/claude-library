## 原文（日本語に翻訳）

Gateway: `managed.policies[].match.groups` や `admin.admin_groups` の空エントリ、および不正な `email_domain` の値（空文字、または `@`・空白・カンマを含むもの）が、これまでは誰にもマッチしないか管理者権限を付与してしまうサイレントな挙動だったのに対し、今後は起動時にエラーとなるようになりました。

## 原文（英語）

Gateway: empty `managed.policies[].match.groups`/`admin.admin_groups` entries and malformed `email_domain` values (empty, or containing `@`, whitespace, or commas) now fail at boot instead of silently matching no one or granting admin access

## 概要

Claude Code Gatewayでは、組織のポリシー設定（`managed.policies[].match.groups`）や管理者判定（`admin.admin_groups`）、メールドメインによるアクセス制御（`email_domain`）を使って、ユーザーへの権限付与を制御します。従来は、これらの設定値に空欄や記述ミス（例えば `email_domain` に `@example.com` のように `@` を含めてしまう、カンマ区切りで複数ドメインを1つの値に書いてしまう等）があっても、Gatewayはエラーを出さずに起動し、結果として「誰にもマッチしないポリシー」や「意図せず管理者権限が付与される」といった重大なセキュリティ上の問題を引き起こす可能性がありました。今回の修正により、これらの不正な設定は起動時に検出され、Gatewayの起動自体が失敗するようになりました。

## 基本的な使い方

この変更はGatewayの管理者設定ファイルの記述に直接関わります。ポリシーやadmin_groups、email_domainを設定する際は、以下のような形式的な誤りに注意する必要があります。

```yaml
# managed 設定ファイルの例
managed:
  policies:
    - match:
        groups: ["engineering"]   # 空配列や空文字列エントリはNG
      # ...

admin:
  admin_groups: ["org-admins"]    # 空文字列エントリはNG

# email_domain の例
email_domain: "example.com"       # OK
# email_domain: ""                # NG: 空文字
# email_domain: "@example.com"    # NG: @ を含む
# email_domain: "example.com, other.com"  # NG: カンマを含む
# email_domain: " example.com"    # NG: 空白を含む
```

不正な値がある状態でGatewayを起動すると、以下のようにエラーとなります。

```bash
gateway restart
# Error: invalid email_domain value "@example.com"
# Boot failed
```

## 実践例

### admin_groupsの空エントリによる意図しない権限付与を防ぐ

設定ファイルの生成スクリプトのバグなどで、`admin_groups` に空文字列が混入してしまうケース。

```yaml
admin:
  admin_groups: ["org-admins", ""]  # 空文字列が混入
```

```bash
gateway restart
# 修正前: 起動は成功するが、空文字列エントリの扱いによっては
#         意図しないユーザーに管理者権限が付与されるリスクがあった
# 修正後:
# Error: empty entry in admin.admin_groups
# Boot failed
```

### groupsの空配列による「誰にもマッチしないポリシー」を検出する

ポリシーのmatch条件に空のgroups配列を指定してしまい、本来適用したいはずのポリシーが誰にも適用されないケース。

```yaml
managed:
  policies:
    - match:
        groups: []   # 空配列
      # 意図: 特定グループに緩いポリシーを適用したかったが
      # 空配列のため実際には誰にもマッチしなかった
```

```bash
gateway restart
# 修正後:
# Error: empty match.groups entry in policy
# Boot failed
```

### email_domainのフォーマットミスを早期発見する

複数ドメインをまとめて1つの値にカンマ区切りで書いてしまうよくある記述ミス。

```yaml
email_domain: "example.com,partner.com"  # カンマを含む不正な値
```

```bash
gateway restart
# Error: malformed email_domain value "example.com,partner.com"
# Boot failed

# 正しくはドメインごとに個別のポリシーエントリを用意する
```

## 注意点

- Claude Code v2.1.232で導入された修正です。
- これは重要なセキュリティ修正です。従来の「サイレントに誰にもマッチしない」「サイレントに管理者権限が付与される」という挙動は、権限設計上のリスクとなり得るため、既存のGateway設定を持つ組織はアップグレード後に起動確認を行い、エラーが出た場合は設定を見直してください。
- `email_domain` に指定できない文字: 空文字、`@`、空白、カンマ。ドメイン名のみを単一の値として指定する必要があります。
- アップグレード後にGatewayが起動しなくなった場合は、まず `managed.policies[].match.groups`、`admin.admin_groups`、`email_domain` の設定値を確認してください。
