## 原文（日本語訳）
Bashツールが、プラグインをリロードするたびに次のコマンド実行時にシェルプロファイルを再読み込みし、数秒間の停止を引き起こしていた問題を修正。現在はプラグインの`bin/`ディレクトリが変更された場合のみ再読み込みされる。

## 原文（英語）
Fixed the Bash tool re-sourcing the shell profile (a multi-second stall on the next command) after every plugin reload; it now does so only when the plugins' `bin/` directories changed

## 概要
Claude CodeのBashツールは、プラグインが提供するコマンドをPATHに反映させるためにシェルプロファイル（`.bashrc`や`.zshrc`など）を読み込み直すことがあります。これまではプラグインがリロードされるたびに毎回プロファイルを再読み込みしており、次に実行するBashコマンドで数秒の遅延が発生していました。今回の修正で、実際にプラグインの`bin/`ディレクトリに変更があった場合のみ再読み込みが行われるようになり、不要な待ち時間がなくなりました。

## 基本的な使い方
特別な操作は不要です。プラグインを頻繁に有効化・無効化したり更新したりする環境で、Bashコマンドの実行速度が改善されます。

```bash
# プラグインを更新した後、続けてBashコマンドを実行する例
claude plugin update my-plugin
# 以前: 次のBashコマンドでシェルプロファイルの再読み込みにより数秒の遅延
# 修正後: bin/ディレクトリに変更がなければ再読み込みされず、即座に実行
```

## 実践例

### プラグインを頻繁に切り替える開発フロー
複数のプラグインを開発しながらClaude Codeでテストしている場合、プラグインをリロードするたびにBashコマンドが数秒止まっていたため、開発体験が損なわれていました。修正後は、`bin/`ディレクトリを変更しないプラグイン更新（設定ファイルの変更など）ではプロファイルの再読み込みがスキップされ、レスポンスが速くなります。

### `bin/`ディレクトリに新しい実行ファイルを追加した場合
プラグインの`bin/`ディレクトリに新しいスクリプトを追加してPATHに反映させたい場合は、従来通りシェルプロファイルが再読み込みされ、新しいコマンドがすぐに使えるようになります。

```bash
# bin/ に新しい実行ファイルを追加した後
ls my-plugin/bin/
# new-script.sh が追加された場合は再読み込みが発生し、PATHに反映される
```

## 注意点
- `bin/`ディレクトリの変更検知に基づく最適化のため、`bin/`以外の変更のみを行った場合は再読み込みされません（通常はそれで十分です）。
- 大規模なシェルプロファイル（多数のツールを初期化するもの）を使っている場合、この修正による体感速度の改善が特に大きくなります。
