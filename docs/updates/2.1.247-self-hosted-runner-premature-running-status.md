## 原文（日本語訳）

セルフホストランナーのセッションが、Claude Codeが実際に起動する前に `running` 状態を報告してしまい、Claude デスクトップアプリから「Claudeが入力を待っています」という時期尚早な通知が送られてしまう問題を修正しました。

## 原文（英語）

Fixed self-hosted runner sessions reporting `running` before Claude Code had started, which could trigger a premature "Claude is waiting for your input" notification from the Claude desktop app

## 概要

GitHub Actionsのセルフホストランナー上でClaude Codeを実行する構成では、セッションの状態がデスクトップアプリなどに連携され、必要に応じてユーザーに通知が送られます。これまでは、実際にClaude Codeプロセスが起動する前の段階でセッションが `running` 状態として報告されてしまうことがあり、その結果、まだ何も処理していないにもかかわらず「Claudeが入力を待っています」という誤った通知がデスクトップアプリから送られることがありました。今回の修正で、Claude Codeが実際に起動した後に `running` 状態が報告されるようになり、誤通知が発生しなくなりました。

## 基本的な使い方

セルフホストランナー上でGitHub Actions経由のClaude Codeセッションを通常通り実行します。

```yaml
runs-on: self-hosted
steps:
  - uses: anthropics/claude-code-action@v1
```

修正後は、Claude Codeのプロセスが実際に起動してから状態が `running` として報告されるため、デスクトップアプリの通知タイミングも正確になります。

## 実践例

### CI上でのセルフホストランナー運用

社内のセルフホストランナーでClaude Codeを使ったワークフローを頻繁に実行しているチームでは、起動前の誤った `running` 報告がなくなることで、無意味な通知に振り回されることが減ります。

### デスクトップアプリで複数セッションを監視している場合

複数のセルフホストランナー上のセッションをデスクトップアプリから監視している場合、実際にはまだ処理が始まっていないセッションについて「入力待ち」と誤解して確認に行く手間がなくなります。

### 通知をトリガーにした自動化との連携

デスクトップアプリの通知をトリガーに何らかの後続処理（例えばSlack転送など）を行っている場合、誤通知の削減によって不要な後続処理の発火も防げます。

## 注意点

- この修正はセルフホストランナー環境における起動シーケンスのタイミングに関するものです
- 通知機能自体はデスクトップアプリ側の機能であり、通知の有効/無効設定には影響しません
