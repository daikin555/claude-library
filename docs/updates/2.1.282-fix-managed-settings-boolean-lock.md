## 原文（日本語訳）

`disableClaudeAiConnectors` や `allowManagedPermissionRulesOnly` のような真偽値のロックキーに誤った型の値が設定されている場合、管理設定がそれを無視していた不具合を修正しました。現在はロックが正しく適用され、起動時にそのキー名が表示されます。

## 原文（英語）

Fixed managed settings ignoring a mistyped value for boolean lock keys such as `disableClaudeAiConnectors` or `allowManagedPermissionRulesOnly`; the lock now applies and startup names the key

## 概要

これはセキュリティに関わる修正です。管理設定（managed settings）で `disableClaudeAiConnectors` や `allowManagedPermissionRulesOnly` のような真偽値（true/false）を期待するロックキーに、文字列の `"true"` や数値の `1` など誤った型の値を設定してしまった場合、これまではそのロック設定自体が黙って無視されてしまい、管理者が意図した制限が適用されないという問題がありました。今回の修正で、誤った型の値であってもロックは正しく適用されるようになり、さらに起動時にどのキーが問題だったかを名指しで警告するようになりました。

## 基本的な使い方

管理設定ファイル（例: `managed-settings.json`）で真偽値キーを設定する際は、正しい型（`true` / `false`）で記述します。

```json
{
  "disableClaudeAiConnectors": true
}
```

型を誤って設定していた場合は、Claude Code起動時の警告でそのキー名が表示されるようになったため、設定ミスに気づきやすくなります。

## 実践例

### エンタープライズのセキュリティポリシー監査

組織全体に配布している管理設定ファイルの中で、意図せず型が間違っていたロックキーを起動時警告から発見し、修正できます。

### 新規ポリシー導入時の検証

新しいロック設定を導入する際、実際に意図通りロックされているかを起動時のメッセージで確認しながら展開できます。

## 注意点

- この修正により、これまで「無視されていたことで結果的に緩い状態になっていた」設定が、意図通り厳格に適用されるようになります。展開前に設定内容を再確認してください
- 対象は真偽値を期待するロックキー全般です
