## 原文（日本語訳）

`crossSessionInbound` と `dialogExpiry` 設定を追加：権限チェックをバイパスして実行中のセッションに送られたクロスセッションメッセージは承認待ちで保留され、それ以外のセッションへのメッセージは自動的に配信されます。

## 原文（英語）

Added `crossSessionInbound` and `dialogExpiry` settings: cross-session messages sent to a session running with bypassed permissions are held for your approval, and messages to other sessions auto-deliver

## 概要

Claude Codeのクロスセッションメッセージング機能（`SendMessage`/`ListAgents`）では、あるセッションから別のセッションへメッセージを送ることができます。受信側が `bypassPermissions` のような権限プロンプトを完全にスキップするモードで動作している場合、届いたメッセージがそのまま自動的に実行に反映されると危険なため、デフォルトではユーザーの承認が必要になります。一方、通常どおり権限プロンプトを出すセッションへのメッセージは、そのまま配信されます。この挙動は `crossSessionInbound` 設定でセッションごとに明示的に上書きでき、承認ダイアログの表示時間は `dialogExpiry` で調整できます。

## 基本的な使い方

セッションの設定ファイルで `crossSessionInbound` を `accept`・`hold`・`refuse` のいずれかに設定します。

```json
{
  "crossSessionInbound": "accept"
}
```

| 値 | 動作 |
| :--- | :--- |
| `accept` | 届いたメッセージをそのままClaudeに配信する |
| `hold` | メッセージごとに通知を出し、配信しない（後で`accept`が適用されれば保留分が解放される） |
| `refuse` | メッセージを配信せずすべて破棄する |

値を何も設定しない場合、Claude Codeは送信元・受信先それぞれのセッションの権限モードから自動的に判断します。受信側が権限プロンプトをバイパスするモード（`bypassPermissions` など）で動いている場合は、送信元も同様にバイパスモードだと分かっているときのみ配信し、それ以外は承認待ちで保留されます。

## 実践例

### 無人実行中のヘッドレスセッションでメッセージを受け取る

`claude -p` で長時間動かしているワーカーに、他のセッションから状況確認のメッセージを自動で届けたい場合は、`--settings` でそのセッションだけ `accept` にします。

```bash
claude -p "マイグレーションを監視して完了したら知らせて" \
  --settings '{"crossSessionInbound": "accept"}'
```

### 権限バイパス中のセッションを誤操作から守る

`bypassPermissions` モードで動いているセッションに他セッションから不用意な指示が飛んでこないよう、承認ダイアログの表示時間を短くしてすぐに破棄されるようにします。

```json
{
  "dialogExpiry": 60000
}
```

上記のように設定すると、承認ダイアログが1分（60000ミリ秒）以内に応答されなければ自動的に閉じ、メッセージは破棄されます（デフォルトは5分）。

### 組織全体でクロスセッションメッセージングを無効化する

管理者はmanaged settingsで送受信の両方を止めることができます。

```json
{
  "permissions": {
    "deny": ["SendMessage", "ListAgents"]
  },
  "crossSessionInbound": "refuse"
}
```

## 注意点

- `crossSessionInbound` の優先順位はスコープによって異なります。project/local設定からの `refuse` は他のどのソースよりも優先され、user設定からの値はmanaged設定や `--settings` の値がない場合にのみ適用されます。
- Plan modeは、バイパス権限が使えるセッションではバイパス側として扱われます。
- 保留中のメッセージへの応答をユーザーが行わないまま `dialogExpiry` の期限（デフォルト5分）を過ぎると、ダイアログは自動的に閉じてメッセージは破棄されます。
- 保留中に受信側セッションの権限モードクラスが変わった場合、Claude Codeは保留メッセージに対してルールを再適用し、配信可能になったものは配信し、通知を表示します。
- Claude Codeは最大100件のメッセージを保留として保持し、それを超えると最も古いものから破棄されます。
- この機能はクロスセッションメッセージング全体と同様、macOSとLinux（WSL 2を含む）で利用可能です。
