## 原文（日本語訳）

バックグラウンドのサブエージェントからのツール権限プロンプトに回答した際、セッションスコープの権限回答（拒否を含む）が失われてしまう不具合を修正しました。

## 原文（英語）

Fixed session-scoped permission answers (including denies) being dropped when answering background subagent tool permission prompts

## 概要

バックグラウンドで動作しているサブエージェントがツール実行の権限確認（パーミッションプロンプト）を出した際に、ユーザーが「このセッションの間は許可/拒否する」といったセッションスコープの回答を選んでも、その回答が正しく記憶されずに消えてしまう不具合がありました。特に「拒否（deny）」を選んだ場合でも記録が失われ、同じ確認が繰り返し表示されたり、意図せずツールが実行されてしまう可能性がありました。今回の修正でこの回答保持の不具合が解消されています。

## 基本的な使い方

この修正はバグフィックスであり、ユーザー側で特別な操作は不要です。バックグラウンドサブエージェント（`Agent` ツールを `run_in_background: true` で起動した場合など）がツール権限を要求してきた際に、「このセッションでは常に許可する」「このセッションでは常に拒否する」を選択すると、以降そのセッション内では選択内容が正しく維持されるようになります。

## 実践例

### バックグラウンドで動くサブエージェントに一括で拒否権限を与える

```
# メインセッションでバックグラウンドタスクを起動
> 大量のログファイルを解析するサブエージェントをバックグラウンドで実行して

# サブエージェントが特定のBashコマンドの実行許可を求めてきたら
# 「Deny for this session」を選択

# 修正前: 同じコマンドパターンで再度確認が表示されてしまう
# 修正後: セッション中は拒否設定が維持され、再確認されない
```

### 複数のバックグラウンドサブエージェントを並行実行する場合

複数のサブエージェントが同時にツール権限を要求するケースでも、それぞれの回答（許可・拒否）がセッション内で正しく個別に保持されるようになりました。

## 注意点

- この修正は「セッションスコープ」の回答（そのセッション限りの許可/拒否）に関するものです。永続的な設定ファイル（`settings.json` など）への保存動作自体を変更するものではありません
- 修正前のバージョンでは、特に「拒否」の回答が失われやすく、意図しないツール実行につながる可能性があったため、バックグラウンドサブエージェントを多用するワークフローでは早めのアップデートが推奨されます
