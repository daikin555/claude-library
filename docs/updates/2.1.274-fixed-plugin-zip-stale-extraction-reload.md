## 原文（日本語訳）
`.zip`から読み込まれるプラグインが、複数回の重複したリロードの後、古い（stale）展開結果から提供されてしまっていた問題を修正。

## 原文（英語）
Fixed a plugin loaded from a `.zip` being served from a stale extraction after several overlapping reloads

## 概要
Claude Codeは`.zip`形式でパッケージ化されたプラグインを、一時ディレクトリに展開してから読み込みます。しかし、短時間にプラグインのリロードが重なって発生すると、展開処理が競合し、古いバージョンの展開結果（stale extraction）が使われ続けてしまうことがありました。この結果、プラグインを更新したはずなのに古い動作のままになるという不具合が起きていました。今回の修正でこの競合状態が解消され、リロードが重なっても常に最新の展開結果が使われるようになりました。

## 基本的な使い方
特別な操作は不要です。`.zip`形式のプラグインを更新・リロードすると、常に最新の内容が反映されるようになります。

```bash
# .zip形式のプラグインを更新する例
claude plugin update my-zip-plugin
```

## 実践例

### プラグインを短時間に連続で更新する場合
CI/CDやスクリプトから短時間に何度もプラグインの更新・リロードを行うと、以前は展開処理の競合により古いプラグインの中身が使われ続けることがありました。修正後は、こうした重複リロードが発生しても最終的に正しい最新版が反映されます。

```bash
# 短時間に複数回リロードするケース
claude plugin update my-zip-plugin
claude plugin reload my-zip-plugin
claude plugin reload my-zip-plugin
# 修正後: 常に最新の展開結果が使われる
```

### 複数の開発者が同時に同じプラグインを更新するチーム開発
チームで同じプラグインパッケージを共有し、複数人がほぼ同時にプラグインを更新・リロードするような環境でも、古い展開結果が混ざり込むリスクが減ります。

## 注意点
- ソースディレクトリから直接読み込むプラグイン（`.zip`を使わない形式）はもともとこの問題の影響を受けません。
- 問題が疑われる場合は、プラグインを一度アンインストールしてから再インストールすることで、古い展開キャッシュをクリアできます。
