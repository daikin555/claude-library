## 原文（日本語訳）

コールドスタート時に古いログイントークンが残っていると、Remote Controlの自動起動が「Remote credentials fetch failed」というエラーで断続的に失敗する問題を修正しました。

## 原文（英語）

Fixed Remote Control auto-start intermittently failing with "Remote credentials fetch failed" on a cold start with a stale login token

## 概要

Remote Controlは、ローカルで実行しているClaude Codeのセッションをスマートフォンやブラウザなど別のデバイスから操作できる機能です。設定によってはClaude Code起動時にRemote Controlを自動的に有効化できますが、これまでは初回起動（コールドスタート）時にローカルに保存された認証情報（ログイントークン）が古くなっている場合、断続的に「Remote credentials fetch failed」というエラーで自動起動が失敗することがありました。今回の修正により、古いトークンが残っている状態でも認証情報の取得処理が正しく行われ、自動起動の失敗が解消されました。

## 基本的な使い方

Remote Controlは `claude remote-control` コマンドで手動起動できるほか、設定で自動起動を有効にしておくと、Claude Code起動時に自動的にリモート接続待受状態になります。

```bash
# 手動でRemote Controlを起動する場合
claude remote-control

# 自動起動が有効な場合、通常の起動だけで
# Remote Controlも自動的に有効化される
claude
```

## 実践例

### 修正前に起きていた問題

しばらく使っていなかったマシンや、認証トークンの更新が行われていない状態でClaude Codeを久しぶりに起動し、Remote Controlの自動起動を試みると、以下のようなエラーで起動に失敗することがありました。

```bash
$ claude
# Remote Controlの自動起動処理が走るが…
Error: Remote credentials fetch failed

# 再度 claude を起動すると成功することもあれば、
# 同じエラーが断続的に再発することもあった
```

これは、コールドスタート時にローカルの認証キャッシュが古いログイントークンを保持していたことが原因でした。

### 修正後の挙動

古いログイントークンが残っている状態でも、認証情報の取得処理が正しくトークンの有効性を判定・更新できるようになり、コールドスタートでもRemote Controlの自動起動が安定して成功するようになりました。

```bash
$ claude
# 古いトークンが残っていても、認証情報が正しく取得され
# Remote Controlが問題なく自動起動する
Remote Control is now active. Connect from the Claude app or claude.ai/code.
```

## 注意点

- Remote Controlの利用にはPro、Max、Team、Enterpriseプランが必要で、APIキーでの利用はサポートされていません
- Remote Controlの利用にはClaude Code v2.1.51以降が必要です（`claude --version` で確認可能）
- それでも認証エラーが発生する場合は、`claude logout` してから再度ログインし、認証情報を作り直すことで解消できる場合があります
- 1つのClaude Codeセッションで同時に接続できるリモートクライアントは1つのみです
