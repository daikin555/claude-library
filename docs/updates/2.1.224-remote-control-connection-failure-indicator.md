## 原文（日本語訳）

Remote Controlを改善し、接続に失敗した場合、8秒で消えるトースト通知だけでなく、詳細情報と再接続用のショートカットを含む、常時表示の失敗インジケーターが表示されるようになりました。

## 原文（英語）

Improved Remote Control: connection failures now show a persistent failure indicator with details and a reconnect shortcut, instead of only an 8-second toast

## 概要

Remote Controlを有効にしたセッションでは、接続状態がターミナル下部のフッターに`/rc active`のようなインジケーターとして表示されます。これまで接続に失敗した際は8秒で自動的に消えるトースト通知でしか知らされず、通知を見逃すとなぜ接続が切れたのか分からなくなることがありました。今回の改善で、接続失敗時には消えずに残る「失敗インジケーター」が表示されるようになり、失敗の詳細と再接続のためのショートカットをいつでも確認できるようになりました。

## 基本的な使い方

Remote Controlセッションを開始した状態で接続が失敗すると、フッターの表示が失敗状態に切り替わります。改めて`/remote-control`を実行することで再接続できます。

```bash
# Remote Controlセッションを開始
claude remote-control

# 何らかの理由で接続が失敗した場合、フッターに失敗インジケーターが表示され続ける
# 再接続する場合
/remote-control
```

## 実践例

### ネットワークが不安定な環境で作業している場合

Wi-Fiの切り替えやVPN接続の変動などでRemote Controlの接続が一時的に失敗するケースでは、以前はトーストを見逃すと「サイレントに繋がっていない」状態に気づけませんでした。改善後は失敗インジケーターが消えずに残るため、作業に集中していても後から気づいて再接続できます。

```text
# フッターの失敗インジケーターを選択（下矢印キー→Enter）してステータスパネルを開く
# セッションURLとQRコードを確認しながら状況を把握する
```

### 出先から再接続する場合

失敗インジケーターには再接続のショートカットが含まれているため、原因を確認したうえでその場で`/remote-control`を再実行し、セッションURLやQRコードを再取得できます。

```bash
# 詳細確認後、再接続
/remote-control
```

### VS Code拡張でも同様に改善

同じv2.1.224では、VS Code拡張機能側で「接続が失敗しているのに接続中と表示され続ける」不具合も修正されており、CLIとエディタ双方で接続状態の表示がより正確になりました。

## 注意点

- 失敗インジケーターはターミナル幅が狭い場合、フッターに収まらず非表示になることがあります。
- Remote Controlは`api.anthropic.com`への直接接続を前提とした機能で、Amazon Bedrock・Google Cloud's Agent Platform・Microsoft Foundryや、`ANTHROPIC_BASE_URL`をカスタムのゲートウェイに向けている場合は利用できません。
- 接続失敗の原因（認証切れ、ネットワーク不通、組織ポリシーによる無効化など）によってエラーメッセージの内容が異なるため、表示された詳細を確認したうえで対処してください。
- `claude remote-control --verbose`を使うと、より詳細なログを確認できます。
