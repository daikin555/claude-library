## 原文（日本語に翻訳）

GitLabのトークン系列（`glrt-`、`gloas-`、`glptt-`、`glagent-`、`glimt-`、`glsoat-`、`glcbt-`、`glft-`、`glffct-`）に対するシークレットのマスキング（redaction）と、ルーティング可能な `glpat-`／`gldt-` トークンの完全マスキングが追加されました。また、`glab` CLIの設定ストアにも、`gh` と同様のサンドボックス保護および認証情報パス保護が適用されるようになりました。

## 原文（英語）

Added secret redaction for GitLab token families (`glrt-`, `gloas-`, `glptt-`, `glagent-`, `glimt-`, `glsoat-`, `glcbt-`, `glft-`, `glffct-`) and full redaction of routable `glpat-`/`gldt-` tokens; the `glab` CLI config store gets the same sandbox and credential-path protection as `gh`

## 概要

Claude Codeは、ファイルの読み取りやコマンド出力の中に含まれるシークレット（トークンなど）を自動的にマスキングする仕組みを持っています。v2.1.232では、この保護対象にGitLab関連の各種トークン（Runner登録トークン、OAuthトークン、パイプライントリガートークン、エージェントトークンなど9系統のプレフィックス）が追加され、さらに外部に送信可能な `glpat-`（Personal Access Token）や `gldt-`（Deploy Token）については全体を完全にマスキングするよう強化されました。あわせて、GitLabのCLIツールである `glab` の設定ファイル（認証情報を含む）についても、GitHub CLI（`gh`）と同等のサンドボックス保護・認証情報パス保護が適用されるようになりました。

## この変更が影響する場面

これはユーザーが明示的に呼び出す機能ではなく、Claude Codeの内部的な安全機構です。以下のような場面で自動的に効果を発揮します。

- Claudeがファイルやコマンド出力の内容を読み取り、その中にGitLabのトークンが含まれていた場合、出力やログ上でマスキングされます。
- サンドボックス環境で `glab` コマンドを実行する際、`glab` の設定ファイル（認証情報を含む）へのアクセスが `gh` と同様に保護されます。

## 実践例

### glabの設定ファイルを誤って読み込んでしまった場合

```
cat ~/.config/glab-cli/config.yml
```

このようなコマンドの出力に認証トークンが含まれていても、対象のトークンプレフィックスに一致する部分は自動的にマスキングされ、生のトークン値がそのまま表示・保存されることを防ぎます。

### ログやCI設定にGitLabトークンが含まれている場合

```
grep -r "glpat-" .gitlab-ci.yml
```

`glpat-` や `gldt-` のようなルーティング可能なトークンは全体が完全にマスキングされるため、CI設定ファイルなどを調査する際にも安全性が高まります。

### サンドボックス内でglabコマンドを実行する場合

```
glab auth status
```

`glab` の設定ストアは `gh` と同じ仕組みでサンドボックス保護・認証情報パス保護が適用されるため、サンドボックス内のプロセスから設定ファイル中の認証情報が漏れるリスクが軽減されます。

## 注意点

- Claude Code v2.1.232での変更です。
- マスキング対象のトークンプレフィックス: `glrt-`、`gloas-`、`glptt-`、`glagent-`、`glimt-`、`glsoat-`、`glcbt-`、`glft-`、`glffct-`（部分マスキング）に加え、`glpat-`・`gldt-`（完全マスキング）。
- これは自動的な保護機能であり、ユーザー側での追加設定は不要です。
- GitHub（`gh`）向けに提供されていた保護がGitLab（`glab`）にも拡張された形の変更です。
