## 原文（日本語に翻訳）

変数を書き込むパラメータが `$PSDefaultParameterValues` をサイレントに上書きし、後続のコマンドのファイルアクセス先をリダイレクトできてしまうPowerShellの権限バイパスを修正しました。

## 原文（英語）

Fixed a PowerShell permission bypass where variable-writing parameters could silently overwrite `$PSDefaultParameterValues` and redirect later commands' file access

## 概要

PowerShellには `$PSDefaultParameterValues` という特殊な自動変数があり、これを設定するとPowerShellの各コマンドレットに渡されるパラメータのデフォルト値を変更できます。この修正が入る前は、Claude Codeが実行を許可したPowerShellコマンドの中に、変数へ値を書き込むパラメータ（例えば `-OutVariable` のような仕組みや代入操作）を悪用して `$PSDefaultParameterValues` をサイレントに書き換えるものが含まれていた場合、それ以降に実行されるコマンドのファイルアクセス先を攻撃者の意図した場所へリダイレクトできてしまう可能性がありました。つまり、一見無害に見えるコマンドの許可が、実際には許可した覚えのないファイルへの読み書きにつながる権限バイパスの経路になり得たということです。この修正により、そのような手口でのパーミッション回避ができなくなりました。

## この変更が影響する場面

これは内部的なセキュリティ修正であり、ユーザーが明示的に呼び出す新機能ではありません。Windows環境でPowerShellコマンドの実行を許可制で運用している場合、以下のような場面で本修正の恩恵を受けます。

- Claude Codeに対して特定のPowerShellコマンドの実行を許可しているプロジェクトで、悪意のあるプロンプトインジェクションやサプライチェーン経由のコード片が `$PSDefaultParameterValues` を書き換えることで、後続コマンドの読み書き先を誘導しようとするケース
- ファイルアクセスに関するパーミッション設定を、コマンドの見た目のパス指定だけに頼っていたケース

## 実践例

### 許可済みコマンドを悪用したファイルリダイレクトの防止

```powershell
# 修正前に懸念されていたシナリオ（概念的な例）
# 一見無害な変数書き込みパラメータを含むコマンドが
# $PSDefaultParameterValues を書き換え、
# 後続の Get-Content や Out-File のデフォルトパスを
# 意図しない場所にリダイレクトしてしまう可能性があった
```

```bash
# 修正後
# $PSDefaultParameterValues のサイレントな上書きが検出・防止され、
# 後続コマンドのファイルアクセス先は想定通りに保たれる
```

### 権限プロンプトの信頼性向上

Claude CodeがPowerShellコマンドに対して表示する権限確認ダイアログが、実際に何にアクセスするかを正しく反映するようになります。

## 注意点

- Claude Code v2.1.232で修正されたセキュリティ修正です。Windows環境でPowerShellを利用している場合に関係します。
- 本修正はセキュリティ上重要な修正のため、Windows環境でClaude Codeを利用している場合は最新バージョンへのアップデートを推奨します。
- 具体的な攻撃手法の詳細な再現手順は、セキュリティ上の理由から公開されていません。
