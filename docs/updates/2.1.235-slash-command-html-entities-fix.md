## 原文（日本語訳）

Claudeが応答を生成している最中にスラッシュコマンドを実行すると、実際の文字ではなくHTMLエンティティ（`&amp;` や `&lt;` など）がそのまま表示されてしまう不具合を修正しました。

## 原文（英語）

Fixed slash commands run while Claude is responding showing HTML entities instead of the actual characters

## 概要

Claude Codeでは `/compact` や `/clear` などのスラッシュコマンドを、Claudeがまだ応答を生成中（ストリーミング中）のタイミングでも実行できます。これまでは、このタイミングでコマンドを実行すると、出力のエスケープ処理の兼ね合いで `&` や `<` などの文字がHTMLエンティティ表記（`&amp;`、`&lt;` など）のまま画面に表示されてしまい、見た目が崩れたり内容が読みにくくなったりする問題がありました。今回の修正で、応答中にスラッシュコマンドを実行しても、これらの文字が正しくデコードされた状態で表示されるようになりました。

## 基本的な使い方

Claudeが長い応答を生成している最中でも、ターミナル上でスラッシュコマンドを入力して割り込み的に実行できます。

```
> /compact
```

修正前は、応答生成中にこのようなコマンドを実行すると、コマンドの出力やその前後のテキストに含まれる記号がHTMLエンティティのまま（例: `if (a &lt; b) { ... }` のように）表示されることがありました。修正後は、同じ操作をしても記号がそのまま正しい文字（`if (a < b) { ... }`）として表示されます。

## 実践例

### 応答生成中に `/compact` でコンテキストを圧縮する

長時間のセッションでコンテキストが膨らんできた際、Claudeの応答完了を待たずに `/compact` を実行して会話を圧縮できます。修正後は、圧縮処理のサマリーやその前後の出力に記号が含まれていても、文字化けのような表示にならず正しく読めます。

### コード片を含む出力を表示中にコマンドを実行する

Claudeが `<div>` や `a && b` のような記号を含むコードを出力している最中に別のスラッシュコマンドを割り込ませても、以前のようにその記号が `&lt;div&gt;` や `a &amp;&amp; b` のようなエンティティ表記に化けることがなくなりました。

### `/clear` で会話をリセットする

応答の途中で会話をリセットしたい場合に `/clear` を実行しても、直前まで表示されていたテキストや確認メッセージが正しい文字で表示されるため、何が起きたのか誤解なく確認できます。

## 注意点

- この不具合は「Claudeが応答中（ストリーミング中）にスラッシュコマンドを実行した場合」に限って発生していました。応答完了後にコマンドを実行する通常の使い方では影響はありませんでした
- 表示の問題であり、コマンド自体の実行結果や副作用（ファイル変更など）には影響していません
