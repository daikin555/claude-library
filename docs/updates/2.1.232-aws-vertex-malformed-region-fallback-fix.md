## 原文（日本語に翻訳）

不正な形式のAWSまたはVertexのリージョン値がリクエストURLの構築に使われてしまう問題を修正しました。現在は不正な値の場合、デフォルトのリージョンにフォールバックするようになりました。

## 原文（英語）

Fixed malformed AWS or Vertex region values being used to build request URLs; they now fall back to the default region

## 概要

AmazonBedrockやGoogle Vertex AIをバックエンドとして利用する場合、Claude Codeはリージョン設定（例: `us-east-1`、`us-central1`など）をもとにAPIリクエスト先のURLを組み立てます。今回の修正前は、環境変数などで指定されたリージョン値が不正な形式（誤字、空文字、無効な値など）だった場合でも、そのままリクエストURLの構築に使われてしまい、接続エラーの原因になっていました。本アップデートにより、不正な形式のリージョン値が検出された場合は、自動的にデフォルトのリージョンにフォールバックするようになりました。

## 基本的な使い方

BedrockまたはVertexのリージョンは環境変数で指定します。修正後は、これらの値が不正な形式であった場合に自動でデフォルトリージョンが使用されます。

```bash
# Bedrockのリージョン指定
export AWS_REGION=us-east-1

# Vertexのリージョン指定
export CLOUD_ML_REGION=us-central1
```

```bash
# 不正な値を指定してしまった場合の例
export AWS_REGION="us-eastt-1"   # タイプミス等の不正な値

# 修正前: この不正な値がそのままリクエストURLに使われ、接続エラーになる
# 修正後: 不正な値を検出し、デフォルトリージョンに自動フォールバックする
```

## 実践例

### 環境変数の設定ミスがあった場合でも処理が継続してほしい場合

CI/CD環境や複数プロジェクトを横断するスクリプトの中で、`AWS_REGION`や`CLOUD_ML_REGION`をテンプレートや変数展開で設定していると、タイプミスや変数展開の失敗により不正なリージョン値が入り込んでしまうことがあります。以前はこの不正な値がそのままリクエストURLの構築に使われ、分かりにくいネットワークエラーとして失敗していました。修正後はデフォルトリージョンにフォールバックするため、少なくともリクエスト自体は継続可能になり、意図しない設定ミスによる完全な停止を防げます。

```bash
# CI環境で誤ったリージョン変数が設定されるケース
export AWS_REGION="${DEPLOY_REGION:-}"  # 空文字になってしまう場合など
# 修正後: 不正・空の値であればデフォルトリージョンにフォールバック
```

### 複数リージョンを切り替えて運用している場合

エンタープライズ環境で複数のAWSリージョンやVertexロケーションを切り替えながら運用している場合、設定ファイルや環境変数の管理ミスによって一時的に無効なリージョン文字列が指定されてしまうことがあります。修正後はこうした不正値によるリクエスト失敗が起きにくくなり、フォールバック先のデフォルトリージョンで動作を継続できるため、運用時のトラブルシューティングが容易になります。

```bash
# 複数リージョンを切り替える運用例
export AWS_REGION=eu-west-1
# 設定ミスで不正な値になった場合でも、
# 修正後はデフォルトリージョンへフォールバックして動作継続
```

## 注意点

- Claude Code v2.1.232での修正です。
- フォールバックはあくまで「不正な形式の値」を検出した場合の保険的な挙動であり、意図したリージョンを明示的に使いたい場合は、正しい値を設定することが重要です。
- フォールバック先のデフォルトリージョンが、利用したいモデルやサービスを提供していない場合は、別途正しいリージョンを設定する必要があります。
- AWS Bedrock・Google Vertex AIそれぞれで、利用可能なリージョン一覧は各クラウドプロバイダーのドキュメントも参照してください。
