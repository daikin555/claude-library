## 原文（日本語訳）

ユーザーが Remote Control をオフにした後でも、セッションの再開（`--resume`、SDKホスト、VS Code拡張機能）が Remote Control を静かに再接続してしまう問題を修正しました。

## 原文（英語）

Fixed a session resume silently reconnecting Remote Control after the user turned it off (`--resume`, SDK hosts, and the VS Code extension)

## 概要

[Remote Control](https://code.claude.com/docs/en/remote-control) を明示的にオフにしたユーザーが、後から `--resume` でセッションを再開したり、SDKホスト経由でセッションを再開したり、VS Code拡張機能でセッションを開いたりすると、Remote Controlが本人の意図に反して**静かに（通知なしに）再接続**されてしまう不具合がありました。これは、オフにしたはずのセッションが再びスマートフォンやブラウザから閲覧・操作可能な状態に戻ってしまうことを意味するため、プライバシーや意図しない共有の観点で望ましくない挙動でした。v2.1.224でこの不具合が修正され、ユーザーが明示的にオフにした設定がセッション再開時にも尊重されるようになりました。

## 基本的な使い方

Remote Controlをオフにする操作自体は従来どおりです。

```text
# セッション内でRemote Controlを無効化
/remote-control
# （すでに接続中の場合は再実行で切断）
```

設定ファイルで恒久的に無効化したい場合は `disableRemoteControl` を利用します。

```json
{
  "disableRemoteControl": true
}
```

## 実践例

### `--resume` でセッションを再開するケース

```bash
# 1. Remote Controlを使っていたセッションを明示的にオフにする
/remote-control   # 「接続済み」→ 再実行で切断

# 2. 後日、同じセッションを --resume で再開
claude --resume <session-id>

# 修正前: 再開時にRemote Controlが自動的に、かつ通知なしで再接続されてしまう
#         → ユーザーが気づかないうちに再びリモートから操作可能な状態になる
# 修正後: ユーザーがオフにした選択が尊重され、再開時に勝手に再接続されない
```

### SDKホスト経由でセッションを再開するケース

Claude Agent SDKなどを使ってホスト側からセッションを再開する場合も同様の問題が発生していました。

```text
# SDKホストがセッションを再開する処理を実行
# 修正前: Remote Controlがオフだったにもかかわらず自動的に再接続される
# 修正後: オフの状態が維持されたままセッションが再開される
```

### VS Code拡張機能でセッションを開き直すケース

```text
# VS Code拡張機能でRemote Controlをオフにした状態のセッションを再度開く
# 修正前: 拡張機能がバックグラウンドでRemote Controlを再接続してしまう
# 修正後: オフの設定が保持され、ユーザーが明示的に /remote-control を
#         実行しない限り再接続されない
```

## 注意点

- この修正は「ユーザーが明示的にオフにした」場合の挙動改善です。`remoteControlAtStartup` を `true` に設定するなど、自動接続を有効化している場合はセッション開始時に接続されるのが意図した挙動です。
- 恒久的にRemote Controlを無効化したい場合は、都度オフにするのではなく `disableRemoteControl` 設定を利用する方が確実です。管理者によるMDM等での強制無効化にも同じ設定が使われます。
- この問題は `--resume` に限らず、SDKホスト経由の再開やVS Code拡張機能でのセッション再開など、複数の経路に影響していました。いずれの経路でもv2.1.224以降は修正されています。
