## 原文（日本語訳）

[VSCode] Claudeが作業中に送信したメッセージについて、Claudeがそのメッセージの処理に着手するまで会話の一番下で待機するように変更しました。

## 原文（英語）

[VSCode] Changed a message sent while Claude is working to wait at the bottom of the conversation until Claude starts on it

## 概要

Claudeが現在のタスクを処理している最中に新しいメッセージを送信すると、そのメッセージはキューに入り、Claudeが着手するまで少し待機時間が発生します。これまでは、送信したメッセージの表示位置が処理の流れの中で不安定になることがありましたが、今回の変更により、Claudeが実際にそのメッセージの処理を開始するまでは、会話の一番下に固定されて表示されるようになりました。これにより、どのメッセージがまだ処理待ちなのかを視覚的に分かりやすく把握できます。

## 基本的な使い方

Claudeが作業中に追加でメッセージを送信するだけで、自動的にこの挙動が適用されます。

```
1. Claudeがタスク処理中に新しいメッセージを送信
2. Claudeが着手するまで、そのメッセージは会話の一番下で待機表示される
3. Claudeが着手すると、通常の会話フローに組み込まれる
```

## 実践例

### タスク処理中に追加の指示を送信するケース

Claudeが長いリファクタリング作業を行っている最中に、「テストも追加して」といった追加指示を送信する場合です。

```
修正前: 追加メッセージの表示位置が処理状況によって不安定になることがある
修正後: 追加メッセージはClaudeが着手するまで会話の一番下に固定表示される
```

### 複数の追加メッセージをキューに入れる場合

作業中に複数のメッセージを連続して送信した場合でも、それぞれが着手されるまで一番下で待機する形で表示されるため、どのメッセージが未処理かを一目で把握できます。

## 注意点

- これはメッセージの表示・整列に関するUI変更であり、メッセージの処理順序やキューイングのロジック自体を変更するものではありません。
- Claudeが処理中のタスクを中断してすぐに新しいメッセージに着手するかどうかは、メッセージの内容や状況によって異なります。
