## 原文（日本語訳）

パラメータのスキーマが空（`{}`）の場合に、MCPツールの引数が本来の型ではなくJSON文字列として送信されてしまう問題を修正しました。

## 原文（英語）

Fixed MCP tool arguments being sent as JSON strings when the parameter's schema is empty (`{}`), instead of their real type

## 概要

MCPツールの中には、パラメータのJSON Schemaが `{}`（型情報が何も定義されていない空スキーマ）になっているものがあります。このような場合、従来のClaude Codeは引数の実際の型（オブジェクトや配列など）を判別できず、JSON文字列としてシリアライズしてツールに渡してしまっていました。これにより、ツール側がオブジェクトや配列を期待しているにもかかわらず文字列を受け取ってしまい、ツール呼び出しが失敗したり意図しない挙動になったりする問題が発生していました。この修正により、スキーマが空の場合でも引数は本来の型のまま正しく送信されるようになります。

## 基本的な使い方

この修正はMCPクライアント内部の引数シリアライズ処理に関するもので、ユーザーが明示的に操作する項目はありません。スキーマが `{}` のパラメータを持つMCPツールを呼び出すと、以下のように改善されます。

```
修正前: tool_call(config="{\"debug\": true, \"retries\": 3}")  // JSON文字列として渡される
修正後: tool_call(config={"debug": true, "retries": 3})          // オブジェクトとして正しく渡される
```

## 実践例

### 型を厳密に定義していないカスタムMCPサーバーとの連携

自作・サードパーティ製のMCPサーバーで、柔軟性を持たせるためにパラメータのスキーマを `{}` としているケースがあります。この修正により、そうしたツールに配列やオブジェクトを渡す際も、文字列化されずに元の型のまま正しく受け渡しされます。

### 動的な設定オブジェクトを渡すツール

任意のキーを持つ設定オブジェクトを受け取るようなMCPツール（スキーマを厳密に固定できないもの）を利用する場合、これまでは受け取り側で文字列をパースし直す必要がありましたが、修正後はツール側の実装をそのまま活かせます。

### 配列引数を持つツールの呼び出し

スキーマが未定義の配列パラメータにリスト（例: タグの配列、IDのリストなど）を渡す場合も、JSON文字列化されることによる二重エンコード問題が解消され、期待通りに配列として渡されます。

## 注意点

- この修正は影響するのはパラメータのJSON Schemaが空（`{}`）のケースに限られます。型が明示的に定義されているパラメータには元々影響していません
- MCPサーバー側のスキーマ定義を変更する必要はなく、Claude Code側の修正のみで解決します
- 既存のツールでこの問題を回避するために文字列パースの後処理を実装していた場合、動作が変わる可能性があるため確認をおすすめします
