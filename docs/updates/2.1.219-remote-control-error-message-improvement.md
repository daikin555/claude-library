## 原文（日本語に翻訳）

「Remote Controlはapi.anthropic.com経由でのみ利用可能です」というエラーメッセージが改善され、原因となった具体的な設定名が表示されるようになりました。

## 原文（英語）

Improved the "Remote Control is only available via api.anthropic.com" error to name the specific setting that caused it

## 概要

Claude CodeのRemote Control機能は、claude.ai/codeやモバイルアプリからローカルセッションを操作するために、Anthropic API（api.anthropic.com）への直接接続を前提としています。従来は、この前提が崩れている場合に一律で「Remote Control is only available via api.anthropic.com」という汎用的なエラーしか表示されず、原因が `ANTHROPIC_BASE_URL` の変更なのか、Bedrock/Vertex等の代替エンドポイント利用なのか、managed settingsによる無効化なのか切り分けが困難でした。バージョン2.1.219では、このエラーメッセージに原因となった具体的な設定名が明示されるようになり、ユーザーは表示された設定を確認するだけで対処できるようになりました。

## 基本的な使い方

エラーが発生した場合、まずはメッセージ本文を確認します。改善後は、例えば以下のように原因設定名が含まれる形でエラーが表示されます。

```
Error: Remote Control is only available via api.anthropic.com
  Blocked by: ANTHROPIC_BASE_URL is set to "https://my-llm-gateway.example.com"
```

原因が判明したら、該当する設定を解除・変更してから再度Remote Controlを起動します。

```bash
# ANTHROPIC_BASE_URL が原因だった場合
unset ANTHROPIC_BASE_URL
claude remote-control
```

## 実践例

### `ANTHROPIC_BASE_URL` が原因の場合

LLMゲートウェイやプロキシ経由で接続する構成では、`ANTHROPIC_BASE_URL` が `api.anthropic.com` 以外を指していると自動的にRemote Controlが無効化されます。改善後のエラーメッセージには、この変数名と現在の値が明示されるため、原因の切り分けが一目で分かります。

```bash
# 現在の設定値を確認
echo "$ANTHROPIC_BASE_URL"

# Remote Controlを使いたいシェルでのみ一時的に解除する
env -u ANTHROPIC_BASE_URL claude remote-control
```

恒常的にゲートウェイ経由で運用しつつ、必要な時だけRemote Controlを使いたい場合は、Remote Control専用のシェルプロファイルや起動スクリプトを分けておくと切り替えがスムーズです。

### managed settingsで無効化されている場合

組織のIT管理者が `disableRemoteControl` をmanaged settingsに設定している場合、エラーメッセージに `disableRemoteControl` という設定名が明示的に含まれるようになります。この場合はローカルでの回避策はなく、組織のポリシーとして意図的に無効化されています。

```bash
# 現在有効な設定（managed settingsを含む）を確認
claude doctor

# 認証状態やログイン方式も合わせて確認
/status
```

このケースに該当する場合は、設定ファイル（`managed-settings.json` など）を自分で編集しても反映されないため、社内のIT管理者やAnthropic Enterpriseの管理者に問い合わせるのが正しい対処法です。

### Bedrock/Vertex/Foundryなど代替APIエンドポイントを利用している場合

Amazon Bedrock、Google CloudのAgent Platform、Microsoft Foundry経由でClaude Codeを利用している場合、そもそもRemote Controlはサポートされていません。この場合エラーメッセージには、利用中の接続方式（例: Bedrock経由であること）が明示され、「設定を直せば使える」ケースと「そもそも非対応」なケースを区別しやすくなりました。

```bash
# 認証・接続方式を確認する
/status
```

`/status` の出力で `CLAUDE_CODE_USE_BEDROCK` や `CLAUDE_CODE_USE_VERTEX` が有効になっている場合は、Remote Control自体が現状非対応のため、api.anthropic.com経由の標準構成（claude.aiアカウントでの `/login`）に切り替える必要があります。

## 注意点

- この改善はエラーメッセージの「分かりやすさ」の改善であり、Remote Controlが利用できる条件そのものが変わったわけではありません。`ANTHROPIC_BASE_URL` を非公式エンドポイントに向けている限り、Remote Controlは引き続き利用できません。
- `ANTHROPIC_API_KEY` や `ANTHROPIC_AUTH_TOKEN` が設定されている場合も、Remote Controlに必要なclaude.ai OAuth認証と競合するため、そちらが原因として表示されることがあります。該当する場合は環境変数を解除し `/login` で再認証してください。
- managed settingsによる無効化は組織のポリシーであり、ユーザー側の設定変更では回避できません。エラーに `disableRemoteControl` と表示された場合は、まず管理者に確認しましょう。
- 原因の切り分けに迷ったら、`claude doctor` と `/status` を併用すると、環境変数・ログイン方式・managed settingsの状態をまとめて確認できます。
