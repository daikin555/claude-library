## 原文（日本語訳）

Claude Desktopのセッション間メッセージが、受信側セッションでクロスセッションメッセージングが無効と読み取られた場合にサイレントに破棄されてしまい、送信側のクエリが数分間「thinking」状態のまま止まってしまう問題を修正しました。

## 原文（英語）

Fixed Claude Desktop inter-session messages being silently dropped by the recipient session when cross-session messaging read as disabled, which left the sender's query "thinking" for many minutes

## 概要

Claude Codeにはセッション間でメッセージをやり取りできるクロスセッションメッセージング機能（`SendMessage`/`ListAgents`）があります。Claude Desktopでは、受信側セッションが誤ってクロスセッションメッセージングを「無効」と判定した場合、送られてきたメッセージが応答なくサイレントに破棄されてしまうバグがありました。この結果、送信側は応答を待ち続け、Claudeが「thinking」（思考中）の状態のまま数分間フリーズしたように見える現象が発生していました。今回の修正でこの取りこぼしが解消されました。

## 基本的な使い方

この修正はClaude Desktop内部のメッセージ配送処理に対するものです。ユーザーが行う操作は通常のクロスセッションメッセージングと変わりません。

1. Claude Desktopで複数のセッションを起動する
2. 一方のセッションから他方のセッションへ`SendMessage`でメッセージを送る
3. 修正後は受信側の状態にかかわらず、メッセージが正しく処理されるか、少なくとも送信側が無限に待機し続けることがなくなる

## 実践例

### 複数プロジェクトを並行して作業している場合

Claude Desktopで別々のプロジェクトを開いた複数のセッションを走らせ、一方のセッションから「このAPI変更はもう一方のセッションに影響するはずだから伝えて」と依頼したケースで、以前は受信側の状態次第でメッセージが黙って消え、送信側が延々と「thinking」のまま固まって見えることがありました。修正後はこのような放置状態が解消されます。

### 長時間応答がないと感じた場合の切り分け

もしこれまで、Claude Desktopでセッション間連携を使った際に「thinking」表示のまま数分以上反応がなくなる現象に遭遇したことがある場合、それはこの不具合が原因だった可能性があります。2.1.234以降ではこの特定の原因については解消されているため、同様の現象が続く場合は別の要因（ネットワークやAPIレート制限など）を疑う必要があります。

## 注意点

- この修正はClaude Desktopでのセッション間メッセージングに関するものです
- クロスセッションメッセージング自体はmacOSおよびLinuxで利用可能な機能です
- メッセージが依然として届かない場合は、受信側セッションでクロスセッションメッセージングが有効になっているか確認してください
