## 原文（日本語訳）

呼び出された（recallされた）ペーストのプレースホルダー番号が、入力欄に反映される際に振り直されるように変更されました。

## 原文（英語）

Changed recalled paste placeholder numbers to renumber when accepted into the input

## 概要

Claude Codeでは、長いテキストや複数行のコンテンツを入力欄にペーストすると、内容がそのまま展開されるのではなく `[Pasted text #1 +120 lines]` のようなプレースホルダーに置き換えられます。これにより入力欄が長大なテキストで埋め尽くされるのを防ぎつつ、実際の内容は送信時にClaudeへ渡されます。v2.1.224では、履歴から過去の入力を呼び出す（recallする）際に含まれていたペーストのプレースホルダー番号が、現在の入力欄に反映されるタイミングで自動的に振り直されるようになりました。これにより、現在の入力欄にすでに存在する番号と衝突し、どのプレースホルダーがどの内容を指しているのか分からなくなる問題を防ぎます。

## 基本的な使い方

通常の利用では、テキストをペーストするだけでプレースホルダーが自動的に発行されます。特別な操作は不要です。

```text
# 長いログをペースト
> [Pasted text #1 +85 lines]
このエラーログの原因を調べてください
```

履歴を上下矢印キーなどで遡って過去の入力を呼び出し、それを現在の入力欄に反映（accept）すると、含まれていたペーストのプレースホルダー番号は現在の入力欄の状態に合わせて自動的に振り直されます。

## 実践例

### 過去の入力を呼び出して番号が衝突するケース

修正前は、以下のような手順で番号の衝突が起こり得ました。

```text
# 1. 長いコードをペーストして送信
> [Pasted text #1 +200 lines] このコードをレビューして

# 2. 新しいターンで別の長いテキストをペースト
> [Pasted text #1 +40 lines]   ← 新しい入力欄でも #1 から採番される

# 3. 履歴を遡って手順1の入力を呼び出し、現在の入力欄に反映
#    修正前: 呼び出した [Pasted text #1] が、
#    手順2で新たに作られた [Pasted text #1] と番号が重複してしまう
```

修正後は、手順3で過去の入力を呼び出して反映した際に、既存の `#1` と衝突しないよう自動的に `#2` などへ振り直されます。そのため、どのプレースホルダーがどの貼り付け内容に対応しているかが常に一意に保たれます。

### 同じ内容を繰り返し送るワークフロー

エラーログやスタックトレースなど、似た内容を何度も貼り付けて質問し直すワークフローでも、番号の整合性が保たれるため、誤って古い貼り付け内容が新しい貼り付けと混同されるリスクが減ります。

```text
> [Pasted text #1 +30 lines] このスタックトレースを直して
# 修正案を試したあと、再度別のスタックトレースをペーストして質問
> [Pasted text #1 +45 lines] まだ再現します
# 直前の入力を呼び出して微修正する場合も、番号は自動的に整合性を保つ
```

## 注意点

- この変更は表示上の番号の振り直しであり、貼り付けられた実際のコンテンツ自体が書き換わるわけではありません。
- 番号の振り直しは、呼び出した入力を現在の入力欄に**反映（accept）した時点**で行われます。呼び出しただけでまだ反映していない状態では番号は変わりません。
- 通常の利用でユーザーが意識する必要はほとんどありませんが、長時間のセッションで何度もペーストと履歴呼び出しを行うワークフローでは、この修正により参照の取り違えが起きにくくなります。
