## 原文（日本語訳）

kitty keyboard protocolに対応したターミナルで、キリル文字など非ラテン文字のキーボードレイアウトを使用している場合にCtrlキーショートカットが発火しない問題を修正しました。

## 原文（英語）

Fixed Ctrl keyboard shortcuts not firing under non-Latin (e.g. Cyrillic) keyboard layouts in kitty-protocol terminals

## 概要

kitty keyboard protocol（Kitty、WezTerm、Ghosttyなど一部のモダンターミナルが対応）を使うと、従来のターミナルより正確なキー入力情報を受け取れます。しかし、これまではキリル文字などの非ラテン文字レイアウトが有効な状態で入力すると、Ctrlを使ったショートカット（例: Ctrl+Cによる中断など）がClaude Code側で正しく認識されず、発火しないという問題がありました。今回の修正により、キーボードレイアウトに関わらずCtrlショートカットが期待どおりに動作するようになりました。

## 基本的な使い方

特別な設定は不要です。kitty keyboard protocol対応ターミナルを使用し、OS側でキリル文字などの非ラテン文字レイアウトに切り替えている状態でも、これまでどおりCtrl+Cなどのショートカットがそのまま使えるようになります。

```
# 例: キーボードレイアウトをロシア語（キリル文字）に切り替えた状態でも
# Ctrl+C でClaude Codeの処理を中断できる
```

## 実践例

### 多言語環境での作業

ロシア語やウクライナ語などキリル文字ベースの入力言語を日常的に使用している開発者が、OSの入力切り替え（IME切り替え）をした状態でもCtrl+CやCtrl+R（履歴検索）などのショートカットを問題なく使えるようになります。

### モダンターミナルの活用

Kitty、WezTerm、Ghosttyといったkitty keyboard protocol対応ターミナルを使っているユーザーは、キーボードレイアウトの違いを気にせず、これまで報告されていた「一部のショートカットだけ効かない」という挙動から解放されます。

### チーム開発でのロケール差異

英語キーボードレイアウトを主に使うメンバーと非ラテン文字レイアウトを使うメンバーが同じCLIツールを使う場合でも、動作の一貫性が保たれるようになります。

## 注意点

- この修正はkitty keyboard protocolに対応したターミナルでのみ関係します。対応していないターミナル（多くの従来型ターミナル）では元々別の入力処理経路が使われます
- レイアウトの切り替え自体はOS側の機能であり、Claude Codeが制御するものではありません
