## 原文（日本語訳）
Monitorツールの通知を改善：スクリプトの最終出力とその終了通知が、2回ではなく1回の通知としてまとめて届くようになり、モデルのターンを1回節約できるようになった。

## 原文（英語）
Improved Monitor tool notifications: a script's final output and its exit now arrive as one notification instead of two, saving a model turn

## 概要
Monitorツールは、バックグラウンドで実行しているスクリプトやプロセスの出力を監視し、変化があるたびにClaudeに通知する機能です。これまでは、スクリプトが最終出力を行った直後にプロセスが終了すると、「最終出力の通知」と「終了通知」の2回に分けて別々の通知が届き、それぞれに対してモデルが応答のターンを消費していました。今回の改善により、この2つがまとめて1回の通知として届くようになり、不要なモデルターンの消費が削減されました。

## 基本的な使い方
Monitorツールの利用方法自体に変更はありません。バックグラウンドプロセスを監視している場合、プロセス終了時の通知が効率化されます。

```bash
# バックグラウンドでスクリプトを実行し、Monitorツールで監視するイメージ
long_running_script.sh &
```

## 実践例

### ビルドスクリプトの完了を監視する場合
ビルドやテストスクリプトをバックグラウンドで実行し、その完了をMonitorツールで待っているケースでは、以前は最終出力の通知と終了通知が別々に届き、モデルが2回応答する必要がありました。改善後は1回の通知にまとまるため、モデルの処理ターンが節約され、レスポンスも速くなります。

```bash
# 例: テストスクリプトの実行と監視
npm test > test-output.log 2>&1 &
# Monitorツールがtest-output.logとプロセス終了を監視
```

### 長時間実行するデプロイスクリプトの監視
デプロイスクリプトのように、最後に成功/失敗のメッセージを出力してすぐに終了するタイプのスクリプトでは、この改善の恩恵が特に大きくなります。

## 注意点
- これは内部的な通知の効率化であり、Monitorツールの基本的な使い方や設定方法に変更はありません。
- スクリプトの最終出力と終了タイミングが大きく離れている場合は、従来通り複数回の通知が届くことがあります。
