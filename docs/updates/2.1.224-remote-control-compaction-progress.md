## 原文（日本語訳）

Remote Controlを改善し、接続されたWeb・モバイルクライアントが、無言の一時停止ではなく、コンパクション（履歴圧縮）の進行状況とコンパクション後の境界を確認できるようになりました。また、`/clear`によるリセットが接続中のクライアントにも反映されるようになりました。

## 原文（英語）

Improved Remote Control: attached web and mobile clients now see compaction progress and the post-compaction boundary instead of a silent pause; `/clear` resets now propagate to attached clients

## 概要

Remote Controlは、ローカルマシンで実行中のClaude Codeセッションを、claude.ai/codeのWebインターフェースやClaude モバイルアプリから遠隔操作できる機能です。実行自体はローカルマシン上で行われ、Web/モバイル側はそのセッションを覗き見るウィンドウとして機能します。これまでは、ローカルセッションで自動コンパクションが走ると、接続中のWeb/モバイルクライアントには何の表示もされず、あたかも応答が止まっているかのように見えることがありました。今回の改善により、コンパクションの進行状況と、コンパクションが完了した「境界」が接続クライアント側にも表示されるようになり、`/clear`でローカルの会話をリセットした場合も、その状態が接続中の全クライアントに伝わるようになりました。

## 基本的な使い方

特別な設定は不要です。Remote Controlセッションを開始していれば、コンパクションが発生した際に自動的に進行状況が接続クライアントに反映されます。

```bash
# ローカルでRemote Controlセッションを開始
claude remote-control

# 表示されたセッションURLをスマートフォンやブラウザで開く
# → 以降、コンパクションが発生してもWeb/モバイル側に進行状況が表示される
```

## 実践例

### 長時間タスクをスマートフォンで見守っている最中にコンパクションが発生した場合

大きめのリファクタリングをローカルで走らせつつ、外出先からスマートフォンのClaudeアプリで進捗を確認しているケースを想定します。以前はコンテキストが圧縮されるタイミングで画面が固まったように見え、セッションが落ちたのか単に処理中なのか判断がつきませんでした。改善後は、コンパクション中であることと、圧縮が完了した境界（post-compaction boundary）がモバイル画面上にも明示されるため、安心して待つことができます。

### チームでWebクライアントから同じセッションを覗いている場合

複数人がclaude.ai/codeの同じRemote Controlセッションを閲覧している状況で、誰かがターミナル側で`/clear`を実行して会話をリセットした場合、以前は接続中の他のクライアントに古い会話がそのまま残ってしまうことがありました。改善後は`/clear`のリセットが即座に全接続クライアントへ伝播するため、表示のずれが起きません。

```text
# ローカルターミナルで
/clear
# → 接続中のWeb/モバイルクライアントの表示も同時にリセットされる
```

### `/compact`を手動実行する場合

手動で`/compact`を実行した場合も同様に、進行状況が接続クライアント側に表示されます。

```text
/compact
```

## 注意点

- Remote Controlは研究プレビュー機能で、Pro・Max・Team・Enterpriseプランで利用可能です（APIキー認証には非対応）。Team/Enterpriseでは管理者が管理コンソールでトグルを有効にする必要があります。
- Remote Control接続中は、会話トランスクリプト（メッセージ・Claudeの応答・ツール実行内容）が同期のためAnthropicのサーバー上にも保存されます。実行自体とファイルシステムへのアクセスはローカルマシン上にとどまります。
- Zero Data Retention(ZDR)など一部のコンプライアンス設定を持つ組織ではRemote Control自体が利用できません。
- この改善はv2.1.224以降のClaude Codeで有効です。
