## 原文（日本語訳）

サブプロセスの起動に失敗した際に未処理のPromise拒否（unhandled promise rejection）が発生する問題を修正しました。例えば、Windows interopが無効化されたWSL環境で `powershell.exe` の起動に失敗する場合などです（v2.1.234での回帰）。

## 原文（英語）

Fixed unhandled promise rejections when a subprocess fails to start, for example `powershell.exe` on WSL with Windows interop disabled (regression in 2.1.234)

## 概要

Claude Codeは内部的にシェルコマンドの実行などのためにサブプロセスを起動することがあります。v2.1.234で発生した回帰により、サブプロセスの起動そのものに失敗した場合（プロセスが見つからない、実行権限がないなど）にその失敗が正しくハンドリングされず、未処理のPromise拒否としてクラッシュやエラーの原因になることがありました。代表的な例が、WSL（Windows Subsystem for Linux）環境でWindows interop機能が無効化されている場合に `powershell.exe` の呼び出しが失敗するケースです。今回の修正でサブプロセスの起動失敗が適切に捕捉されるようになり、この回帰が解消されました。

## 基本的な使い方

特別な操作は不要です。サブプロセスの起動に失敗するような環境（例えばWindows interopが無効なWSL）でClaude Codeを使っていても、以前のようにセッションが不安定になることなく、エラーとして適切に処理されます。

```bash
# WSL環境で、Windows interop（Windowsバイナリの直接実行）が無効化されている場合
claude
# powershell.exeなどWindows側の実行ファイルを呼び出そうとするサブプロセスが
# 起動に失敗しても、未処理のPromise拒否によるクラッシュが起きなくなった
```

## 実践例

### Windows interopを無効化したWSL環境での利用

`/etc/wsl.conf` などでWindows interopを無効化している開発環境では、`powershell.exe` のようなWindows側の実行ファイルをサブプロセスとして起動しようとすると失敗します。修正前（v2.1.234の回帰後）はこの失敗が未処理のPromise拒否として表面化し、予期しない動作につながることがありましたが、修正後は失敗が正しくエラーとして扱われます。

### 存在しない、または実行権限のないコマンドを内部的に呼び出そうとした場合

環境によってPATHが通っていない外部コマンドや、実行権限のないバイナリをClaude Codeが内部的に呼び出そうとするケースでも、起動失敗が適切にハンドリングされ、セッション全体の安定性に影響しにくくなりました。

## 注意点

- これはv2.1.234で入り込んだ回帰の修正であり、v2.1.233以前から利用している場合はそもそも影響を受けていなかった可能性があります。
- WSLでWindows interopを意図的に無効化している構成は、セキュリティやサンドボックス化の目的で使われることがあり、そうした環境での安定性が改善されます。
