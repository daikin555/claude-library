## 原文（日本語訳）

非常に長いセッションにおいて、会話がコンパクション（要約による圧縮）された後、autoモードがサンドボックス化されたコマンドのネットワークアクセスを何度もチェックし直して拒否し続けてしまう不具合を修正しました。

## 原文（英語）

Fixed auto mode in very long sessions repeatedly re-checking and denying sandboxed commands' network access after the conversation had been compacted

## 概要

autoモード（コマンド実行の可否を自動判断する権限モード）では、サンドボックス化されたコマンドがネットワークアクセスを必要とする場合、一度許可されたはずの判断が本来は再利用されます。しかし非常に長いセッションで会話がコンパクション（コンテキストを要約して圧縮する処理）された後、この判断状態が正しく引き継がれず、同じ種類のコマンドに対して毎回ネットワークアクセスの可否を再チェックし、しかも拒否してしまう不具合がありました。今回の修正でこの問題が解消され、コンパクション後もネットワークアクセスの許可判断が正しく維持されるようになりました。

## 基本的な使い方

ユーザー側での操作は不要です。autoモードでサンドボックス化されたコマンドを実行しているセッションが長時間続き、コンテキストがコンパクションされた後も、ネットワークアクセスを伴うコマンドが従来通りに実行できるようになります。

```bash
claude --permission-mode auto

> パッケージをインストールしてビルドし、テストを実行して
```

## 実践例

### 長時間の自律実行タスクでnpm installなどが失敗しなくなる

長時間にわたる自動実行タスクの途中でコンテキストがコンパクションされても、その後の `npm install` や `curl` などネットワークアクセスを伴うサンドボックス化コマンドが、修正前のように毎回拒否されることがなくなります。

```bash
claude -p "依存関係を最新化し、ビルドとテストを繰り返し実行して問題を修正して" --permission-mode auto

# 会話が長時間・大量のツール呼び出しでコンパクションされる
# 修正前: コンパクション後、npm install などのネットワークアクセスが毎回拒否される
# 修正後: コンパクション後も正しく許可判断が維持され、コマンドが実行される
```

### CI的な長時間バッチジョブでの安定動作

数時間にわたる自律的なリファクタリング・依存関係更新ジョブなど、コンパクションが複数回発生するような使い方でも、ネットワークアクセスの挙動が安定します。

```bash
claude -p "全パッケージの依存関係を段階的に更新し、都度テストを実行" --permission-mode auto &

# 複数回のコンパクションをまたいでも、
# サンドボックスコマンドのネットワークアクセス判断が一貫して維持される
```

## 注意点

- この不具合はautoモードかつサンドボックス化されたコマンド実行に限定して発生していたものです
- 発生条件は「非常に長いセッション」かつ「会話がコンパクションされた後」であり、短いセッションでは影響を受けません
- 修正後もネットワークアクセスの許可自体はサンドボックスのポリシーに従って判断されるため、本来許可されるべきでないアクセスまで許可されるようになるわけではありません
- 同様の症状（長時間セッションでの権限判断の不安定さ）に心当たりがある場合は、最新版へのアップデートで解消される可能性があります
