## 原文（日本語訳）

アイドル・リタイア・起動タイムアウトによって解放されたセルフホストランナー上のセッションが、セッション終了後フックの処理が完了する前に、別のランナー上で再開されてしまうことが稀にある問題を修正しました。

## 原文（英語）

Fixed self-hosted runner sessions released on idle, retire, or startup timeout occasionally resuming on another runner before the post-session hook had finished

## 概要

セルフホスト環境（self-hosted environments）では、組織が用意したランナーがセッションを実行し、アイドル状態が続いた場合やランナーのリタイア、起動タイムアウトが発生した場合にはそのセッションを解放し、後で別のランナーが引き継いで再開できるようにしています。これまでは、セッションが解放された際にそのランナー上で走るセッション終了後フック（post-session hook）の処理が完了する前に、別のランナーが同じセッションを再開してしまうことが稀にありました。これにより、後片付け処理と新しいセッションの実行が競合する可能性がありました。今回の修正により、終了後フックの完了を待ってから他のランナーでの再開が行われるようになりました。

## 基本的な使い方

この修正はセルフホストランナーの内部的なセッション引き継ぎロジックに関するものであり、ユーザーやランナー管理者が明示的に操作する必要はありません。通常どおりセルフホスト環境でセッションを実行するだけです。

```
claude self-hosted-runner start
```

修正前は、あるランナー上のセッションがアイドルタイムアウトやランナーのリタイア、起動タイムアウトによって解放されると、そのランナーで実行中だった終了後フック（クリーンアップ処理など）が終わりきらないうちに、別の空いているランナーが同じセッションを拾って再開してしまうことがありました。修正後は、終了後フックの完了が保証されてから次のランナーへ引き継がれるようになっています。

## 実践例

### アイドルタイムアウトでセッションが解放される場合

しばらく操作のないセッションがアイドルタイムアウトによって元のランナーから解放されたとき、修正前はそのランナー上のクリーンアップ処理（一時ファイルの削除やロックの解放など）が終わる前に、別のランナーがセッションを再開してしまうことがありました。修正後は、クリーンアップが完了してから次のランナーに引き継がれるため、後片付けと新セッションの実行が競合しません。

### ランナーのリタイアや起動タイムアウトが発生する場合

デプロイの入れ替えなどでランナーが計画的にリタイアされる場合や、ランナーの起動処理がタイムアウトした場合にも、解放されたセッションが別のランナーへ引き継がれます。修正前はここでも終了後フックの完了前に再開が発生する可能性がありましたが、修正後はフック処理の完了を待ってから安全に引き継がれます。

## 注意点

- この問題は「稀に（occasionally）」発生するとされているタイミング依存の競合状態であり、常に再現するものではありません。
- セルフホスト環境は現在Team・Enterpriseプランでのパブリックベータ機能であり、管理者が「Allow self-hosted environments」を有効化している必要があります。
- 終了後フックでリポジトリのクリーンアップや機密情報の削除などを行っている構成では、この修正によって後片付けの完了がより確実に保証されます。
