## 原文（日本語訳）

直接Anthropic API接続で、かつテレメトリがオフの場合、autoモードは既定でサーバー側の分類器を使用するように変更しました（`CLAUDE_CODE_AUTO_MODE_SERVER=0` でオプトアウト可能）。

## 原文（英語）

Changed auto mode to use the server-side classifier by default on a direct Anthropic API connection when telemetry is off (`CLAUDE_CODE_AUTO_MODE_SERVER=0` opts out)

## 概要

Claude Codeの「autoモード」は、タスクの内容に応じて適切な権限モードやモデルを自動的に判断する機能です。この判断にはこれまでローカルの分類ロジックが使われることがありましたが、直接Anthropic APIに接続しており、かつテレメトリがオフになっている環境では、既定でサーバー側の分類器を利用するように変更されました。サーバー側の分類器はより高精度な判断が期待できますが、環境によってはこの変更を望まない場合もあるため、環境変数でオプトアウトする手段も用意されています。

## 基本的な使い方

既定の挙動を維持する場合は特に何もする必要はありません。従来のローカル分類器の挙動に戻したい場合は以下を設定します。

```bash
export CLAUDE_CODE_AUTO_MODE_SERVER=0
```

## 実践例

### より高精度なタスク分類を活用したい場合

autoモードの判断精度を重視するチームでは、既定のサーバー側分類器をそのまま利用することで、より適切な権限モードやモデル選択の恩恵を受けられます。

### 完全にオフライン・ローカル完結を重視する運用

サーバーとの追加通信を避けたい、あるいは以前の挙動との一貫性を重視する場合は、`CLAUDE_CODE_AUTO_MODE_SERVER=0` を設定してローカル分類器の挙動を維持できます。

## 注意点

- この変更は「直接Anthropic API接続」かつ「テレメトリオフ」という条件を満たす環境にのみ適用されます。Bedrock・Vertex経由や、テレメトリが有効な環境では対象外です
- サーバー側分類器はリクエスト内容の一部をサーバーに送って判定するため、通信内容のポリシー上の懸念がある場合はオプトアウトを検討してください
