## 原文（日本語訳）
軽度のメモリ圧迫状態にあるマシンで、バックグラウンドコマンドが30分間アイドル状態になると停止されていた問題を修正。現在はメモリが致命的に不足している場合にのみ停止されるようになり、デバッグログにその理由が記録されるようになった。

## 原文（英語）
Fixed background commands being stopped after 30 idle minutes on machines under mild memory pressure; they're now stopped only when memory is critically low, and the debug log says why

## 概要
Claude Codeはメモリ使用量を監視し、必要に応じてバックグラウンドで実行中のコマンドを停止することがあります。これまでは、マシンが軽度のメモリ圧迫状態にあるだけでも、30分間アイドル状態が続いたバックグラウンドコマンドが停止されてしまい、長時間の監視スクリプトなどが意図せず終了することがありました。今回の修正により、停止条件がメモリが致命的に不足している場合に限定され、さらにデバッグログに停止理由が明記されるようになりました。

## 基本的な使い方
特別な設定は不要です。バックグラウンドで実行したコマンドが以前より安定して継続実行されるようになります。停止された場合は、デバッグログでその理由を確認できます。

```bash
# デバッグログを有効にして原因を確認する例
claude --debug
```

## 実践例

### 長時間のログ監視・待機スクリプトをバックグラウンド実行する場合
`tail -f`のようなログ監視コマンドや、長時間アイドル状態が続く待機処理をバックグラウンドで実行している場合、以前はマシンが軽く負荷を受けただけで30分後に強制停止されることがありました。修正後は、実際にメモリが致命的に不足している場合のみ停止されるため、意図せぬ中断が減ります。

```bash
# バックグラウンドでのログ監視例
tail -f /var/log/app.log &
```

### コマンドが停止された理由を調査する場合
バックグラウンドコマンドが停止された際は、デバッグログに「メモリが致命的に不足したため停止した」といった理由が記録されるようになったため、原因調査がしやすくなりました。

```bash
# デバッグログで停止理由を確認
claude --debug 2>&1 | grep -i "background"
```

## 注意点
- メモリが実際に致命的なレベルまで不足した場合は、引き続きバックグラウンドコマンドが停止されます。これは安全のための挙動です。
- メモリ不足によりコマンドが頻繁に停止される場合は、マシンのメモリ増設や同時実行するバックグラウンドタスク数の見直しを検討してください。
