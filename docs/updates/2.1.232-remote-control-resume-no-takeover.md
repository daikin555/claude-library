## 原文（日本語に翻訳）

会話を再開（resume）しても、同じマシン上でまだRemote Controlを保持している別のClaude Codeから、Remote Controlを黙って奪わないようになりました。そのマシンでRemote Controlを移したい場合は `/remote-control` を実行してください。

## 原文（英語）

Remote Control: resuming a conversation no longer silently takes Remote Control away from another Claude Code on the same machine that still has it; run `/remote-control` there to move it

## 概要

これはRemote Controlのバグ修正です。同じマシン上で複数のClaude Codeセッションを起動している場合、一方のセッションでRemote Controlが有効になっている状態で、別のセッションで会話を再開（`claude --resume` や `/resume` など）すると、以前は明示的な操作なしにRemote Controlの制御権が新しく再開したセッション側へ黙って移ってしまうことがありました。今回の修正により、会話の再開だけではRemote Controlの制御権は移動しなくなり、意図せず別端末側の接続が奪われる問題がなくなりました。制御権を明示的に移したい場合は、Remote Controlを持たせたいセッション側で `/remote-control` を実行します。

## 基本的な使い方

Remote Controlの制御権を移したい場合は、移動先のセッションで明示的にコマンドを実行します。

```bash
# 制御権を持たせたいセッション（同じマシン上の別ウィンドウ/別ターミナルなど）で実行
/remote-control
```

単に別のセッションで会話を再開しただけでは、Remote Controlは元のセッションに残ったままになります。

```bash
claude --resume
# これだけではRemote Controlの制御権は移動しない
```

## 実践例

### 複数ターミナルで同じマシンの作業を切り替える

1つのターミナルタブでRemote Controlを有効にしてモバイルから操作していたところ、別のタブで過去の会話を再開したいケースです。修正前は再開した瞬間にRemote Controlが新しいタブ側へ移ってしまい、モバイル側の接続が意図せず切れることがありました。修正後は再開しただけでは制御権が移らないため、モバイル側の作業を邪魔されません。

### 一時的に別セッションを確認してから元の作業に戻る

過去のセッションの内容を軽く確認するために別ウィンドウで `/resume` した場合でも、Remote Controlを使っているメインのセッションの接続が維持されます。制御権を移したくなった場合のみ、確認用のセッション側で `/remote-control` を実行すれば明示的に切り替えられます。

### チームで同じマシンを共有する開発環境

複数人が同じリモート開発マシン上でそれぞれ別のClaude Codeセッションを扱う場合、ある人が会話を再開したことで別の人のRemote Control接続が意図せず奪われる、といった事故を防げます。

## 注意点

- Remote Controlの制御権を意図的に別セッションへ移したい場合は、必ず移動先のセッションで `/remote-control` を実行してください。
- この修正は「会話の再開」による暗黙の制御権移動を防ぐものであり、`/remote-control` による明示的な移動の挙動自体は変わりません。
- 同一マシン上での複数セッション運用時に特に関係する変更です。単一セッションのみを使っている場合は挙動に影響しません。
