## 原文（日本語訳）
Stopプロンプトフックが会話中のすべてのブロック発生時にプロンプト全体を再送信してしまう問題を修正しました。繰り返しのブロックは、500文字のラベルで条件を示すようになりました。

## 原文（英語）
Fixed Stop prompt hooks re-sending their whole prompt on every block in a conversation; repeat blocks now name the condition with a 500-character label

## 概要
Stopフックは、Claudeが応答を終了しようとするタイミングで条件をチェックし、必要に応じて停止をブロックする機能です。同じ条件によるブロックが会話中に繰り返し発生する場合、従来はブロックのたびにフックのプロンプト全体が再送信されており、無駄なトークン消費や冗長な処理が発生していました。今回の修正により、繰り返しのブロックでは、条件を要約した最大500文字のラベルのみが使われるようになり、効率が改善されました。

## 基本的な使い方
Stopフックは `settings.json` の `hooks` セクションで設定します。

```json
{
  "hooks": {
    "Stop": [
      {
        "hooks": [
          { "type": "command", "command": "./check-condition.sh" }
        ]
      }
    ]
  }
}
```

## 実践例

### 修正前の挙動
同じ条件でStopフックが繰り返しブロックを発生させる会話では、そのたびにフックのプロンプト全文が再送信され、会話が長くなるほど無駄なコンテキスト消費が増えていきました。

### 修正後の挙動
同じ条件による繰り返しのブロックでは、条件を表す500文字以内のラベルのみが使用されるようになり、無駄なプロンプトの再送信が抑制されました。

## 注意点
- 500文字を超えるような詳細な条件文をフックで使用している場合、繰り返しブロック時のラベルは要約された形になる点に留意してください。
- Stopフックの設計自体（条件のロジック）には変更がなく、あくまで繰り返し時の効率化に関する修正です。
