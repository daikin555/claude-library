## 原文（日本語訳）

フックのエラーメッセージに、解決済みのプラグインパスではなく `${CLAUDE_PLUGIN_ROOT}` という文字列そのものが表示されてしまう不具合を修正しました。

## 原文（英語）

Fixed hook error messages showing a literal `${CLAUDE_PLUGIN_ROOT}` instead of the resolved plugin path

## 概要

プラグインが提供するフックは、`${CLAUDE_PLUGIN_ROOT}` という変数を使ってプラグイン自身のインストールディレクトリを参照できます。フックの実行自体では正しく実際のパスに解決されますが、フックがエラーになった際に表示されるエラーメッセージ内では、この変数が解決されずに `${CLAUDE_PLUGIN_ROOT}` という文字列のまま出力されてしまい、どのプラグイン・どのパスで問題が起きたのかが分かりにくいという不具合がありました。今回の修正により、エラーメッセージ内でも実際に解決されたパスが表示されるようになりました。

## 基本的な使い方

フックの設定や実行方法自体は変わりません。フックがエラーを起こした際に表示される内容が改善されます。

修正前のエラーメッセージ例:

```
Hook failed: ${CLAUDE_PLUGIN_ROOT}/scripts/check.sh: command not found
```

修正後のエラーメッセージ例:

```
Hook failed: /home/user/.claude/plugins/my-plugin/scripts/check.sh: command not found
```

## 実践例

### プラグインフックのデバッグ

自作プラグインのフックスクリプトでパス関連のエラーが起きた場合、エラーメッセージに実際のファイルパスが表示されるため、どのファイルが問題なのかを即座に特定できます。

### `--debug` オプションを使った調査

`--debug` を付けて実行した際のログでも、解決済みのパスが表示されるため、フックの実行経路を追跡しやすくなります。

### 複数プラグインが同種のフックを提供している環境での切り分け

複数のプラグインが同じ種類のフック（例: `PreToolUse`）を登録している場合、エラーメッセージの実パスを見ることで、どのプラグインのフックが失敗したのかを区別しやすくなります。

## 注意点

- この修正はエラーメッセージの表示内容に関するものであり、フック自体の実行時の変数解決ロジックには変更はありません
- `${CLAUDE_PLUGIN_ROOT}` はフック定義内で使う変数であり、通常の実行が成功している場合はこれまでも正しく解決されていました
