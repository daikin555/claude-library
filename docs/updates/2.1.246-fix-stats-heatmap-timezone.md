## 原文（日本語訳）

`/stats` のアクティビティヒートマップで、UTCより東のタイムゾーンにおいて各日のアクティビティが1マス分ずれて表示される不具合（例: 日曜日の活動が月曜日のマスに表示される）を修正しました。

## 原文（英語）

Fixed `/stats` activity heatmap showing each day's activity one cell off (Sunday's count under Monday) in timezones east of UTC

## 概要

`/stats` コマンドは、日々のClaude Code利用状況をカレンダー形式のヒートマップで可視化します。しかし、日本や東アジア・オーストラリアなど、UTCより東のタイムゾーンで利用している場合、日付の境界計算に問題があり、実際にはある曜日に行った作業が1マス分ずれた翌日の曜日のマスに集計されてしまう不具合がありました（例：日曜日の活動量が月曜日のマスに表示される）。今回の修正で日付の境界がローカルタイムゾーンに基づいて正しく計算されるようになり、各日のアクティビティが正しい曜日のマスに表示されます。

## 基本的な使い方

`/stats` を実行してヒートマップを表示するだけです。特別な設定は不要です。

```
/stats
```

日本時間（UTC+9）などUTCより東のタイムゾーンで利用している場合、修正前は日曜日の活動が月曜日のマスにずれて表示されていましたが、修正後は正しい曜日のマスに表示されます。

## 実践例

### 日本時間での日々の作業ログの確認

日本時間で深夜や早朝に作業した場合でも、`/stats` のヒートマップ上で正しい日付・曜日にカウントされるようになり、実際の作業パターンを正確に把握できます。

### チームの活動傾向をタイムゾーンをまたいで比較

UTCより東のタイムゾーンにいるメンバーと西のタイムゾーンにいるメンバーの活動傾向を比較する際、集計のズレによる誤解が生じなくなります。

### 週次・月次の振り返りでの正確な集計

週末の作業量を振り返る際など、曜日ごとの集計が正確であることが重要な場面で、より信頼できるデータを確認できます。

## 注意点

- この修正はヒートマップの表示（曜日への割り当て）に関するものであり、記録されている生の利用データ自体は元々正しく保存されていました
- タイムゾーンの判定はシステムのローカルタイムゾーン設定に基づきます。システムのタイムゾーン設定が誤っている場合は、引き続きずれが発生する可能性があります
