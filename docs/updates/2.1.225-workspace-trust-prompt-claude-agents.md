## 原文（日本語訳）

信頼されていないディレクトリに対して、`claude agents` に `claude` コマンドの動作に合わせたワークスペース信頼プロンプトを追加しました。

## 原文（英語）

Added a workspace trust prompt to `claude agents` for untrusted directories, matching the behavior of `claude`

## 概要

Claude Code の `claude agents` コマンド（バックグラウンドエージェント管理）が、信頼されていないディレクトリで実行される際に、メイン `claude` コマンドと同じワークスペース信頼確認プロンプトを表示するようになりました。これは重要なセキュリティ機能で、リポジトリに含まれる悪意のある CLAUDE.md、設定ファイル、またはフックから保護します。これまで `claude agents` はこのプロンプトをスキップしていたため、セキュリティギャップが閉じられました。

## 基本的な使い方

新しいディレクトリで `claude agents` コマンドを実行すると、以下のようなワークスペース信頼プロンプトが表示されます：

```
Quick safety check: Is this a project you created or one you trust?

This folder contains .claude/ configuration that could affect Claude Code's behavior.
Configuration found:
  - allow rules: Bash(npm *)
  - additional directories: ./docs

Options:
  1. Yes, I trust this folder
  2. No, continue without these permissions
```

**プロンプトへの対応：**

1. **「Yes, I trust this folder」を選択** - ワークスペースを信頼済みとして保存し、その `.claude/` 設定の許可ルールと追加ディレクトリがこのセッション以降に適用されます

2. **「No, continue without these permissions」を選択** - 信頼は保存されず、許可ルールが無視されたまま作業を続けます

## 実践例

### 新しいプロジェクトリポジトリでのエージェント起動

チームから受け取った新しいリポジトリで `claude agents` を使用する場合：

```bash
cd ~/projects/team-project
claude agents
```

リポジトリに `.claude/settings.json` に許可ルールが含まれている場合、信頼プロンプトが表示されます。プロンプトで許可ルールを確認してから **Yes** を選択します。

### バックグラウンドセッション派遣時の信頼確認

`claude agents` で複数のバックグラウンドセッションを派遣する場合、各セッションが信頼されていないディレクトリで開始されるとプロンプトが表示されます：

```bash
claude agents --cwd ~/projects/untrusted-repo
# ワークスペース信頼プロンプトが表示される
```

### カスタム設定を持つディレクトリでの自動信頼

一度ワークスペースを信頼すると、同じディレクトリでの以降の `claude agents` 実行ではプロンプトが表示されません：

```bash
# 最初の実行 - プロンプト表示
claude agents

# 2回目以降 - プロンプトなし（信頼済みとして記憶）
claude agents --model opus
```

### 複数のワークスペース管理

異なるディレクトリで複数のプロジェクトを管理する場合、各ディレクトリの信頼状態は独立して管理されます：

```bash
cd ~/project-a
claude agents  # project-a の信頼プロンプト

cd ~/project-b
claude agents  # project-b の信頼プロンプト（独立）
```

## 注意点

### 信頼状態の保存

- **保存場所**：ワークスペースの信頼状態は、Git リポジトリ内では `.git` ルートをキーに保存されます。Git リポジトリ外では、起動したディレクトリをキーに保存されます

- **ホームディレクトリの例外**：ホームディレクトリから実行した場合、信頼状態は一時的にセッション内のみで保持され、ディスクに保存されません

- **親ディレクトリの信頼**：親ディレクトリを信頼しても、ネストされたプロジェクトの許可ルールは自動では適用されません。各プロジェクトでの信頼確認が必要です

### セキュリティ上の考慮

このプロンプトにより、以下の悪意のある設定から保護されます：

- リポジトリに含まれた悪意のある `.claude/settings.json` の許可ルール
- 危険な実行フック（PreToolUse, PreCommand など）
- 追加ディレクトリ設定による予期しないファイルアクセス

### 信頼状態のリセット

信頼状態をリセットする方法は公式ドキュメントでは明記されていません。必要に応じて、セキュリティ重視の場合は初回起動ごとに確認し直すことを検討してください。
