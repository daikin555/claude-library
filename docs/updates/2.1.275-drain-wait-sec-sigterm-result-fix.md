## 原文（日本語訳）

`--drain-wait-sec` を指定した自己ホストランナーで、SIGTERMによるドレイン処理中に完了したターンの最終結果が失われてしまう不具合を修正しました。ランナーは現在、ターンの結果が報告されるまで少し待機するようになりました。

## 原文（英語）

Fixed self-hosted runners with `--drain-wait-sec` losing the final result of a turn that finished during a SIGTERM drain; the runner now waits briefly for the turn to be reported

## 概要

`--drain-wait-sec` は、自己ホストランナーがSIGTERMシグナルを受け取った際に、実行中のターンを強制終了せず、指定した秒数だけ「ドレイン（drain）」猶予を与えて処理を完了させるためのオプションです。しかし、ドレイン猶予の期間中にちょうどターンが完了した場合、その最終結果がランナーに報告される前にプロセスが終了してしまい、結果が失われる不具合がありました。今回の修正により、ランナーはターンの結果が確実に報告されるまで少し待ってから終了するようになり、ドレイン中の結果消失が解消されました。

## 基本的な使い方

```bash
claude runner start --drain-wait-sec 30
```

SIGTERMを受け取った際に、最大30秒間はドレイン処理として現在のターンの完了と結果報告を待ってから終了します。

## 実践例

### CI/CDのデプロイ更新でランナーが再起動される場合

Kubernetesやオートスケーリング環境でローリングアップデート時にSIGTERMが送られる自己ホストランナーでは、修正前はちょうどターンが完了するタイミングでシグナルを受けると、その結果が失われて呼び出し元に何も返らないことがありました。修正後は結果が報告されるまで短く待機するため、こうした結果の消失が起きなくなりました。

```bash
claude runner start --drain-wait-sec 15
# SIGTERM受信時、ターンが完了間際であれば結果報告を待ってから終了する
```

### 短いドレイン時間を設定している場合との違い

`--drain-wait-sec` に短い値を設定している場合でも、ターンの結果報告自体は今回の修正で優先的に扱われるため、極端なタイミングのズレによる結果消失のリスクが軽減されます。

## 注意点

- `--drain-wait-sec` はあくまで「猶予時間」であり、無制限に待機するわけではありません。指定した時間を過ぎればランナーは終了します。
- 自己ホストランナーの具体的な設定方法やオプションの詳細は、最新の公式ドキュメントを参照してください。
