# セキュリティ・権限チェックに関する複数の修正（MCP OAuth、サンドボックス、cp/mv）

## 原文（日本語に翻訳）

- サーバーがリダイレクトした際に、MCP OAuthリクエストがリフレッシュトークンなどの機密情報を別のホストに送信する問題を修正
- 読み取り専用のBashコマンドが、権限プロンプトなしにサンドボックス外で実行される場合がある問題を修正
- Bashの権限チェックが、誤ったフォルダを基準にファイル書き込みを判定し、プロンプトを表示しない問題を修正
- ディレクトリへの `cp` や `mv` が書き込むファイルに対して、denyルールと保護ファイルのプロンプトが適用されない問題を修正
- `grep -r foo "$PWD/src"` のようなBash読み取りが、パスを直接書いた同じコマンドでは確認なしに実行されるのに権限を求める問題を修正
- `/bin/cp` のようにパスで指定した `cp` と `mv` にも、通常の `cp` と `mv` と同じパスチェックを適用するよう変更

## 原文（英語）

- Fixed MCP OAuth requests sending secrets such as refresh tokens to another host when a server redirected them
- Fixed a case where a read-only Bash command ran outside the sandbox without a permission prompt
- Fixed a case where Bash permission checks judged a file write from the wrong folder and didn't prompt
- Fixed deny rules and protected-file prompts not applying to the file that a `cp` or `mv` into a directory writes
- Fixed Bash reads such as `grep -r foo "$PWD/src"` asking for permission when the same command with the path typed out runs without asking
- Changed `cp` and `mv` spelled by a path, such as `/bin/cp`, to get the same path checks as `cp` and `mv`

## 概要

2.1.321では、権限とサンドボックスまわりの重要な修正が複数入っています。MCP OAuthの機密情報の漏えい経路の遮断、権限プロンプトのすり抜けの解消、`cp`/`mv` に対するdenyルールの適用などです。

## 基本的な使い方

特別な操作は不要です。アップデートするだけで適用されます。

```bash
claude update
```

## 実践例

### denyルールで保護したファイルの確認

```json
{
  "permissions": {
    "deny": ["Edit(.env)"]
  }
}
```

この設定下で `cp config/new.env .` のようにディレクトリ宛てのコピーが `.env` を上書きする場合も、denyルールが適用されます。

### フルパス指定のコマンド

`/bin/cp` や `/bin/mv` で実行しても、`cp`/`mv` と同じパスチェックが行われます。

## 注意点

- 以前は確認なしで通っていた操作が、プロンプトを表示するようになる場合があります。
- 逆に `$PWD` を使った読み取りの不要なプロンプトは減ります。
- MCP OAuthを使うチームは、早めのアップデートを推奨します。
