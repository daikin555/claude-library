## 原文（日本語訳）

権限ダイアログが改善されました。表示テキストと「今後確認しない」オプションが、実際に許可される内容と常に一致するようになりました。また、内容を完全に表示できない場合には「今後確認しない」オプション自体が表示されなくなりました。

## 原文（英語）

Improved permission dialogs: display text and "don't ask again" options now always match what a grant would cover, and "don't ask again" is withheld when contents cannot be fully displayed

## 概要

Claude CodeはBashコマンドの実行やファイルの変更など、影響のある操作を行う前にユーザーに許可を求める権限ダイアログを表示します。ここで「Yes, and don't ask again（今後は確認しない）」を選ぶと、その許可内容が `.claude/settings.local.json` に保存され、以降は同様の操作を確認なしで実行できるようになります。今回の改善は、ダイアログに表示される文言と「今後確認しない」を選んだ場合に実際に付与される許可の範囲を一致させ、また出力やコマンド内容が長すぎるなどの理由で全体を表示しきれない場合には、意図しない範囲の許可を防ぐために「今後確認しない」の選択肢自体を出さないようにするものです。

## 基本的な使い方

ユーザーが行う操作は今まで通りです。Bashコマンドの実行やファイル編集などで権限ダイアログが表示された際、そこに書かれている説明文が、実際に「Yes, and don't ask again」を選んだ場合に許可される範囲そのものであると信頼できるようになります。

```bash
> npm run build && npm test を実行して

# 権限ダイアログの例
Bash command
  npm run build && npm test

Allow this command?
❯ 1. Yes
  2. Yes, and don't ask again for npm commands in this project
  3. No
```

## 実践例

### 複合コマンドの許可範囲を正しく把握する

`&&` や `|` でつながれた複合コマンドを実行しようとした場合、「今後確認しない」を選ぶとどの部分のコマンドが許可対象になるのかが分かりにくいことがありました。今回の改善により、表示されるテキストが実際に保存される許可ルールと一致するため、意図せず広い範囲のコマンドを許可してしまうリスクが減ります。

### 出力が長すぎて全文表示できないケース

差分やコマンド内容が非常に長く、ダイアログに全体を表示しきれない場合、これまでは省略された内容のまま「今後確認しない」を選べてしまう可能性がありました。今回の変更では、こうした場合に「今後確認しない」の選択肢自体が表示されなくなるため、中身を確認しないまま恒久的な許可を与えてしまうことを防げます。

### 権限設定ファイルの内容を確認する

「今後確認しない」で許可した内容は `.claude/settings.local.json` に保存されます。ダイアログの表示と実際の許可内容が一致するようになったため、このファイルを後から確認したときに「思っていたより広い範囲を許可していた」という食い違いが起きにくくなります。

## 注意点

- 内容を完全に表示できない場合は「今後確認しない」自体が選べなくなるため、毎回都度確認が必要になるケースが増える可能性があります
- ファイル編集の承認はセッション終了までの一時的なものであり、`.claude/settings.local.json` には保存されません（保存対象はBashコマンドやWebFetchのドメイン許可など）
- 許可ルールは deny → ask → allow の順で評価され、最初に一致したルールが優先されます
