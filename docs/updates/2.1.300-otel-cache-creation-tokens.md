# OpenTelemetry api_request イベントでキャッシュ書き込みを有効期間別に確認する

## 原文（日本語に翻訳）

OpenTelemetry の `api_request` イベントに `cache_creation_5m_tokens` と `cache_creation_1h_tokens` を追加しました。キャッシュ書き込みを有効期間ごとに分けて確認できます。

## 原文（英語）

Added `cache_creation_5m_tokens` and `cache_creation_1h_tokens` to the OpenTelemetry `api_request` event, splitting cache writes by lifetime

## 概要

プロンプトキャッシュの書き込みトークン数が、5分キャッシュと1時間キャッシュに分けて `api_request` イベントへ記録されるようになりました。有効期間によって書き込みの扱いが異なるため、コスト分析をより正確に行えます。

## 基本的な使い方

```bash
export CLAUDE_CODE_ENABLE_TELEMETRY=1
export OTEL_LOGS_EXPORTER=otlp
claude
```

エクスポートされた `api_request` イベントの属性に、上記2つのフィールドが含まれます。

## 実践例

### 1時間キャッシュの効果を測る

`cache_creation_1h_tokens` を集計し、待機を挟む作業でどれだけ1時間キャッシュが書き込まれているかを把握できます。

### コスト試算の精度を上げる

両フィールドを別々に集計することで、有効期間ごとの書き込み量にもとづく試算ができます。

## 注意点

- テレメトリを有効にしている場合のみ出力されます。
- 属性の正確な名称や型は公式のモニタリングドキュメントで確認してください。
