## 原文（日本語訳）

`permissions`、`autoMode`、`worktree`、`attribution` の管理設定で、ネストされた値が1つでも不正な場合にブロック全体が無視されていた不具合を修正しました。現在は残りの部分が引き続き適用されます。

## 原文（英語）

Fixed managed `permissions`, `autoMode`, `worktree` and `attribution` settings being ignored entirely when one nested value was invalid; the rest of the block now still applies

## 概要

管理設定の `permissions`、`autoMode`、`worktree`、`attribution` といった設定ブロックの中で、ネストされた値のうち1つでも形式が不正なものがあると、これまではそのブロック全体がまるごと無視されてしまい、意図した制限が一切適用されない状態になっていました。今回の修正により、一部の値が不正であっても、それ以外の有効な設定は引き続き適用されるようになりました。

## 基本的な使い方

管理設定ファイルにこれらのブロックを記述する際、万が一一部のキーの値を誤って記述しても、残りの正しい設定は失われずに機能します。

```json
{
  "permissions": {
    "allow": ["Bash(git *)"],
    "deny": ["Bash(rm -rf *)"]
  }
}
```

## 実践例

### 大規模な管理設定ファイルの部分的な不備への耐性向上

多数の項目を含む管理設定ファイルで、レビュー漏れにより一部の値に誤りがあっても、それ以外の権限制限やworktree・attributionの設定は引き続き有効に機能し、セキュリティ全体が丸ごと無効化されるリスクが減ります。

### 段階的な設定変更のロールアウト

新しいポリシー項目を段階的に追加していく過程で、一部の記述にミスがあっても既存の他の制限が無効化されない、より安全な運用が可能になります。

## 注意点

- 不正な値そのものは依然として適用されません。起動時の警告やログを確認し、該当箇所は速やかに修正してください
- 「壊れたブロック全体が無視される」という以前の挙動に依存した設定をしていた場合は、新しい挙動に合わせて設定を見直す必要があります
