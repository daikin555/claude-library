## 原文（日本語訳）

`/goal`: バックグラウンドタスクによってゴールの待機が30分以上続く場合、Claudeは無期限に待つのではなく、状況を確認しにいくようになりました（`CLAUDE_CODE_GOAL_CHECKIN_MINUTES=0` を設定するとオプトアウトできます）

## 原文（英語）

`/goal`: when background tasks keep a goal waiting for 30+ minutes, Claude now checks in on them instead of waiting indefinitely (set `CLAUDE_CODE_GOAL_CHECKIN_MINUTES=0` to opt out)

## 概要

`/goal` コマンドで完了条件を設定して自律的に作業を進めている際、長時間かかるバックグラウンドタスク（ビルドやテスト実行など）の完了をひたすら待ち続けてしまうことがありました。この改善により、バックグラウンドタスクの完了待ちが30分を超えると、Claudeが自発的に状況を確認しにいくようになり、ゴールの達成に向けた進行が止まりにくくなります。環境変数 `CLAUDE_CODE_GOAL_CHECKIN_MINUTES` でこの動作を制御でき、`0` に設定すると従来どおり無期限に待つ挙動に戻せます。

## 基本的な使い方

特別な操作は不要です。`/goal` でゴールを設定し、バックグラウンドタスクが実行されている状態で30分以上待機が続くと、自動的にClaudeが状況確認を行います。

```
/goal npm run buildが成功し、npm testがすべてパスする
```

長時間のビルド・テストがバックグラウンドで動いている間、Claudeは定期的に進捗を確認します。

## 実践例

### 長時間ビルドを伴うゴール設定

```
/goal Dockerイメージのビルドが完了し、コンテナが正常に起動する
```

Dockerビルドがバックグラウンドで30分以上かかる場合、Claudeはタスクをただ待ち続けるのではなく、ログを確認したり進捗を報告したりしながらゴール達成に向けて動き続けます。

### チェックイン間隔を無効化する

デフォルトの30分チェックインが不要な場合（極端に長いバッチ処理を待たせたい場合など）は、環境変数でオプトアウトできます。

```bash
export CLAUDE_CODE_GOAL_CHECKIN_MINUTES=0
claude
```

### CI的な長時間タスクとの組み合わせ

```
/goal 全リージョンへのデプロイスクリプトが正常終了する
```

デプロイに数十分かかるケースでも、Claudeが定期的に状況確認を行うことで「固まっているのか進んでいるのか分からない」状態を避けられます。

## 注意点

- デフォルトのチェックイン間隔は30分です
- `CLAUDE_CODE_GOAL_CHECKIN_MINUTES=0` を設定すると、この自動チェックインを無効化し、以前と同様にバックグラウンドタスクの完了を無期限に待ちます
- あくまで「状況確認」であり、タスクを強制的に中断させるものではありません
- `/goal` コマンド自体を使用していない通常のセッションには影響しません
