## 原文（日本語訳）

diffの中にbase64文字列のような非常に長い1行が含まれている場合に、トランスクリプトの表示が深刻に遅くなる不具合を修正しました。このような行は、省略記号（マーカー）付きで切り詰めて表示されるようになりました。

## 原文（英語）

Fixed a severe transcript slowdown when a diff contained a very long single line (e.g. a base64 string); such lines now render truncated with a marker

## 概要

ファイル編集の差分（diff）をトランスクリプトに表示する際、これまでは行の長さに関わらず全文を描画しようとしていました。base64エンコードされた画像データやミニファイされたコードのように、1行が数万文字にも及ぶような極端に長い行がdiffに含まれると、その描画処理が原因でトランスクリプト全体の表示が著しく遅くなる問題がありました。今回の修正で、そのような長い行は自動的に切り詰められ、省略されたことを示すマーカーとともに表示されるようになりました。

## 基本的な使い方

特別な操作は不要です。base64文字列などを含むファイルを編集し、diffを表示させると、修正後の挙動を確認できます。

```diff
- oldValue = "..."
+ newValue = "iVBORw0KGgoAAAANSUhEUgAAAAEAAAAB... (以下、非常に長い1行が続く)"
```

修正後は、この長い行が一定の長さで切り詰められ、省略マーカーとともに表示されるため、トランスクリプト全体の表示速度に影響しません。

## 実践例

### 画像やバイナリデータをbase64で埋め込んだファイルを編集する場合

設定ファイルやHTML内にbase64エンコードされた画像を直接埋め込んでいるプロジェクトでdiffを確認する際、以前は表示が固まったように遅くなっていましたが、修正後は快適に操作できます。

### ミニファイされたJS/CSSファイルを扱う場合

ビルド後の圧縮済みファイルなど、1行が非常に長いファイルを編集対象にした場合でも、diff表示のパフォーマンスが安定します。

### ロックファイルや自動生成ファイルの差分を確認する場合

`package-lock.json` のような長い行を含む自動生成ファイルの変更を確認する際にも、表示の遅延なくスムーズにトランスクリプトを閲覧できます。

## 注意点

- 表示上は切り詰められますが、実際のファイル内容や適用されるdiff自体が変更されるわけではありません
- 切り詰められた行の全文を確認したい場合は、エディタなどで直接ファイルを開く必要があります
- この修正は表示パフォーマンスに関するものであり、diffの適用結果には影響しません
