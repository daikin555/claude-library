## 原文（日本語訳）

クロスセッション `SendMessage` を追加：Claude Codeのセッション同士が、どのマシン上にあってもメッセージをやり取りできるようになりました。`ListAgents` で相手を探せます（macOSとLinux対応）。

## 原文（英語）

Added cross-session `SendMessage`: Claude Code sessions can now message each other, on any of your machines, with `ListAgents` to discover them (macOS and Linux)

## 概要

これまで複数のClaude Codeセッションを並行して動かしている場合、あるセッションで得た知見や状況を別のセッションに伝えるにはユーザーが手動でコピー&ペーストする必要がありました。新しいクロスセッションメッセージング機能では、Claudeが `ListAgents` ツールで到達可能な相手（サブエージェント、同一マシン上の他のセッション、Remote Control経由の他マシンのセッション）を発見し、`SendMessage` ツールでテキストメッセージを送信できます。会話履歴やファイルそのものは送られず、Claudeが書いたテキストのみが相手に届きます。

## 基本的な使い方

ユーザーがツールを直接呼び出すことはなく、自然言語で指示するとClaudeが判断して送信します。

```text
> 別のターミナルで動いているセッションに、マイグレーションが終わったか聞いて
```

到達可能なセッション一覧を自分で確認したい場合は `/list-agents`（エイリアス `/peers`）を実行します。

```text
> /list-agents
```

## 実践例

### 並行するworktree間で変更内容を共有する

同じリポジトリを複数のworktreeで作業しているとき、一方のセッションで行った変更が他方に影響する場合、Claudeにその内容を伝えてもらえます。

```text
> 今やった認証まわりのリファクタリングの内容を、
  payments-api の worktree で作業しているセッションに伝えて
```

### 長時間実行タスクの完了を別セッションに通知する

大きなテスト実行やマイグレーションを見ているセッションから、別セッションへ完了報告を送らせることができます。

```text
> このテストが終わったら、結果をメインの作業セッションに知らせて
```

### 他のマシンのセッションに返信する（Remote Control経由）

Remote Controlで接続している場合、他マシンや `Claude Code on the web` から届いたメッセージに対してだけ返信できます（こちらから新規にメッセージを開始することはできません）。

```text
> (他マシンのセッションからメッセージが届いた後)
> さっきの質問に、DBのスキーマは変更不要だと返信して
```

## 注意点

- Claude Code v2.1.224以降が必要で、macOSとLinux（WSL 2含む）でのみ利用できます。ネイティブWindowsでは利用できません。
- Amazon Bedrock、Claude Platform on AWS、Google Cloud's Agent Platform、Microsoft Foundryでは利用できません。
- `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`・`DISABLE_TELEMETRY`・`DO_NOT_TRACK`・`DISABLE_GROWTHBOOK` のいずれかが有効だと、機能フラグの評価ができずクロスセッションメッセージングも無効になります。
- 同一マシン上のセッション同士は、各セッションが持つ「inboxソケット」経由で直接やり取りされ、Anthropicのサーバーを経由しません。別マシンのセッションとの通信はAnthropicサーバー経由になります。
- 受信したメッセージはユーザーに代わって権限プロンプトを承認したり、設定（権限設定・`CLAUDE.md`など）を変更したりすることはできません。メッセージ内のコマンド文字列（例: `/compact`）もプレーンテキストとして扱われ、実行されません。
- 権限プロンプトをバイパスして実行中のセッションへのメッセージは、`crossSessionInbound` 設定に応じて承認待ちで保留されることがあります（詳細は `crossSessionInbound`/`dialogExpiry` の記事を参照）。
- `SendMessage`・`ListAgents` を権限のdenyルールに追加すれば、送信・一覧取得を無効化できます。
