## 原文（日本語訳）

特殊な形式のuserinfoを持つgitリモートのホストを誤って読み取ってしまい、誤ったホスト向けのリンク生成やホスト固有の挙動が発動していた不具合を修正しました。

## 原文（英語）

Fixed repository detection mis-reading the host of git remotes with unusual userinfo, producing links and repo-specific behavior for the wrong host

## 概要

Claude Codeは現在のリポジトリのgitリモートURLを解析して、GitHub/GitLabなどのホストを判定し、PRリンクの生成やホスト固有の機能（マーケットプレイス連携など）を切り替えています。今回の修正前は、`https://user:pass@host/...` のようにユーザー名・パスワード（userinfo）部分に特殊文字が含まれるリモートURLの場合、パース処理がuserinfoとホスト部分を取り違えてしまい、実際とは異なるホストとして誤判定されることがありました。これにより誤ったホストへのリンクが生成されたり、本来意図しないホスト固有の挙動が適用されたりする可能性がありました。今回の修正でこの解析ロジックが正しく修正されています。

## 基本的な使い方

この修正はバグフィックスであり、ユーザー操作は不要です。gitリモートのURLにuserinfo（認証情報部分）が含まれる構成のリポジトリを使っている場合でも、Claude Codeが正しいホストを認識するようになります。

## 実践例

### 認証情報付きのHTTPS URLをリモートに設定している場合

```bash
git remote add origin "https://ci-bot:sp3cial%40char@github.example.com/org/repo.git"
```

修正前はuserinfo中の特殊文字（`%40` などのエンコードされた記号）の影響でホスト部分の抽出に失敗し、`github.example.com` ではなく誤ったホストとして扱われることがありました。修正後は正しく `github.example.com` として認識されます。

### 自己ホストのGitLab/GitHub Enterpriseを使う場合

社内の自己ホスト型Gitサーバーに対して認証情報付きのURLでリモートを設定しているチームでは、PRリンクの生成先やマーケットプレイス制限（`strictKnownMarketplaces` など）のホスト判定が正しく行われるようになり、意図しない外部ホスト向けの挙動が発動するリスクが減ります。

## 注意点

- この不具合はセキュリティ関連の判定（信頼するホストの識別など）にも影響し得るため、認証情報付きのリモートURLを使っている環境ではアップデートを推奨します
- 通常の `git@host:org/repo.git` 形式（SCP風）や、userinfoを含まないURLでは影響が小さいと考えられます
