## 原文（日本語に翻訳）

事前登録済みのOAuthクライアントを使用するMCPサーバー（Slackなど）で、リダイレクトURIの不一致によりMCPのOAuthサインインが失敗する問題を修正しました。

## 原文（英語）

Fixed MCP OAuth sign-in failing with a redirect URI mismatch for servers that use a pre-registered OAuth client, such as Slack.

## 概要

Claude Codeは `/mcp` コマンドなどからMCPサーバーへOAuth 2.0で認証（サインイン）できます。通常、Claude CodeはローカルのループバックアドレスにOAuthコールバック用の一時的なポートを立ててリダイレクトを受け取りますが、Slackのように認可サーバー側で「事前登録済みのOAuthクライアント（固定のリダイレクトURIをあらかじめ登録している）」を使用するMCPサーバーでは、Claude Codeが生成するリダイレクトURIと、サーバー側に事前登録されたリダイレクトURIが一致せず、サインインが失敗するという不具合がありました。v2.1.231でこの不一致が修正され、こうした事前登録型のOAuthクライアントを使うMCPサーバーでも正しくサインインできるようになりました。

## 基本的な使い方

MCPサーバーの認証は `/mcp` コマンドまたは `claude mcp login` から行います。

```bash
# Claude Codeセッション内で
> /mcp
# 認証が必要なMCPサーバーを選択し、OAuthフローを開始
```

```bash
# シェルから直接ログインする場合
claude mcp login slack
```

## 実践例

### Slack連携用MCPサーバーへのサインイン

```bash
# Slack用のMCPサーバーを設定済みの場合
claude mcp login slack

# ブラウザが開き、Slackの認可画面が表示される
# 認可後、Claude Codeへリダイレクトされ、サインインが完了する
# （v2.1.231以前はここでリダイレクトURI不一致によりエラーになっていた）
```

### SSH越しなどブラウザが自動で開けない環境での利用

```bash
claude mcp login slack
# ローカルにブラウザがない場合は認可URLが表示される
# 表示されたURLをローカルマシンのブラウザで開き、
# 認可後のリダイレクトURLを貼り付けて認証を完了する
```

### `/mcp`パネルからの再認証

```bash
> /mcp
# 一覧からSlack等の対象サーバーを選び、再認証を実行
# 修正後はリダイレクトURI不一致のエラーが発生しなくなる
```

## 注意点

- Claude Code v2.1.231で修正されました
- 影響を受けていたのは、認可サーバー側で「事前登録済みのOAuthクライアント（固定のリダイレクトURIを要求するタイプ）」を使用するMCPサーバーで、Slackが代表例として挙げられています
- 動的クライアント登録（Dynamic Client Registration）に対応した一般的なMCPサーバーでは、この問題は発生していなかった可能性があります
- サインインに失敗する場合は、まずClaude Codeを最新バージョンに更新してください
- 認証情報をクリアしたい場合は `claude mcp logout <name>` を使用できます
