## 原文（日本語訳）
`ListPlugins` ツールの説明を改善し、Claude がこれを「claude.ai アカウントで有効化されているプラグインの一覧」であり、`/plugin` でローカルにインストールされたプラグインの一覧ではないと正しく理解できるようにしました

## 原文（英語）
Improved the `ListPlugins` tool description so Claude knows it lists plugins enabled on your claude.ai account, not plugins installed locally with `/plugin`

## 概要
Claude Code には `/plugin` コマンドでローカルにインストールするプラグインの仕組みと、claude.ai アカウント側で有効化するプラグインの仕組みの2種類が存在します。これまで `ListPlugins` という内部ツールの説明が曖昧で、Claude がこの2つを混同し、誤った回答をしてしまうことがありました。今回の修正でツールの説明が明確化され、ユーザーからの質問に対してより正確に回答できるようになります。

## 基本的な使い方
ユーザーが直接 `ListPlugins` ツールを呼び出すことはありません。Claude に対してプラグインについて質問すると、内部的にこのツールが適切な文脈で使われます。

```
「今、claude.aiアカウントで有効になっているプラグインを教えて」
# → ListPluginsツールが呼ばれ、アカウント側で有効なプラグインの一覧が返る
```

## 実践例

### アカウント側のプラグインとローカルプラグインを区別して質問する
```
「claude.aiアカウントで有効なプラグインの一覧を教えて」
# → ListPluginsツールがアカウント設定由来の一覧を返す

「/pluginでローカルにインストールしたプラグインを教えて」
# → こちらは/plugin コマンド自体やローカル設定を確認する形で回答される
```

### 混同による誤回答が起きていたケース
```
# 修正前: 「有効なプラグインは？」と聞くと、
#   ローカルインストール済みプラグインとアカウント側プラグインが
#   混同されて回答されることがあった
# 修正後: ツールの説明が明確化され、Claudeが情報源を正しく区別して回答する
```

## 注意点
- これは内部ツールの説明文の改善であり、ユーザーが直接操作する機能ではありません。
- ローカルプラグインの管理は引き続き `/plugin` コマンドから行います。
- アカウント側のプラグイン有効化は claude.ai の設定画面から行います。
