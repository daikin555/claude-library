# 無人リトライモードで使用制限の待機上限を設定する

## 原文（日本語に翻訳）

`CLAUDE_CODE_RETRY_WATCHDOG_MAX_USAGE_LIMIT_WAIT_MS` を追加しました。無人リトライモード（`CLAUDE_CODE_RETRY_WATCHDOG`）で、リセットまでの時間が長すぎる使用制限に達した場合、待機せずにリクエストを終了します。

## 原文（英語）

Added `CLAUDE_CODE_RETRY_WATCHDOG_MAX_USAGE_LIMIT_WAIT_MS` so unattended retry mode (`CLAUDE_CODE_RETRY_WATCHDOG`) ends a request at a usage limit that resets too far away instead of waiting

## 概要

無人リトライモードでは、使用制限に達すると制限が解除されるまで待機します。この環境変数で待機時間の上限をミリ秒で指定すると、リセットが上限より先の場合は待たずにリクエストを終了できます。CIやバッチ処理が長時間ブロックされるのを防げます。

## 基本的な使い方

```bash
export CLAUDE_CODE_RETRY_WATCHDOG=1
# 最大30分（1,800,000ミリ秒）まで待機し、それ以上かかる場合は終了
export CLAUDE_CODE_RETRY_WATCHDOG_MAX_USAGE_LIMIT_WAIT_MS=1800000
claude -p "テストを実行して失敗を修正して"
```

## 実践例

### CIジョブの無駄な待機を避ける

ジョブの実行時間に上限がある環境では、待機上限を短く設定しておくと、制限が数時間後にリセットされる場合に早く失敗として検知できます。

### 夜間バッチで短時間の制限だけ待つ

数分で解除される制限は待って継続し、翌日までリセットされない制限では終了する、といった運用ができます。

## 注意点

- 値はミリ秒単位です。
- 上限を超える場合、リクエストは待機せず終了します。呼び出し側でのエラー処理を用意してください。
- 無人リトライモード（`CLAUDE_CODE_RETRY_WATCHDOG`）が有効なときに意味を持ちます。
