## 原文（日本語訳）

Sonnet 5のデフォルトの自動コンパクトウィンドウが、フルの100万トークンコンテキストに対応するように変更されました。これにより、100万トークンウィンドウを使用しているセッションは、これまでの約934,000トークンではなく、約967,000トークン付近で自動コンパクトが行われるようになります。

## 原文（英語）

Changed Sonnet 5's default auto-compact window to its full 1M context, so sessions on the 1M window now auto-compact at about 967K tokens instead of about 934K

## 概要

Claude Codeは会話のコンテキストが一定量を超えると、古い内容を要約して圧縮する「自動コンパクト」を行います。これまでSonnet 5で100万トークンのコンテキストウィンドウを利用している場合でも、自動コンパクトの閾値は実際のウィンドウサイズより控えめな約934Kトークンに設定されていました。今回の変更で、閾値がフルの100万トークンコンテキストに合わせて約967Kトークンまで引き上げられ、コンパクトが発生するまでより長く会話を続けられるようになりました。

## 基本的な使い方

ユーザーが何かを設定する必要はありません。Sonnet 5で100万トークンのコンテキストウィンドウが有効なセッションでは、自動的に新しい閾値（約967Kトークン）が適用されます。

```bash
# 100万トークンコンテキストが有効な環境でSonnet 5を使用する場合、
# 特別な設定なしで自動コンパクトの閾値が約967Kトークンになる
claude
```

## 実践例

### 長時間の大規模リファクタリング作業

多数のファイルを読み込みながら進める大規模なリファクタリングでは、コンテキストの消費が早くなります。閾値が約934Kから約967Kに上がったことで、コンパクトが発生するまでの作業量が増え、要約による情報損失の頻度を抑えられます。

### 大きなログやドキュメントを読み込む調査タスク

大量のログファイルや仕様書を読み込んで分析するようなタスクでも、より多くのトークンを消費してから自動コンパクトに入るため、直前のやり取りがより長く保持されます。

### 100万トークンウィンドウを活用したコードベース全体の把握

大規模なコードベース全体を一度に把握させたい場合、自動コンパクトが発生するタイミングが遅くなることで、より広い範囲のコンテキストを保ったまま作業を継続できます。

## 注意点

- この変更はSonnet 5で100万トークンのコンテキストウィンドウが有効な場合に適用されます
- 自動コンパクト自体を無効にする設定ではなく、発生する閾値のタイミングが変わるだけです
- コンテキストウィンドウが100万トークンより小さい設定やモデルでは、この変更の影響はありません
