## 原文（日本語訳）

アクティブな `/goal` のようなフック駆動セッションで、リアクティブな圧縮（compaction）後に再度コンテキストが溢れた場合に、圧縮されずに「Prompt is too long」というエラーで終了してしまう問題を修正しました。

## 原文（英語）

Fixed hook-driven sessions (such as an active `/goal`) ending with "Prompt is too long" instead of compacting when the context overflowed again after a reactive compaction

## 概要

`/goal` のようにフックによって自律的に動作し続けるセッションでは、コンテキストが上限に近づくと自動的に圧縮（compaction）が行われます。しかし、圧縮が一度行われた後に再びコンテキストが上限に達した場合、2回目以降の圧縮が正しくトリガーされず、「Prompt is too long」というエラーでセッションがそのまま終了してしまう不具合がありました。今回の修正で、圧縮後に再度コンテキストが溢れた場合でも正しく再度の圧縮が行われるようになり、長時間の自律実行がエラーで中断されにくくなりました。

## 基本的な使い方

`/goal` などフック駆動で長時間動作するセッションを通常どおり実行するだけで、修正の恩恵を受けられます。

```
/goal 大規模リファクタリングを完了させる
```

## 実践例

### 長時間実行される `/goal` セッション

大きなゴールを設定して長時間Claude Codeに作業させている場合、以前はコンテキストが2回目に上限へ達した時点で「Prompt is too long」エラーにより処理が停止していましたが、修正後は自動的に再圧縮が行われ、作業が継続されます。

### フックによる反復的な自動化ワークフロー

カスタムフックを使って反復的にコンテキストを消費するようなワークフローでも、圧縮が繰り返し正しく機能するようになったため、長時間にわたる自動化タスクの安定性が向上します。

## 注意点

- 圧縮は自動的に行われますが、圧縮によって文脈の詳細が失われる可能性がある点は変わりません。重要な情報は適宜メモやファイルに残しておくことが推奨されます。
- 非常に頻繁にコンテキストが上限に達するようなワークフローでは、タスクの分割や `/goal` の粒度を見直すことも検討してください。
