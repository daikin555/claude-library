## 原文（日本語訳）

コマンドサンドボックスのファイルシステム設定が `--setting-sources` を反映していなかった問題が修正されました。

## 原文（英語）

Fixed the command sandbox's filesystem configuration not respecting `--setting-sources`

## 概要

Claude Codeのコマンドサンドボックス機能は、Bashなどのコマンド実行をファイルシステムアクセスの観点で制限する仕組みです。`--setting-sources` フラグを使うと、どの設定ファイル（ユーザー設定、プロジェクト設定、ローカル設定など）を読み込むかを制御できますが、これまでサンドボックスのファイルシステム設定部分はこのフラグを正しく反映しておらず、意図した設定ソース以外の内容がサンドボックスの許可・拒否ルールに影響してしまう可能性がありました。今回の修正により、サンドボックスのファイルシステム設定も `--setting-sources` で指定した設定ソースだけを正しく参照するようになりました。

## 基本的な使い方

`--setting-sources` で読み込む設定ソースを絞り込んで実行した場合、サンドボックスのファイルシステム制限にもその絞り込みが正しく反映されるようになりました。

```bash
claude --setting-sources project -p "このディレクトリでテストを実行して"
```

この例では、プロジェクト設定に定義されたサンドボックスのファイルシステムルールのみが適用され、ユーザー設定やローカル設定に含まれる無関係なルールが混入することはありません。

## 実践例

### CI環境で設定ソースを限定してサンドボックスを厳密に運用する

CIパイプラインで `--setting-sources project` のように設定ソースを明示的に絞り込んで実行しているチームは、この修正によってサンドボックスのファイルシステムアクセス制御が意図どおりに機能するようになり、想定外のディレクトリへのアクセスを防ぎやすくなります。

### 複数の設定レイヤーを持つプロジェクトでの検証

ユーザー設定・プロジェクト設定・ローカル設定など複数のレイヤーでサンドボックス関連の設定を分けて管理している場合、`--setting-sources` を使って特定のレイヤーのみを対象にサンドボックスの動作を検証しやすくなります。

### セキュリティレビューでのサンドボックス設定の切り分け

`security-review` のようなセキュリティ検証作業の際に、どの設定ソースがサンドボックスのファイルシステムルールに影響しているかを `--setting-sources` で切り分けて確認できるようになり、監査がしやすくなります。

## 注意点

- この修正はファイルシステム設定に関するものです。サンドボックスの他の制限（ネットワークアクセスなど）については別途確認してください
- `--setting-sources` を指定しない通常の実行では、これまでと同様にすべての設定ソースが読み込まれます
- サンドボックス機能自体を有効化していない環境ではこの修正の影響はありません
