## 原文（日本語訳）

組み込みの `claude-api` スキルを読み込む際のコンテキストコストを、参照ドキュメントをオンデマンドで読み込む方式に変更することで、約200,000トークン以上から約25,000トークンに削減しました。

## 原文（英語）

Reduced the context cost of loading the built-in `claude-api` skill from ~200k+ tokens to ~25k by loading reference docs on demand

## 概要

`claude-api` はClaude API（Messages API）を使ったアプリケーション開発を支援する組み込みスキールで、Python・TypeScript・Go・Javaなど8言語分のリファレンスドキュメントを内包しています。従来はスキール読み込み時にこれらのドキュメントを一括で読み込んでいたため、コンテキストウィンドウを200,000トークン以上も消費することがありました。今回の改善で、実際に必要なドキュメントのみをオンデマンドで読み込む方式に変更され、消費量が約25,000トークンまで大幅に削減されました。

## 基本的な使い方

ユーザー側で特別な設定は不要です。`/claude-api` スキルを利用する、またはClaude API関連の実装をClaudeに依頼すると、必要な言語・トピックのドキュメントだけが段階的に読み込まれるようになります。

```
> /claude-api Pythonでストリーミングのサンプルコードを書いて
```

このように依頼すると、Python向けのストリーミング関連ドキュメントのみが読み込まれ、他言語や無関係なトピック（バッチ処理やMCP連携など）のドキュメントは読み込まれません。

## 実践例

### 長時間のセッションでのコンテキスト圧迫を回避

これまでは `claude-api` スキルを一度使うと200k超のトークンをコンテキストに常駐させてしまい、長時間のペアプログラミングセッションで他の会話やファイル内容を圧迫する原因になっていました。今回の改善により、スキール利用後もコンテキストに余裕が残るため、より多くのファイルや会話履歴を維持したまま作業を続けられます。

### 特定言語のみを使うプロジェクトでの効率化

TypeScriptのみでClaude APIを利用するプロジェクトの場合、Python・Go・Java向けのリファレンスは読み込まれず、TypeScript関連のドキュメントのみが必要に応じてロードされるため、無駄なトークン消費がありません。

### トークン使用量の変化に気づくポイント

`/cost` や `/usage` コマンドでセッションのトークン消費を確認した際、`claude-api` スキルを使った直後のコンテキスト増加が以前よりも小さくなっていることに気づくはずです。以前は1回の利用で200k+トークンが一気に消費されていたケースが、今回のバージョンでは25k程度に収まります。

## 注意点

- 必要なドキュメントをオンデマンドで読み込む方式のため、複雑なタスクで複数言語・複数トピックにまたがる場合は、その分だけ追加でトークンが消費されます
- スキール自体の機能や提供される情報の正確性は変わりません。あくまでコンテキスト効率の改善です
- 他の組み込みスキール（`/doctor` や `/code-review` など）には直接関係しない変更です
