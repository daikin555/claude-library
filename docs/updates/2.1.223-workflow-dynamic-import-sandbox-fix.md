## 原文（日本語に翻訳）

ワークフロースクリプトが動的な `import()` を使ってワークフローサンドボックスの外でコードを実行できてしまう問題を修正しました。

## 原文（英語）

Fixed workflow scripts being able to use dynamic `import()` to run code outside the workflow sandbox

## 概要

Claude Codeのワークフロー機能では、スクリプトが制限された実行環境（サンドボックス）内で動作するよう設計されており、意図しないファイルアクセスやシステムへの影響を防いでいます。今回修正された問題は、ワークフロースクリプト内でJavaScriptの動的インポート構文（`import()`）を利用することで、このサンドボックスの制約を回避し、本来アクセスできないはずのモジュールやコードをサンドボックス外の権限で実行できてしまうというものでした。v2.1.223では、動的importの挙動が制御され、ワークフロースクリプトが意図したサンドボックス境界を超えられないように修正されています。

## 基本的な使い方

この修正はワークフロー実行エンジンの内部的な制約強化であり、通常の利用方法自体に変更はありません。アップデート後は、ワークフロースクリプトを従来どおり作成・実行するだけで、サンドボックスの境界がより厳格に保たれます。

```bash
# 最新バージョンへの更新
claude update
claude --version
```

```bash
# ワークフローの実行（例）
claude workflow run my-workflow.yaml
```

## 実践例

### 既存のワークフロースクリプトが引き続き正しく動作するか確認する

サンドボックス内で完結する正当なモジュール利用（静的な `import` や許可されたAPI呼び出し）は引き続き問題なく動作します。アップデート後に既存ワークフローを再実行し、想定どおりの結果になるか確認します。

```bash
claude workflow run existing-workflow.yaml --dry-run
```

### 外部から取得したワークフロー定義を利用する場合の注意

Marketplaceや外部リポジトリから取得したワークフロー・スキル・エージェント定義を利用する際は、信頼できる提供元のものであるかを確認したうえで導入することが重要です。

```json
{
  "strictKnownMarketplaces": ["your-org/*"],
  "blockedMarketplaces": []
}
```

### CI環境でワークフローを自動実行する場合のバージョン管理

自動化パイプラインでワークフローを実行している場合は、サンドボックス関連の修正を確実に取り込むため、パッチバージョンを固定してアップデートを反映します。

```bash
npm install -g @anthropic-ai/claude-code@2.1.223
claude --version
```

## 注意点

- 本修正はセキュリティ上重要な変更のため、ワークフロー機能を利用している場合はv2.1.223以降への速やかなアップデートを推奨します。
- 動的import以外にサンドボックスを回避する経路が存在しないかは継続的に調査・修正が行われる領域であるため、最新バージョンを維持することが重要です。
- 具体的な回避手口の詳細はchangelogに明記されておらず、本記事でも再現可能な手順は扱いません。
- 信頼できないソースから取得したワークフロー定義やスクリプトを実行する際は、サンドボックスの保護に過度に依存せず、内容を事前にレビューすることが推奨されます。
