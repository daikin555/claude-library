## 原文（日本語訳）

Claude Code DesktopまたはVS Codeがホストしている Remote Control セッション中にユーザーへ送信されたファイルが正しくアップロードされるようになり、スマートフォンやWeb上で空のカードとして表示される代わりに開けるようになりました。

## 原文（英語）

Fixed: files sent to the user during Remote Control sessions hosted by Claude Code Desktop or VS Code now upload, so they open on phone and web instead of showing an empty card

## 概要

Remote Controlは、ローカルマシンで実行しているClaude Codeセッションを、スマートフォンやWebブラウザ（claude.ai/codeやClaudeアプリ）から操作できる機能です。今回の修正前は、Claude Code DesktopやVS Code拡張機能がホストしているRemote Controlセッションにおいて、Claudeがユーザーに送信したファイル（スクリーンショットや生成物など）が正しくアップロードされず、スマートフォンやWeb側では中身の見えない空のカードとして表示されてしまうことがありました。修正後は、これらのホスト環境からでもファイルが確実にアップロードされ、接続先のデバイスで正しく開けるようになりました。

## 基本的な使い方

Remote Controlの使い方自体は変わりません。ローカルでClaude Code Desktopまたは VS Code拡張機能を使ってセッションを開始し、Remote Controlを有効にすると、スマートフォンやWebブラウザから同じセッションに接続して操作を継続できます。

```
1. Claude Code Desktop（またはVS Code拡張機能）でセッションを開始
2. Remote Controlを有効化してペアリング
3. claude.ai/code またはClaudeモバイルアプリから接続
4. Claudeがファイルを送信すると、スマートフォン/Web側でもそのまま開ける
```

## 実践例

### スクリーンショットをスマートフォンで確認する

デスクトップでClaudeにUIの実装を依頼し、生成されたスクリーンショットをRemote Control経由でスマートフォンから確認するケースです。

```
デスクトップ側:
> このコンポーネントのプレビュー画像を送って

Claude> [screenshot.pngを送信]

スマートフォン側（Remote Control接続中）:
# 修正前: 空のカードが表示され、画像を開けない
# 修正後: 画像が正しく表示され、タップして拡大表示できる
```

### VS Code拡張機能ホストのセッションでレポートファイルを受け取る

VS Code上でClaude Codeを動かしながら外出し、電車の中でWebブラウザからRemote Controlに接続してレポートやログファイルを確認する場合も、ファイルが正しく開けるようになりました。

### 生成されたドキュメントを外出先で確認

長時間かかるドキュメント生成タスクをデスクトップで開始し、完了通知をスマートフォンで受け取った後、生成されたMarkdownファイルなどをその場で開いて確認できます。

## 注意点

- この不具合はClaude Code Desktop、またはVS Code拡張機能がRemote Controlセッションをホストしている場合に発生していました
- ターミナル（CLI）単体でホストしているRemote Controlセッションでは影響範囲が異なる可能性があるため、環境に応じて挙動を確認してください
- Remote Controlはリサーチプレビュー機能であり、Team/Enterpriseプランでは管理者が明示的に有効化する必要があります
