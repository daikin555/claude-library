# /permissions が無効なルールを拒否し理由を表示

## 原文（日本語に翻訳）

`/permissions` が、次回起動時にスキップされてしまうルール（ツール名のない `rm -rf` など）を追加時点で拒否し、理由を表示するようになりました。

## 原文（英語）

Improved `/permissions` to refuse a rule that would be skipped at the next start, such as `rm -rf` with no tool name, and to show the reason

## 概要

無効な権限ルールを保存してしまい、次回起動時に黙って無視される問題を防ぎます。ルールを追加した時点でエラーと理由が分かります。

## 基本的な使い方

`/permissions` でルールを追加します。ツール名を付けた正しい形式にします。

```text
Bash(rm -rf:*)   # 正しい（ツール名つき）
rm -rf           # 拒否される（ツール名なし）
```

## 実践例

### deny ルールの設定ミスを防ぐ

安全のために書いた deny ルールが無効のまま気付かない、という事態を避けられます。表示された理由に従って `Tool(pattern)` 形式に直してください。

## 注意点

- 手動で `settings.json` を編集した場合の検証とは別なので、記述ミスには引き続き注意してください。
