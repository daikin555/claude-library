## 原文（日本語訳）

サブコマンドの前にワイルドカードを置くBash許可ルール（例: `Bash(git * main)`）に対して、起動時に警告を表示するようになりました。このようなルールは、サブコマンドの前に挿入されたオプションにもマッチしてしまうためです。

## 原文（英語）

Added a startup warning for Bash allow rules with a wildcard before the subcommand (e.g. `Bash(git * main)`), since they also match options inserted before the subcommand

## 概要

`Bash(git * main)` のように、コマンド名とサブコマンドの間にワイルドカード `*` を挟む許可ルールは、想定しているサブコマンド（この例では `main` ブランチに対する操作）だけでなく、そこに挿入された任意のオプションにもマッチしてしまいます。たとえば `git -c core.pager=evilcmd main` のような、意図しない危険なオプション付きコマンドまで許可してしまう可能性があり、セキュリティ上の抜け穴になり得ます。今回のアップデートで、Claude Codeはこの種のルールを起動時に検出し、警告を表示するようになりました。

## 基本的な使い方

`.claude/settings.json` や `settings.local.json` の `permissions.allow` に以下のようなルールが含まれている場合、Claude Code起動時に警告が表示されます。

```json
{
  "permissions": {
    "allow": ["Bash(git * main)"]
  }
}
```

警告が表示されたら、ワイルドカードの位置を見直し、サブコマンドの前ではなく後ろ（引数部分）に置くようにルールを書き換えることが推奨されます。

## 実践例

### 特定ブランチへの操作だけを許可したい場合

`Bash(git checkout main)` や `Bash(git push origin main)` のように、サブコマンドを固定し、ワイルドカードは末尾の可変部分にのみ使うようにします。

```json
{
  "permissions": {
    "allow": ["Bash(git checkout main*)"]
  }
}
```

### 既存の権限設定を一括見直しする場合

チームの `settings.json` に多数のBash許可ルールが積み重なっている場合、起動時警告をきっかけに、サブコマンド前にワイルドカードを置いているルールを棚卸しし、意図した範囲だけを許可するルールに修正します。

### CI環境での権限設定レビュー

CIで使う設定ファイルにも同様のパターンが紛れていることがあります。警告メッセージを確認し、`Bash(npm * install)` のような表記を `Bash(npm install*)` のように改めることで、意図しないオプション注入を防ぎます。

## 注意点

- これは警告であり、既存のルールの動作を自動的に変更するものではありません。ルールの見直しはユーザー側で行う必要があります
- ワイルドカードがサブコマンドの後ろにある場合は対象外です。問題となるのは「コマンド名とサブコマンドの間」にワイルドカードがあるパターンです
- 該当パターンは意図せず広い範囲のコマンドを許可してしまうリスクがあるため、可能な限り具体的なルールに書き換えることが推奨されます
