## 原文（日本語訳）

`..` や `/.vol` 形式のカーネルパスを介してmacOSの `/Network` に到達するリポジトリ内シンボリックリンク、またはmacOSの `/home` を指すルールへのシンボリックリンクが一覧表示される経路で、CLAUDE.mdやルールが起動時に読み込まれてしまう問題を修正しました。

## 原文（英語）

Fixed CLAUDE.md and rules being read at startup through a repository symlink reaching macOS's `/Network` via `..` or a `/.vol`-style kernel path, or a rules link to macOS's `/home` being listed

## 概要

これはセキュリティに関わる修正です。悪意のあるリポジトリに、`..` を使った相対パスやmacOS固有の `/.vol` 形式のカーネルパスを利用して `/Network`（ネットワークマウントポイント）や `/home` といったリポジトリ外の場所を指すシンボリックリンクが仕込まれていた場合、Claude Codeの起動時にそのリンク先の内容がCLAUDE.mdやルールファイルとして読み込まれてしまう可能性がありました。今回の修正で、こうした経路によるリポジトリ外ファイルの読み込みが防がれるようになりました。

## 基本的な使い方

ユーザー側の対応は不要です。信頼できないリポジトリをチェックアウトしてClaude Codeを起動する際にも、この保護が自動的に適用されます。

## 実践例

### 信頼できないOSSリポジトリのレビュー

外部から取得したオープンソースリポジトリをレビュー目的でチェックアウトし、Claude Codeで作業する際にも、意図しない外部ファイルの読み込みリスクが低減されます。

### CI/CDでの自動チェックアウト環境

自動化されたパイプラインでPRの内容を検証する際、悪意あるシンボリックリンクを含むリポジトリからの情報漏えいリスクへの防御が強化されます。

## 注意点

- これはmacOS特有のパス構造（`/Network`、`/.vol`、`/home`）を悪用する手口に対する防御です
- 正規のCLAUDE.mdやルールファイルの読み込みには影響しません
