## 原文（日本語訳）

要約リクエストが拒否された場合にコンパクション（会話の圧縮）が失敗していた不具合を修正しました。現在はフォールバックモデルで再試行するようになりました。

## 原文（英語）

Fixed compaction failing when the summarization request is refused; it now retries on a fallback model

## 概要

会話が長くなり、コンテキストウィンドウの上限に近づくとClaude Codeは自動的に「コンパクション」（過去の会話を要約して圧縮する処理）を行います。しかし、要約のためのリクエストがモデルによって拒否（refusal）された場合、コンパクション自体が失敗し、それ以上会話を続けられなくなる不具合がありました。今回の修正により、要約が拒否された場合には自動的にフォールバックモデルで再試行されるようになり、コンパクションが失敗しにくくなりました。

## 基本的な使い方

ユーザー側の操作は不要です。コンテキストが長くなり自動コンパクションが実行される際に、内部的にこの改善が適用されます。手動でコンパクションを実行することもできます。

```
/compact
```

## 実践例

### 長時間の大規模リファクタリングセッション

大量のファイルを読み書きする長時間セッションでコンテキストが圧迫された際、要約が拒否されて作業が止まってしまうリスクが減り、セッションを継続しやすくなります。

### センシティブな内容を含む会話の圧縮

要約対象の内容によっては安全性の観点からモデルが要約を拒否することがありますが、フォールバックモデルでの再試行によって、こうしたケースでも会話の継続性が保たれやすくなります。

## 注意点

- フォールバックモデルでの要約は、元のモデルでの要約と品質や粒度が異なる場合があります
- 再試行してもなお失敗する場合は、`/compact` の手動実行や不要な文脈の削除を検討してください
