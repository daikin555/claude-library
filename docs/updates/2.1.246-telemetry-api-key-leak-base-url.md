## 原文（日本語訳）

Anthropicへのテレメトリおよびメトリクスのリクエストが、サードパーティゲートウェイ用に設定されたAPIキー（`ANTHROPIC_BASE_URL`）を含んで送信されてしまう問題を修正しました。認証情報は、それが本来向けられたホストにのみ送信されるようになりました。

## 原文（英語）

Fixed telemetry and metrics requests to Anthropic carrying the API key configured for a third-party gateway (`ANTHROPIC_BASE_URL`); a credential is now only sent to its own host

## 概要

Claude Codeは `ANTHROPIC_BASE_URL` を設定することで、サードパーティのAPIゲートウェイ経由でAnthropic APIにアクセスする構成をサポートしています。この構成ではゲートウェイ用の専用APIキーを使うことが一般的です。しかし、これまではテレメトリやメトリクスをAnthropic本体に送信する際にも、このゲートウェイ用のAPIキーが誤って一緒に送信されてしまうという問題がありました。これは意図しない相手先への認証情報の漏出にあたるセキュリティ上の懸念事項です。今回の修正で、各認証情報は本来送信されるべきホストにのみ送られるようになり、この漏出が解消されました。

## 基本的な使い方

ユーザー側での設定変更は不要です。`ANTHROPIC_BASE_URL` を設定してサードパーティゲートウェイを利用している場合でも、テレメトリ送信時にそのゲートウェイ用のAPIキーがAnthropicに送られることはなくなりました。

```bash
export ANTHROPIC_BASE_URL="https://my-gateway.example.com"
export ANTHROPIC_API_KEY="gateway-specific-key"
claude
# 修正後: テレメトリ/メトリクスの送信先ごとに正しい認証情報のみが使われる
```

## 実践例

### サードパーティゲートウェイ経由での利用

企業内プロキシやサードパーティのAPIゲートウェイを介してClaude Codeを利用している構成で、ゲートウェイ専用のキーがAnthropicのテレメトリエンドポイントに漏れる心配がなくなりました。

### セキュリティ・コンプライアンス要件への対応

認証情報の送信先を厳密に管理する必要があるエンタープライズ環境において、各サービスに対して意図した認証情報のみが渡されることが保証され、セキュリティレビューを通しやすくなります。

### テレメトリ収集を有効にした運用

`OTEL` 関連の設定やClaude Codeの利用状況メトリクス収集を有効化している組織でも、ゲートウェイの認証情報が意図しない形でAnthropic側に渡ることなく、安全にテレメトリを活用できます。

## 注意点

- この修正はセキュリティ上重要な修正です。サードパーティゲートウェイを利用している場合は、最新バージョンへの更新を推奨します
- `ANTHROPIC_BASE_URL` を設定していない標準的な構成では、この問題は発生していませんでした
