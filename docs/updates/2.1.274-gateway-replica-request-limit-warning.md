## 原文（日本語訳）

Claude appsゲートウェイに、各リプリカが上流へ同時送信する上限である256件を超えるリクエストを抱えている場合の警告と、その上限値を示す起動時ログ行を追加しました。

## 原文（英語）

Added a Claude apps gateway warning when a replica has more requests open than the 256 it sends upstream at once, and a startup log line showing that limit

## 概要

Claude appsゲートウェイの各リプリカは、上流（Anthropic API側）へ同時に送信できるリクエスト数に256件という上限を持っています。これまでこの上限は暗黙的で、超過した際の可視性がありませんでしたが、今回の変更により、上限を超えるリクエストを抱えている場合に警告が出るようになり、また起動時のログにもこの上限値が明示されるようになりました。これにより、スケーリングの問題やボトルネックを早期に発見しやすくなります。

## 基本的な使い方

Claude appsゲートウェイを起動すると、ログに上限値が表示されます。

```
[startup] gateway replica upstream concurrency limit: 256
```

リプリカが抱えるオープンリクエスト数がこの上限を超えると、警告が出力されます。

```
[warn] replica has 312 open requests, exceeding the 256 upstream concurrency limit
```

## 実践例

### 高負荷時のスケーリング判断

トラフィックが急増した際にこの警告ログを監視することで、リプリカ数を増やすべきタイミングやロードバランサーの設定を見直すべきタイミングを判断する材料になります。

```bash
# ログを監視して警告発生時にアラートを飛ばす例
tail -f gateway.log | grep "exceeding the 256 upstream concurrency limit"
```

### キャパシティプランニング

起動時ログに明示される上限値（256）を基準に、想定される同時利用者数からどの程度のリプリカ数が必要かを見積もることができます。

## 注意点

- 上限値（256）自体は今回の変更で設定可能になったわけではなく、可視化が改善されたのみです。
- 警告が頻発する場合は、リプリカ数の追加やアーキテクチャの見直しを検討する必要があります。
- この機能はClaude appsゲートウェイ（自己ホスト型のエンタープライズ構成）に限定されます。
