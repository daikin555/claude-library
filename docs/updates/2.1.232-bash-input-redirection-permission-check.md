## 原文（日本語に翻訳）

Bashの入力リダイレクト（`< file`）が、引数として同じ内容を指定した場合と同様に、全プラットフォームで権限チェックされるようになりました。

## 原文（英語）

Bash input redirections (`< file`) are now permission-checked like their argument spellings on all platforms

## 概要

これは権限まわりのバグ修正です。Claude Codeは、Bashコマンドが特定のファイルを読み書きしようとする際に権限ルールと照合しますが、これまで `< file` という入力リダイレクト構文を使った場合、`command file` のように引数として同じファイルを渡した場合と比べて、権限チェックが一貫していないことがありました。プラットフォームによってこの挙動に差があり、入力リダイレクトを使うことで意図した権限チェックをすり抜けてしまう可能性がありました。今回の修正により、入力リダイレクトも引数指定と同じ基準で、全プラットフォームにわたって一貫して権限チェックされるようになりました。

## 基本的な使い方

この修正はバグ修正であり、ユーザー側の設定変更は不要です。以下のように入力リダイレクトでファイルを読み込むコマンドも、引数でファイルを指定した場合と同様に権限ルールと照合されます。

```bash
# 入力リダイレクトでファイルを読み込む
sort < data.txt

# 引数でファイルを指定する場合と同等の権限チェックが行われる
sort data.txt
```

## 実践例

### 機密ファイルへのアクセスを制限している場合

特定のディレクトリ配下のファイルへのアクセスを拒否するルールを設定している場合、以前は入力リダイレクトを使うことでそのルールをすり抜けられる可能性がありましたが、修正後は同様にブロックされます。

`.claude/settings.json`:
```json
{
  "permissions": {
    "deny": [
      "Read(./secrets/**)"
    ]
  }
}
```

```bash
# 以前: 入力リダイレクトだと拒否ルールが効かない可能性があった
grep password < secrets/config.env

# 修正後: 引数指定と同様に拒否される
grep password secrets/config.env
```

### 特定ファイルの読み込みのみ許可している場合

許可リストで特定ファイルの読み込みだけを許可している場合も、入力リダイレクトと引数指定のどちらでアクセスしても同じ基準で判定されるようになり、意図しない抜け道がなくなります。

```bash
diff < a.txt b.txt
```

### CIやサンドボックス環境での自動実行

自動化されたワークフローでBashコマンドを生成・実行する際、入力リダイレクトを使うスクリプトでも、引数指定のスクリプトと同じ権限ポリシーが一貫して適用されるようになるため、セキュリティ上の抜け道を心配せずに権限ルールを設計できます。

## 注意点

- 本修正はセキュリティに関わる一貫性の改善です。以前バージョンで入力リダイレクトを使って権限ルールをすり抜けられていたケースがあった場合、修正後は同じルールでブロックされるようになります。
- Claude Codeが認識するリダイレクト構文には `<`（入力）、`>`、`>>`（出力）などがあり、いずれも権限チェックの対象です。
- プラットフォーム間（macOS/Linux/Windowsなど）での挙動差も本修正で解消されています。
