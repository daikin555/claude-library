# 「always allow」がsettings.local.json未作成のプロジェクトで保存されない不具合を修正

## 原文（日本語訳）

`.claude/settings.local.json` がまだ存在しないプロジェクトで、「always allow（常に許可）」の選択が保存されない問題を修正しました。

## 原文（英語）

Fixed "always allow" not saving in a project that has no .claude/settings.local.json yet

## 概要

Claude Codeでは、ツール実行の許可を求められた際に「Yes, and don't ask again（常に許可する）」を選択すると、そのルールが `.claude/settings.local.json` に保存され、次回以降は確認なしで実行できるようになります。しかし、そのプロジェクトでまだ `.claude/settings.local.json` ファイルが一度も作成されていない場合、選択した「always allow」が保存されずに失われてしまう不具合がありました。2.1.252ではこの問題が修正され、初回でも確実にルールが保存されるようになりました。

## 基本的な使い方

Bashコマンドなどの実行時に表示される権限確認ダイアログで「Yes, and don't ask again」を選択するだけで、自動的に `.claude/settings.local.json` が作成（または更新）され、許可ルールが記録されます。

```bash
# 例: 初めて npm test を実行しようとすると確認ダイアログが表示される
npm test
```

ダイアログで「常に許可」を選択すると、以下のようなファイルが自動生成されます。

```json
// .claude/settings.local.json
{
  "permissions": {
    "allow": [
      "Bash(npm test:*)"
    ]
  }
}
```

## 実践例

### 1. 新規プロジェクトで初めてClaude Codeを使う場合

`.claude/` ディレクトリすらまだ存在しない新規プロジェクトでも、最初の「always allow」選択が正しく保存されるようになりました。

```bash
cd new-project
claude
# 何らかのBashコマンド実行時に「Yes, and don't ask again」を選択
```

### 2. CI導入前にローカルで許可ルールを蓄積する場合

チームで共有する `.claude/settings.json` を整備する前段階として、個人のローカル環境で `always allow` を積み重ねてワークフローを効率化するケースでも、確実にルールが記録されるため安心して使えます。

```bash
# 蓄積されたルールを確認
cat .claude/settings.local.json
```

### 3. 手動でファイルを事前作成しなくても良い

以前は不具合を回避するために空の `.claude/settings.local.json` を手動で作っておくワークアラウンドが必要な場合がありましたが、今回の修正によりその手順は不要になりました。

```bash
# 修正前の回避策（もう不要）
mkdir -p .claude
echo '{}' > .claude/settings.local.json
```

## 注意点

- `.claude/settings.local.json` は個人用の設定ファイルであり、通常 `.gitignore` に含まれ、チームでは共有されません。チーム共有用のルールは `.claude/settings.json` に記述してください。
- ローカルの許可ルールはプロジェクトのdeny設定より優先される場合があるため、意図しないコマンドまで許可されていないか定期的に見直すことをおすすめします。
- 既存のプロジェクトで過去にこの不具合の影響を受けていた場合、失われた許可ルールは自動復元されないため、再度「always allow」を選択し直す必要があります。
