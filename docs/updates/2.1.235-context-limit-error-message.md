## 原文（日本語訳）

コンテキスト上限に達した際のエラーメッセージが改善され、auto-compact（自動圧縮）がオフになっている場合はその旨が明示され、`/config` から再度有効化する方法を案内するようになりました。

## 原文（英語）

Improved the context-limit error to say when auto-compact is off and point to `/config` to re-enable it

## 概要

Claude Codeは会話がコンテキストウィンドウの上限に近づくと、通常は自動的に会話履歴を要約・圧縮する「auto-compact」機能によって作業を継続できるようにしています。しかし、この機能が `/config` で無効化されている場合、コンテキスト上限に達すると自動での回復ができずエラーになりますが、従来のエラーメッセージではその原因がauto-compactの無効化にあることが分かりにくいものでした。今回の改善により、エラーメッセージ自体にauto-compactがオフである旨と、`/config` から再度有効化できることが明記されるようになり、ユーザーが原因と対処法をその場で理解できるようになりました。

## 基本的な使い方

auto-compactを無効にしたまま長時間・大量のやり取りを続け、コンテキストウィンドウの上限に達すると、次のようなメッセージが表示されます。

```bash
> (長時間のセッションを継続中...)

Error: Context limit reached. Auto-compact is currently off.
Re-enable it in /config to allow the session to compact automatically.
```

このメッセージに従って `/config` を開き、auto-compactを有効化することで、以降は上限に近づいた際に自動で会話が圧縮され、作業を継続できるようになります。

## 実践例

### auto-compactを意図的にオフにして長時間作業していた場合

会話の要約による情報の欠落を避けるためにauto-compactをオフにして作業していると、コンテキスト上限に達した際にセッションが継続できなくなります。以前はここで単に上限到達のエラーが出るだけでしたが、今回からは「auto-compactがオフになっているためです」という原因が明示されるため、`/compact` を手動実行するか `/config` で自動化を有効にするかを迷わず判断できます。

### `/config` からauto-compactを再度有効にする

```bash
> /config

# Auto-compact の項目を有効に切り替える
```

有効化しておけば、次回以降コンテキスト上限に近づいた時点で自動的に圧縮が行われ、今回のようなエラーで作業が中断することを防げます。

### 手動で `/compact` を使い分ける

auto-compactを無効のまま運用したい場合は、上限に達する前に自分のタイミングで `/compact` を実行して要約するという運用も可能です。エラーメッセージの改善により、「なぜ止まったのか」「どう直せばいいのか」がその場で分かるため、こうした手動運用をしているユーザーも状況を把握しやすくなります。

## 注意点

- auto-compactを無効化している場合、コンテキスト上限に達すると自動では回復せず、セッションが停止する点は変わりません。今回の改善はあくまでエラーメッセージの分かりやすさの向上です
- `/config` での設定変更が既存セッションにどこまで即時反映されるかは状況によって異なる場合があります。反映されない場合は新しいセッションを開始してください
- auto-compactを有効にすると会話履歴が要約されるため、詳細な文脈が失われる可能性がある点は従来通り考慮が必要です
