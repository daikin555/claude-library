## 原文（日本語に翻訳）

通常とは異なる形式の `git push` の出力を解析する際に、まれにハング（応答なし状態）が発生する不具合を修正しました。

## 原文（英語）

Fixed a rare hang when parsing unusual `git push` output

## 概要

Claude Codeは、ブランチをリモートにpushしたりPRを作成したりする際に内部で `git push` を実行し、その出力を解析して結果（成功・失敗、リモートURLなど）を判断しています。これまで、`git push` の出力が通常とは異なる特殊な形式（フックからの追加出力や、特定のGitホスティングサービス独自のメッセージなど）になっている場合、その解析処理がまれにハングし、コマンドが完了しないまま応答が返ってこなくなることがありました。今回の修正により、このような特殊な出力パターンでもパース処理が正常に完了するようになりました。

## 基本的な使い方

Claude Codeにブランチのpushやコミットを依頼する際、内部で `git push` が実行されます。

```text
このブランチをリモートにpushして
```

Claude Code自身に頼らず、通常通り手元で `git push` を実行して結果を確認することもできます。

```bash
git push origin feature/my-branch
```

pushの出力が特殊な内容になっていないか確認したい場合は、以下のように出力をそのまま確認できます。

```bash
git push origin feature/my-branch 2>&1 | tee push-output.log
```

## 実践例

### pre-push/post-receiveフックからの出力が多いリポジトリでのpush

サーバー側でpre-receiveやpost-receiveフックが有効になっており、大量の追加メッセージ（Lintの警告や通知など）が `git push` の出力に含まれるリポジトリでは、この出力を解析する処理がまれにハングすることがありました。

```bash
git push origin main
# フックからの追加出力が大量に返ってくる環境
```

修正後は、このような出力パターンでもClaude Codeがpush結果を正しく解析し、後続の処理（PR作成のURL表示など）に問題なく進めます。

### GitHub/GitLab以外のGitホスティングサービスを使っている場合

社内Gitサーバーや、独自のメッセージフォーマットを返すGitホスティングサービスを使っている場合、`git push` の出力形式が一般的なGitHub/GitLabの形式と異なることがあります。

```text
このブランチをpushして、リモートに作成されたPR用URLを教えて
```

このようなケースでも、出力解析のハングが解消されたことで、Claude Codeが安定してpush結果を報告できるようになります。

### pushがハングしているように見える場合の切り分け

pushの応答が返ってこない場合、まず手元のターミナルで直接 `git push` を実行し、Claude Code側の解析処理の問題なのか、ネットワークや認証の問題なのかを切り分けます。

```bash
time git push origin feature/my-branch
```

改善されない場合は、デバッグログを取得してGitHub Issuesに報告することが推奨されます。

```bash
claude --debug > debug-git-push.log 2>&1
```

## 注意点

- 本修正はあくまで「出力の解析」に起因するハングの修正であり、ネットワーク遅延や認証エラーなど他の原因によるpushの遅延・失敗を解消するものではありません。
- 発生頻度は「まれ（rare）」とchangelogに記載されており、特定の出力形式に依存して起きる不具合であるため、通常の利用では気づかないケースも多いと考えられます。
- アップデート後も同様のハングが発生する場合は、`git push` の出力内容（機密情報を除いたもの）とデバッグログを添えて報告すると原因調査に役立ちます。
