# modの読み込みとツール呼び出しの権限まわりの挙動変更

## 原文（日本語に翻訳）

- Claudeが書いたmodは、autoおよびbypassモードでは確認なしに有効化され（管理設定の `allowUnsandboxedCommands: false` や `allowManagedDomainsOnly` があっても）、`dontAsk` モードでは読み込まれないよう変更
- modの独自ツール呼び出し（`$.tool.call`、`$.mcp.call`）は、自分のaskルールや `dontAsk`・`-p` 実行でも権限プロンプトを出さないよう変更。denyルールと組織ポリシーは引き続き適用される
- ヘッドレスセッションで、`.claude/skills` 内のmodのファイルが変更されたときに再読み込みするよう変更。無効化するには `CLAUDE_CODE_PLUGIN_DIR_WATCH=0` を設定

## 原文（英語）

- Changed mods Claude writes to turn on without asking in auto and bypass modes, even with managed `allowUnsandboxedCommands: false` or `allowManagedDomainsOnly`, and not to load in `dontAsk` mode
- Changed mods' own tool calls (`$.tool.call`, `$.mcp.call`) to raise no permission prompt, even under your own ask rules or in `dontAsk` and `-p` runs; deny rules and organization policy still apply
- Changed headless sessions to reload mods in `.claude/skills` when their files change; set `CLAUDE_CODE_PLUGIN_DIR_WATCH=0` to turn this off

## 概要

modの有効化・ツール呼び出し・再読み込みに関する挙動が変わりました。自動化された実行（auto、bypass、`-p`）でmodが止まらず動作しやすくなる一方、`dontAsk` モードではClaudeが書いたmodは読み込まれません。

## 基本的な使い方

ヘッドレス実行で自動再読み込みをオフにする例です。

```bash
CLAUDE_CODE_PLUGIN_DIR_WATCH=0 claude -p "タスクを実行して"
```

## 実践例

### mod内のツール呼び出し

```js
// modの中でツールやMCPを呼び出す
await $.tool.call("Read", { file_path: "README.md" });
await $.mcp.call("server", "tool", {});
```

これらの呼び出しは権限プロンプトを出しませんが、denyルールや組織ポリシーは有効です。

### 長時間のヘッドレスセッション

`.claude/skills` 内のmodを編集すると、セッションを再起動せずに反映されます。

## 注意点

- modのツール呼び出しはaskルールを素通りします。重要な制限はdenyルールで定義してください。
- `dontAsk` モードではClaudeが書いたmodは読み込まれません。
- 上記のコード例は説明用の概念例です。実際のAPIはドキュメントを確認してください。
