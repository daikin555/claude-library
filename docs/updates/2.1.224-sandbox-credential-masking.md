## 原文（日本語訳）

サンドボックスの認証情報マスキングオプションを追加：構造化された環境変数値向けの `extract` と `onExtractNoMatch`、JWTを考慮したマスキングを行う `decode: "jwt"` と `maskClaims`、AWS SigV4の再署名を行う `awsPairs`／`sigv4`。これらは `network.tlsTerminate` を必要とし、ユーザー設定・管理設定・`--settings` からのみ有効になります。

## 原文（英語）

Added sandbox credential-masking options: `extract` and `onExtractNoMatch` for structured env values, `decode: "jwt"` with `maskClaims` for JWT-aware masking, and `awsPairs`/`sigv4` for AWS SigV4 re-signing; these need `network.tlsTerminate` and are honored only from user, managed, or `--settings` settings

## 概要

Claude CodeのサンドボックスBashツールには、環境変数やファイルの値を実際の認証情報の代わりにプレースホルダー（センチネル）に置き換え、許可したホストへのリクエスト時だけサンドボックスプロキシが本物の値に差し替える「マスキング」機能があります。今回の更新では、`DATABASE_URL` のような構造化された値の一部だけをマスクする `extract`、JWTのペイロードクレーム単位でマスクできる `decode: "jwt"` / `maskClaims`、AWSのSigV4署名を伴うリクエストを正しく再署名するための `awsPairs` / `sigv4` が追加されました。いずれも `network.tlsTerminate` が有効であることが前提で、リポジトリの `.claude/settings.json` では無効化され、ユーザー設定・管理設定・`--settings` フラグからのみ有効になります。

## 基本的な使い方

環境変数をまるごとマスクする基本形はこれまでどおりです。

```json
{
  "sandbox": {
    "enabled": true,
    "network": {
      "tlsTerminate": {},
      "allowedDomains": ["*.github.com"]
    },
    "credentials": {
      "envVars": [
        { "name": "GH_TOKEN", "mode": "mask", "injectHosts": ["api.github.com"] }
      ]
    }
  }
}
```

## 実践例

### `DATABASE_URL` の一部だけをマスクする（extract / onExtractNoMatch）

接続文字列全体をマスクすると値をパースするツールが壊れてしまうため、`extract` の正規表現でパスワード部分だけを置き換えます。

```json
{
  "sandbox": {
    "credentials": {
      "envVars": [
        {
          "name": "DATABASE_URL",
          "mode": "mask",
          "extract": "://[^:]+:([^@]+)@",
          "onExtractNoMatch": "error"
        }
      ]
    }
  }
}
```

`onExtractNoMatch` は、パターンが何にもマッチしなかった場合の挙動を `warn`（デフォルト、警告してマスクせず通す）・`deny`（サンドボックス内で変数を未設定にする）・`error`（サンドボックスの起動自体を止める）から選べます。

### JWTのクレーム単位でマスクする（decode: "jwt" / maskClaims）

JWT形式のトークンをそのまま構造を保った偽トークンに置き換えつつ、`sub` など特定のクレームだけを隠したい場合に使います。

```json
{
  "sandbox": {
    "credentials": {
      "envVars": [
        {
          "name": "SESSION_JWT",
          "mode": "mask",
          "decode": "jwt",
          "maskClaims": ["sub", "email"]
        }
      ]
    }
  }
}
```

### AWS認証情報をまとめて再署名する（awsPairs / sigv4）

慣例的な変数名（`AWS_ACCESS_KEY_ID` など）以外の名前でAWS認証情報を保持している場合、`awsPairs` で明示的にペアリングします。

```json
{
  "sandbox": {
    "credentials": {
      "envVars": [
        { "name": "MY_KEY_ID", "mode": "mask", "injectHosts": ["*.amazonaws.com"] },
        { "name": "MY_SECRET_KEY", "mode": "mask" },
        { "name": "MY_SESSION_TOKEN", "mode": "mask" }
      ],
      "awsPairs": [
        {
          "accessKeyIdVar": "MY_KEY_ID",
          "secretAccessKeyVar": "MY_SECRET_KEY",
          "sessionTokenVar": "MY_SESSION_TOKEN"
        }
      ],
      "sigv4": {
        "presigned": "passthrough"
      }
    }
  }
}
```

`sigv4` では、プロキシが再署名できないリクエスト形式（`streaming`＝aws-chunkedアップロード、`presigned`＝署名付きURL、`sigv4a`＝非対称署名）ごとに、エラーにする代わりに `passthrough` でそのままフォワードするかを指定できます。

## 注意点

- これらのオプションはすべてClaude Code v2.1.224以降が必要です。
- `network.tlsTerminate` が設定されていないと、マスキング自体は失敗し、コマンドにはセンチネルしか見えないままサーバー側の認証も失敗します（情報漏洩は起きません）。
- `mask` エントリ、`network.tlsTerminate`、`credentials.allowPlaintextInject` は、リポジトリの `.claude/settings.json` や `.claude/settings.local.json` では無視され、ユーザー設定・管理設定・`--settings` からのみ有効です。
- `decode` と `extract` は同じエントリで併用できません（ファイルへの `decode: "jwt"` は例外的に `extract` と併用可能）。
- AWSのシークレットキーだけをマスクしてアクセスキーIDをマスクしないと、プレースホルダーで署名されたリクエストをプロキシが検出できず失敗するため、両方をセットでマスクする必要があります。
- macOSでは、ファイルルールでのマスキングはファイルシステム分離が有効な間 `deny` として扱われるため、`extract`/`decode` の効果はファイルシステム分離を無効にした場合のみ発揮されます。
