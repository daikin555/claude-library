## 原文（日本語訳）

セッションを別のマシンで再開した場合や、スクラッチパッドがクリアされた場合に、Artifactの更新が「File not found」で失敗する不具合を修正しました。ページの最後に公開されたバージョンが復元されるようになりました。

## 原文（英語）

Fixed Artifact updates failing with "File not found" after a session resumes on another machine or its scratchpad is cleared: the page's last published version is restored

## 概要

Artifact機能は、Claude Codeが作成したコンテンツ（コードやドキュメントなど）を独立したページとして公開・更新できる機能です。この更新処理は内部的にローカルの「スクラッチパッド」領域のファイルを参照しますが、セッションを別のマシンで再開したり、スクラッチパッドがクリアされたりすると、参照先のファイルが存在せず「File not found」エラーでArtifactの更新が失敗する不具合がありました。今回の修正により、こうした状況ではそのページの最後に公開されたバージョンが自動的に復元されてから更新処理が行われるようになりました。

## 基本的な使い方

特別な操作は不要です。通常どおりArtifactを作成・更新するだけで、修正の恩恵を受けられます。

## 実践例

### 別のマシンでセッションを再開してArtifactを更新する

自宅のPCで作成したArtifactを含むセッションを、オフィスのPCで `claude --resume` して更新しようとすると、修正前はスクラッチパッドのファイルが存在せず更新が失敗していました。修正後は最後に公開されたバージョンが自動的に復元され、そこから更新を続けられます。

```bash
# マシンAでArtifactを作成・公開したセッションを、マシンBで再開
claude --resume <session-id>
# Artifactの更新も正常に行える
```

### スクラッチパッドがクリアされた後の更新

一時ファイル領域のクリーンアップなどでスクラッチパッドの内容が失われた場合でも、同様に最後に公開されたバージョンから復元されるため、Artifactの更新を継続できます。

## 注意点

- 復元されるのは「最後に公開されたバージョン」です。公開前の未保存の変更がスクラッチパッド上にのみ存在していた場合、その変更は復元されない可能性があります。
- Artifactを頻繁に更新する場合は、重要な変更のタイミングで公開しておくことを推奨します。
