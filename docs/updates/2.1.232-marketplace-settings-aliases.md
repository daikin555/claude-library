## 原文（日本語に翻訳）

設定項目として、`additionalMarketplaces` と `allowedMarketplaces` が、それぞれ `extraKnownMarketplaces` と `strictKnownMarketplaces` のより分かりやすいエイリアスとして受け付けられるようになりました。

## 原文（英語）

Settings: `additionalMarketplaces` and `allowedMarketplaces` are now accepted as friendlier aliases for `extraKnownMarketplaces` and `strictKnownMarketplaces`

## 概要

プラグインマーケットプレイスの設定に使う `extraKnownMarketplaces`（追加で認識させるマーケットプレイス）と `strictKnownMarketplaces`（利用を許可するマーケットプレイスを厳格に制限する設定）は、キー名だけでは役割が直感的に分かりにくいという課題がありました。v2.1.232では、これらの設定に対してより分かりやすい名前のエイリアス `additionalMarketplaces` と `allowedMarketplaces` が追加され、どちらの名前でも同じ設定として認識されるようになりました。

## 基本的な使い方

`settings.json`（あるいは管理者向けのmanaged settings）で、以下のように新しいエイリアスを使って設定できます。

```json
{
  "additionalMarketplaces": [
    { "source": "github", "repo": "my-org/my-marketplace" }
  ],
  "allowedMarketplaces": [
    { "source": "github", "repo": "my-org/my-marketplace" }
  ]
}
```

## 実践例

### 新しいエイリアスキーでマーケットプレイスを追加する

```json
{
  "additionalMarketplaces": [
    { "source": "gitlab", "repo": "my-group/plugin-marketplace" }
  ]
}
```

従来の `extraKnownMarketplaces` の代わりに `additionalMarketplaces` を使っても、同じ挙動でマーケットプレイスが追加登録されます。

### 組織の管理設定で許可リストを制御する

```json
{
  "allowedMarketplaces": [
    { "source": "github", "repo": "trusted-org/marketplace" }
  ]
}
```

管理者向けのmanaged settingsで、`strictKnownMarketplaces` の代わりに `allowedMarketplaces` を使って利用可能なマーケットプレイスを制限できます。

### 既存のextraKnownMarketplaces設定との互換性

```json
{
  "extraKnownMarketplaces": [
    { "source": "github", "repo": "my-org/legacy-marketplace" }
  ]
}
```

既存の設定ファイルで `extraKnownMarketplaces` や `strictKnownMarketplaces` を使っている場合も、そのまま変更なく動作し続けます。新旧どちらのキー名を使っても構いません。

## 注意点

- Claude Code v2.1.232での変更です。
- `extraKnownMarketplaces` / `strictKnownMarketplaces` という従来のキー名も引き続き利用可能で、後方互換性があります。
- `strictKnownMarketplaces`（`allowedMarketplaces`）は、プラグインが由来するマーケットプレイス自体を照合する設定であり、マーケットプレイス内の個々のエントリの供給元までは制限しない点に注意してください。
