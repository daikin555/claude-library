## 原文（日本語に翻訳）

Claude DesktopやIDEから開始されたRemote Controlセッションが、ローカルセッションを再開するたびにclaude.ai上で新しいセッションとして表示されてしまっていた問題を修正しました。今後は既存のセッションに正しく再接続されるようになります。

## 原文（英語）

Fixed Remote Control sessions started from Claude Desktop or an IDE appearing as a new claude.ai session each time the local session was resumed; they now reattach to the existing one

## 概要

Claude DesktopアプリやIDE統合から開始したRemote Controlセッションは、claude.ai側の画面からも同じセッションとしてアクセスできるようになっています。しかし、これまではローカル側のセッションを一度中断して再開（resume）するたびに、claude.ai側では別の新しいセッションとして扱われてしまい、セッション一覧に重複したエントリが増えていく、あるいは会話の連続性が分かりにくくなるという問題がありました。今回の修正により、ローカルセッションを再開した際には、claude.ai側の既存のセッションに正しく再接続（reattach）されるようになりました。

## この変更が影響する場面

新機能というよりバグ修正で、以下のような場面で体感的な変化があります。

- Claude DesktopやIDE（VS Code拡張など）からRemote Controlセッションを開始し、日をまたいで作業を再開するような使い方をしている場合
- claude.ai側のセッション一覧で、同じ作業に対応するセッションが再開のたびに増えてしまい、見づらくなっていた場合

## 実践例

### Claude Desktopでの作業を日をまたいで再開する

```bash
# 1日目: Claude DesktopからRemote Controlセッションを開始
# claude.ai 側にセッションAとして表示される

# ローカルセッションを一旦終了

# 2日目: 同じプロジェクトでローカルセッションを再開(resume)
# 修正前:
#   claude.ai 側にセッションBという「新規セッション」が
#   別途作成され、セッションAとの継続性が失われていた
#
# 修正後:
#   claude.ai 側の既存セッションAに正しく再接続され、
#   同じ会話の続きとして表示される
```

### IDEからの利用でのセッション一覧の整理

```bash
# IDE拡張機能からRemote Controlセッションを頻繁に開始・再開する開発者の場合
# 修正前: セッション一覧に同じ作業に対応する重複セッションが蓄積
# 修正後: 再開のたびに既存セッションへ正しく紐づき、
#         セッション一覧がすっきりと保たれる
```

## 注意点

- Claude Code v2.1.232で修正されたバグ修正です。Claude DesktopまたはIDE統合からRemote Controlセッションを開始した場合に関係します。
- ターミナルから直接 `claude` を起動してRemote Controlを利用するケースでの挙動については、この項目の対象範囲を超えるため、詳細は公式ドキュメントを参照してください。
- 本修正適用前に作成された重複セッションが自動的に統合されるわけではなく、今後の再開から正しい挙動になります。
