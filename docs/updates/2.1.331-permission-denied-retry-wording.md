# PermissionDenied フックの retry: true の通知内容を変更

## 原文（日本語に翻訳）

`PermissionDenied` フックの `retry: true` が Claude に伝える内容を変更しました。ユーザーがその呼び出しを求めた場合に限り、拒否された呼び出しを再実行します。

## 原文（英語）

Changed what a `PermissionDenied` hook's `retry: true` tells Claude: make the refused call again only if you asked for that call

## 概要

フックが拒否後の再試行を許可しても、Claude が勝手に同じ操作を繰り返さないよう、再試行の条件が明確になりました。

## 基本的な使い方

```json
{ "retry": true }
```
をフックの出力に含めると、Claude には「ユーザーが求めた呼び出しの場合のみ再実行する」と伝わります。

## 実践例

### 自動モードでの拒否後の挙動

分類器が拒否した操作でも、ユーザーが明示的に依頼したものだけが再試行対象になります。

## 注意点

- `retry: true` は無条件の再実行指示ではなくなりました。
- 既存フックの挙動に依存している場合は確認してください。
