## 原文（日本語訳）

`http` として設定されたMCPサーバーのうち、レガシーのHTTP+SSEのみに対応しているサーバーが、最初のリクエストに対して422やその他の4xxエラーを返した場合に接続に失敗する問題を修正しました。

## 原文（英語）

Fixed MCP servers configured as `http` that only speak legacy HTTP+SSE failing to connect when they answer the first request with 422 or another 4xx error

## 概要

MCPサーバーには新しいStreamable HTTPトランスポートと、旧来のHTTP+SSEトランスポートの2種類があります。`http` として設定されたMCPサーバーが実際にはレガシーのHTTP+SSEにしか対応していない場合、Claude Codeが最初にStreamable HTTPとしてリクエストを送信し、サーバーがそれに対して422や他の4xx系エラーを返すと、フォールバックがうまく機能せず接続自体に失敗していました。今回の修正でこのフォールバック処理が正しく行われるようになり、レガシーなMCPサーバーでも `http` 設定のまま問題なく接続できるようになりました。

## 基本的な使い方

`.mcp.json` などの設定でMCPサーバーを `http` タイプとして登録している場合、特別な設定変更は不要です。

```json
{
  "mcpServers": {
    "legacy-server": {
      "type": "http",
      "url": "https://example.com/mcp"
    }
  }
}
```

## 実践例

### レガシーなHTTP+SSEサーバーへの接続

古い実装のMCPサーバー（Streamable HTTPに未対応で、HTTP+SSEのみをサポート）に対して `http` として接続設定をしている場合、これまでは初回リクエストへの4xxレスポンスが原因で接続できないことがありましたが、修正後は自動的にレガシートランスポートへフォールバックして正常に接続できます。

### `/mcp` コマンドでの接続確認

接続に問題がないかを確認する場合は、`/mcp` コマンドでサーバーの接続状態を確認できます。

```
/mcp
```

## 注意点

- サーバー側がStreamable HTTPとHTTP+SSEのどちらにも対応していない、あるいはまったく異なるエラーを返す場合は、引き続き接続に失敗する可能性があります。
- MCPサーバーの設定タイプ（`http` / `sse` / `stdio`）は、サーバーの実装に合わせて正しく指定することが推奨されます。
