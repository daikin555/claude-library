## 原文（日本語訳）

同じ呼び出しの中で他のパラメータも不正だった場合に、ツール入力の検証エラーが未知・欠落・誤記のパラメータの1つしか名指ししていなかった不具合を修正しました。現在はそれらもすべて列挙されるようになりました。

## 原文（英語）

Fixed tool input validation errors naming only an unknown, missing or mistyped parameter when other parameters in the same call were also invalid; those are now listed too

## 概要

MCPサーバーやカスタムツールを呼び出す際、パラメータが未知だったり、必須パラメータが欠けていたり、名前を誤記していたりすると検証エラーが表示されます。これまでは、1回の呼び出しの中に複数の問題があっても、そのうち1つしかエラーメッセージに表示されず、残りの問題は次に再実行して初めて分かるという非効率な状態でした。今回の修正で、同じ呼び出しの中にある複数の不正パラメータがすべて一度に列挙されるようになりました。

## 基本的な使い方

ユーザー側の対応は不要です。ツールやMCPサーバーの開発中にパラメータの間違いが複数あっても、エラーメッセージから一度にすべて把握できます。

## 実践例

### カスタムMCPサーバー・ツールの開発時のデバッグ効率化

新しいMCPツールを開発している際、パラメータ名の誤記や型の不一致が複数箇所にあっても、1回のエラー表示ですべての問題箇所を確認し、まとめて修正できます。

### スキルやコマンドの定義ミスの早期発見

カスタムスキルやスラッシュコマンドの定義で複数のパラメータ指定ミスがあった場合も、修正のたびに再実行して1つずつ発見する手間が省けます。

## 注意点

- この修正はエラーメッセージの情報量を増やすものであり、検証ロジック自体の挙動を変えるものではありません
- MCPサーバーやカスタムツールを自作・デバッグする開発者にとって特に有用な改善です
