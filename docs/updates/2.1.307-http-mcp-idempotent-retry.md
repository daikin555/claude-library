# HTTP MCP ツール呼び出しの二重送信を修正（冪等なツールのみ再試行）

## 原文（日本語に翻訳）

- 呼び出しの途中で接続が閉じたときに HTTP MCP ツール呼び出しが二重に送信される問題を修正。再試行されるのは読み取り専用または冪等なツールのみになりました

## 原文（英語）

- Fixed HTTP MCP tool calls being sent twice when the connection closed mid-call; only read-only or idempotent tools are now retried

## 概要

HTTP 接続が呼び出し中に切れた際、書き込み系ツールが自動再送されて二重実行される恐れがありました。今後は読み取り専用または冪等と宣言されたツールのみが再試行されます。

## 基本的な使い方

更新のみで反映されます。MCP サーバー側でツールに注釈（アノテーション）を付けておくと、再試行の対象かどうかが明確になります。

```json
{
  "name": "get_issue",
  "annotations": { "readOnlyHint": true }
}
```

## 実践例

### Issue 作成ツールの二重作成を防ぐ

`create_issue` のような非冪等ツールは接続断で再送されないため、重複 Issue が作られません。

### 参照系ツールの安定性

`get_issue` のような読み取り専用ツールは、一時的な切断でも自動的に再試行されます。

## 注意点

- 接続断で失敗した書き込み系ツールは、結果を確認してから手動で再実行してください。
- 自作 MCP サーバーでは、ツールの注釈を適切に設定することを推奨します。
