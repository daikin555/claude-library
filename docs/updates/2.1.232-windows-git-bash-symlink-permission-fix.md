## 原文（日本語に翻訳）

Git BashがCygwin形式のシンボリックリンクをたどってしまい、パス検証がそれを通常のファイルとして扱ってしまうWindowsの権限バイパスを修正しました。これらのリンクを経由した書き込みには、今後は権限承認が必要になります。

## 原文（英語）

Fixed a Windows permission bypass where Git Bash followed Cygwin-style symlinks that path validation saw as regular files; writes through them now require permission approval

## 概要

Windows環境のGit Bashは、Cygwin方式で実装された独自のシンボリックリンク（通常のNTFSシンボリックリンクとは異なる形式のファイル）をサポートしています。これまでClaude Codeのパス検証ロジックは、こうしたCygwin形式のシンボリックリンクを「通常のファイル」として認識してしまい、実際にはリンク先の別ファイルへの書き込みであるにもかかわらず、権限確認をすり抜けて書き込みが行われてしまう可能性がありました。この修正により、Cygwin形式のシンボリックリンクが正しく検出されるようになり、そのリンクを経由した書き込みには通常のファイル書き込みと同様に権限承認が必要になりました。

## この変更が影響する場面

これは内部的なセキュリティ修正であり、新機能ではありません。以下のような場面で影響があります。

- Windows上でGit Bashをシェルとして使用し、リポジトリ内やその周辺にCygwin形式のシンボリックリンクが存在する環境
- Claude Codeに対して特定のファイルパスへの書き込みのみを許可している設定で、そのパスがCygwin形式のシンボリックリンクだった場合

## 実践例

### シンボリックリンク経由の書き込みが権限確認の対象になる

```bash
# Windows + Git Bash 環境
# .config が Cygwin 形式のシンボリックリンクで
# 別の場所（例: 機密設定ファイル）を指しているケース

ls -la .config
# lrwxrwxrwx ... .config -> /c/secrets/real-config

# 修正前:
# パス検証が .config を「通常のファイル」と誤認し、
# 権限確認なしにリンク先への書き込みが行われる可能性があった

# 修正後:
# .config への書き込み要求時に、リンク先への書き込みとして
# 適切に権限確認ダイアログが表示される
```

### 許可設定の再確認

特定パスへの書き込みを事前許可している場合、そのパスがシンボリックリンクでないかを見直すことで、意図しないファイルへの書き込みを防げます。

```bash
# 許可リストの例
# "Write(./output/*)" のような許可設定をしている場合、
# ./output がシンボリックリンクでないことを確認しておくと安全
```

## 注意点

- Claude Code v2.1.232で修正されたセキュリティ修正です。Windows + Git Bash環境に固有の問題です。
- macOSやLinuxの標準的なシンボリックリンク、あるいはWindowsのネイティブNTFSシンボリックリンクとは別に、Git Bash特有のCygwin形式シンボリックリンクを対象とした修正です。
- 本修正の適用後、Cygwin形式のシンボリックリンクを経由した書き込みでは新たに権限確認が表示されるようになるため、既存のワークフローで自動化していた書き込み処理がある場合は挙動の変化に注意してください。
