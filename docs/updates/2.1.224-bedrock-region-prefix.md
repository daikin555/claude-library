## 原文（日本語訳）

Bedrock向けに `ANTHROPIC_BEDROCK_REGION_PREFIX` 環境変数を追加しました。`AWS_REGION` から自動的に導出されるクロスリージョンInference Profileの代わりに、特定のプレフィックスを優先させることができます。

## 原文（英語）

Added `ANTHROPIC_BEDROCK_REGION_PREFIX` env var for Bedrock to prefer a specific cross-region inference profile over the `AWS_REGION`-derived one

## 概要

Amazon Bedrock上でClaude Codeを使う場合、組み込みのデフォルトモデルは `us.`・`eu.`・`apac.`・`us-gov.`・`global.` といったクロスリージョンInference Profileのプレフィックスに解決されます。従来このプレフィックスはAWSリージョンから自動導出される仕組みしかありませんでしたが、`ANTHROPIC_BEDROCK_REGION_PREFIX` を設定することで、リージョンに関わらず優先したいプレフィックスを明示的に指定できるようになりました。たとえば `us-*` リージョンで動かしつつも、アカウントで有効化されている `global.` のInference Profileを使いたい場合などに便利です。

## 基本的な使い方

```bash
export CLAUDE_CODE_USE_BEDROCK=1
export AWS_REGION=us-east-1
export ANTHROPIC_BEDROCK_REGION_PREFIX=global

# us-east-1で動かしていても、opusエイリアスは
# us.anthropic.claude-opus-5 ではなく
# global.anthropic.claude-opus-5 に解決される
```

## 実践例

### アカウントでglobalプロファイルのみ有効な場合

組織のBedrockアカウントで `global.` のInference Profileのみが有効化されており、AWSリージョンから自動導出される地理特化プレフィックス（`us.` など）は使えない、というケースで指定します。

```bash
export CLAUDE_CODE_USE_BEDROCK=1
export AWS_REGION=us-west-2
export ANTHROPIC_BEDROCK_REGION_PREFIX=global
```

### モデルバージョンは固定せず、プレフィックスだけ変えたい場合

`ANTHROPIC_DEFAULT_OPUS_MODEL` などで特定のモデルIDに固定する方法もありますが、Claude Codeの組み込みデフォルトモデルを使い続けつつプレフィックスだけ変更したい場合は、こちらの環境変数の方が簡潔です。

```bash
# 固定ピン留め（モデルIDそのものを指定する場合）
export ANTHROPIC_DEFAULT_OPUS_MODEL='eu.anthropic.claude-opus-4-8'

# プレフィックスのみ指定する場合（デフォルトモデルは追随する）
export ANTHROPIC_BEDROCK_REGION_PREFIX=eu
```

### AWS GovCloud環境での注意

GovCloudリージョン（`us-gov-*`）では、この環境変数の値に関わらず常に `us-gov.` プレフィックスが使われます。

```bash
export AWS_REGION=us-gov-west-1
# ANTHROPIC_BEDROCK_REGION_PREFIX を設定しても無視され、
# 常に us-gov. プレフィックスが使われる
```

## 注意点

- Claude Code v2.1.224以降が必要です。
- 有効な値は `us`・`eu`・`apac`・`jp`・`au`・`global` のいずれかです。不正な値を設定した場合は、リージョンから導出されるデフォルトのプレフィックスにフォールバックします。
- このプレフィックスはあくまで「優先」であり保証ではありません。Claude CodeがアカウントのInference Profile一覧を取得できる場合は、優先プレフィックスのプロファイル→該当するいずれかのプロファイル→優先プレフィックス付きの組み込みモデルID、の順で解決を試みます。プロファイル一覧が取得できない場合は、可用性チェックなしでそのままプレフィックスが適用されるため、対象のプレフィックスが有効化されていないと400エラーになることがあります。
- 自分で指定したInference Profile ID・ARNや `modelOverrides` の値は書き換えられません。
