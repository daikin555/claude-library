## 原文（日本語訳）

利用できなくなったペーストを削除するとコマンドのテキストが変わってしまう場合に、キャンセル・確認ステップを追加しました。

## 原文（英語）

Added a cancel-and-confirm step when removing an unavailable paste changes a command's text

## 概要

Claude Codeでは、大きなテキストや画像を貼り付けると、入力欄には `[Pasted text #1 +50 lines]` のようなプレースホルダーだけが表示され、実際の内容は裏側で保持されます。しかしセッションを跨いだ再開や時間経過などにより、このプレースホルダーが参照する元のペースト内容が失われ「利用できない（unavailable）」状態になることがあります。今回の変更により、そうした利用できないペーストを削除する操作がコマンドの文面自体を変えてしまう場合、Claude Codeは変更を即座に適用せず、キャンセルするか確定するかをユーザーに確認するステップを挟むようになりました。

## 基本的な使い方

通常の利用では特別な操作は不要です。利用できなくなったペーストのプレースホルダーを含むコマンドを編集・実行しようとしたときに、確認ダイアログが表示された場合は、内容を確認したうえで確定（そのまま送信）するかキャンセルするかを選択します。

```text
> [Pasted text #1 +120 lines] このログからエラー原因を調べて

# ペースト内容が失われている場合、削除によりコマンド文が
# 「このログからエラー原因を調べて」だけに変わってしまうため、
# 送信前に確認ダイアログが表示される
```

## 実践例

### セッションを再開したときの誤操作を防ぐ

`/resume` で古いセッションを再開し、以前貼り付けた大きなログや差分を参照するコマンドを再送しようとした際に、ペーストが失効していると意図せず短いテキストだけが送信されてしまうことがありました。確認ステップにより、送信前に「本当にこの内容で良いか」を確認できます。

```text
> claude
> /resume

# 過去に貼り付けたペーストを含むコマンド履歴を再利用しようとすると、
# ペーストが失効していれば確認ダイアログが挟まる
```

### 長時間セッションでのペーストの経年劣化に気づく

長時間実行しているセッションでは、古いペースト参照が徐々に無効化されていくことがあります。確認ダイアログが出た時点で、貼り付け直しが必要だと気づけます。

```text
> [Pasted text #3 +300 lines] このdiffをレビューして

# 数時間後にこのコマンドを再実行しようとすると、
# ペーストが失効していることに確認ダイアログで気づける
```

## 注意点

- この確認ステップは、ペーストの削除によって「コマンドのテキスト内容が変わる」場合にのみ表示されます。内容に影響しない場合は従来どおり自動的に処理されます。
- 確認をキャンセルした場合は、元のプレースホルダーを含む状態のまま編集を続けられるため、ペーストを貼り直すなどの対応が可能です。
- 関連する修正として、同バージョンでは「再呼び出し・復元されたペースト内容が、経年劣化やプレースホルダー番号の衝突により誤ったデータを添付したりテキストを失ったりする」不具合も修正されています。
