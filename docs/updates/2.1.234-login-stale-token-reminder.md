## 原文（日本語訳）

`CLAUDE_CODE_OAUTH_TOKEN` が設定された状態で `/login` を実行した後、古いトークンに関するリマインダーがClaudeの自動再開ターンに漏れて表示されることがなくなり、ユーザーにのみ表示されるようになりました。

## 原文（英語）

Fixed: after `/login` while `CLAUDE_CODE_OAUTH_TOKEN` is set, the stale-token reminder no longer leaks into Claude's automatically resumed turn — it now appears only to you

## 概要

環境変数 `CLAUDE_CODE_OAUTH_TOKEN` が設定されている状態でセッション中に `/login` を実行すると、Claude Codeはそのセッションを新しいログイン情報に切り替えます。しかし、Claude Codeは新しいセッションを開始するたびに `CLAUDE_CODE_OAUTH_TOKEN` を再度読み込むため、環境変数を削除しない限り「古いトークンが設定されたままです」といったリマインダーが表示される仕組みになっています。今回の修正前は、このリマインダーがユーザー向けの表示だけでなく、Claudeが処理を自動的に再開するターン（モデルへの入力）にも紛れ込んでしまうことがありました。修正後は、このリマインダーは常にユーザーにのみ表示され、Claudeが受け取る会話コンテキストを汚染しなくなりました。

## 基本的な使い方

`CLAUDE_CODE_OAUTH_TOKEN` を設定した状態で `/login` を使う操作自体は変わりません。

```bash
export CLAUDE_CODE_OAUTH_TOKEN="your-token"
claude
> /login
# 新しいアカウントでログインし、現在のセッションはそちらに切り替わる
```

ログイン後、ターミナル上にはこの環境変数が残っている旨のリマインダーが表示されますが、修正後はこれが常にユーザー向けの表示に留まります。

## 実践例

### 自動継続タスクの途中で/loginした場合

Claudeが長時間タスクの途中で応答が途切れ、自動的に再開する状況で `/login` を挟んだケースです。

```bash
export CLAUDE_CODE_OAUTH_TOKEN="old-token"
claude
> 大きなリファクタリングタスクを実行して
[途中で応答が途切れ、自動的に再開される]
> /login
[ブラウザでログイン完了]

# 修正前: 古いトークンに関するリマインダー文言が、
#         自動再開されたClaudeへの入力に混入し、
#         Claudeが無関係な内容に反応してしまうことがあった
# 修正後: リマインダーはユーザー向け表示のみで、
#         Claudeの自動再開ターンには一切含まれない
```

### CI/CD環境からインタラクティブセッションに切り替えた場合

CI用に `CLAUDE_CODE_OAUTH_TOKEN` を設定した環境をそのままローカル開発に流用し、対話的に `/login` して別アカウントに切り替えるようなワークフローでも、ターン内容がクリーンに保たれます。

### 環境変数を削除し忘れたまま作業を続ける場合

`unset CLAUDE_CODE_OAUTH_TOKEN` を忘れてシェルプロファイルに残したまま作業を続けても、リマインダーはあくまでユーザーへの注意喚起として機能し、Claudeの応答品質やタスク遂行に悪影響を与えなくなりました。

## 注意点

- リマインダーそのものが不要になったわけではありません。恒久的な対策としては、シェルプロファイルや設定ファイルの `env` ブロックから `CLAUDE_CODE_OAUTH_TOKEN` を削除することが推奨されます
- `/login` は現在のセッションのログイン情報を切り替えますが、新しいセッションを開始するたびに環境変数を再読み込みする挙動自体は変わっていません
- この修正は表示の分離に関するものであり、認証の優先順位やトークンの有効期限管理ロジックには影響しません
