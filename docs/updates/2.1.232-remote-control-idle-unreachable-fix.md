## 原文（日本語に翻訳）

しばらく操作されていない（アイドル状態の）Remote Controlセッションが、新しく接続したクライアントからは「到達不能（unreachable）」に見えてしまう問題を修正しました。

## 原文（英語）

Fixed Remote Control sessions appearing unreachable to newly attached clients while idle

## 概要

Claude CodeのRemote Control機能を使うと、デスクトップやVS Codeで実行中のセッションに、スマートフォンやブラウザなど別のデバイスから接続して操作できます。今回の修正前は、しばらく操作が行われずアイドル状態が続いたセッションに対して、新たに接続しようとしたクライアントからそのセッションが「到達不能」と誤って表示されることがありました。本アップデートにより、アイドル状態のセッションでも新規クライアントから正しく到達可能と認識されるようになりました。

## 基本的な使い方

Remote Controlはデスクトップ／VS CodeでClaude Codeセッションを実行しつつ、別デバイスから同じセッションに接続する機能です。セッション一覧やURL経由で接続すると、既存のセッションに参加できます。

```bash
# デスクトップ側でセッションを開始（Remote Controlは自動的に有効）
claude

# セッションをしばらく放置（アイドル状態）
# ...数十分〜数時間、操作なし...

# phone や別のブラウザから claude.ai/code を開き、
# セッション一覧から同じセッションに接続
# 以前: アイドル状態のセッションが「到達不能」と表示されることがあった
# 修正後: アイドル状態でも正しく接続可能と表示される
```

## 実践例

### 会議や休憩を挟んで長時間放置したセッションに後から接続する場合

デスクトップでコーディングセッションを開始した後、会議や休憩でしばらく操作をしないまま放置し、後から外出先のスマートフォンで続きを見ようとするケースです。以前はこのようなアイドル状態のセッションが新規クライアントから「到達不能」と表示され、接続できないことがありました。この修正により、放置時間の長さに関わらず正しくセッション一覧に「接続可能」として表示されるようになります。

```bash
# デスクトップでセッション開始
claude

# 長時間の会議で放置

# 外出先のスマートフォンから claude.ai/code にアクセス
# セッション一覧に正しく「オンライン」として表示される
```

### バックグラウンドで長時間実行中のタスクを別デバイスから確認する場合

大きなリファクタリングやテストの実行など、時間のかかるタスクをバックグラウンドで走らせている間、Claude Code側の対話がしばらく発生しないことがあります。この間にセッションがアイドル扱いとなり、別デバイスから接続確認をしても到達不能に見えてしまう不具合がありましたが、今回の修正で解消されています。

```bash
# バックグラウンドタスク実行中（対話が発生しない期間）
claude

# 別デバイスでステータス確認
# 修正後は正しく接続・進捗確認が可能
```

## 注意点

- Claude Code v2.1.232での修正です。
- Remote Controlは Pro、Max、Team、Enterprise プランで利用可能です（Team・Enterpriseでは管理者による有効化が必要な場合があります）。
- 症状が再発する場合は、クライアント・ホスト双方を最新バージョンに更新した上で再接続してください。
- ネットワーク環境（社内プロキシやファイアウォールなど）によっては、別途接続設定が必要な場合があります。
