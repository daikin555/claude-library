## 原文（日本語訳）

BashおよびPowerShellがディスクのフルクォータを「Exit code 1」の裏に隠してしまい、大きな出力ファイルを一時領域に残していた不具合を修正しました。

## 原文（英語）

Fixed Bash and PowerShell hiding a full disk quota behind "Exit code 1" and leaving large output files in temp

## 概要

コマンドの出力が大きく、ディスククォータ（容量制限）を超過してしまった場合、これまでは単に「Exit code 1」としか表示されず、実際の原因がディスク容量不足であることが分かりにくい状態でした。さらに、書き込みに失敗した大きな一時出力ファイルがtempディレクトリに残り続け、ディスクを圧迫する要因にもなっていました。今回の修正で、ディスククォータ超過が原因であることが明示されるようになり、不要な一時ファイルも適切に処理されるようになりました。

## 基本的な使い方

ユーザー側の対応は不要です。ディスク容量不足が発生した場合、エラーメッセージからより具体的な原因を確認できるようになります。

## 実践例

### 大量出力を伴うビルド・テストコマンドの実行

大規模なビルドログやテスト結果など、出力が非常に大きくなるコマンドを実行する際に、単なる「Exit code 1」ではなく、ディスク容量不足という具体的な原因にすぐ気づけます。

### CI環境でのディスク容量管理

ディスク容量が限られたCI環境でコマンドが謎の失敗をする場合、まず本当の原因がディスク容量なのかを判別しやすくなり、無駄なデバッグ時間を減らせます。

## 注意点

- 根本的な対処にはディスク容量の確保（不要ファイルの削除やボリューム拡張）が必要です
- 一時ファイルが既に大量に残っている場合は、OSの一時ディレクトリを確認しクリーンアップすることを検討してください
