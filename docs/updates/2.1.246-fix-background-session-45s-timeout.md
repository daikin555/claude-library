## 原文（日本語訳）

Claude Codeの起動ディレクトリが削除されていた場合、マシンがスリープしていた場合、またはホストのプロセス起動が遅い場合に、バックグラウンドセッションが45秒後に開けなくなってしまう不具合を修正しました。

## 原文（英語）

Fixed background sessions failing to open after 45 seconds when Claude Code's starting directory had been deleted, the machine had slept, or the host is slow to start processes

## 概要

Claude Codeのバックグラウンドセッション機能は、裏側で別プロセスとしてセッションを起動し、後からそれを開いて操作できるようにするものです。これまでは、セッションの起動ディレクトリが後から削除されていたり、マシンがスリープ状態から復帰した直後だったり、あるいはホスト環境でのプロセス起動が普段より遅かったりすると、一定のタイムアウト（45秒）を超えてバックグラウンドセッションを開けなくなる不具合がありました。今回の修正でこれらのケースが解消され、こうした条件下でもバックグラウンドセッションを正常に開けるようになりました。

## 基本的な使い方

通常通りバックグラウンドセッションを起動し、後からそれを開くだけです。

```
# バックグラウンドでセッションを開始
claude --background

# 後からセッション一覧を確認して再度開く
```

修正後は、起動ディレクトリが削除された場合やマシンのスリープ復帰直後でも、タイムアウトによる失敗が発生しにくくなります。

## 実践例

### 長時間バックグラウンドで走らせた後にノートパソコンをスリープさせた場合

バックグラウンドセッションを開始した後にノートパソコンを閉じてスリープさせ、後で開いて確認しようとしても、以前はタイムアウトで開けないことがありましたが、修正後は正常に開けます。

### 一時ディレクトリを起動場所にしてセッションを開始した場合

一時的な作業ディレクトリでバックグラウンドセッションを開始し、そのディレクトリが何らかの理由で削除された後にセッションを開こうとしても、以前より安定して動作するようになりました。

### リソースが限られた低速なホスト環境で運用する場合

CI環境やスペックの低いリモートホストなど、プロセスの起動自体に時間がかかる環境でバックグラウンドセッションを使う場合でも、45秒のタイムアウトで失敗しにくくなりました。

## 注意点

- 起動ディレクトリ自体が削除されている場合、セッションを開けても元のディレクトリに依存する一部の操作は依然として影響を受ける可能性があります
- 極端に遅い環境では、タイムアウトの緩和だけでは解決しないケースも残る可能性があるため、根本的な起動速度の改善が望ましい場合もあります
- この修正はバックグラウンドセッションを開く際の信頼性に関するものです
