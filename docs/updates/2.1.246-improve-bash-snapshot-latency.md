## 原文（日本語訳）

bashシェルでのBashツールのレイテンシを改善しました。スナップショット関数を再生する際に、関数ごとにbase64エンコードのサブシェルを起動する方式をやめました。

## 原文（英語）

Improved Bash tool latency on bash shells by replaying snapshot functions without a base64 subshell per function

## 概要

Claude CodeのBashツールは、シェル環境（エイリアスや関数など）を再現するために、コマンド実行前にシェルスナップショットを再生します。これまではスナップショットに含まれる関数を復元する際、関数一つひとつに対してbase64エンコード用のサブシェルを起動していたため、関数の数が多い環境ではその都度オーバーヘッドが発生していました。今回の改善でこのサブシェル起動が不要になり、bashシェルでのBashツールの実行レイテンシが短縮されました。

## 基本的な使い方

この改善は内部的な最適化であり、ユーザーが何かを設定する必要はありません。通常通りBashツールでコマンドを実行するだけで、より高速な起動を体感できます。

```
ls -la
```

## 実践例

### 多数のシェル関数・エイリアスを定義している環境

`.bashrc` などに多数のカスタム関数を定義している開発環境では、これまでBashツールの初回実行時にそのオーバーヘッドが蓄積して遅延を感じることがありましたが、今回の改善で短縮されます。

### 一つのセッションで多数のBashコマンドを繰り返し実行するワークフロー

ビルド・テスト・lintなどを何度も繰り返し実行するようなワークフローでは、コマンド実行ごとのわずかなレイテンシ削減が積み重なり、全体の応答性向上につながります。

### CI/CD的に多くの短いコマンドを連続実行する場合

自動化されたパイプラインの中でClaude Codeが多数の短いBashコマンドを連続実行するケースでは、1回あたりのオーバーヘッド削減の効果がより顕著に表れます。

## 注意点

- 対象はbashシェルでの実行に関する改善です。他のシェル（zshなど）における挙動は本項目の範囲外です
- 機能面での変更はなく、レイテンシの改善のみが目的です
