## 原文（日本語訳）

保存されたトランスクリプトに破損したメッセージコンテンツブロックが含まれている場合に、セッションの再開または起動が失敗する不具合を修正しました。

## 原文（英語）

Fixed sessions failing to resume or start when their saved transcript contains a malformed message content block

## 概要

Claude Codeのセッションは、各メッセージが複数の「コンテンツブロック」（テキスト、ツール呼び出し、ツール結果など）で構成されるトランスクリプトとして保存されます。このコンテンツブロックの一部が壊れている場合、セッションの再開だけでなく、新規セッションの起動自体が失敗してしまう不具合がありました。今回の修正で、壊れたコンテンツブロックがあってもセッションの起動・再開が正常に行えるようになりました。

## 基本的な使い方

特別な操作は不要です。通常どおりセッションを起動・再開してください。

```bash
claude
claude --continue
claude --resume
```

## 実践例

### セッション起動時のエラー

修正前は、ホームディレクトリやプロジェクトディレクトリに保存された過去のトランスクリプトに壊れたコンテンツブロックがあると、新しいセッションを起動しようとしても失敗することがありました。

```bash
# 修正前: 破損したコンテンツブロックが原因で起動自体が失敗することがあった
claude

# 修正後: 破損したブロックがあっても正常に起動する
claude
```

### `--continue` での直近セッション再開

直近のセッションを継続する `--continue` オプションでも、同様に破損したコンテンツブロックが原因で再開に失敗するケースがありましたが、この修正で解消されています。

## 注意点

- 破損の原因（ネットワーク切断やディスクI/Oエラーなど）そのものを防ぐものではなく、破損データが存在しても動作を継続できるようにする耐障害性の改善です。
- 重要なセッションのトランスクリプトは、定期的にバックアップを取ることを推奨します。
