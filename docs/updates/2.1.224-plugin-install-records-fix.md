## 原文（日本語訳）

同じプラグインを複数のプロジェクトにインストールした際、プラグインのインストール記録が気付かれないまま破損してしまう問題を修正しました。

## 原文（英語）

Fixed plugin install records being silently corrupted when the same plugin is installed in multiple projects

## 概要

Claude Codeのプラグイン機能では、`/plugin install` でインストールしたプラグインの情報がインストール記録として保存され、`/plugin` から有効化・無効化・削除などの管理を行えます。しかし、同一のプラグインを複数の異なるプロジェクトでそれぞれインストールすると、その記録が気付かないうちに破損してしまう不具合がありました。破損したインストール記録は、プラグインの状態管理（有効/無効の切り替えや削除）を不安定にする原因になっていました。この修正により、同じプラグインを複数プロジェクトへインストールしても、インストール記録が正しく保たれるようになりました。

## 基本的な使い方

プラグインのインストール方法自体は変わりません。

```bash
# マーケットプレイスを追加
/plugin marketplace add anthropics/claude-code

# プラグインをインストール
/plugin install my-plugin@claude-plugins-official
```

同じプラグインを別のプロジェクトディレクトリでインストールしても、それぞれのインストール記録が正しく管理されます。

## 実践例

### 複数のプロジェクトで同じプラグインを使い回す場合

チームで共通利用しているプラグイン（例: Lintルールセットやコードレビュー補助プラグイン）を、複数のリポジトリで個別にインストールするケースです。

```bash
cd ~/projects/service-a
claude
/plugin install lint-helper@team-marketplace

cd ~/projects/service-b
claude
/plugin install lint-helper@team-marketplace

# 修正前: service-bでのインストール時に、
# 既存（service-aで作成済み）のインストール記録が
# 気付かれないまま破損し、
# /pluginでの有効化・無効化・削除操作が
# 不安定になることがあった

# 修正後: プロジェクトごとのインストール記録が
# 正しく独立して管理され、破損しない
```

### プラグインの有効化・無効化・削除を行う場合

複数プロジェクトにまたがってインストールしたプラグインを、プロジェクトごとに管理する操作です。

```bash
/plugin
# プラグイン管理画面から対象プラグインを選択し、
# 有効化・無効化・削除を行う

# 修正前: 記録破損により、意図したプロジェクトとは
# 異なる箇所でエラーが出たり、
# 一覧に正しく表示されないことがあった

# 修正後: どのプロジェクトでインストールしたプラグインも
# 正確に一覧・管理できる
```

### 大規模なマルチリポジトリ環境での運用

多数のリポジトリを横断して同じプラグインセットを標準採用している組織では、記録破損の影響が広範囲に及びやすい状況でした。今回の修正により、こうした環境でもプラグインのインストール状態を安心して管理できます。

## 注意点

- 既にこの不具合の影響でインストール記録が破損している場合、アップデートを適用しても自動的に修復されるわけではないため、該当プラグインを一度削除して再インストールすることを推奨します
- プラグインの管理状態に不審な点がある場合は、`/plugin` を開いてインストール済みプラグインの一覧を確認してください
- マーケットプレイスの追加・削除自体には影響しません
