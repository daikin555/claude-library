# Remote Controlセッションが接続不良時に数分間停止する不具合を修正

## 原文（日本語訳）

Claude DesktopまたはVS Codeでホストされている Remote Control セッションが、claude.aiへの接続状態が不安定なときにツール完了後も数分間停止（スタール）してしまう問題を修正しました。

## 原文（英語）

Fixed Remote Control sessions hosted by Claude Desktop or VS Code stalling for minutes after a tool finished when the connection to claude.ai was degraded

## 概要

Remote Controlは、claude.ai（Web/モバイル）とローカルで動作しているClaude Codeセッションを接続し、外出先からでも作業を継続できる機能です。しかし、claude.aiとの接続品質が低下した状態で、Claude DesktopやVS Code拡張からRemote Controlセッションをホストしていると、ツールの実行自体は完了しているにもかかわらず、その後の応答表示が数分間止まってしまう不具合がありました。2.1.252ではこの問題が修正され、接続が不安定な状況でもツール完了後の応答がスムーズに反映されるようになりました。

## 基本的な使い方

Remote Controlは、Claude DesktopまたはVS Code上でローカルセッションを開始し、claude.ai/code やモバイルアプリから接続することで利用します。

```bash
# ターミナルまたはClaude Desktop / VS Code拡張でClaude Codeセッションを開始
claude
```

1. claude.ai/code をブラウザで開く、またはモバイルアプリを起動する
2. コンピューターアイコンと緑色のステータスドットが表示されているセッションを選択して接続する
3. 外出先からプロンプトを送信し、ローカルマシン上でタスクが実行される

## 実践例

### 1. 外出先でモバイルからタスクの進捗を確認する

自宅やオフィスのマシンでClaude Codeセッションを開始し、外出中にスマートフォンのモバイル通信（Wi-Fiより不安定な回線）から接続して進捗を確認するようなケースで、以前は接続品質が低いとツール完了後の表示が数分遅延することがありました。今回の修正でこの遅延が解消されます。

### 2. VS Code拡張でRemote Controlをホストしながら別デバイスで確認する

VS Code上でClaude Codeセッションを開き、別の端末のブラウザからclaude.ai/codeで同じセッションに接続して作業内容を確認する運用でも、接続が不安定なネットワーク環境（カフェのWi-Fi、テザリングなど）で応答の反映が速くなります。

### 3. Claude Desktopでホストしたセッションをチームメンバーと共有

Claude Desktopでホストしているセッションに、管理者が許可したRemote Controlを通じて他デバイスから接続する場合も、接続断・再接続が頻発する環境での体験が改善されます。

## 注意点

- Remote Controlは全プランで利用可能ですが、Team・Enterpriseプランではデフォルトで無効になっており、管理者がClaude Code管理設定でRemote Controlのトグルを有効化する必要があります。
- Remote Controlはクラウドへのセッション移行ではなく、あくまでローカルマシンで実行中のセッションへの同期レイヤーです。ローカルマシンがスリープ・シャットダウンしている場合はセッションを継続できません。
- 通信はすべてAnthropic APIを経由しTLSで暗号化されますが、接続品質そのものに依存する部分（今回のような表示遅延など）は今後も発生し得るため、重要な作業は引き続き手元の端末で行うことを推奨します。
