## 原文（日本語訳）

エスケープシーケンスのプレフィックス直後でマウスレポートが複数回の読み取りに分割されて到着した場合、`<35;150;7M` のような文字列がプロンプトに挿入されてしまう問題を修正しました。

## 原文（英語）

Fixed text like `<35;150;7M` being inserted into the prompt when a mouse report arrived split across reads right after the escape prefix

## 概要

ターミナルはマウス操作（クリックやスクロールなど）をエスケープシーケンス形式のマウスレポートとしてアプリケーションに送信します。通常はこのシーケンス全体が一度に読み取られて正しく解釈されますが、タイミングによってはエスケープ文字（プレフィックス）だけが先に届き、残りの座標・ボタン情報が別の読み取りタイミングで到着することがありました。この修正前は、その場合にシーケンスの後半部分がそのままテキストとして解釈され、`<35;150;7M` のような制御文字列がユーザーの入力プロンプトに混入してしまうことがありました。

## 基本的な使い方

ユーザー側で対応することは特にありません。マウスサポートが有効なターミナル（マウスでのスクロールやクリックが可能な環境）でClaude Codeを操作していると、この修正の効果を自然に受けられます。

```
# 修正前: ターミナル上でスクロールなどの操作をすると
# プロンプトに <35;150;7M のような文字列が意図せず入力される場合があった
# 修正後: そのような文字列が混入せず、プロンプトはクリーンなまま
```

## 実践例

### 高速スクロール時の安定性

出力が多い画面をマウスで素早くスクロールした際、読み取りが分割されるタイミングが発生しやすくなります。この修正により、そうした操作の直後でもプロンプトに余計な文字列が残りません。

### リモート接続・低速環境での利用

SSH経由やレイテンシの高い接続でClaude Codeを使う場合、データが複数回に分かれて届くことが増えるため、この種の分割受信によるバグが発生しやすい環境でした。今回の修正で、こうした環境でも安定して動作します。

### マウス操作を併用するワークフロー

ターミナル上でテキスト選択やクリックによるカーソル移動などマウス操作を頻繁に行うユーザーにとって、入力欄が意図しない文字列で汚れるリスクがなくなります。

## 注意点

- この問題はマウスレポートのプレフィックス直後で読み取りが分割されるという、特定のタイミング条件下でのみ発生していたものです
- 修正はターミナルからの入力解析処理内部の挙動であり、ユーザー側の設定変更は不要です
