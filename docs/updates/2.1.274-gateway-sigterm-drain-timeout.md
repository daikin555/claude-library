## 原文（日本語訳）
Claudeアプリのゲートウェイが、SIGTERMを受信するとすべての開いているストリームを即座に切断してしまう問題を修正しました。現在は、終了前に進行中のリクエストが最大25秒間（`CLAUDE_GATEWAY_DRAIN_TIMEOUT_MS`）完了するのを待つようになりました。

## 原文（英語）
Fixed Claude apps gateway cutting every open stream on SIGTERM: it now lets in-flight requests finish for up to 25 seconds before exiting (`CLAUDE_GATEWAY_DRAIN_TIMEOUT_MS`)

## 概要
サーバープロセスの再起動やデプロイの際、ゲートウェイはSIGTERMシグナルを受け取って終了処理を行います。従来はSIGTERMを受信すると、進行中のストリーミングリクエストもすべて即座に切断されてしまい、ユーザーの応答が途中で打ち切られる問題がありました。今回の修正により、SIGTERM受信後も進行中のリクエストを最大25秒間（環境変数 `CLAUDE_GATEWAY_DRAIN_TIMEOUT_MS` で設定可能）だけ待ってから終了する「グレースフルドレイン」の仕組みが導入されました。

## 基本的な使い方
デフォルトでは25秒のドレインタイムアウトが適用されます。必要に応じて環境変数でこの時間を変更できます。

```bash
CLAUDE_GATEWAY_DRAIN_TIMEOUT_MS=30000
```

## 実践例

### 修正前の挙動
デプロイ時にゲートウェイへSIGTERMが送信されると、ストリーミング中の応答が途中で強制的に切断され、ユーザーには不完全な出力しか届きませんでした。

### 修正後の挙動
SIGTERM受信後も、進行中のリクエストは最大25秒間（またはカスタム設定した時間）だけ処理が継続され、正常に完了してからプロセスが終了するようになりました。これにより、デプロイ中のユーザー体験が向上します。

## 注意点
- `CLAUDE_GATEWAY_DRAIN_TIMEOUT_MS` はミリ秒単位で指定する環境変数で、デフォルトは25秒（25000ミリ秒）相当です。
- ドレイン時間を過度に長く設定すると、デプロイやロールアウトの完了が遅くなる可能性があるため注意が必要です。
- これはサーバーサイドのインフラ設定であり、通常のクライアント利用者が直接意識する項目ではありません。
