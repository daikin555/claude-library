## 原文（日本語訳）
[Claude Tag] US3、AP1、AP2、US1-FEDサイト向けのDatadogプリセットを追加。新規に作成するDatadog接続は、Datadogの読み取り・クエリ系APIルートのみに制限されるようになった。

## 原文（英語）
[Claude Tag] Added Datadog presets for the US3, AP1, AP2 and US1-FED sites; new Datadog connections are now limited to Datadog's read and query API routes

## 概要
Claude TagのDatadog連携プリセットが拡充され、これまでの主要サイトに加えてUS3、AP1、AP2、US1-FEDの各Datadogサイトに対応しました。Datadogは複数のリージョン・コンプライアンス要件ごとに異なるサイト（ドメイン）を提供しており、利用しているサイトに合わせたプリセットを選べるようになります。また同時に、新規作成されるDatadog接続はセキュリティ強化のため読み取り・クエリ系APIルートのみに制限され、意図しない書き込み操作ができないようになりました。

## 基本的な使い方
Claude Tag管理設定のアクセスバンドルからCredentialsタブを開き、利用しているDatadogサイト（例: AP1）に対応するプリセットを選択して接続情報を入力します。

```
Claude Tag 管理設定 > アクセスバンドル > Credentials タブ
> プリセットを選択: "Datadog (AP1)"
> APIキー/アプリケーションキーを入力 > 保存
```

## 実践例

### APAC/米国政府向けなど特定リージョンのDatadogを利用している組織
US1-FED（米国政府向け）やAP1・AP2（アジア太平洋）といった特定のDatadogサイトを使っている組織でも、対応するプリセットを選ぶだけで正しいエンドポイントに接続できます。

```
組織のDatadogサイト: ap1.datadoghq.com
> プリセット "Datadog (AP1)" を選択して接続
```

### Slack上からダッシュボードのメトリクスを確認する
読み取り・クエリAPIに限定された接続を使い、Claudeに「直近1時間のレイテンシメトリクスを見せて」のように依頼すると、Datadog上のデータを取得して要約させることができます。書き込み系の操作（モニターの変更など）はできない仕様のため安全に利用できます。

## 注意点
- 新規に作成するDatadog接続は読み取り・クエリ系APIに限定されるため、ダッシュボードやモニターの作成・変更など書き込みを伴う操作はできません。
- 既存のDatadog接続については、この制限が自動的には適用されない可能性があるため、必要に応じて設定を確認してください。
- 利用しているDatadogサイトのドメイン（例: datadoghq.com、us3.datadoghq.com、ap1.datadoghq.com、ddog-gov.com）に対応したプリセットを選ぶ必要があります。
