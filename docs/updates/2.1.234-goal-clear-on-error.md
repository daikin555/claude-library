## 原文（日本語訳）

ターンが復旧不可能なエラー（認証の失効、クレジット残高の枯渇、コンテキストオーバーフローなど）で終了した場合、`/goal` は設定されたままにならず、通知とともに自動的にクリアされるようになりました。

## 原文（英語）

`/goal` now clears itself with a notice when a turn dies on an unrecoverable error (e.g. revoked auth, an exhausted credit balance, or a context overflow) instead of staying armed

## 概要

`/goal` は完了条件を設定し、Claudeがその条件を満たすまで自律的にターンを繰り返す機能です。従来、認証の失効やクレジット残高の枯渇、コンテキストオーバーフローといった復旧不可能なエラーでターンが異常終了しても、`/goal` は設定されたまま（armed状態）残ってしまい、ユーザーが気づかないまま放置されるおそれがありました。今回の修正で、こうした復旧不可能なエラーが発生した場合は `/goal` が自動的に解除され、その旨がユーザーに通知されるようになりました。

## 基本的な使い方

ユーザー側の操作は変わりません。`/goal` で完了条件を設定して自律実行させている最中に、認証切れなどの致命的なエラーが発生すると、以下のような通知とともに `/goal` が自動的に解除されます。

```
> /goal テストが全て通ること

...(自律実行中)...

⚠ Goal cleared: turn ended with an unrecoverable error (authentication revoked).
Please re-authenticate and set a new goal if needed.
```

## 実践例

### 長時間実行中にAPI認証が失効した場合

夜間バッチのように `/goal` を使って長時間Claudeを走らせていた際、APIキーやOAuthトークンが失効すると、以前は `/goal` が有効なまま止まってしまい、再認証後に古い設定が残っているのか分かりにくい状態でした。今回の修正により、認証エラーが発生した時点で `/goal` は自動解除され、通知が表示されるため、再認証後に新しいgoalを設定し直すべきだと明確にわかります。

### クレジット残高が枯渇した場合

API利用のクレジット残高が尽きてリクエストが失敗した場合も、`/goal` は自動的にクリアされ、通知されます。残高をチャージした後、誤って古いgoal設定のまま再開してしまうことを防げます。

### コンテキストオーバーフローが発生した場合

非常に長いセッションでコンテキストウィンドウの上限を超えてしまった場合も同様に `/goal` が解除されます。セッションを整理・圧縮した後、必要であれば改めて `/goal` を設定し直す運用になります。

## 注意点

- 解除されるのは「復旧不可能」と判断されたエラーの場合のみです。一時的なネットワークエラーなど回復可能なケースでは、`/goal` は引き続き有効なまま次のターンを試みます
- `/goal` が解除された後は、通知の内容に従って原因（認証・残高・コンテキストなど）を解消してから、必要に応じて再度 `/goal` を設定してください
- この修正は `/goal` が有効な状態でのエラーハンドリングに関するものであり、`/goal` 自体の完了条件の判定ロジックには影響しません
