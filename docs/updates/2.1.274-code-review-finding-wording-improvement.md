## 原文（日本語訳）

[Code Review] Code Reviewが投稿する各指摘の言い回しを改善しました。誰が影響を受けるか、コードのどこで問題が発生するか、そして修正方法を、短くわかりやすい文章で冒頭に示すようになりました。

## 原文（英語）

[Code Review] Improved how Code Review words each posted finding: short plain sentences that say who is affected, where the code goes wrong, and the fix up front

## 概要

Code Reviewはプルリクエストに対して自動的に指摘（finding）をコメントとして投稿しますが、これまでの指摘文は冗長だったり、問題の核心や修正方法が分かりにくい書き方になっていることがありました。今回の改善により、各指摘は「誰が影響を受けるか」「コードのどこで問題が起きるか」「どう修正すればよいか」を、短く平易な文章で冒頭に明示するようになり、レビューを受け取った開発者が素早く内容を理解し対応できるようになりました。

## 基本的な使い方

特別な設定は不要です。Code Reviewが有効なリポジトリでPRを作成すると、改善された文言で指摘が投稿されます。

```
gh pr create --title "Add user authentication" --body "..."
```

## 実践例

### わかりやすい指摘文の例

修正前は「この関数にはエッジケースの考慮が不足している可能性があります」のように曖昧な指摘になりがちでしたが、修正後は以下のように具体的になります。

```
影響を受ける対象: 未認証ユーザー
問題箇所: auth.ts の 42行目、トークン検証がnullチェックを行っていない
修正案: `if (!token) return unauthorized();` を追加する
```

### レビュー結果を素早く判断する

複数の指摘がPRに投稿された場合でも、各指摘の冒頭に影響範囲と修正案が明示されるため、開発者はどの指摘から対応すべきかを素早く判断できます。

## 注意点

- 指摘の検出ロジック自体（何を指摘するか）が変わったわけではなく、あくまで文章表現の改善です
- 既存のプルリクエストに投稿済みの指摘文は遡って書き換えられません。新規のレビューから適用されます
