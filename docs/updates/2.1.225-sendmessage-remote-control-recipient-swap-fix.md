## 原文（日本語訳）

SendMessage: 既に確認されたリモートコントロール受取人が、そのセッション独自のリスト確認に失敗した場合に、このマシン上の同名セッションに置き換わることは決してない

## 原文（英語）

SendMessage: a Remote Control recipient you already confirmed is never swapped for a same-named session on this machine when its own list couldn't be checked

## 概要

複数マシンでセッションを実行する際に、別マシンのセッションへのメッセージ送信を確認したにもかかわらず、リモートセッションのエージェントリスト更新に失敗すると、Claude Codeが誤ってローカルマシンに存在する同じ名前のセッションに受取人を置き換えてしまう可能性がありました。この修正により、一度確認したリモート受取人が意図しないセッションに置き換わることが防止され、メッセージが正しい宛先に確実に送信されるようになります。

## 基本的な使い方

`SendMessage`ツールでメッセージを別セッションに送信する際、最初に受取人を指定するとClaudeがそのセッションを確認します。同じ名前のセッションが複数存在する場合、`/list-agents`コマンドの出力には各セッションの作業ディレクトリが表示され、または短い識別子が付与されて区別されます。リモートコントロール経由で別マシンのセッションに接続している場合、一度確認した受取人はセッションの再確認に失敗しても変更されません。

## 実践例

### 複数マシンで同じディレクトリ名のセッションが存在する場合

開発マシンとビルドサーバーで同じプロジェクト名のセッションを実行している場合を想定します。

```text
# 開発マシンの /list-agents 出力
- dev-project-1a (~/projects/dev-project)
- build-service [Remote Control]

# SendMessageで build-service に確認済みのメッセージを送信
Claude: "ビルド完了。デプロイ準備ができています"
```

この時点でローカルマシンにも `dev-project` という名前のセッションが存在していても、一度 `build-service` (リモート) への送信が確認されたら、その受取人は置き換わりません。修正前は、リモートセッションのリスト確認失敗時に誤ってローカルの `dev-project` に置き換わる可能性がありました。

### ネットワークが一時的に不安定でリモートエージェントリストが更新できない場合

ノートパソコンを別の場所に移動した際に、リモートコントロール接続が一時的に不安定になる場合があります。

```text
# 最初のメッセージ送信時に remote-session を確認
Claude: "マイグレーション完了。新しいカラムは tenant_id です"
→ SendMessage to: remote-session [確認済み]

# その直後、ネットワーク遅延でリモートセッションのリストが更新できない
# 修正前：ローカルに同名セッションがあれば誤って置き換わる可能性あり
# 修正後：remote-session への送信が確実に続行される
```

ネットワーク接続が不安定でも、一度確認した受取人情報は保持されるため、メッセージ送信に失敗することなく正しいセッションに届きます。

## 注意点

- この修正は**メッセージ配信の正確性と安全性を高める** - 誤ったセッションへのメッセージ送信が防止されます
- 複数マシンや同じディレクトリ構成を持つセッションを実行する環境で特に重要です
- **ユーザーアクションは不要** - 修正はClaude Code側で自動的に適用されます
- リモートセッションとローカルセッションが同名の場合、`/list-agents`で識別情報を確認すると区別が容易になります
- この修正は Claude Code v2.1.225 以降に適用されます
