## 原文（日本語訳）

`/claude-api cost-optimize` が追加されました。既存プロジェクトのClaude API利用コストをプロファイリングし、キャッシュ、トークンの使い方、バッチ処理、effort、モデル選択といったコストレバーを、一度に一つずつ計測しながら調整していくことができます。

## 原文（英語）

Added `/claude-api cost-optimize` to profile an existing project's Claude API spend and work through cost levers (caching, token hygiene, batch, effort, model choice) one measured change at a time

## 概要

Claude APIを使ったプロジェクトのコストを下げたいと思っても、どこに無駄があるのか、どのレバー（プロンプトキャッシュ、トークンの整理、バッチ処理、effortレベル、モデル選択など）から手をつけるべきかを判断するのは簡単ではありません。`/claude-api cost-optimize` は既存プロジェクトのAPI利用状況をプロファイリングし、効果が見込めるコストレバーを一つずつ計測しながら適用していく手順を案内してくれます。当てずっぽうの最適化ではなく、変更前後の効果を確認しながら進められる点が特徴です。

## 基本的な使い方

対象プロジェクトのディレクトリで `/claude-api cost-optimize` を実行します。

```
/claude-api cost-optimize
```

現在のAPI呼び出しパターンやコスト構造の分析結果が示され、キャッシュ導入やモデル変更など、効果が期待できる改善案を一つずつ提示・検証しながら進めていきます。

## 実践例

### プロンプトキャッシュが活用されていないケースを見つける

繰り返し送信している長いシステムプロンプトやコンテキストがキャッシュされていない場合、それを検出して `cache_control` の追加を提案し、導入前後のコスト差を計測します。

### 不要に大きいモデルを使っているタスクを特定する

単純な分類や抽出タスクに対して過剰に高性能（かつ高コスト）なモデルを使っている箇所を洗い出し、より軽量なモデルへの切り替えを検証します。

### バッチ処理に向いているワークロードを移行する

リアルタイム応答が不要な大量処理を、Batches APIに移行することでコストを抑えられるかどうかを検討し、実際の効果を計測します。

### effortレベルやトークン使用量の見直し

不必要に高いreasoning effortや冗長なプロンプト・出力によるトークン消費を洗い出し、effortレベルの調整やプロンプトの整理を提案します。

## 注意点

- 一度に複数の変更を適用するのではなく、一つずつ変更を計測しながら進める設計になっているため、効果測定には元のコスト状況を把握しておく必要があります
- 実際の利用状況（ログやAPI呼び出し履歴）にアクセスできることが前提となる場合があります
- モデル変更やキャッシュ導入は品質・レイテンシへの影響も伴うため、コストだけでなく出力品質も併せて確認することが推奨されます
