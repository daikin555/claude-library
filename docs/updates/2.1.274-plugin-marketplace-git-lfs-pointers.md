## 原文（日本語訳）
プラグインおよびマーケットプレイスのクローン処理が変更され、Git LFSファイルをダウンロードせずポインターのまま残すようになりました。チェックアウト内で `git lfs pull` を実行するとダウンロードされます。

## 原文（英語）
Changed plugin and marketplace clones to leave Git LFS files as pointers instead of downloading them; `git lfs pull` in the checkout fetches them

## 概要
Claude Codeのプラグインやマーケットプレイスのリポジトリの中には、Git LFS（Large File Storage）で管理された大きなファイルを含むものがあります。これまでのクローン処理では、これらのLFSファイルも通常通りダウンロードされていましたが、これは不要な帯域とディスク容量を消費し、クローンを遅くする原因になっていました。今回の変更により、クローン時にはLFSファイルはポインター（実体を指す軽量な参照）のまま残され、実際のダウンロードは行われなくなりました。

## 基本的な使い方
プラグインやマーケットプレイスの追加・更新は今まで通り行えます。LFSファイルの実体が必要な場合は、チェックアウトされたディレクトリで `git lfs pull` を実行します。

```bash
cd ~/.claude/plugins/<plugin-directory>
git lfs pull
```

## 実践例

### プラグインを通常通り追加する場合
LFSファイルを含むプラグインをインストールしても、クローン自体は高速化され、LFSファイルはポインターのままになります。

```bash
claude plugin install my-plugin@my-marketplace
```

### LFSファイルの実体が必要な場合
アセットファイルなど、LFS管理された実際のファイル内容が必要な場合は、該当のチェックアウトディレクトリ内で明示的に取得します。

```bash
cd ~/.claude/plugins/repos/my-marketplace/my-plugin
git lfs pull
```

## 注意点
- LFSファイルを直接参照する機能を持つプラグインの場合、ポインターのままではファイル内容が正しく読み込めない可能性があるため、事前に `git lfs pull` が必要です。
- `git-lfs` コマンドがローカル環境にインストールされている必要があります。
- この変更はクローン時の挙動に関するものであり、マーケットプレイスやプラグイン自体の機能には影響しません。
