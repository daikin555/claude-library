## 原文（日本語に翻訳）

managed settingsの読み込みに失敗した際、Cloud gatewayの`/login`が「Press Enter to continue」の後にサイレント終了するか、無応答なターミナルを残していた問題を修正しました。現在は原因が表示されるようになりました。

## 原文（英語）

Fixed Cloud gateway `/login` exiting silently or leaving an unresponsive terminal after "Press Enter to continue" when managed settings failed to load; the reason is now shown

## 概要

Enterprise環境などでCloud gateway経由のログインを利用する場合、組織が配布するmanaged settings（管理者設定）の読み込みに失敗すると、以前は`/login`コマンドが「Press Enter to continue」というメッセージの後、何のエラーも出さずに終了するか、ターミナルが応答しなくなるという問題がありました。原因がまったく表示されないため、利用者にとってはログインできない理由が分からず対処が困難でした。本アップデートにより、managed settingsの読み込みに失敗した場合はその理由が画面に明示されるようになりました。

## 基本的な使い方

Cloud gateway経由でログインする際の通常フローは以下の通りです。managed settingsの読み込みに問題があった場合、修正後は失敗理由がターミナルに表示されます。

```bash
claude /login
# ブラウザでの認証フローを実施
# "Press Enter to continue" と表示された後...

# 修正前: managed settingsの読み込みに失敗すると
#   → 何も表示されず終了、またはターミナルが無応答になる

# 修正後: managed settingsの読み込みに失敗すると
#   → 例: "Failed to load managed settings: <理由>" のように
#     具体的な失敗理由が表示される
```

## 実践例

### 社内ネットワークからmanaged settingsの配布元に到達できない場合

Enterprise環境では、`managed-settings.json`が社内のMDMや構成管理システム経由で配布されることがあります。VPN未接続やネットワーク障害などでこの配布元に到達できない場合、以前は`/login`が原因不明のまま停止していました。修正後は「managed settingsを読み込めなかった」ことと、可能であればその具体的な理由（ネットワークエラー、パーミッションエラーなど）が表示されるため、管理者への問い合わせや自身での切り分けがしやすくなります。

```bash
claude /login
# → managed settingsの読み込みに失敗した理由が表示される
# 例: ネットワーク未接続、設定ファイルの構文エラーなど
```

### CI/CDや自動化スクリプトからログインを実行している場合

自動化パイプラインの中で`claude /login`相当の処理を実行している場合、以前はサイレントに失敗したりターミナルが無応答になったりすると、パイプラインがハングしたりタイムアウトするまで原因が分からず、デバッグに時間がかかっていました。修正後はエラー理由がログに出力されるため、パイプラインのログを見るだけで原因を特定できます。

```bash
claude /login 2>&1 | tee login.log
# managed settingsの問題があれば login.log に理由が記録される
```

## 注意点

- Claude Code v2.1.232での修正です。
- 本修正はエラーメッセージの可視化が中心であり、managed settings自体の配布・設定不備は別途管理者側での対応が必要です。
- Cloud gatewayを利用したログインはEnterprise/Team環境での構成が前提です。個人利用のプランでは通常関係しません。
