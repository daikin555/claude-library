## 原文（日本語訳）

`/rename` を実行すると、テーマのプロンプト枠色（カスタムテーマの `promptBorder` を含む）がデフォルトのシアン色に置き換えられてしまう不具合を修正しました。枠色は `/color` で明示的に選択しない限り、テーマの色を保持するようになりました。

## 原文（英語）

Fixed `/rename` replacing the theme's prompt border color (including a custom theme's `promptBorder`) with the default cyan; the border now keeps your theme's color unless you pick one with `/color`

## 概要

Claude Codeでは会話やセッションを `/rename` でリネームできますが、これまではこのコマンドを実行すると、意図せずプロンプトの枠色がデフォルトのシアン色にリセットされてしまう不具合がありました。カスタムテーマで `promptBorder` を独自の色に設定していたユーザーにとっては、リネームするたびに見た目が変わってしまうという煩わしい問題でした。今回の修正で、`/rename` を実行してもプロンプト枠色はテーマ本来の色を維持し、`/color` で明示的に色を選んだ場合のみ変更されるようになりました。

## 基本的な使い方

通常通り `/rename` でセッション名を変更しても、プロンプトの枠色は変わりません。

```
/rename my-feature-branch
```

修正前はこのコマンド実行後に枠色がシアンに変わってしまいましたが、修正後は現在のテーマ（カスタムテーマを含む）の `promptBorder` の色がそのまま保持されます。

## 実践例

### カスタムテーマを使っているユーザーの見た目維持

独自のカラーパレットでカスタムテーマを作成し、`promptBorder` を特定の色に設定している場合、`/rename` を何度実行しても枠色が意図せず変わることがなくなります。

### セッション管理を頻繁に行うワークフロー

複数のタスクごとにセッションをリネームして整理する運用をしている場合、リネームのたびに見た目がリセットされる煩わしさがなくなります。

### `/color` で明示的に枠色を変更するケース

ユーザーが `/color` コマンドで意図的に別の枠色を選んだ場合は、その選択が正しく反映されます。`/rename` によって上書きされることはありません。

```
/color
```

## 注意点

- この修正はプロンプトの枠色（`promptBorder`）に関するものであり、他のUI要素の色には影響しません
- `/color` で明示的に色を選択した場合はその設定が優先されます。テーマのデフォルト色に戻したい場合は、テーマの再選択や設定のリセットが必要です
