## 原文（日本語訳）
ホスト型セッションの挙動を変更：コンテナの再起動後、未回答の権限プロンプトを再度表示するのではなく、そのまま表示し続けるようにしました

## 原文（英語）
Changed hosted sessions to keep an unanswered permission prompt up after a container restart, instead of asking again

## 概要
ホスト型（クラウド上のコンテナで実行される）セッションでは、コンテナが再起動されるタイミングがあります。これまでは、権限プロンプトに未回答のまま再起動が発生すると、そのプロンプトが失われて改めて同じ確認が表示されることがありました。今回の変更により、未回答の権限プロンプトはコンテナ再起動をまたいで維持されるようになり、ユーザーは同じ確認を繰り返し求められることなく、元のプロンプトに回答を続けられます。

## 基本的な使い方
ユーザー側の操作は変わりません。ホスト型セッションで権限プロンプトが表示された状態でコンテナが再起動されても、そのプロンプトはそのまま維持されます。

```
# ホスト型セッションで危険なコマンド実行の許可を求められている最中に
# コンテナが再起動された場合
# → 以前: プロンプトが消え、再度確認される
# → 今後: 同じプロンプトが維持され、再確認は不要
```

## 実践例

### 長時間実行中のホスト型セッションでの権限確認
```
# ホスト型セッションで「このファイルを削除してよいですか？」という
# 権限プロンプトが表示されたまま、インフラ側でコンテナが再起動された
# → プロンプトはそのまま維持され、ユーザーが戻ってきたときに
#   同じ確認に回答できる
```

### 一時的な接続断からの復帰
```
# ネットワークの問題でホスト型セッションへの接続が一時的に切れ、
# 再接続時にコンテナが再起動されていた
# → 未回答だった権限プロンプトが消えずに残っているため、
#   作業を中断した箇所からスムーズに再開できる
```

## 注意点
- この変更はホスト型（クラウド実行）セッションに関するものです。ローカル実行のセッションには直接関係しません。
- プロンプトの内容自体や、承認・拒否の判断基準が変わるわけではありません。
- コンテナの状態管理に依存するため、極端に長い再起動やインフラ側の障害では挙動が異なる場合があります。
