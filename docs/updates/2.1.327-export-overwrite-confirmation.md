# /export が既存ファイルを無断で上書きしないように修正

## 原文（日本語に翻訳）

`/export` が確認なしに既存のファイルを上書きする問題を修正しました。ダイアログで確認するようになり、`/export <name>` は既存ファイルを残したうえで `/export` の実行を促します。

## 原文（英語）

Fixed `/export` overwriting an existing file without asking: the dialog now asks, and `/export <name>` keeps the file and says to run `/export`

## 概要

会話のエクスポート先に同名ファイルがあっても、以前は黙って上書きされていました。今回の修正で、上書き前に確認が入ります。

## 基本的な使い方

```text
/export
```

ダイアログで保存先を指定し、既存ファイルがある場合は上書きの可否を選びます。

## 実践例

### ファイル名を指定した場合

```text
/export session-notes.md
```

`session-notes.md` が既にあると、ファイルは変更されず、`/export`（ダイアログ版）を実行するよう案内されます。

### 別名で保存して履歴を残す

`/export notes-2026-11-18.md` のように日付入りの名前にすれば衝突しません。

## 注意点

- スクリプト的に `/export <name>` で上書きし続ける運用はできなくなります。
- 重要なエクスポートはバージョン管理下に置くと安全です。
