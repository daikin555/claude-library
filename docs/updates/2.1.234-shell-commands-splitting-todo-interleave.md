## 原文（日本語訳）

連続したシェルコマンドの間にtodo/タスクの更新が挟まると、「Ran 1 shell command」という表示行が複数に分裂してしまう問題を修正しました。

## 原文（英語）

Fixed consecutive shell commands splitting into multiple "Ran 1 shell command" rows when todo/task updates were interleaved between them

## 概要

Claudeが複数のシェルコマンドを連続して実行する際、通常はまとめて「Ran N shell commands」のように集約表示されます。しかし、その間にTodoWriteによるタスクリストの更新や、サブタスクの更新が挟まると、集約が途切れて「Ran 1 shell command」という行がコマンドごとにバラバラに表示されてしまう不具合がありました。今回の修正により、間にtodo/タスク更新が挟まっても、連続するシェルコマンドの表示が正しく集約されるようになりました。

## 基本的な使い方

特別な操作は不要です。Claudeが複数のコマンドを実行しながらタスク管理（TodoWrite）を並行して更新するような場面で、表示がより見やすく整理されます。

## 実践例

### タスクリストを更新しながら複数コマンドを実行する場面

Claudeがビルド・テスト・リント等を順に実行しつつ、進捗をtodoリストに反映していくようなワークフローで効果が分かりやすくなっています。

```
[Claude]
1. npm run lint を実行
2. todoリストを更新（lint完了）
3. npm run test を実行
4. todoリストを更新（test完了）
5. npm run build を実行
```

修正前: 「Ran 1 shell command」が3回バラバラに表示され、todo更新のたびに表示が分断される
修正後: todo更新を挟んでいても関連するシェルコマンド群がまとまって表示され、UIがすっきりする

### 長い自律実行タスクでのログ視認性向上

多数のコマンドとタスク更新が交互に発生する長時間の自律実行（例: リファクタリングやマイグレーション作業）でも、コマンド実行ログが読みやすい単位でグルーピングされます。

## 注意点

- 表示上の集約ロジックの修正であり、実際のコマンド実行結果やタスク管理の挙動自体に変更はありません
- 集約される範囲はUIの表示仕様に依存するため、今後のバージョンで挙動が調整される可能性があります
