## 原文（日本語に翻訳）

ヘッドレスモードのstream-json形式におけるinitイベントに `mcp_server_errors` フィールドを追加しました。これは `--mcp-config` で指定されたエントリのうち、設定バリデーションによってスキップされたものを一覧表示します。ターミナルで通常実行した場合には、起動時に警告メッセージが表示されます。

## 原文（英語）

Added `mcp_server_errors` to the headless stream-json init event, listing `--mcp-config` entries skipped by config validation; terminal runs print a startup warning

## 概要

`claude -p --output-format stream-json` によるヘッドレス実行では、セッション開始時に `init` イベントがJSON Linesとして出力されます。今回のアップデートにより、この `init` イベントに `mcp_server_errors` フィールドが追加され、`--mcp-config` で指定したMCPサーバー設定のうちバリデーションに失敗してスキップされたエントリを、プログラムから直接検知できるようになりました。CIパイプラインや自動化スクリプトでMCP設定ミスを見逃さずに検知したい場合に特に有用です。

## 基本的な使い方

```bash
claude -p "MCPサーバーの状態を確認して" \
  --mcp-config ./mcp-config.json \
  --output-format stream-json
```

出力される `init` イベントの例（一部抜粋）:

```json
{
  "type": "system",
  "subtype": "init",
  "session_id": "b3f1c2e4-1234-4a9b-9c3d-0a1b2c3d4e5f",
  "cwd": "/home/runner/work/my-project",
  "model": "claude-sonnet-5",
  "permissionMode": "default",
  "mcp_servers": [
    { "name": "filesystem", "status": "connected" }
  ],
  "mcp_server_errors": [
    {
      "name": "broken-server",
      "reason": "invalid_command",
      "message": "Config entry 'broken-server' skipped: 'command' field is missing"
    }
  ],
  "tools": ["Bash", "Read", "Edit", "..."]
}
```

`mcp_server_errors` が空配列であれば、指定した `--mcp-config` のすべてのエントリが正常にロードされたことを意味します。

## 実践例

### CIパイプラインでMCP設定ミスを検知する

`jq` で `mcp_server_errors` の有無をチェックし、空でなければパイプラインを失敗させます。

```bash
claude -p "デプロイ前チェックを実行" \
  --mcp-config ./mcp-config.ci.json \
  --output-format stream-json > session.jsonl

INIT_LINE=$(head -n1 session.jsonl)
ERRORS=$(echo "$INIT_LINE" | jq '.mcp_server_errors')

if [ "$(echo "$ERRORS" | jq 'length')" -gt 0 ]; then
  echo "MCPサーバー設定にエラーがあります:"
  echo "$ERRORS" | jq -r '.[] | "- \(.name): \(.message)"'
  exit 1
fi
```

### 複数MCP設定ファイルを結合した際の検証

複数の `--mcp-config` ファイルを併用するチームで、どのエントリが実際に読み込まれたかを監視スクリプトで比較する例です。

```bash
claude -p "セットアップ確認" \
  --mcp-config ./team-mcp.json \
  --mcp-config ./local-mcp.json \
  --output-format stream-json | \
  jq -c 'select(.subtype == "init") | {loaded: .mcp_servers, skipped: .mcp_server_errors}'
```

```json
{
  "loaded": [
    { "name": "filesystem", "status": "connected" },
    { "name": "github", "status": "connected" }
  ],
  "skipped": [
    {
      "name": "local-db",
      "reason": "duplicate_name",
      "message": "Config entry 'local-db' skipped: name conflicts with an already-loaded server"
    }
  ]
}
```

### 通常のターミナル実行での警告確認

ヘッドレスでなく通常の対話モードで実行した場合も、同様のバリデーションが働き、起動時にターミナルへ警告が出力されます。

```bash
claude --mcp-config ./mcp-config.json
```

```
Warning: 1 MCP server config entry was skipped due to validation errors.
  - broken-server: 'command' field is missing
```

## 注意点

- `mcp_server_errors` は `init` イベント（stream-jsonの最初のイベント）にのみ含まれます。セッション途中で動的に追加されたMCPサーバーのエラーはここには反映されません。
- このフィールドはあくまで「設定バリデーション時点でスキップされたエントリ」を対象としており、接続後にランタイムでMCPサーバーがクラッシュした場合のエラーは別途 `mcp_servers` の `status` フィールドなどで確認する必要があります。
- ターミナルでの警告表示はデフォルトの動作であり、`--output-format text` などでも同様に起動時警告が表示されます。警告を抑制するオプションは現時点では提供されていないため、CIで出力をパースする場合は標準エラー出力と標準出力を混在させないよう注意してください。
