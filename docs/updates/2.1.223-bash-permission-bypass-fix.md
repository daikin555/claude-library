## 原文（日本語に翻訳）

巧妙に細工されたコマンドがコマンドの一部を権限チェックから隠すことができてしまうBash権限バイパスを修正しました。

## 原文（英語）

Fixed a Bash permission bypass where a crafted command could hide parts of itself from permission checks

## 概要

Claude Codeは、Bashツールでコマンドを実行する前に、そのコマンド文字列を解析して許可（allow）・確認（ask）・拒否（deny）ルールと照合し、必要に応じてユーザーに承認を求めます。今回修正された問題は、コマンド文字列の書き方を工夫することで、実際に実行される内容の一部を権限チェックのロジックから見えないようにできてしまうというものでした。結果として、本来であれば確認プロンプトが表示されるべき危険な操作が、ユーザーの承認なしに実行されてしまう可能性がありました。v2.1.223ではコマンド解析ロジックが強化され、こうした細工によるすり抜けが防止されています。

## 基本的な使い方

この修正はClaude Code本体の内部ロジックに対するものであり、ユーザー側で特別な操作を行う必要はありません。アップデート後は、通常どおりBashコマンドを実行するだけで、より正確な権限チェックの恩恵を受けられます。

```bash
# Claude Codeを最新バージョンに更新
claude update

# バージョンを確認
claude --version
```

権限ルールの設定自体は従来どおり `settings.json` の `permissions` セクションで行います。

```json
{
  "permissions": {
    "ask": ["Bash(rm:*)", "Bash(curl:*)"],
    "deny": ["Bash(sudo:*)"]
  }
}
```

## 実践例

### アップデート後に権限ルールが期待どおり機能するか確認する

`ask` に設定しているコマンドを実行し、確認プロンプトがきちんと表示されることを確認します。

```bash
# ask ルールに設定したコマンドを含む操作をClaudeに依頼する
claude -p "一時ファイルを削除して"
# → rm を含むコマンドの提案時に、権限プロンプトが表示されることを確認する
```

### 組織のガバナンス設定を運用している場合の再確認

チームやOrganizationレベルで `deny` / `ask` ルールを管理設定（managed settings）として配布している場合、更新後にルールが引き続き有効であるかを確認します。

```bash
# 管理設定ファイルの内容を確認
cat /Library/Application\ Support/ClaudeCode/managed-settings.json 2>/dev/null \
  || cat /etc/claude-code/managed-settings.json 2>/dev/null
```

### CI/CDなど自動実行環境でのバージョン固定

自動化環境ではセキュリティ修正を確実に取り込むため、最新パッチバージョンを明示的に指定してインストールすることを推奨します。

```bash
npm install -g @anthropic-ai/claude-code@2.1.223
claude --version
```

## 注意点

- 本修正はセキュリティ上重要な変更のため、v2.1.223以降への速やかなアップデートを推奨します。
- 悪用の具体的な手口（どのような文字列細工がバイパスを引き起こしていたか）はchangelogに明記されておらず、本記事でも詳細な再現手順は扱いません。
- `--dangerously-skip-permissions` を使用している場合、そもそも権限チェック自体がスキップされるため、この修正の影響を受けません。信頼できる環境以外での使用は避けてください。
- 権限ルールを厳格に運用している場合でも、生成AIが提案するコマンドは実行前に内容を確認する習慣を持つことが推奨されます。
