## 原文（日本語訳）
セルフホストランナーが、アクセスチェックの際にGitホストが拒否した読み取り専用リポジトリをスキップし、セッション開始自体を失敗させないように変更されました。

## 原文（英語）
Changed self-hosted runners to skip a read-only repository the git host refuses at the access check instead of failing the session start

## 概要
Claude Codeをセルフホストランナー環境（CI/CDなど）で使用する場合、セッション開始時に関連リポジトリへのアクセス権をチェックします。これまでは、Gitホスト側が読み取り専用リポジトリへのアクセスを拒否すると、セッション開始自体が失敗していました。今回の変更により、そのようなリポジトリはスキップされるだけになり、セッション自体は正常に開始できるようになりました。CI環境で複数リポジトリを扱う際の堅牢性が向上します。

## 基本的な使い方
セルフホストランナーの設定自体に変更は不要です。通常通りセッションを開始すれば、アクセスできないリポジトリは自動的にスキップされます。

```yaml
# セルフホストランナーのワークフロー設定例（概念図）
runner: self-hosted
repositories:
  - org/readable-repo
  - org/restricted-repo  # アクセス拒否されてもスキップされる
```

## 実践例

### 変更前の挙動
セルフホストランナーが複数のリポジトリにアクセスしようとした際、そのうち1つが読み取り専用でGitホスト側からアクセスを拒否されると、セッション全体の開始が失敗していました。

### 変更後の挙動
同じ状況でも、アクセスが拒否されたリポジトリだけがスキップされ、他のリポジトリへのアクセスが可能であればセッションは正常に開始されます。

## 注意点
- スキップされたリポジトリの内容はセッション内で利用できないため、そのリポジトリの情報が必要なタスクでは別途アクセス権の確認が必要です。
- この変更はGitホスト側のアクセスチェックで明示的に拒否されたケースに関するものです。
