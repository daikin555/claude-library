## 原文（日本語訳）

メッセージの先頭500文字にMarkdown記法が含まれていない場合にメッセージ全体でMarkdownレンダリングが無効化されてしまう不具合、および `+` 記法や `N)` 形式のリスト、setext形式の見出しでレンダリングが無効化されてしまう不具合を修正しました。

## 原文（英語）

Fixed markdown rendering being disabled for a whole message when its first 500 characters contained no markdown, and for `+`/`N)` lists and setext headings

## 概要

Claude Codeはメッセージ内容がMarkdownかどうかを判定してレンダリング（見出しや強調、リストなどの整形表示）を行いますが、この判定処理に2つの問題がありました。1つ目は、メッセージの先頭500文字だけを見てMarkdown記法の有無を判定していたため、Markdown記法がメッセージの後半にしか出てこない場合、メッセージ全体のレンダリングが無効化されてしまう問題です。2つ目は、`+` を使ったリストや `1)` のような番号付きリスト、underlineで見出しを表すsetext形式（`見出し\n===`）が、そもそもMarkdown記法として認識されず、レンダリングが無効化されてしまう問題です。今回のアップデートで両方が修正され、これらの記法も正しくMarkdownとして認識・整形表示されるようになりました。

## 基本的な使い方

特別な操作は不要です。Claude Codeからの出力に該当する記法が含まれていれば、修正後は自動的にMarkdownとして整形表示されます。

```
+ 項目A
+ 項目B
+ 項目C

1) 最初の手順
2) 次の手順
```

修正後は、これらの記法も箇条書きとして正しく描画されます。

## 実践例

### 長い説明文の後半に箇条書きが出てくる場合

冒頭の500文字が長文の説明文で、箇条書きや強調表現がその後に初めて出てくるような出力でも、修正後はメッセージ全体が正しくMarkdownとしてレンダリングされます。

### `+` 記法でリストを書くスタイルを好む場合

`-` や `*` ではなく `+` を使ってリストを書く出力に対しても、修正後は箇条書きとして正しく整形表示されます。

### `N)` 形式の番号付きリストやsetext見出しを含む出力の場合

`1)` `2)` のようなカッコ付き番号のリストや、`見出し` の下に `===` や `---` を引くsetext形式の見出しを含む出力でも、正しく見出しやリストとして認識され表示されます。

## 注意点

- この修正は表示上のレンダリング判定に関するものであり、実際のメッセージ内容そのものが変わるわけではありません
- Markdownとして認識されるかどうかの判定基準が変わったため、以前はプレーンテキスト表示だった出力が、修正後はMarkdownとして整形表示されるようになる場合があります
- 意図的にプレーンテキストとして表示したい場合、記法が誤って解釈されないよう出力内容に注意が必要です
