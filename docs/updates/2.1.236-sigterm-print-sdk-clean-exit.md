## 原文（日本語訳）

print/SDKモードでのSIGTERMは、終了前に中断されたターンや擬似的なツール拒否を記録しなくなりました。実行中のコマンドは引き続き終了され、プロセスも引き続き終了コード143で終了します。

## 原文（英語）

SIGTERM in print/SDK mode no longer records an interrupted turn or synthetic tool denials before exiting; running commands are still terminated and the process still exits with code 143

## 概要

`claude --print` やClaude Agent SDK経由でClaude Codeを実行している際、外部からSIGTERMを送って処理を止めることがあります。これまでは、SIGTERMを受け取ると終了前に「ターンが中断された」という記録や、実行中だったツール呼び出しに対する擬似的な拒否（synthetic tool denial）がセッション履歴に書き込まれていました。今回の修正により、これらの余計な記録が残らなくなり、実行中のコマンドの終了処理や、終了コード143でプロセスが終了するという基本的な挙動はそのまま維持されます。これにより、SIGTERMによる終了がセッション履歴やログをより汚さない、クリーンな形になりました。

## 基本的な使い方

特別な操作は不要です。printモードやSDK経由でClaude Codeを実行しているプロセスに対してSIGTERMを送ると、実行中のコマンドは終了され、プロセス自体も終了コード143で終了しますが、以前のように中断ターンや擬似的なツール拒否が記録として残ることはなくなります。

```bash
claude --print "長時間かかるタスクを実行して" &
PID=$!
sleep 5
kill -TERM $PID
echo $?  # 143
```

## 実践例

### SDK統合からセッションを安全に停止する

Claude Agent SDKを使ってバックグラウンドでエージェントを動かしているアプリケーションが、タイムアウトやユーザーのキャンセル操作をきっかけにセッションを止めたい場合、対象プロセスにSIGTERMを送ります。以前は、この終了によって不要な「中断ターン」や「擬似的なツール拒否」がセッション履歴に混入し、後からログを解析する際にノイズとなっていましたが、今回の修正でその心配がなくなりました。

```python
import subprocess
import signal

proc = subprocess.Popen(["claude", "-p", "長時間タスクを実行"])
# タイムアウトなどでキャンセルしたい場合
proc.send_signal(signal.SIGTERM)
proc.wait()
assert proc.returncode == 143
```

### CI/CDパイプラインでのタイムアウト処理

CIジョブの中でClaude Codeをprintモードで呼び出し、一定時間内に終わらない場合はジョブランナーがSIGTERMでプロセスを止めるケースがあります。この際、実行中のシェルコマンドはこれまでどおり確実に終了され、プロセスも終了コード143で終わるため、CIのタイムアウト検知ロジックには影響がありません。一方で、セッションログに不要な中断記録が残らなくなるため、後からログを監査する際の見通しがよくなります。

### ログ・監視システムとの連携

セッションのトランスクリプトを収集して分析している監視基盤がある場合、SIGTERMによる終了が「実際のツール拒否」と誤って記録されなくなったことで、拒否イベントの集計や異常検知の精度が向上します。

## 注意点

- 終了コードは引き続き143（128 + SIGTERMのシグナル番号15）です
- 実行中のBashコマンドなどはこれまでどおり確実に終了されます
- この変更はprint/SDKモードに関するものであり、通常の対話型セッションでのCtrl+Cによる中断とは挙動が異なる場合があります
