## 原文（日本語訳）

複数行のプロンプトをクリアした後にプロンプトの上に空白の帯が残ってしまう問題と、フルスクリーンモードでターミナルを一旦別サイズにリサイズしてから元に戻した際にペインが再描画されない問題を修正しました。

## 原文（英語）

Fixed a blank band that could remain above the prompt after clearing a multi-line prompt, and panes not repainting after resizing the terminal away and back, in fullscreen mode

## 概要

Claude Codeのフルスクリーン表示モードには、2つの描画に関する不具合がありました。1つ目は、複数行にわたって入力したプロンプトをクリア（消去）した際に、プロンプトの上部に空白の帯（何も表示されない領域）が残ってしまう問題です。2つ目は、ターミナルのサイズを一旦変更してから元のサイズに戻した場合に、フルスクリーンモード内の各ペイン（表示領域）が正しく再描画されず、古い表示が残ったままになってしまう問題です。今回の修正で、いずれのケースでも画面が正しく再描画されるようになりました。

## 基本的な使い方

特別な操作は不要です。複数行のプロンプトを入力してクリアしたり、ターミナルサイズを変更したりしても、これまでのように不要な空白や古い表示が画面に残ることがなくなりました。

```bash
claude
# フルスクリーンモードで複数行のプロンプトを入力後、Ctrl+CやEscなどでクリア
# 修正前: プロンプト上部に空白の帯が残ることがあった
# 修正後: クリア後の表示が正しく整う

# ターミナルウィンドウを一旦小さく（または大きく）してから元のサイズに戻す
# 修正前: ペインが再描画されず古い表示が残ることがあった
# 修正後: 元のサイズに戻すと正しく再描画される
```

## 実践例

### 長い複数行プロンプトを書いてからキャンセルする場合

複数行にわたる長い指示文を入力した後、送信をやめて入力内容をクリアするようなケースで、以前はプロンプトの上に不要な空白の帯が残り、画面がやや乱れて見えることがありました。修正後はクリア操作後の表示がきれいに整います。

### ウィンドウの最小化・復元やモニター切り替え時

ターミナルウィンドウを一時的に最小化してサイズが変わった状態から元の大きさに戻したり、外部モニターへの接続・切断でウィンドウサイズが一時的に変化したりした場合、以前はフルスクリーンモード内のペインが古い内容のまま再描画されないことがありました。修正後はサイズが元に戻った際に正しく再描画されます。

## 注意点

- どちらも表示上の不具合であり、Claudeとのやり取りの内容そのものには影響していませんでしたが、画面が乱れることで作業状況を把握しづらくなる問題でした。
- 手動で画面をクリアしたり再描画を強制したりする必要はなくなりました。
