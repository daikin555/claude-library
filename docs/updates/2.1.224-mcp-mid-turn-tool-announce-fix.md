## 原文（日本語訳）

ターンの途中で接続されたMCPツールが、モデルに名前が通知されないままツール検索（ツールサーチ）用に保留（deferred）されてしまう問題を修正しました。

## 原文（英語）

Fixed MCP tools that connect mid-turn being deferred for tool search without their names announced to the model

## 概要

Claude CodeはMCPツールをコンテキスト消費を抑えるために「deferred（保留）」状態で扱い、必要になった時点で `ToolSearch` を通じてスキーマを取得する仕組みを採用しています。この仕組みでは、通常セッション開始時にdeferredなツール名の一覧がモデルに案内されます。しかし、MCPサーバーがセッションの最初ではなく会話の途中（ターンの途中）で接続された場合、そのMCPツールはdeferred扱いにはなるものの、ツール名がモデルに案内されないままになってしまう不具合がありました。その結果、Claudeはツールの存在自体を知らず、`ToolSearch` で見つけることもできませんでした。この修正により、ターン途中で接続されたMCPツールについても、名前がきちんとモデルに通知されるようになりました。

## 基本的な使い方

MCPサーバーの接続方法自体に変更はありません。セッション中に新しいMCPサーバーが接続されると、そのツールが利用可能になります。

```bash
claude
# セッション中に新しいMCPサーバーが接続された場合、
# そのサーバーが提供するツール名がClaudeに通知される
```

Claudeは通知されたツール名をもとに `ToolSearch` を呼び出し、必要なツールのスキーマを取得して使用できます。

## 実践例

### セッション途中でMCPサーバーが遅延起動するケース

起動に時間がかかるMCPサーバー（例: 大規模なデータベース接続やクラウドサービス連携）が、セッション開始直後ではなくやや遅れて接続完了するケースです。

```text
# 修正前:
# セッション開始時に案内されたdeferredツール一覧には
# まだ接続されていないMCPサーバーのツールが含まれておらず、
# 後から接続が完了しても名前が案内されないため、
# ClaudeはToolSearchでそのツールを見つけることができなかった
# → ユーザーが「〇〇のツールを使って」と依頼しても
#   Claudeがツールの存在に気づけない

# 修正後:
# 接続完了時にツール名がモデルに通知されるため、
# Claudeはその場でToolSearchを使って
# 該当ツールのスキーマを取得し、利用できる
```

### ユーザーが会話中に新しいMCPサーバーを手動で追加する場合

会話の途中で `/mcp` コマンドや設定変更によって新しいMCPサーバーを追加した場合の挙動が改善されます。

```bash
# セッション中に新しいMCPサーバーを追加
/mcp add my-custom-server

# 修正前: サーバーが接続されても、
# ツール名がモデルに案内されないままdeferred状態になり、
# Claudeが認識できないことがあった

# 修正後: 接続完了とともにツール名が案内され、
# 続けて依頼したタスクの中でそのまま利用できる
```

### 動的にMCPサーバーが増減する自動化ワークフロー

オーケストレーションツールなどがタスクに応じて動的にMCPサーバーを起動・接続するようなワークフローでは、ターン途中での接続が頻繁に発生します。この修正により、こうしたワークフローでも新しく接続されたツールが確実にClaudeへ認識されるようになり、ツールが見えないことによるタスク失敗が減ります。

## 注意点

- この修正はMCPツールのツール検索（tool search）機能が有効な場合に関係します
- ツール名が通知されるタイミングは接続完了時点であり、接続に時間がかかるMCPサーバーの場合は引き続き接続完了まで待つ必要があります
- `ENABLE_TOOL_SEARCH=auto` などツール検索の挙動を変更する設定を利用している場合も、通知の仕組み自体はこの修正の対象です
