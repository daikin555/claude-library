## 原文（日本語訳）
- ターミナルでMCPタスクのサポートを追加：MCPサーバーがツール呼び出しをタスクとして実行する場合、Claude Codeは直ちにそれをバックグラウンドに移し、完了時に結果をClaudeに伝えます。
- 環境変数 `CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND` を追加：MCPタスクを直ちにバックグラウンドへ移さず、ツール呼び出しの中で待機させます。
- 変更：MCPタスクは、フィーチャーフラグ取得なしでもターミナルで動作します（Bedrock、Vertex、Foundry、LLMゲートウェイ、`DISABLE_TELEMETRY`）。無効化するには `CLAUDE_CODE_DISABLE_MCP_TASKS=1` を設定します。

## 原文（英語）
- Added support for MCP tasks in the terminal: when an MCP server runs a tool call as a task, Claude Code moves it to the background right away and tells Claude the result when it finishes
- Added the `CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND` environment variable to make Claude Code wait for an MCP task inside its tool call instead of moving it to the background right away
- Changed MCP tasks to work in the terminal without feature-flag fetching (Bedrock, Vertex, Foundry, LLM gateways, `DISABLE_TELEMETRY`); set `CLAUDE_CODE_DISABLE_MCP_TASKS=1` to turn them off

## 概要
長時間かかるMCPツール呼び出しがタスクとして実行される場合、Claude Codeが自動でバックグラウンドへ移し、Claudeは待たずに作業を続けられます。完了すると結果がClaudeに通知されます。

## 基本的な使い方
MCPサーバーがタスク実行に対応していれば、特別な設定なしで動作します。挙動を変えたい場合は環境変数を使います。

```bash
# ツール呼び出し内で完了まで待つ
export CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND=1

# MCPタスク機能自体を無効化
export CLAUDE_CODE_DISABLE_MCP_TASKS=1
```

## 実践例

### 重いビルドやデータ処理を並行して進める
バックグラウンド化により、その間にClaudeが他のファイル編集などを進められます。

### 結果が必要な後続処理がある場合
次の手順が結果に依存するなら、`CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND=1` で待機させると流れが単純になります。

## 注意点
- サーバー側がタスク実行に対応している場合のみ有効です。
- Bedrock、Vertex、Foundry、LLMゲートウェイ、`DISABLE_TELEMETRY` 環境でも使えるようになりました。
