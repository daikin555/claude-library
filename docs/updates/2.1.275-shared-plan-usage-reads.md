## 原文（日本語訳）
プランの使用状況の読み取りを改善：同一マシン上のエディタウィンドウと非対話セッションが、それぞれ個別に使用状況エンドポイントを呼び出す代わりに、直近1分以内に行われた読み取り結果を共有するようになりました

## 原文（英語）
Improved plan-usage reads: editor windows and non-interactive sessions on one machine now share a read made in the last minute instead of each calling the usage endpoint

## 概要
Claude Code は、契約プランの使用量（利用上限や残量など）を確認するために内部的に使用状況エンドポイントへ問い合わせます。複数のエディタウィンドウや非対話（ヘッドレス）セッションを同時に開いていると、それぞれが個別に問い合わせを行い、無駄な通信が発生していました。今回の改善で、同一マシン上のセッション間で直近1分以内の読み取り結果をキャッシュ的に共有するようになり、無駄なAPI呼び出しが減ります。

## 基本的な使い方
ユーザー側で行う操作はありません。バックグラウンドで自動的に最適化されます。

```
# 例: 同じマシンで複数のVS Codeウィンドウ・複数のターミナルセッションを開いていても、
# プラン使用状況の問い合わせは1分間に1回程度に集約される
```

## 実践例

### 複数エディタウィンドウを並行して使う場合
```
# VS Codeを2つのプロジェクトで開き、それぞれでClaude Codeを使用
# → 以前は各ウィンドウが個別に使用状況を取得していたが、
#   直近1分の結果が共有されるため呼び出し回数が減る
```

### CI等での非対話セッションと通常セッションの併用
```
claude -p "テストを実行して結果を要約して"
# 同時に対話型セッションも起動している場合でも、
# 使用状況の問い合わせが重複しにくくなる
```

## 注意点
- この変更は内部的な最適化であり、表示される使用状況の値そのものが不正確になることはありません（最大で1分程度の遅延が生じる可能性があります）。
- ユーザーが設定変更を行う必要はありません。
- 複数マシンをまたいだセッション間では共有されません。
