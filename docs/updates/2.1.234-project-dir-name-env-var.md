## 原文（日本語訳）

オプションの環境変数 `CLAUDE_CODE_PROJECT_DIR_NAME` を追加しました。セッションごとに独自の設定ディレクトリを割り当てるホスト環境では、プロジェクトごとのトランスクリプト保存ディレクトリに短い名前を指定できるようになります。

## 原文（英語）

Added the optional `CLAUDE_CODE_PROJECT_DIR_NAME` environment variable: hosts that give each session its own config directory can choose a short name for the per-project transcript directory

## 概要

Claude Codeはセッションのトランスクリプト（会話履歴）を、通常はプロジェクトの絶対パスから生成された長いディレクトリ名で `~/.claude/projects/` 配下に保存します。CI環境やマルチテナントホスティング環境など、セッションごとに独自の設定ディレクトリ（`CLAUDE_CONFIG_DIR` など）を割り当てる仕組みを持つホストでは、このディレクトリ名が扱いにくいことがありました。`CLAUDE_CODE_PROJECT_DIR_NAME` を設定すると、そのプロジェクト用トランスクリプトディレクトリの名前を任意の短い文字列で明示的に指定できます。

## 基本的な使い方

環境変数にディレクトリ名を設定してからClaude Codeを起動します。

```bash
export CLAUDE_CODE_PROJECT_DIR_NAME="my-service"
claude
```

これにより、そのセッションのトランスクリプトは自動生成された長いパス名ではなく、`my-service` という短い名前のディレクトリ配下に保存されます。

## 実践例

### CI/CDパイプラインでの利用

ジョブごとに一時的な設定ディレクトリを用意するCI環境で、トランスクリプトの場所を予測可能にできます。

```bash
export CLAUDE_CONFIG_DIR="/tmp/claude-config-${CI_JOB_ID}"
export CLAUDE_CODE_PROJECT_DIR_NAME="job-${CI_JOB_ID}"
claude -p "テストを実行して結果を要約して"
```

ジョブ終了後、`job-${CI_JOB_ID}` という名前でトランスクリプトを回収できます。

### マルチテナントホスティングサービス

複数ユーザーのセッションをホストするサービスで、ユーザーIDやワークスペース名をそのままディレクトリ名に使えます。

```bash
export CLAUDE_CODE_PROJECT_DIR_NAME="tenant-${TENANT_ID}-workspace"
claude
```

長いハッシュ化されたパス名を運用側で解決する必要がなくなります。

### コンテナオーケストレーション環境

Kubernetes上でPodごとに使い捨ての設定ディレクトリを割り当てる場合、Pod名などをそのまま利用できます。

```bash
export CLAUDE_CODE_PROJECT_DIR_NAME="${HOSTNAME}"
claude
```

## 注意点

- あくまでオプションの環境変数であり、設定しない場合は従来通り自動生成された名前が使われます
- セッションごとに独自の設定ディレクトリを持たない通常のローカル利用では、基本的に設定する必要はありません
- 同じ名前を複数のセッションで使い回すと、トランスクリプトの保存先が衝突する可能性があるため、一意な値を指定することが推奨されます
- この変数はトランスクリプト保存先の「名前」のみを制御するものであり、保存先そのものの親ディレクトリを変更したい場合は `CLAUDE_CONFIG_DIR` など別の設定と組み合わせる必要があります
