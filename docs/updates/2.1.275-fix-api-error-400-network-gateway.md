## 原文（日本語に翻訳）

APIのエラーレスポンスを書き換えるネットワークゲートウェイの配下にいるユーザーが、betaリクエストヘッダーが拒否された際に毎ターン `API Error: 400` に遭遇していた問題を修正

## 原文（英語）

Fixed a terminal `API Error: 400` on every turn for users behind a network gateway that rewrites API error responses when a beta request header is rejected

## 概要

企業のネットワークゲートウェイの中には、通過するAPIレスポンス（特にエラーレスポンス）の内容を書き換えるものがあります。このようなゲートウェイの配下で、Claude CodeがAPIリクエストに付与するbetaリクエストヘッダーがサーバー側で拒否された場合、書き換えられたエラーレスポンスをClaude Codeが正しく処理できず、毎ターン `API Error: 400` が発生してセッションが使い物にならなくなる不具合がありました。今回の修正により、このようなネットワーク環境でも正常に動作するようになりました。

## 基本的な使い方

この修正は内部的なエラーハンドリングの改善であり、特別な設定は不要です。ネットワークゲートウェイ配下の環境でも通常通りClaude Codeを利用できます。

```bash
claude
```

## 実践例

### 修正前の挙動

企業プロキシやゲートウェイがAPIのエラーレスポンスの形式を書き換える環境で、betaヘッダーが拒否されるたびに `API Error: 400` が発生し、ターンを実行するたびにエラーで停止してしまっていました。

### 修正後の挙動

書き換えられたエラーレスポンスも適切に処理されるようになり、ネットワークゲートウェイ配下でも毎ターンのエラーが発生せず、正常にセッションを継続できるようになりました。

```bash
# 企業のネットワークゲートウェイ配下でも
# 毎ターンのAPI Error: 400が発生しなくなった
claude
```

## 注意点

- この問題は、APIレスポンスを書き換える特殊なネットワークゲートウェイ環境に限定して発生していました
- 通常のネットワーク環境（ゲートウェイなし、またはレスポンスを書き換えないプロキシ）では影響していませんでした
- それでもエラーが解消しない場合は、ネットワーク管理者にゲートウェイの設定（betaヘッダーの扱い）を確認することを推奨します
