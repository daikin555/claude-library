## 原文（日本語訳）
中断されたツール呼び出しバッチのうち、1つの呼び出しがメッセージ付きで承認されていた場合、再開されたバックグラウンドエージェントがそのバッチの半分をそのまま保持してしまう問題を修正しました。

## 原文（英語）
Fixed a resumed background agent keeping half of an interrupted tool batch when one of its calls was approved with a message

## 概要
バックグラウンドエージェントが複数のツール呼び出しをまとめて実行している最中に中断された場合、再開時にはバッチ全体が一貫した状態で処理されるべきです。しかし、バッチ内の1つの呼び出しがメッセージ付きで承認されていた場合に限り、再開後のエージェントが古いバッチの一部（半分）を保持したまま処理を続けてしまう不具合がありました。これにより、意図しないツール呼び出しの重複や状態不整合が発生する可能性がありました。今回の修正でこの問題は解消されています。

## 基本的な使い方
通常通りバックグラウンドエージェントを起動し、途中でツール呼び出しの承認を求められた際にメッセージを添えて承認します。中断が発生しても、再開時は正しい状態から再開されます。

```
claude --agent background-task
# 途中でツール呼び出しの承認ダイアログが表示される
# メッセージ付きで承認 → 中断 → 再開
```

## 実践例

### 修正前の挙動
複数のツール呼び出しを含むバッチのうち1つをメッセージ付きで承認した直後にセッションが中断されると、再開後のエージェントが古いバッチの残り半分の呼び出し情報を引きずったまま動作してしまうことがありました。

### 修正後の挙動
再開時にはバッチの状態が正しくクリーンアップされ、古い呼び出し情報が残ることなく処理が継続されます。

## 注意点
- この問題は特にバックグラウンドエージェントを長時間実行し、承認メッセージを併用するワークフローで顕在化しやすいものでした。
- 通常のフォアグラウンドでの単一ツール呼び出しには影響しません。
