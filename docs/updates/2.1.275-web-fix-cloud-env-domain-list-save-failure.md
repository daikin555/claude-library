## 原文（日本語訳）
[Claude Code on the web] 許可ドメインリストが非常に長いクラウド環境が、保存時には成功するもののセッション開始のたびに失敗していた不具合を修正。現在は保存時点で失敗し、どの程度リストを削減すべきかを表示する。

## 原文（英語）
[Claude Code on the web] Fixed cloud environments with a very long allowed-domains list saving fine and then failing every session start; saving now fails up front and says how much to trim

## 概要
Claude Code on the webのクラウド環境では、アクセスを許可するドメインのリストを設定できますが、このリストが長くなりすぎると内部的な制限を超えてしまい、設定自体は保存できてもセッション開始時に毎回失敗するという問題がありました。今回の修正により、制限を超える長さのドメインリストは保存の時点でエラーとなり、どれだけ削減すればよいかが具体的に表示されるようになりました。これにより、後になってセッションが起動できないという分かりにくい失敗を未然に防げます。

## 基本的な使い方
クラウド環境の設定画面で許可ドメインリストを編集し、保存します。リストが長すぎる場合は、保存時に「あとN件削除してください」といった趣旨のエラーメッセージが表示されます。

```
Cloud environment settings > Allowed domains > 保存
→ (リストが長すぎる場合) "リストが長すぎます。あと◯件削除してください"
```

## 実践例

### 大量の許可ドメインを一括登録しようとした場合
社内で利用する多数の外部サービスドメインをまとめて許可リストに追加しようとした際、上限を超えていれば保存前に警告が出るため、どこを削るべきか把握しやすくなります。

```
1. 許可ドメインを100件以上入力
2. 「保存」をクリック
3. エラー: "ドメインリストが上限を超えています。あと◯件削減してください"
```

### 修正前に発生していた問題
修正前は保存自体は成功してしまい、実際にクラウドセッションを開始しようとするたびに毎回失敗するという、原因が分かりにくい状態になっていました。修正後はこの問題が保存時点で解消されます。

## 注意点
- 許可ドメインリストには内部的な上限があります。大量のドメインを登録する場合はワイルドカードの活用など、リストを簡潔にする工夫を検討してください。
- 既存の環境で既にこの問題の影響を受けていた場合は、ドメインリストを見直して再保存することを推奨します。
