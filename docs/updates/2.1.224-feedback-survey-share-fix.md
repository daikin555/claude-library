## 原文（日本語訳）

フィードバックアンケートのトランスクリプト共有が長いセッションで静かに失敗する問題を修正しました。共有に失敗した場合、成功メッセージではなくエラーが表示されるようになりました。

## 原文（英語）

Fixed the feedback survey's transcript share silently failing on long sessions; a failed share now shows an error instead of a success message

## 概要

Claude Codeでは、セッションの区切りで「How is Claude doing this session?」というフィードバックアンケートが表示されることがあり、評価に加えてセッションのトランスクリプト（会話ログ）をAnthropicと共有するか選択できます。共有を選択すると会話履歴やサブエージェントのログがアップロードされますが、これまでは長いセッションでアップロードが失敗しても画面上は成功したかのように表示されてしまい、ユーザーが気づかないまま共有が実際には行われていない、という問題がありました。今回の修正で、アップロードに失敗した場合は正しくエラーメッセージが表示されるようになりました。

## 基本的な使い方

フィードバックアンケートが表示された際、トランスクリプト共有への同意を選択すると、バックグラウンドでセッションログのアップロードが行われます。

```bash
# セッション終了時などに表示されるアンケート
How is Claude doing this session? [1-5]
Can Anthropic look at your session transcript to help us improve Claude Code? [y/n]

# "y" を選択するとトランスクリプトのアップロードが開始される
```

## 実践例

### 修正前に起きていた問題

数時間にわたる長いセッションや、サブエージェントを多用した大規模なセッションでフィードバックアンケートに回答し、トランスクリプト共有に同意すると、アップロード処理がタイムアウトやサイズ超過などで失敗することがありました。しかし画面には共有が完了したかのような成功メッセージが表示されており、ユーザーは実際にはデータが送信されていないことに気づけませんでした。

```bash
# 長時間のリファクタリングセッション終了後
Can Anthropic look at your session transcript to help us improve Claude Code? [y/n]
> y

# 実際にはアップロードが失敗しているにもかかわらず
"Thanks for sharing your feedback!" のような成功表示が出てしまっていた
```

### 修正後の挙動

アップロードが失敗した場合は、成功メッセージではなく明示的なエラーメッセージが表示されるようになり、ユーザーは共有が失敗したことを正しく把握できます。

```bash
Can Anthropic look at your session transcript to help us improve Claude Code? [y/n]
> y

# アップロードに失敗した場合
"Failed to share transcript. Please try again." のようなエラーが表示される
```

## 注意点

- フィードバックアンケートおよび `/feedback` コマンドは `DISABLE_FEEDBACK_COMMAND=1` 環境変数で無効化できます
- フィードバックアンケート経由で共有されたトランスクリプトの保持期間は最長6ヶ月ですが、`/feedback`・`/bug`・`/share` コマンド経由での共有は5年間保持される点が異なります
- トランスクリプトには会話履歴だけでなく、直近のリクエストのモデル設定やシステムプロンプト（CLAUDE.mdの内容を含む）が含まれる場合があるため、共有前に内容を意識しておくことを推奨します
