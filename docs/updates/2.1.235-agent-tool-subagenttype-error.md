## 原文（日本語訳）

Agentツールが、実際には利用できないセッションでも「general-purpose」というデフォルトのサブエージェントが使えるかのように振る舞ってしまう不具合を修正しました。`subagent_type` を省略した際、そのセッションでgeneral-purposeエージェントが利用できない場合は、代わりに利用可能なエージェント一覧を示す明確なエラーが返されるようになりました。

## 原文（英語）

Fixed the Agent tool advertising a general-purpose default in sessions where that agent is unavailable: an omitted `subagent_type` there now gets a clear error listing the available agents

## 概要

Claude CodeのAgentツールはタスクをサブエージェントに委任する際、`subagent_type` を指定しない場合はデフォルトで「general-purpose」エージェントが呼び出される想定でした。しかし、general-purposeエージェントがそもそも利用できないように構成されたセッション（例えばカスタムのエージェント構成や制限された環境）では、この前提が崩れ、エラーメッセージがその状況を正しく反映していませんでした。今回の修正により、`subagent_type` が省略され、かつgeneral-purposeが利用不可な場合には、そのセッションで実際に呼び出し可能なエージェントの一覧を含む分かりやすいエラーが表示されるようになります。

## 基本的な使い方

通常、Agentツールを使うタスクを委任する際は `subagent_type` にエージェント名を明示的に指定します。

```
Agent(description="コードベース調査", subagent_type="Explore", prompt="...")
```

修正前は、`subagent_type` を省略した際にgeneral-purposeエージェントが存在しない構成だと、原因の分かりにくいエラーになったり、存在しないエージェントが呼ばれたかのような誤解を招く挙動になっていました。修正後は、省略時にgeneral-purposeが使えない場合、利用可能なエージェント名（例: `Explore`, `Plan`, `claude-code-guide` など）が列挙されたエラーメッセージが返るため、次にどのエージェント名を指定すればよいかがその場で分かります。

## 実践例

### カスタムエージェント構成のプロジェクトでの委任

`.claude/agents/` にプロジェクト固有のサブエージェントのみを定義し、general-purposeを含めない構成にしている場合、`subagent_type` を省略してAgentツールを呼び出すと、以前は分かりにくい失敗をしていましたが、修正後は次のようなエラーで利用可能なエージェント名が提示されます。

```
Error: subagent_type is required in this session.
Available agents: code-reviewer, test-runner, doc-writer
```

### エラーメッセージを見てから正しいエージェント名を指定し直す

エラーで列挙されたエージェント名を確認したうえで、`subagent_type` を明示的に指定して再実行します。

```
Agent(description="テスト実行", subagent_type="test-runner", prompt="...")
```

### CI/自動化パイプラインでの委任タスクのデバッグ

自動化スクリプトからAgentツールを呼び出す際に `subagent_type` を渡し忘れていたケースでも、原因不明のタイムアウトやハングではなく、利用可能なエージェント一覧を含む即時エラーとして検出できるようになり、デバッグ時間を短縮できます。

## 注意点

- この修正はエラーメッセージの明確化が目的であり、general-purposeエージェント自体を新たに使えるようにするものではありません
- サブエージェントの一覧はセッションの構成（組み込みエージェントとプロジェクト・ユーザー定義のカスタムエージェント）によって変わるため、エラーに表示される内容も環境ごとに異なります
- `subagent_type` の一致は大文字・小文字や区切り文字（ハイフン／アンダースコア）を区別しません
