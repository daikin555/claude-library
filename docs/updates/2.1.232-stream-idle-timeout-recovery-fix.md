## 原文（日本語に翻訳）

Bedrock・Vertex・gateway経由のデプロイにおいて、ストリームのアイドルタイムアウトエラーが発生した際にリクエストを失敗させてしまい、回復（リトライ）できていなかった問題を修正しました。

## 原文（英語）

Fixed stream idle timeout errors failing the request instead of recovering on Bedrock, Vertex, and gateway deployments

## 概要

Claude CodeはAPIレスポンスをストリーミング形式で受信しますが、一定時間データが流れてこない「アイドルタイムアウト」が発生することがあります。今回の修正前は、AmazonBedrock・Google Vertex AI・LLM gateway経由のデプロイにおいて、このアイドルタイムアウトが発生するとリクエスト全体が失敗として扱われ、ユーザーの操作が中断されてしまっていました。本アップデートにより、こうしたタイムアウトが発生してもリクエストを失敗させるのではなく、正しく回復（リトライなど）できるようになりました。

## 基本的な使い方

BedrockやVertex、gateway経由でClaude Codeを利用している場合、ストリーミングレスポンスの受信中にネットワークの遅延やサーバー側の一時的な停滞でアイドルタイムアウトが発生することがあります。この状況での挙動が今回改善されました。

```bash
# Bedrock経由での利用例
export CLAUDE_CODE_USE_BEDROCK=1
export AWS_REGION=us-east-1
claude

# Vertex経由での利用例
export CLAUDE_CODE_USE_VERTEX=1
export CLOUD_ML_REGION=us-central1
claude

# 修正前: ストリーム中にアイドルタイムアウトが発生すると
#   → リクエスト全体が失敗し、応答が途切れる
# 修正後: アイドルタイムアウトが発生しても
#   → 回復処理が行われ、応答が継続される
```

## 実践例

### 大きなコード生成やリファクタリング中に長い無応答区間が発生する場合

大規模なコード生成やツール呼び出しの合間には、モデル側やネットワーク経路で一時的にデータの送出が止まる区間が発生することがあります。以前はこうした区間がアイドルタイムアウトの閾値を超えると、それまでの生成内容ごとリクエストが失敗として扱われ、最初からやり直しになることがありました。修正後はこのようなタイムアウトが発生しても回復処理が行われるため、作業が中断されにくくなります。

```bash
# Bedrock/Vertex/gateway経由で大規模なタスクを実行中
claude
# ストリームが一時的に停滞しても、修正後は回復して継続する
```

### 社内ゲートウェイやプロキシ経由でネットワーク遅延が発生しやすい環境の場合

LLM gatewayや社内プロキシを経由して接続している環境では、ネットワーク経路の複雑さから遅延やアイドル区間が発生しやすくなります。以前はこうした環境で頻繁にストリームタイムアウトによるリクエスト失敗が発生し、作業効率が低下していました。修正後はタイムアウトからの回復が組み込まれたため、ネットワーク環境に起因する一時的な停滞があっても、より安定して作業を継続できます。

```bash
# gateway経由での利用例
export ANTHROPIC_BASE_URL=https://your-gateway.example.com
claude
# ネットワーク遅延によるアイドルタイムアウトが発生しても
# 修正後はリクエストが失敗せず回復する
```

## 注意点

- Claude Code v2.1.232での修正です。対象はAmazonBedrock・Google Vertex AI・LLM gateway経由のデプロイです。
- 直接Anthropic APIを利用している場合は、この修正の対象となる経路とは異なる場合があります。
- 回復処理が行われても、根本的なネットワーク不安定やサーバー側の障害が続く場合は、最終的にエラーとなることがあります。
- 頻繁にタイムアウトが発生する場合は、ネットワーク環境やゲートウェイの設定も併せて確認してください。
