## 原文（日本語訳）

ファイルディスクリプタが枯渇したマシン上で標準入力（stdin）経由のコマンドを実行した際、バックグラウンドセッションがクラッシュしてワーカーを再起動してしまう不具合を修正しました。

## 原文（英語）

Fixed background sessions crashing and restarting their worker when a command fed through stdin ran on a machine that had run out of file descriptors

## 概要

Claude Codeのバックグラウンドセッションは、標準入力（stdin）を通じてコマンドを実行できます。長時間稼働しているマシンや多数のプロセスを起動しているマシンでは、システム全体のファイルディスクリプタが枯渇することがあり、そのような状況でstdin経由のコマンドを実行すると、バックグラウンドセッションのワーカープロセスがクラッシュして再起動してしまう不具合がありました。今回の修正でこのクラッシュが解消され、ファイルディスクリプタ不足時にもより安定して動作するようになりました。

## 基本的な使い方

特別な操作は不要です。バックグラウンドセッションでのコマンド実行は通常どおり行えます。

```bash
# バックグラウンドセッションでstdin経由のコマンドを実行する例
echo "some input" | claude --print
```

## 実践例

### 長時間稼働環境でのバックグラウンド実行

CI環境や長時間起動し続けるサーバー上で多数のバックグラウンドセッションを並行実行していると、ファイルディスクリプタが枯渇することがあります。修正前はこの状態でstdin経由のコマンドを実行するとワーカーがクラッシュ・再起動し、実行中のタスクが中断されることがありました。修正後はこのような環境でも安定して継続実行されます。

### リソース制限のあるコンテナ環境

`ulimit` でファイルディスクリプタ数が制限されたコンテナ環境でも、同様の問題が発生する可能性がありましたが、今回の修正で改善されています。

## 注意点

- この修正はクラッシュを防ぐものであり、ファイルディスクリプタ自体の枯渇を解消するものではありません。根本的な対策としては、システムの `ulimit -n` を適切に引き上げることも検討してください。
- 大量のバックグラウンドセッションを同時実行する場合は、システムリソースの監視を推奨します。
