## 原文（日本語訳）

権限不足（403 insufficient_scope）で拒否されたMCPツール呼び出しが、これまでは「サインインの期限切れ」として報告されていた問題を修正しました。エラーは不足している権限の名前を明示し、`/mcp` での再認証を案内するようになりました。

## 原文（英語）

Fixed MCP tool calls refused with 403 insufficient_scope being reported as an expired sign-in: the error now names the missing permissions and points to `/mcp` re-authentication

## 概要

OAuth認証を利用するMCPサーバーでは、トークンのスコープ（権限範囲）が不足しているとサーバー側が403 `insufficient_scope` エラーを返すことがあります。これまでこのエラーは誤って「サインインの期限切れ」として扱われており、ユーザーは実際には権限が足りないだけなのに、原因が分からないままサインインし直そうとしてしまうことがありました。今回の修正で、このエラーが発生した場合には不足している具体的な権限名が表示され、`/mcp` コマンドで再認証を行うよう明確に案内されるようになりました。

## 基本的な使い方

権限不足のエラーが発生すると、以下のようなメッセージが表示されるようになります。

```
Error: MCP server "example" refused the tool call — missing scope: "resources:write"
Hint: run `/mcp` to re-authenticate with the required permissions.
```

案内に従って再認証します。

```
/mcp
```

## 実践例

### 権限が追加されたMCPサーバーへの再接続

MCPサーバー側で新しいスコープが必要なツールが追加された場合、既存の認証トークンでは権限が不足し403エラーになります。修正後は不足しているスコープ名がエラーに明示されるため、`/mcp` で再認証すべきだとすぐに判断できます。

```
/mcp
```

### 最小権限で発行されたトークンを使っている場合

組織のポリシーにより最小権限のOAuthトークンを発行している環境では、特定のツールを呼び出そうとした際に権限不足エラーが起きやすくなります。エラーメッセージに含まれる権限名を管理者に伝えることで、必要なスコープの付与を迅速に依頼できます。

## 注意点

- このエラーは認証切れではなく権限不足が原因であるため、単にサインインし直すだけでは解決しない場合があります。管理者にスコープの追加を依頼する必要があることがあります。
- MCPサーバー側が返す権限名の表記は、サーバーの実装に依存します。
