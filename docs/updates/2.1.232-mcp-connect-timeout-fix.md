## 原文（日本語に翻訳）

MCPサーバーがプロトコルバージョンの確認要求に応答しない、または不正な形式の応答を返した際に、接続処理が30秒のタイムアウト時間いっぱいハングしてしまう問題を修正しました。

## 原文（英語）

Fixed MCP connections hanging for the full 30-second connect timeout when a server fails to answer or sends a malformed reply to the protocol-version probe

## 概要

Claude CodeがMCP（Model Context Protocol）サーバーに接続する際、最初にプロトコルバージョンを確認するための問い合わせ（protocol-version probe）を送信します。これまで、接続先のMCPサーバーがこの問い合わせに応答しない、あるいは不正な形式の応答を返してきた場合、Claude Code側はその不具合を早期に検出できず、規定の接続タイムアウトである30秒間まるまる待機してからようやく失敗と判定していました。この修正により、応答なしや不正な応答を早期に検出し、無駄な待ち時間なく接続失敗を判定できるようになりました。

## この変更が影響する場面

新機能というより挙動改善のバグ修正です。以下のような場面で体感的な変化があります。

- 設定ミスや一時的な不調で応答しないMCPサーバーをclaude設定に含んでいる場合、Claude Code起動時やMCP接続時の待ち時間が短縮されます
- 開発中のMCPサーバーがプロトコルバージョン確認への応答を正しく実装できていない場合、問題の切り分けが速くなります

## 実践例

### 応答しないMCPサーバーがある場合の起動速度改善

```bash
# .mcp.json に、現在ダウンしている/応答しないMCPサーバーが設定されている場合
claude

# 修正前:
# そのMCPサーバーへの接続試行で最大30秒間ハング
# 他のMCPサーバーの接続や通常の起動処理も待たされる体感があった

# 修正後:
# プロトコルバージョン確認への応答不良を早期検出し、
# 短時間で接続失敗と判定して先に進む
```

### 開発中のMCPサーバーのデバッグ

自作MCPサーバーを開発していて、プロトコルバージョンの応答フォーマットに不備がある場合。

```bash
# 開発中のMCPサーバーをclaude設定に追加してテスト
claude mcp add my-dev-server -- node ./my-server.js

claude
# 修正後: 不正な形式の応答が早期に検出されるため、
# 「30秒待ってからやっと失敗が分かる」というデバッグの手間が減る
```

## 注意点

- Claude Code v2.1.232で修正されたバグ修正です。
- 接続タイムアウトの上限自体（30秒）が変更されたわけではなく、応答不良や不正な応答を早期検出できるようになったことで、実際に待たされる時間が短縮される点がポイントです。
- 正常に応答するMCPサーバーの接続時間には影響しません。
