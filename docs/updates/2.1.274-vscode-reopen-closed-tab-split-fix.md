## 原文（日本語訳）
閉じたClaudeタブを再度開いた際、そのロックされたグループが別のClaudeタブとファイルの両方を保持している場合にエディタレイアウトが分割されてしまう不具合が修正されました。

## 原文（英語）
[VSCode] Fixed reopening a closed Claude tab splitting the editor layout when its locked group still holds another Claude tab and a file

## 概要
VSCode拡張機能はClaudeのタブが開かれているエディタグループをロックする仕組みを持っていますが、これまでは、閉じたClaudeタブを再度開こうとした際に、そのロック済みグループの中に別のClaudeタブとファイルタブの両方が既に存在していると、意図せずエディタレイアウトが新たに分割されてしまう不具合がありました。今回の修正により、このようなケースでも不要なレイアウト分割が発生しなくなりました。

## 基本的な使い方
特別な操作は不要です。閉じたClaudeタブを通常の方法（履歴からの再オープンなど）で開くだけです。

## 実践例

### 修正前の挙動
ロックされたエディタグループの中に、別のClaudeタブと通常のファイルタブが両方存在している状態で、閉じたClaudeタブを再度開くと、エディタレイアウトが予期せず分割され、画面のレイアウトが乱れることがありました。

### 修正後の挙動
同じ状況で閉じたClaudeタブを再度開いても、既存のロック済みグループ内に適切に配置され、不要なレイアウト分割は発生しなくなりました。

## 注意点
- この修正は「エディタグループのロック機能」と組み合わせて発生していたレイアウト関連の不具合です。`claudeCode.lockEditorGroups` 設定でロック自体を無効化している場合は、そもそもこの問題の影響を受けません。
- 複数のClaudeタブを同時に開いて作業するワークフローで特に影響が大きい修正です。
