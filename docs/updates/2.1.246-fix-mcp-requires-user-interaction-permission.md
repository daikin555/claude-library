## 原文（日本語訳）

`requiresUserInteraction` が指定されたMCPツールの権限確認プロンプトに、依然として「はい、今後は確認しない」という選択肢が表示されていた問題を修正しました。この選択肢は許可ルールを書き込んでいましたが、ツール自体はそのルールを無視していました。

## 原文（英語）

Fixed MCP tools marked `requiresUserInteraction` still offering "Yes, and don't ask again" in their permission prompt; the option wrote an allow rule the tool then ignored

## 概要

MCPツールには、実行のたびに必ずユーザーの操作・確認を必要とする `requiresUserInteraction` というフラグを設定できます。しかし、これまでは権限確認プロンプトに「はい、今後は確認しない」という選択肢が誤って表示されており、ユーザーがこれを選ぶと許可ルールがsettingsに書き込まれるものの、ツール自体は `requiresUserInteraction` の性質上そのルールを無視して毎回確認を求め続けるという矛盾した動作になっていました。今回の修正で、この選択肢自体が表示されなくなり、ユーザーの誤解や無駄な設定変更を防ぎます。

## 基本的な使い方

`requiresUserInteraction: true` を指定したMCPツールを呼び出すと、権限確認プロンプトには「一度だけ許可」に類する選択肢のみが表示され、「今後は確認しない」は表示されなくなります。

```json
{
  "name": "my_tool",
  "requiresUserInteraction": true
}
```

## 実践例

### 決済や破壊的操作を伴うMCPツールの開発

支払い処理やデータ削除など、毎回人間の確認が必須なMCPツールを実装する場合、`requiresUserInteraction` を設定しておけば、ユーザーが誤って「今後は確認しない」を選んでしまう余地がなくなります。

### 社内向けMCPサーバーの権限設計

社内ツール向けのMCPサーバーで、特定の操作について必ず都度承認を求める設計にしたい場合、この修正によって意図した通りに毎回確認が挟まれる動作が保証されます。

### 既存の誤った許可ルールのクリーンアップ

以前のバージョンで誤って書き込まれた許可ルールがsettings.jsonに残っている場合、それらは今後 `requiresUserInteraction` ツールには効果を持たないため、必要であれば手動で整理しておくとよいでしょう。

## 注意点

- `requiresUserInteraction` が設定されたツールは、常にユーザーの明示的な確認を必要とする仕様であり、これは仕様通りの動作です
- 以前のバージョンで誤って作成された許可ルールが残っていても、対象ツールの動作には影響しません（ツールがそのルールを無視するため）が、設定の見通しをよくするために削除しておくことを推奨します
