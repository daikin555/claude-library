## 原文（日本語訳）

プラグインキャッシュが、同一のプラグインに対してSHAを名前とする重複ディレクトリを作成してしまう問題を修正しました。

## 原文（英語）

Fixed the plugin cache creating duplicate SHA-named directories for the same plugin

## 概要

Claude Codeはプラグインをインストールする際、内容のハッシュ（SHA）を名前としたディレクトリにキャッシュを保存する仕組みを持っています。しかし従来はこのキャッシュ管理に不具合があり、本来は同一と判定されるべきプラグインに対して、複数のSHA名ディレクトリが重複して作成されてしまうことがありました。これによりディスク容量が無駄に消費されたり、どのディレクトリが実際に使用されているキャッシュなのか分かりにくくなったりする問題がありました。この修正により、同一プラグインに対して不要な重複ディレクトリが作成されなくなります。

## 基本的な使い方

この修正はプラグインキャッシュの内部管理ロジックに関するもので、ユーザー側の操作は不要です。プラグインをインストール・更新する際、以降は同じプラグインに対して重複したキャッシュディレクトリが作成されなくなります。

```
修正前:
~/.claude/plugins/cache/
├── a1b2c3.../   # 同じプラグインの重複ディレクトリ
└── a1b2c3d4.../ # 同じプラグインの重複ディレクトリ

修正後:
~/.claude/plugins/cache/
└── a1b2c3.../   # 1つのディレクトリのみ
```

## 実践例

### プラグインを頻繁にインストール・アップデートする環境

複数のプラグインを継続的に追加・更新している環境では、キャッシュディレクトリが積み重なりやすい状況でしたが、この修正により重複が発生しなくなり、キャッシュ全体のサイズが不必要に肥大化しません。

### ディスク容量が限られたCI環境

CI環境などディスク容量に制約がある場合、プラグインキャッシュの重複ディレクトリが積み重なるとディスク不足の原因になり得ましたが、修正後はこのリスクが軽減されます。

### プラグイン開発者によるローカルテスト

プラグインを開発しながら何度もローカルでインストール・再読み込みを繰り返すワークフローでは、以前は重複キャッシュが増えて紛らわしい状態になることがありましたが、修正後は同一内容のプラグインが正しく1つのキャッシュとして扱われます。

## 注意点

- 既にディスク上に重複して作成されてしまったキャッシュディレクトリは、この修正だけでは自動的にはクリーンアップされない場合があります。気になる場合はキャッシュディレクトリを手動で確認してください
- この修正はキャッシュの管理ロジックに関するものであり、プラグイン自体の機能や動作には影響しません
