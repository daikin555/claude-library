## 原文（日本語に翻訳）

サブエージェントは、デフォルトで最大3階層の深さまでネストしたサブエージェントを生成できるようになりました（従来は1階層まで）。ネストを無効化したい場合は、環境変数 `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH=1` を設定してください。

## 原文（英語）

Subagents can now spawn nested subagents up to depth 3 by default (was 1); set CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH=1 to disable nesting

## 概要

Claude CodeのAgentツールでは、メインのエージェントがサブエージェントを呼び出し、そのサブエージェントがさらに別のサブエージェントを呼び出すという「ネスト」構造が利用できます。これまではこの階層がデフォルトで1段階（メインから呼ばれたサブエージェントは、それ以上サブエージェントを生成できない）に制限されていましたが、今回のアップデートでデフォルトの許容深度が3階層に引き上げられました。これにより、オーケストレーター役のサブエージェントがさらに複数の専門サブエージェントを束ねるような、多層的なマルチエージェント構成がデフォルト設定のまま実現できるようになります。

## 基本的な使い方

追加の設定は不要で、Claude Code 2.1.219以降ではそのままネストが3階層まで有効になります。例えば、メインエージェントから呼び出した「調査オーケストレーター」サブエージェントが、内部でさらに「コード検索担当」「ドキュメント検索担当」といった専門サブエージェントを呼び出す、という構成が特別な設定なしに動作します。

ネストの深さを従来通り1階層に制限したい場合は、環境変数を設定します。

```bash
export CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH=1
```

`settings.json` の `env` フィールドに記述して、プロジェクト単位・組織単位で恒久的に適用することも可能です。

```json
{
  "env": {
    "CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH": "1"
  }
}
```

## 実践例

### 多層オーケストレーションによる大規模リファクタリング調査

大規模なコードベースの移行作業などでは、トップレベルのメインエージェントが「モジュール別オーケストレーター」サブエージェントを複数起動し、各オーケストレーターがさらに「静的解析担当」「テスト実行担当」「依存関係調査担当」といった専門サブエージェントを配下に呼び出す、という3階層構成が可能になります。

```
メインエージェント
└─ orchestrator: フロントエンド移行担当（深度1）
   ├─ subagent: コンポーネント一覧調査（深度2）
   └─ subagent: 型定義の互換性チェック（深度2）
└─ orchestrator: バックエンド移行担当（深度1）
   ├─ subagent: APIエンドポイント調査（深度2）
   └─ subagent: DBスキーマ差分調査（深度2）
```

このように、各領域担当のオーケストレーターに調査を委譲しつつ、それぞれがさらに専門タスクへ分解できるため、1回のリクエストでより広範囲かつ並列的な調査が行えます。

### コードレビューエージェントが観点別のサブレビュアーを呼び出す

コードレビュー用のサブエージェントが、単独ですべてを見るのではなく、「セキュリティ観点担当」「パフォーマンス観点担当」「命名規則担当」といった、さらに専門化されたサブエージェントを内部で呼び出して知見を集約する、という設計が可能になります。従来はこの構成を組もうとしても2階層目のサブエージェント生成が拒否されていましたが、今回のアップデートでデフォルトのまま動作するようになりました。

### CI/CD環境でネストを意図的に無効化する

一方で、CI環境やコスト・実行時間を厳密に制御したいバッチ処理では、サブエージェントが際限なく増殖することを避けたい場合があります。そのようなケースでは、パイプラインの環境変数として深度を1に固定します。

```yaml
# .github/workflows/claude-review.yml の一部
env:
  CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH: "1"
```

こうすることで、メインエージェントから呼び出されたサブエージェントがさらにサブエージェントを生成することを防ぎ、実行時間やAPIコストの見積もりを立てやすくなります。

## 注意点

- ネストの階層が深くなるほど、トークン消費量や実行時間、APIコストが増大する可能性があります。特にオーケストレーター構成を多用する場合は、コスト監視を併用することを推奨します。
- 深度3はあくまでデフォルト値であり、将来的に上限値自体が変更される可能性があります。挙動を固定したい場合は環境変数で明示的に指定しておくと安全です。
- `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH=1` に設定すると、既存のオーケストレーター型サブエージェント定義（`.claude/agents` 配下でさらにAgentツールを呼び出す設計のもの）が意図通りに動作しなくなる場合があるため、既にネスト構成を利用しているプロジェクトでは変更前に動作確認が必要です。
- サブエージェントの重複した並列実行は、同一ファイルへの競合した書き込みなど、意図しない副作用を招くことがあります。深いネスト構成を組む際は、各サブエージェントの責務範囲を明確に分離してください。
