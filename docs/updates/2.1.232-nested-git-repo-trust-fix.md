## 原文（日本語に翻訳）

ネストしたGitリポジトリが親ディレクトリの信頼設定を継承してしまっていた問題を修正しました。今後は各リポジトリごとに個別の信頼確認が必要になります。

## 原文（英語）

Fixed nested git repositories inheriting trust from a parent directory; each repository now requires its own trust confirmation

## 概要

Claude Codeは、初めて開いたディレクトリに対して「このフォルダを信頼するか」を確認するトラストダイアログを表示し、ユーザーが承認したディレクトリでのみツール実行などを行います。しかし、ある親ディレクトリを信頼済みにした状態で、その配下にネストした別のGitリポジトリ（サブモジュールや、意図的・偶発的にリポジトリ内に含まれた別のGitリポジトリなど）が存在する場合、これまでは親の信頼設定がネストしたリポジトリにもそのまま継承されてしまい、そのリポジトリ独自の信頼確認がスキップされていました。この修正により、ネストしたGitリポジトリはそれぞれ独立して信頼確認を求められるようになりました。

## この変更が影響する場面

これは内部的なセキュリティ修正であり、新機能ではありません。以下のような場面で影響があります。

- モノレポやサブモジュールなど、1つの信頼済みディレクトリ配下に複数のGitリポジトリが存在するプロジェクト構成
- 信頼していない外部リポジトリを、既に信頼済みの親ディレクトリの中にクローンまたは展開した場合

## 実践例

### サブモジュールを含むプロジェクトでの信頼確認

```bash
# ~/projects/main-app を既に信頼済みとする
cd ~/projects/main-app
claude
# ✓ main-app は信頼済みのため確認なしで起動

# main-app 配下にネストした別のGitリポジトリがある場合
cd ~/projects/main-app/vendor/some-library
git status
# .git ディレクトリを持つ独立したリポジトリ

claude
# 修正前: main-app の信頼設定を継承し、確認なしで起動していた
# 修正後: このリポジトリ固有の信頼確認ダイアログが表示される
```

### 外部から取得したリポジトリを親ディレクトリ内に展開したケース

```bash
# 信頼済みのワークスペース内に、外部から取得した
# 検証前のリポジトリを配置してしまった場合

cd ~/trusted-workspace
git clone https://example.com/unknown-repo.git
cd unknown-repo
claude
# ✓ unknown-repo は独立したGitリポジトリとして
#   個別に信頼確認が求められる
```

## 注意点

- Claude Code v2.1.232で修正されたセキュリティ修正です。
- モノレポ構成やサブモジュールを多用するプロジェクトでは、ネストしたリポジトリごとに信頼確認が表示されるようになるため、これまでより確認回数が増える場合があります。これは意図した挙動であり、信頼していないコードが親ディレクトリの信頼設定を経由して実行されることを防ぐためのものです。
- 信頼設定はリポジトリ単位で管理されるようになったため、ネストしたリポジトリを恒常的に使う場合は、それぞれを個別に信頼済みとして承認する必要があります。
