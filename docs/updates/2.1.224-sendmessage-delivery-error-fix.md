## 原文（日本語訳）

チームメイトの受信箱（inbox）への書き込みが実際には失敗していたにもかかわらず、`SendMessage` が「Message sent（メッセージを送信しました）」と報告していた問題を修正しました。配信に失敗した場合は、現在はエラーとして報告されます。

## 原文（英語）

Fixed `SendMessage` reporting "Message sent" when the write to a teammate's inbox had actually failed; failed deliveries are now reported as errors

## 概要

Claude Codeのエージェントチーム機能では、チームメイト間のメッセージは各エージェントの受信箱（inboxファイル）にJSONを追記する形でやり取りされます。従来は、このinboxへの書き込みが何らかの理由（ディスク容量不足、権限エラー、ファイル破損など）で失敗した場合でも、`SendMessage` は成功時と同じ「Message sent」というメッセージを返していました。この修正により、書き込みに失敗した場合は正しくエラーとして報告されるようになり、Claudeや呼び出し元が配信失敗に気づけるようになりました。

## 基本的な使い方

チームリードやチームメイトからのメッセージ送信方法自体は変わりません。

```
SendMessage(to="backend-agent", message="APIエンドポイントの実装が完了しました。レビューをお願いします。")
```

配信に成功すれば、これまでどおり成功が報告されます。配信に失敗した場合は、これまでの「Message sent」という誤った成功報告ではなく、エラーとして報告されるようになりました。

## 実践例

### 受信箱への書き込みが失敗するケース

ディスクフルや権限の問題などでチームメイトのinboxファイルへの書き込みが失敗した場合の挙動が変わります。

```
# 修正前:
# inboxへの書き込みが失敗しても "Message sent" と表示され、
# 送信側のエージェントはメッセージが届いたと誤認したまま
# 後続のタスクを進めてしまっていた

SendMessage(to="teammate-x", message="タスクAが完了しました")
> Message sent   # 実際には配信されていない

# 修正後:
# 書き込み失敗はエラーとして明示的に報告される
SendMessage(to="teammate-x", message="タスクAが完了しました")
> Error: failed to deliver message to teammate-x's inbox
```

### タスクの引き継ぎで応答が来ないと感じた場合の切り分け

チームでの共同作業中、送信したはずのメッセージにチームメイトが反応しない、というケースの原因切り分けが容易になります。

```
# 修正前: SendMessageが常に成功を返すため、
# 「メッセージは届いているのに相手が反応しない」のか
# 「そもそも配信が失敗していた」のかを区別できなかった

# 修正後: 配信失敗時はその場でエラーが返るため、
# 再送信やチームメイトの状態確認など、
# 適切なリカバリー行動をすぐに取れる
```

### 自動化されたチームワークフローでの信頼性向上

長時間稼働するマルチエージェントのワークフローでは、メッセージ配信の失敗が静かに握りつぶされると、タスクの進行状況全体に影響が及びます。今回の修正により、配信失敗が早期に検知できるため、ワークフローの信頼性が向上します。

## 注意点

- この修正はエージェントチーム機能（`CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS` などで有効化する実験的機能）を利用している場合に関係します
- エラーが報告された場合は、対象のチームメイトが生存しているか、inboxのディスク容量や権限に問題がないかを確認してください
- 配信エラーを受け取った際の自動リトライは行われないため、必要に応じて呼び出し側（Claude自身やユーザー）が再送信を判断する必要があります
