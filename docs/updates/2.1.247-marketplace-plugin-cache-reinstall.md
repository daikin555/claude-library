## 原文（日本語訳）

バージョン番号を持たないマーケットプレイスプラグインを2つ目のスコープにインストールした際、稼働中のセッションが使用しているライブキャッシュディレクトリが削除・再作成されてしまい、実行中のセッションを乱す可能性があった問題を修正しました。

## 原文（英語）

Fixed a version-less marketplace plugin's live cache directory being deleted and recreated on a second-scope install, which could disrupt a running session using it

## 概要

Claude Codeのプラグインは、ユーザースコープやプロジェクトスコープなど複数のスコープに個別にインストールできます。バージョン番号を持たないマーケットプレイスプラグインについては、あるスコープへの2回目のインストール処理が、既に別のセッションで使用中のキャッシュディレクトリを削除してから再作成してしまうことがありました。これにより、そのプラグインを使って稼働していたセッションのファイル参照が一時的に失われ、動作が乱れる可能性がありました。今回の修正により、稼働中のキャッシュを不必要に破棄しないようになりました。

## 基本的な使い方

通常通りプラグインをインストールします。

```
/plugin install my-plugin@my-marketplace
```

バージョンを指定しないプラグインを別のスコープ（例: プロジェクトスコープの後にユーザースコープ）へ追加でインストールしても、既存の稼働中セッションのキャッシュには影響しません。

## 実践例

### 複数セッションで同じプラグインを使っている場合

あるセッションでプラグインを使いながら作業を続けている最中に、別のターミナルやスコープで同じプラグインを再インストールしても、稼働中セッションのキャッシュが壊されないため、作業を中断せずに済みます。

### チーム開発でのプラグイン配布

プロジェクトスコープとユーザースコープの両方にマーケットプレイスプラグインを展開するようなチーム運用でも、片方のインストール操作がもう片方の実行環境に悪影響を与えなくなりました。

### CI/CDやスクリプトによる自動インストール

自動化スクリプトが複数スコープへ順にプラグインをインストールするような構成でも、既存のライブセッションを壊すリスクが減り、より安全に運用できます。

## 注意点

- 影響を受けるのはバージョン番号を持たない（バージョンレスの）マーケットプレイスプラグインです
- 問題が発生するのは「2つ目のスコープへのインストール」というタイミングに限られていました
- 明示的にバージョンを固定しているプラグインでは元々この問題は発生しません
