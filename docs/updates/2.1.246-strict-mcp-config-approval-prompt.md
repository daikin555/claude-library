## 原文（日本語訳）

`--strict-mcp-config` を使ったセッションが、実際には読み込まれることのない `.mcp.json` のサーバーについて承認を求めてしまい、バックグラウンドセッションが起動時に待機状態のまま止まってしまう問題を修正しました。

## 原文（英語）

Fixed `--strict-mcp-config` sessions prompting to approve `.mcp.json` servers they would never load, which left background sessions waiting at startup

## 概要

`--strict-mcp-config` フラグは、指定した設定に含まれるMCPサーバーのみを読み込み、プロジェクトの `.mcp.json` に定義された他のサーバーは無視するオプションです。しかし、このフラグを使っていても、実際には読み込まれることのない `.mcp.json` 内のサーバーについて承認確認のプロンプトが表示されてしまう不具合がありました。対話モードであればユーザーが承認するかどうかを選べますが、バックグラウンドで動かしているセッションでは誰も応答できず、起動時にそのまま待機状態で止まってしまうという実害がありました。今回の修正で、読み込まれないサーバーについては承認を求めなくなり、`--strict-mcp-config` の意図通りの挙動になりました。

## 基本的な使い方

`--strict-mcp-config` を使う場合、指定した設定に含まれないサーバーについて余計な承認プロンプトは表示されなくなりました。

```bash
claude --mcp-config ./my-mcp-config.json --strict-mcp-config
# 修正後: .mcp.json のサーバーは読み込まれず、承認プロンプトも表示されない
```

## 実践例

### バックグラウンドやCIでの自動実行

CIパイプラインやバックグラウンドプロセスとして `--strict-mcp-config` 付きでClaude Codeを起動する場合、以前は無関係な `.mcp.json` サーバーの承認待ちで処理がハングしていました。修正後は起動時に止まることなく処理が進みます。

### 複数プロジェクトを横断する厳格な設定管理

チームの `.mcp.json` にはさまざまなMCPサーバーが定義されているが、特定の自動化タスクでは限定した設定のみを使いたい、という場面で `--strict-mcp-config` を安心して使えるようになりました。

### 起動時の不要な対話を排除する

自動化スクリプトの中でClaude Codeを呼び出す際、意図しない承認プロンプトによってスクリプトが停止するリスクがなくなり、非対話的なワークフローが安定します。

## 注意点

- `--strict-mcp-config` を指定していない通常のセッションでは、`.mcp.json` のサーバーは通常通り読み込まれ、必要に応じて承認プロンプトが表示されます
- 承認プロンプトが不要になるのは「実際に読み込まれないサーバー」に限られ、指定した設定内のサーバーについては引き続き通常の承認フローが適用されます
