## 原文（日本語訳）

（Windows/macOS）ヘッドレスセッションが、異常終了したセッションによって `~/.claude/sessions` に残された古いエントリをクリーンアップしない不具合を修正しました。

## 原文（英語）

Windows/macOS: Fixed headless sessions not cleaning up stale entries in `~/.claude/sessions` left by sessions that exited uncleanly

## 概要

Claude Codeはヘッドレスモード（`-p` などの非対話実行）でセッション情報を `~/.claude/sessions` に記録します。しかし、プロセスが強制終了やクラッシュなどで正常に終了しなかった場合、そのセッションのエントリが残り続け、後続のヘッドレスセッションが起動時にこれらの古いエントリをクリーンアップしない不具合がWindowsとmacOSで発生していました。今回の修正により、異常終了によって残された古いセッションエントリが適切に削除されるようになりました。

## 基本的な使い方

ヘッドレスモードでセッションを実行する際の挙動自体は変わりません。

```bash
claude -p "このリポジトリのテストを実行して結果を要約して"
```

修正後は、過去に異常終了したヘッドレスセッションの古いエントリが `~/.claude/sessions` に蓄積されず、新しいセッション起動時に自動的に整理されます。

## 実践例

### CI/CDパイプラインでの繰り返し実行

CIジョブの中でヘッドレスモードのClaude Codeを繰り返し実行する構成では、ジョブがタイムアウトやキャンセルで異常終了することがありますが、その際に残る古いセッションエントリが今後は溜まり続けません。

### 自動化スクリプトからの定期実行

cronやタスクスケジューラなどからヘッドレスセッションを定期的に呼び出す運用で、一部の実行が失敗しても `~/.claude/sessions` が肥大化することを防げます。

### ローカル開発でのバッチ処理

ローカル環境で複数のヘッドレスセッションを連続して実行し、途中で中断（Ctrl+Cなど）した場合でも、次回起動時に古いエントリが適切に片付けられます。

## 注意点

- この修正はWindowsとmacOSに関する記述ですが、セッションエントリの蓄積自体はプラットフォーム共通の問題である可能性があるため、他プラットフォームでの挙動が気になる場合は最新バージョンへの更新を推奨します
- `~/.claude/sessions` に大量の古いエントリが既に存在する場合、それらは新しいセッション起動時のクリーンアップ処理によって整理されます
