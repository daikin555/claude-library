## 原文（日本語に翻訳）

- mod の `tool.check` の回答に `decider: "person"` を追加しました。パーミッションダイアログまたはホストのコールバックだけが承認でき、誰にも確認できない環境では mod の理由付きで拒否されます。
- mod の `tool.check` イベントに `e.isReadOnly` を追加しました。ツール呼び出しが読み取り専用の場合に設定されます。

## 原文（英語）

Added `decider: "person"` to a mod's `tool.check` answer: only the permission dialog or a host's callback can approve the ask, and it is refused with the mod's reason where nobody can be asked

Added `e.isReadOnly` to a mod's `tool.check` event, set when the tool call is read-only

## 概要

mod の `tool.check` で、人間による承認を必須にできるようになりました。`decider: "person"` を返すと、承認できるのはパーミッションダイアログかホストのコールバックのみで、確認できる相手がいない環境では mod が示した理由とともに拒否されます。また、`e.isReadOnly` により読み取り専用の呼び出しを判別できます。

## 基本的な使い方

以下は概念を示す擬似コードです。mod の正確な API 形式は公式ドキュメントで確認してください。

```js
// 擬似コード
tool.check((e) => {
  if (e.isReadOnly) return; // 読み取り専用は対象外
  return { decision: "ask", decider: "person", reason: "本番環境への変更は人の承認が必要です" };
});
```

## 実践例

### 書き込み系だけ人の承認を必須にする

`e.isReadOnly` で読み取りを除外し、それ以外に `decider: "person"` を適用します。

### 無人実行での安全策

誰も承認できない環境では自動的に拒否されるため、意図しない実行を防げます。

## 注意点

- 上記コードは仕様の説明用の擬似コードで、実際のシグネチャとは異なる可能性があります。
- 同バージョンでは mod の `settings.read` フックの仕様も変更されています。
