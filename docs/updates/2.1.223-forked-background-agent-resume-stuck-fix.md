## 原文（日本語に翻訳）

フォークされたバックグラウンドエージェントをresumeする際に、フォーク元（親）のプロンプトの再構築に失敗すると、そのエージェントがセッションの残り時間中ずっと「already resuming（すでに再開処理中）」の状態のまま固まってしまう不具合を修正しました。

## 原文（英語）

Fixed forked background agents getting stuck "already resuming" for the rest of the session when rebuilding the fork's parent prompt failed during resume

## 概要

Claude Codeでは、現在の会話をバックグラウンドでフォークし、システムプロンプトやツール定義を共有した派生タスクとして走らせることができます。フォークはコンテキストの重いタスクを安価に処理できる一方、resume（再開）時にはフォーク元の会話からプロンプトキャッシュを再構築する処理が必要です。この再構築処理が何らかの理由で失敗すると、従来はエラー状態から回復できず、そのエージェントは「already resuming」という表示のまま、セッションが終了するまでずっと操作不能になっていました。今回の修正により、プロンプト再構築に失敗した場合でも状態が正しくリセットされ、再度resumeを試みたり、エージェントを終了させたりできるようになりました。

## 基本的な使い方

バックグラウンドで動いているフォークエージェントの一覧やステータスを確認するには、通常のバックグラウンドタスク一覧の確認方法を使います。

```text
/agents
```

特定のエージェントにメッセージを送って再開（resume）する場合は、エージェントIDや名前を指定します。

```text
# 例: フォークされたエージェント "fork-1" にメッセージを送って再開する
Continue the investigation and report back when done.
```

## 実践例

### 長時間タスクをフォークして裏で走らせる

コンテキストの多いリファクタリング調査などを、現在の会話をフォークして裏で実行させます。

```text
/agents fork "リポジトリ全体のimport文の整合性をチェックして、壊れているものをリストアップして"
```

修正前は、このフォークをresumeするタイミングで親プロンプトの再構築に失敗すると、そのエージェントが恒久的に「already resuming」で固まってしまい、セッション内で復旧できませんでした。修正後は失敗時に状態が正しく戻るため、再度resumeするか、別のフォークを作り直すかを選べます。

### 複数のフォークを並行して走らせ、後からまとめて確認する

複数の調査タスクをそれぞれフォークとして起動しておき、あとでまとめて結果を確認する運用です。

```text
/agents fork "APIエンドポイントの一覧を洗い出して"
/agents fork "未使用の依存パッケージを洗い出して"
```

いずれかのフォークでresume時にエラーが発生しても、今回の修正により他のフォークやセッション全体への影響を最小限に抑えられます。

### resumeが固まった場合の切り分け

もし特定のエージェントが応答しなくなった場合、まずそのエージェントに対して簡単なメッセージを送ってresumeを試み、改善しなければセッションを再起動して切り分けます。

```bash
claude --debug > debug-fork-resume.log 2>&1
```

## 注意点

- 本修正はフォークされたバックグラウンドエージェント固有の不具合であり、通常のサブエージェント呼び出し（都度新規起動）には影響しません。
- プロンプト再構築自体が失敗する根本原因（親セッションの履歴が壊れている、キャッシュが失効しているなど）は別途解消が必要な場合があります。
- 「already resuming」で固まった状態は、修正前のバージョンではセッションを終了するまで解消しないため、該当する場合は最新版へのアップデートが推奨されます。
