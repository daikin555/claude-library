## 原文（日本語訳）

`keybindings.json` に不明なアクション名を指定したバインディングがあると、そのキーが黙って無効化されてしまう不具合を修正しました。今後は該当のバインディングをスキップしてデフォルトのバインディングを維持し、`--debug` を付けて実行した場合は警告がログに出力されるようになりました。

## 原文（英語）

Fixed a `keybindings.json` binding with an unknown action name silently deadening that key; it is now skipped so the default binding keeps working, and a warning is logged under `--debug`

## 概要

`keybindings.json` でキーバインドをカスタマイズする際、タイプミスなどでアクション名を誤って指定してしまうことがあります。これまではそのような不明なアクション名を含むバインディングが存在すると、該当のキーが何のエラーも表示されずに完全に機能しなくなり、デフォルトの動作も含めて一切反応しなくなる不具合がありました。原因の特定が難しく、ユーザーが困惑する要因になっていました。今回の修正で、不明なアクション名のバインディングは無視され、そのキーには元のデフォルトのバインディングが適用されるようになりました。また `--debug` オプション付きで実行すると、無視されたバインディングについて警告がログに出力されます。

## 基本的な使い方

`keybindings.json` にタイプミスなどで不正なアクション名を書いてしまっても、そのキー自体はデフォルトの動作を維持します。

```json
{
  "ctrl+s": "submitPromptt"
}
```

（`submitPrompt` のタイプミス）このような不正な指定があっても、`ctrl+s` は無効化されず、デフォルトの `submitPrompt` のバインディングが有効なままになります。

## 実践例

### `--debug` でキーバインド設定の誤りに気付く

自分の `keybindings.json` の設定が正しく反映されているか不安な場合、`--debug` を付けて起動することで、不明なアクション名を含むバインディングについての警告を確認できます。

```bash
claude --debug
```

### チーム共有のキーバインド設定を安全に配布

チームで共通の `keybindings.json` を配布する際、Claude Codeのバージョン間でアクション名が変更・廃止されていた場合でも、他のキーバインドやデフォルト動作全体が壊れることなく安全に動作します。

### 新しいアクション名への移行期間中の安全性確保

将来のバージョンでアクション名が変更された場合でも、古い設定ファイルを使っているユーザーの操作性が完全に失われることを防ぎます。

## 注意点

- 不明なアクション名のバインディングはスキップされるだけで、`keybindings.json` の該当エントリ自体が自動修正されるわけではありません。手動で正しいアクション名に修正する必要があります
- 警告は `--debug` を付けて実行した場合にのみログに出力されます。通常起動時には表示されません
