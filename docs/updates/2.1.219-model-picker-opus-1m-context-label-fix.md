## 原文（日本語に翻訳）

`/model` ピッカーにおいて、統合されたOpusの行が「Opus (1M context)」ではなく単に「Opus」と表示されていた不具合を修正しました。

## 原文（英語）

Fixed the `/model` picker showing the merged Opus row as plain "Opus" instead of "Opus (1M context)"

## 概要

Claude Code v2.1.219以前では、`/model` コマンドで表示されるモデル選択画面において、複数のOpusモデル（例: Opus 4.8とOpus 5など）が1つの行にマージされて表示される際、本来「Opus (1M context)」と表示されるべきラベルが単に「Opus」とだけ表示されてしまう不具合がありました。これにより、そのOpus行が1Mトークンという大規模なコンテキストウィンドウに対応したモデルであることが一目でわからず、ユーザーが気づかないまま作業を進めてしまう可能性がありました。今回の修正により、ラベルが正しく「Opus (1M context)」と表示されるようになり、モデル選択時にコンテキストウィンドウの規模を正確に把握できるようになりました。

## 基本的な使い方

Claude Codeのセッション内で `/model` コマンドを実行するだけで、選択可能なモデルの一覧がピッカー形式で表示されます。

```
> /model
```

修正後は、Opusの行が以下のように、1Mコンテキスト対応であることが明示された状態で表示されます。

```
? モデルを選択してください:
  Sonnet
  Opus (1M context)
  Haiku
```

矢印キーで選択し、Enterキーで確定することでモデルを切り替えられます。

## 実践例

### 大規模なコードベースを読み込む前にコンテキスト量を確認する

数十〜数百ファイルにまたがるリポジトリ全体の解析や、大量のログファイルの調査を行う場合、通常のコンテキストウィンドウでは情報が切り詰められてしまうことがあります。`/model` を実行し、「Opus (1M context)」の表記を確認してから選択することで、大容量のコンテキストが必要な作業であることを意識しながらモデルを切り替えられます。

```
> /model
# 「Opus (1M context)」を選択

> このリポジトリ全体（src/配下の全ファイル）を読み込んで、
  アーキテクチャ上の重複やレイヤー違反を洗い出してください
```

### 用途に応じてコンテキストサイズとコストのバランスを取る

1Mコンテキスト対応のOpusは大規模な入力を扱える一方で、通常のタスクではオーバースペックになりコストや応答速度の面で不利になることがあります。ラベルが正しく表示されるようになったことで、以下のように用途ごとにモデルを使い分ける判断がしやすくなります。

```
# 小規模な単一ファイルの修正 → Sonnetで十分
> /model
# 「Sonnet」を選択
> utils/date.tsのタイムゾーン処理のバグを直してください

# 巨大なモノレポ全体を横断する調査 → 1M contextのOpusを選択
> /model
# 「Opus (1M context)」を選択
> monorepo全体でこの非推奨APIを使っている箇所をすべて洗い出し、
  移行計画を提案してください
```

### CI/CDログなど長大なテキストを1回のセッションで解析する

ビルドログやテスト結果など、非常に長いテキストをまとめて渡して原因分析させたい場合にも、コンテキストサイズの表示は重要な判断材料になります。

```
> /model
# ピッカーで「Opus (1M context)」であることを確認してから選択

> 添付した10万行のCIログ全体を解析し、
  失敗の根本原因と再発防止策をまとめてください
```

## 注意点

- 「Opus (1M context)」という表示はあくまでUI上のラベルの問題であり、今回の修正はモデル自体の性能やコンテキストウィンドウの実際のサイズを変更するものではありません。
- 組織やプランによっては1Mコンテキスト対応のOpusが利用できない、または追加のレート制限・料金体系が適用される場合があるため、実際に選択する前に契約プランの詳細を確認してください。
- モデル一覧の表示内容やマージ条件（どのOpusバージョン同士が1行に統合されるか）は今後のアップデートで変更される可能性があるため、最新の挙動は都度 `/model` で確認することを推奨します。
- 大きなコンテキストウィンドウを使用すると、入力トークン数に応じてコストやレイテンシが増加する場合があるため、常に1Mコンテキストモデルを選べばよいわけではなく、タスクの規模に応じた使い分けが重要です。
