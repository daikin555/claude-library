## 原文（日本語に翻訳）

ネイティブビルドの音声モードで、音声サービスが接続を拒否した際に「listening…」の状態で固まってしまう問題を修正しました。現在は拒否があった場合、即座に表示されるようになりました。

## 原文（英語）

Fixed voice mode on native builds getting stuck on "listening…" when the voice service rejected the connection; the rejection is now shown immediately

## 概要

Claude Codeのネイティブビルド（デスクトップアプリなど）には、音声で指示を出せる音声モードがあります。今回の修正前は、バックエンドの音声サービスが何らかの理由で接続を拒否した場合、UI上は「listening…（聞き取り中…）」という表示のまま反応がなくなり、実際には接続が失敗していることに気づけない状態になっていました。本アップデートにより、接続拒否が発生した場合は即座にその旨がユーザーに表示されるようになり、無反応な状態で待たされることがなくなりました。

## 基本的な使い方

音声モードはネイティブビルドのUIから音声入力アイコンを選択することで開始します。接続に問題がある場合、修正後はすぐにエラー表示に切り替わります。

```text
1. Claude Codeのネイティブアプリで音声入力を開始
2. 通常は "listening…" と表示され、マイクからの音声を待機
3. 修正前: 音声サービス側で接続が拒否されても "listening…" のまま変化しない
4. 修正後: 接続拒否が発生すると、その場でエラー内容が表示される
```

## 実践例

### ネットワーク制限やファイアウォールで音声サービスへの接続が拒否される場合

社内ネットワークやVPN環境で、音声サービスへのWebSocket接続などがファイアウォールでブロックされているケースです。以前はこの場合でも画面上は「listening…」のまま何も起きず、ユーザーはマイクに向かって話し続けても反応がなく、何が起きているのか分かりませんでした。修正後は接続拒否が即座に表示されるため、ネットワーク側の問題であるとすぐに判断でき、必要であればテキスト入力に切り替えるなどの対応が取れます。

```text
音声入力を開始
→ 修正後: 「接続が拒否されました」等のメッセージが即座に表示される
→ ネットワーク設定の確認、またはテキスト入力への切り替えを検討
```

### 音声サービス側の一時的な障害やレート制限に遭遇した場合

音声サービス側で一時的な障害やレート制限が発生し、接続が拒否されることがあります。以前はこうした一時的な問題が発生してもUI上は無反応な「listening…」状態が続き、ユーザーが問題に気づくまでに時間がかかっていました。修正後は拒否理由がすぐに表示されるため、時間を置いて再試行する、あるいはサポートに問い合わせるといった判断を素早く行えます。

```text
音声入力を開始
→ 修正後: 拒否理由（例: サービス側エラー）が即座に表示される
→ 少し時間を置いて再試行、または他の入力方法を利用
```

## 注意点

- Claude Code v2.1.232での修正です。ネイティブビルド（デスクトップアプリ）における音声モードが対象で、ターミナル上のvoice dictation機能とは異なります。
- 表示されるエラー内容は接続拒否の理由によって異なる場合があります。
- 音声モードが継続して利用できない場合は、テキスト入力への切り替えや、ネットワーク・アカウント設定の確認を検討してください。
