## 原文（日本語訳）

組織のサインイン強制について、ホスト側から提供された設定やユーザーごとのWindowsレジストリ設定が存在していても、管理者の管理設定（managed settings）が読み取れない場合は、起動時にただちに終了するように変更されました。

## 原文（英語）

Changed organization sign-in enforcement to exit at start when the administrator's managed settings cannot be read, even if host-supplied or per-user Windows registry settings exist

## 概要

組織によっては、管理者が管理設定（managed settings）で特定のサインイン方法を強制し、それ以外の方法でのログインを許可しないという運用を行っています。これまでは、管理設定ファイル自体が読み取れない状況でも、ホスト側から提供された設定やユーザーごとのWindowsレジストリ設定が存在していれば、それらを使ってサインイン強制のチェックが継続されてしまう可能性がありました。今回の変更で、管理者の管理設定が読み取れない場合は、他の設定の有無にかかわらず起動時点で即座に終了するようになり、意図しない設定のフォールバックによってポリシーが迂回されるリスクを防ぎます。

## 基本的な使い方

エンドユーザーが直接操作する項目はありません。組織のサインイン強制が有効な環境で、管理者の管理設定ファイルが破損している、権限の問題で読み取れない、あるいは配置場所が誤っているといった状況が発生すると、Claude Codeは起動時にエラーで終了します。

```bash
claude
# 管理設定が読み取れない場合:
# → 起動時にエラーが表示され、プロセスが終了する
```

管理者は管理設定ファイルの配置場所やアクセス権限を確認し、正しく読み取れる状態に修正する必要があります。

## 実践例

### 管理設定ファイルの配置ミスによる誤動作の防止

管理者が管理設定ファイルを誤ったパスに配置してしまった場合、以前はホスト設定やユーザーごとのレジストリ設定にフォールバックしてしまい、意図したポリシーが適用されないまま起動が続行される可能性がありました。今回の変更で、こうした設定ミスの状況を明確な起動失敗として検知できます。

### Windows環境でのレジストリ設定との整合性確保

Windows環境でユーザーごとのレジストリ設定が残っている場合でも、組織全体のポリシーを定義する管理設定が優先されるべきです。管理設定が読み取れないという異常な状態では、レジストリ設定の有無に関わらず起動を止めることで、意図しないポリシーの迂回を防ぎます。

### セキュリティ監査でのフェイルセーフ動作の確認

セキュリティチームが「管理設定が壊れた場合にClaude Codeがどう振る舞うか」を検証する際、フェイルオープン（緩い設定へのフォールバック）ではなく、フェイルクローズ（起動を止める）の挙動になっていることを確認できます。

## 注意点

- この挙動は組織のサインイン強制（enforcement）が有効な構成に関係するものです
- 管理設定ファイルが正しく配置・読み取り可能であれば、通常の起動フローに影響はありません
- 管理設定が読み取れないことでClaude Codeが起動しなくなった場合、管理者は管理設定ファイルのパス、フォーマット、アクセス権限を確認する必要があります
