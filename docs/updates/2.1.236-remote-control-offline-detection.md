## 原文（日本語訳）

Remote Controlが、CLIプロセスが終了したりターミナルが閉じられたりした際に、そのセッションを数秒以内にオフラインとしてマークするようになりました。

## 原文（英語）

Remote Control now marks a session offline within seconds when the CLI exits or its terminal closes

## 概要

Remote Controlは、`claude.ai/code` やスマートフォンのClaudeアプリから、手元のマシンで実行中のClaude Codeセッションに接続して操作を続けられる機能です。Claude自体は接続元のブラウザやアプリ側ではなく、常にローカルマシン上で動作し続けるため、ローカルのCLIプロセスが終了したりターミナルウィンドウが閉じられたりすると、そのセッションはもう操作できません。これまでは、こうした切断が起きてもリモート側の表示にオンライン状態が反映されるまでに時間がかかることがありましたが、今回の改善でCLIの終了やターミナルクローズが数秒以内に検知され、リモート側の表示に即座に反映されるようになりました。

## 基本的な使い方

ユーザーが特別な操作をする必要はありません。Remote Controlでセッションに接続している状態でローカル側のターミナルを閉じたり、`claude` プロセスを終了させたりすると、接続先のブラウザやモバイルアプリ側の表示が数秒以内に「オフライン」に切り替わります。

```
# ローカルのターミナルで実行中のセッションを終了する
Ctrl+C（またはターミナルウィンドウを閉じる）
```

修正前は、実際にはセッションが応答不能になっているにもかかわらず、リモート側の画面上ではしばらくオンラインのまま表示され続けることがありました。改善後は、ローカル側の切断がすぐにリモート側へ反映されるため、ユーザーは「操作できるセッションかどうか」を画面上で正しく判断できます。

## 実践例

### 外出先からスマートフォンで進捗を確認する場合

デスクで作業を始めたセッションをスマートフォンのClaudeアプリから確認しようとしたとき、その間にPCがスリープしたりターミナルが閉じられたりしていれば、アプリの画面には数秒以内にオフライン状態が表示されます。これにより、応答のないセッションに向けてメッセージを送り続けてしまう事態を防げます。

### 複数デバイスでセッションを切り替えながら作業する場合

ノートPCのターミナルで作業していたセッションを閉じ、別の作業に移った場合、ブラウザ版の `claude.ai/code` を開いている別のデバイス側でもオフライン状態がすぐに反映されるため、そのセッションへの再接続を試みるべきかどうかを迷わず判断できます。

## 注意点

- Remote Controlはリサーチプレビュー段階の機能で、Team・Enterpriseプランでは管理者が有効化しない限りデフォルトで無効です
- オフライン検知が速くなったのはローカル側のプロセス終了やターミナルクローズを検知する経路の話であり、ネットワーク断など他の切断要因の扱いが変わるわけではありません
- ローカルマシンをスリープさせずにセッションを継続したい場合は、SSH先などで `tmux` や `screen` の中でセッションを起動しておくと、ターミナルを閉じてもプロセス自体は生き続けます
