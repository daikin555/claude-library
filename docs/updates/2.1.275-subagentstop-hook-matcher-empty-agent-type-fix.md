## 原文（日本語訳）

特定の `matcher` を指定した `SubagentStop` フックが、エージェント種別（agent type）が空だったすべての停止中サブエージェントに対して発火してしまう不具合を修正しました。

## 原文（英語）

Fixed `SubagentStop` hooks with a specific `matcher` firing for every stopping subagent whose agent type was empty

## 概要

`SubagentStop` フックは、サブエージェントの実行が終了したタイミングで発火するフックで、`matcher` を使って特定の種類のサブエージェントだけに絞り込んで実行できます。しかし、サブエージェントのエージェント種別が空文字列になっているケースでは、特定の `matcher` を指定していても、そのフックが本来対象外であるはずのすべての空種別サブエージェントに対して発火してしまう不具合がありました。今回の修正により、`matcher` の絞り込みが意図通りに機能するようになりました。

## 基本的な使い方

`.claude/settings.json` などで `SubagentStop` フックに `matcher` を指定する例です。

```json
{
  "hooks": {
    "SubagentStop": [
      {
        "matcher": "code-reviewer",
        "hooks": [
          {
            "type": "command",
            "command": "echo 'code-reviewer subagent finished'"
          }
        ]
      }
    ]
  }
}
```

## 実践例

### 特定のサブエージェントタイプだけに通知を送りたい場合

`code-reviewer` エージェントが終了したときだけSlack通知を送るようなフックを設定していても、修正前はエージェント種別が空のサブエージェント（例えば汎用的な内部処理など）が終了するたびに誤って発火してしまうことがありました。修正後は `matcher` に一致しないサブエージェントでは発火しません。

```json
{
  "hooks": {
    "SubagentStop": [
      {
        "matcher": "code-reviewer",
        "hooks": [{ "type": "command", "command": "notify-slack.sh" }]
      }
    ]
  }
}
```

### 複数のmatcherを使い分けている場合

複数の `matcher` パターンでサブエージェントごとに異なる後処理スクリプトを実行するような構成でも、エージェント種別が空のサブエージェントが混ざっていると誤発火の影響範囲が広がっていましたが、この修正で解消されています。

## 注意点

- `matcher` を指定しない（空の）`SubagentStop` フックは、従来どおりすべてのサブエージェント終了時に発火します。
- フックの設定を変更した後は、意図した種別のサブエージェントでのみ発火するか、簡単なテストで確認することを推奨します。
