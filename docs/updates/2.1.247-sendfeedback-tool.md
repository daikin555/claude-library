## 原文（日本語訳）

`SendFeedback` ツールが追加されました。セッション中に何か問題が発生した場合、Claudeがフィードバック報告書のドラフトを作成し、ユーザーが確認したうえで `/feedback` から送信できるようになります（`feedbackDrafts` 設定で無効化可能）。

## 原文（英語）

Added the `SendFeedback` tool: when something goes wrong in a session, Claude can draft a feedback report for you to review and send from `/feedback` (turn off with the `feedbackDrafts` setting)

## 概要

これまでセッション中にバグや不具合に遭遇した場合、ユーザー自身が状況を思い出しながら `/feedback` コマンドで報告文を書く必要がありました。`SendFeedback` ツールにより、問題が起きたその場でClaudeが状況を把握したうえでフィードバック報告のドラフトを自動生成し、ユーザーはそれを確認・編集して送信するだけで済むようになります。報告の質が上がり、送信までの手間も減ります。

## 基本的な使い方

ユーザーが明示的に呼び出す必要はありません。セッション中に予期しないエラーや不具合が発生すると、Claudeが自動的に `SendFeedback` ツールでドラフトを作成します。

```
（何らかのエラーが発生した後）
Claude: フィードバック報告のドラフトを作成しました。/feedback で内容を確認し、送信できます。
```

`/feedback` を実行すると、ドラフトの内容を確認・編集してから送信するかどうかを選べます。

## 実践例

### ツール実行エラーに遭遇したとき

コマンド実行やファイル操作で予期しないエラーが起きた場合、Claudeがエラー内容や再現手順を含むドラフトを自動生成します。ユーザーは技術的な詳細をゼロから書く必要がありません。

### 挙動がおかしいと感じたとき

Claudeの応答や動作が期待と異なると感じた場面でも、その場の文脈を踏まえたフィードバックドラフトが用意されるため、後から状況を再現して報告する手間が省けます。

### 組織的にフィードバックドラフトを無効化したいとき

チームによっては自動ドラフト作成を望まない場合もあります。その際は設定でこの挙動自体をオフにできます。

```json
{
  "feedbackDrafts": false
}
```

## 注意点

- ドラフトは自動送信されません。必ず `/feedback` でユーザーが内容を確認してから送信する必要があります
- `feedbackDrafts` 設定を `false` にすると、この自動ドラフト作成機能全体を無効化できます
- ドラフトにはセッションの文脈情報が含まれる可能性があるため、送信前に内容を確認することが推奨されます
